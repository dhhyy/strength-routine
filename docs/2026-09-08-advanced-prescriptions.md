# 9/8 · 휴식·템포·슈퍼세트·AMRAP 상세 명세

작성일: 2026-09-08. 사용자의 “문서 쓰고 다 구현해줘”는 직전 답변에서 미구현이라고 밝힌 **휴식 시간·템포·슈퍼세트·AMRAP**을 관리자 편집부터 사용자 프로그램 확인·실제 세트 기록·저장 복원까지 연결하는 요청으로 해석한다.

**설계 초안. 구현·검증 결과를 아직 기입하지 않았다.** 아래는 개발과 시험을 맞추기 위한 계약이며 실제 코드·화면·실행 결과를 대조한 뒤 §12를 채운다. 이전 관리자 기능의 189개 통과는 이 네 기능의 검증 결과가 아니다. 시뮬레이터를 실행하지 않고, 실제 기기·OS 종료·잠금화면 검증은 별도로 남긴다.

기존 [정밀 편집 명세](2026-09-08-admin-precise-editor.md), [기록 마감 명세](2026-09-08-session-lifecycle.md), [로드맵 R04·R05](2026-09-08-development-roadmap.md)를 계승한다. 운영자는 1명이며 별도 내부 Flutter 관리자에서 작성한다. 관리자 웹 서버·인증·온라인 게시·구독·운동 사전·백업 복원 등 전체 로드맵이 이번 요청만으로 완료되는 것은 아니다.

## 1. 부족했던 부분과 완료의 의미

현재 정밀 편집기는 주차·세션·운동·세트를 독립적으로 편집하지만, 최종 `ProgramSet`은 반복·RIR·중량·필수 여부만 표현한다. 휴식이나 템포를 설명란에 적으면 사용자 기록 화면에서 해당 세트의 지시로 읽을 수 없다. 두 운동을 슈퍼세트라고 적어도 다음 세트 이동은 운동별로 펼친 순서를 따르며, AMRAP도 고정 반복과 구별되지 않는다.

이번 완료 기준은 입력칸 추가가 아니다. 관리자가 한 세트의 휴식·템포·AMRAP을 바꾸고 두 운동을 슈퍼세트로 묶은 뒤 검토·새 버전 저장·내보내기할 수 있어야 한다. 새 프로그램을 시작한 사용자에게 지시와 순서가 보이고, 실제 반복 수를 직접 기록하며 휴식 상태를 확인할 수 있어야 한다. 저장 후 다시 읽어도 같은 처방·기록·타이머가 남아야 한다.

기존 5개 프로그램의 운동량이나 처방을 자동 변경하지 않는다. 아래 수치와 운동 A/B는 편집·시험용 합성 자료이고 실제 사용자에게 추천하는 프로그램이 아니다.

## 2. 범위와 판단

| 대상 | 이번 연결 범위 | 별도로 남는 기능 |
|---|---|---|
| 휴식 | 개별 세트의 휴식 초, 미지정/0초 구분, 저장된 실제 완료에서 명시 시작하는 앱 내 타이머·일시정지/재개·종료·복원 | 자동 시작·사용자 임의 시간·OS 알림·잠금화면·워치·소리/진동·백그라운드 서비스 |
| 템포 | 개별 세트의 4구간 지시, 입력 검증, 검토/사용자 화면 표시, 스냅샷 보존 | 메트로놈·센서 기반 수행 측정·실제 템포 자동 판정 |
| 슈퍼세트 | 같은 세션의 연속 운동 그룹, 교차 세트 순서, 다음 미기록 세트 안내 | 서킷 전용 시간 제한·라운드 타이머·드롭세트·복합 스크립트 |
| AMRAP | 고정 반복과 구분되는 세트 유형, 기준 반복 안내, 실제 반복 직접 기록 | AMRAP 성과에 따른 자동 증량·진급·실패 자동 판정 |
| 관리자 | 기존 정밀 편집, raw 초안, 복사/정렬/undo, 변경 검토, 새 버전 저장과 내보내기 | 원격 로그인·게시·동시 편집·과거 게시 버전 복구 |
| 사용자 | 프로그램/결과/운동/검색 표시, 수행 순서, 실제 기록, 영구 저장 | 기기 동기화·원격 프로그램 즉시 갱신 |

주당 세션 수가 모든 주에 같아야 한다는 기존 제약은 유지한다. 반복 범위·워밍업 유형·대량 조정·자동 디로딩까지 이 작업에 포함한 것으로 설명하지 않는다.

## 3. 데이터 계약

아래는 이번 구현에서 사용할 계약이다. 원본 프로그램 구조와 경로 ID를 바꾸지 않고 추가 정보를 같은 스냅샷에 넣는다. 코드 구현과 실제 시험의 완료 여부는 §12에 별도로 기록한다.

### 3.1 세트 처방

| 필드 | 의미 | 누락된 옛 데이터 | 검증 원칙 |
|---|---|---|---|
| `restSeconds` | 해당 세트 뒤에 안내할 휴식 시간 | `null`·미지정 | 0~3600의 정수 또는 미지정. 미지정과 명시적 0초를 구별한다. |
| `tempo` | 편심 → 하단 정지 → 구심 → 상단 정지의 4구간 지시 | `null`·미지정 | 각 구간은 0~9초, 구심 구간만 `X` 허용. 정규식은 `^[0-9]-[0-9]-[0-9X]-[0-9]$`이다. |
| `isAmrap` | 실제 가능한 반복 수를 사용자가 기록하는 세트임을 표시 | `false` | 불리언만 허용한다. 고정 반복과 같은 문구로 표시하지 않는다. |
| 기존 `repetitions` | 고정 반복 수 또는 AMRAP의 기준 반복 수 | 기존 값 | 관리자 최종 입력은 기존 1~100 정수 계약을 따른다. AMRAP에서 달성 여부를 자동 판정하지 않는다. |

AMRAP은 반복 수 필드를 없애거나 `0`, `-1`, 임의의 큰 수로 치환하지 않는다. 처방의 기준 반복 수와 실제 반복 수를 분리한다. 기준 반복은 달성해야만 완료할 수 있는 최소값이 아니다. 실제 완료 기록의 반복 수는 사용자가 수행한 양수이며, 처방값을 완료 사실로 자동 채우지 않는다. RIR의 `0`과 미지정은 계속 구분한다.

템포는 문자열에 기호를 아무렇게나 추가하는 메모가 아니다. 사용자에게 구간 순서를 설명하고 `3-1-X-0` 같은 표기를 읽을 수 있게 한다. `X`는 구심 구간의 빠른 동작 지시이며 초 단위 측정값이 아니다. `31X0`, `3-1-x-0`, `10-0-1-0`, `X-0-1-0`은 정한 최종 형식에 맞지 않는다. 템포 지시는 실제 수행을 측정한 결과가 아니므로 완료 저장에 실제 템포를 날조하지 않는다.

### 3.2 슈퍼세트 그룹

`ProgramExercise.supersetGroup`은 세션 안 그룹을 식별하는 선택 문자열이다. 값은 앞뒤 공백을 제외한 1~40자 ID이며 빈 값은 그룹 미지정이다. 그룹은 운동 이름이나 메인 리프트로 추정하지 않는다. 한 운동의 모든 세트가 그 운동의 그룹 순서에 참여한다. 그룹은 해당 세션에만 유효하며 다른 주차나 세션에서 같은 라벨을 사용해도 같은 운동 기록으로 합치지 않는다.

최소 유효 조건은 다음과 같다.

1. 그룹이 없으면 기존 단독 운동 순서다.
2. 한 그룹에는 최소 두 운동이 있어야 한다.
3. 같은 그룹의 운동은 세션 목록에서 연속해야 한다.
4. 운동·세트 ID는 기존 안정적인 식별자를 유지한다.
5. 서로 다른 세트 수를 허용하고 존재하는 세트만 교차한다. 없는 세트를 만들거나 원본 세트를 삭제하지 않는다.

운동 하나를 삭제하거나 이동해 그룹이 불완전해져도 편집 중 raw 초안은 보존한다. 프로그램 검토에서는 위치와 오류를 안내하고 확정을 막는다. 편집기가 다른 운동을 몰래 같은 그룹에 넣거나 그룹을 풀지 않는다.

### 3.3 관리자 raw 초안

휴식 숫자와 템포는 입력 중 문자열 그대로 저장한다. 예를 들어 휴식 `9.`와 템포 `3-`는 최종 처방으로 확정할 수 없지만, 초안 저장·앱 재진입에서 원문이 남아야 한다. 검증은 `변경 검토`에서 수행한다.

새 필드는 기존 깊은 복사·주차 덮어쓰기·프로그램 복제·undo/redo·초안 저장의 구성요소다. 화면에서만 들고 있고 JSON에서 누락되는 값을 만들지 않는다. undo는 현재 편집 세션의 최대 50단계라는 기존 범위를 따른다. 이미 확정한 카탈로그나 사용자 기록을 undo로 바꾸지 않는다.

## 4. 저장 형식과 하위 호환

세 종류의 파일 버전은 서로 다르다. 운동 파일의 버전을 카탈로그 버전으로 안내하지 않는다.

| 파일 | 이번 개발 전 | 새 기능 파일의 계약 |
|---|---|---|
| 소비자 카탈로그 | `schemaVersion: 1` | v1/v2 읽기. 고급 처방이 있으면 v2, 없으면 v1 쓰기. |
| 관리자 작업 파일 | v1/v2 읽기, v2 쓰기 | v1/v2/v3 읽기. 고급 처방 또는 고급 초안 입력이 있으면 v3, 없으면 v2 쓰기. |
| 사용자 운동 파일 | v1/v2/v3 읽기, v3 쓰기 | v1/v2/v3/v4 읽기. 진행/보관 계획에 고급 처방이 있으면 v4, 없으면 v3 쓰기. |
| 실행 휴식 타이머 | 없음 | 운동 파일 경로 뒤에 `.rest-timer.json`을 붙인 별도 로컬 파일. 운동 기록과 원자적으로 함께 쓰는 파일이 아니다. |

단순히 선택 필드를 추가하고 같은 envelope 버전을 계속 쓰면 구 앱의 `fromJson`이 새 필드를 무시한 뒤 덮어쓸 수 있다. 따라서 새 포맷은 읽기 호환을 제공하면서 이전 앱의 손실 쓰기를 막는 방향으로 구분한다. 새 reader 역시 구 envelope 안에 고급 처방 필드가 있으면 거절한다. 버전 숫자만 낮춰서 새 데이터를 구 파일로 위장하지 않는다.

고급 속성이 미지정이고 AMRAP이 꺼져 있는 기존 세트는 기본 형식으로 남길 수 있다. 따라서 새 기능을 사용하지 않는 기본 5개 `assets/programs.json`의 bytes를 바꿀 이유가 없다. 반면 명시적 휴식 0초는 새로운 의미를 담으므로 고급 속성이다. 관리자에서 아직 잘못된 휴식 `9.`를 입력한 상태도 raw 초안을 보존할 새 형식이 필요하다.

미지원 버전·틀린 타입·잘못된 참조·잘못된 새 처방은 읽기 오류이며, 원본 파일을 빈 상태로 교체하지 않는다. **필드 누락만 기본값으로 이행**하고 명시적으로 잘못된 값은 조용히 정상값으로 바꾸지 않는다.

원래 진행/보관 계획은 선택 당시 프로그램 스냅샷을 계속 사용한다. 관리자 카탈로그를 개정해도 기존 사용자 계획의 휴식·템포·세트 유형·순서를 자동 갱신하지 않는다. 새 사용 또는 사용자가 새로 시작하는 계획에서 개정 프로그램을 선택한다.

## 5. 관리자 화면 흐름

1. 관리자 목록의 `정밀 편집`으로 기존 프로그램을 열거나 `복제해서 만들기`로 별도 프로그램을 시작한다.
2. 주차 → 세션 → 운동 → 개별 세트를 선택한다.
3. 개별 세트의 휴식·템포·AMRAP을 조절한다. RIR·중량·필수 여부와 각각 독립이다.
4. 같은 세션에서 연속 운동들을 슈퍼세트 그룹으로 지정한다.
5. 입력 저장 상태를 확인하고 필요하면 복사·순서 변경·undo/redo를 사용한다.
6. 기존 프로그램을 바꿨다면 새 버전을 입력한다.
7. `변경 검토`에서 새 필드와 그룹 구성, 반복 방식, 전체 실행 순서를 확인한다.
8. `검토한 프로그램 저장`의 파일 저장이 성공한 뒤 확정 목록을 바꾼다.
9. 내보낸 카탈로그를 다시 읽어 새 처방과 버전이 남아 있는지 확인한다.

세트 변경 비교에는 휴식·템포·AMRAP 변경도 포함한다. 그룹 변경은 운동 수준의 의미 변화이므로 단순 세트 추가/삭제 수치만으로 검토했다고 표시하지 않는다. 이전값/새값과 전체 구성 중 어떤 부분을 직접 비교하는지 분명히 보여준다.

좁은 화면에서는 입력을 세로로 배치하고 큰 글자에서도 라벨을 자르지 않는다. 데스크톱에서는 기존 정밀 편집의 열 구성을 유지한다. 글꼴·색·간격은 [앱 디자인 시스템](03-design-system.md)을 따르며 기본 보라색 컨트롤이나 숫자 입력 때문에 한글 폰트가 깨지는 상태를 남기지 않는다.

## 6. 사용자 화면과 실행 순서

### 6.1 프로그램 확인

프로그램 상세·시작 전 결과·운동 기록·운동 검색의 동일 세트는 같은 의미를 보여준다. 화면마다 하나는 `8회`, 다른 하나는 `AMRAP`으로 보이는 모순을 피한다. 휴식 미지정은 처방하지 않은 것이고, `휴식 없음`은 명시적 0초다.

기본 표시 요소는 반복 방식, 목표 중량, RIR, 필수/선택, 휴식, 템포다. 미지정 선택 필드를 빈 기호로 길게 나열할 필요는 없지만, 지정된 내용은 세트 상세에서 빠짐없이 확인할 수 있어야 한다. 슈퍼세트에는 그룹과 운동 간 순서를 표시한다.

### 6.2 교차 순서 예시

합성 세션에 단독 운동 C가 먼저 있고, 같은 그룹의 운동 A는 3세트, B는 2세트라고 가정한다. 그룹 내 순서는 다음과 같다.

`A 1세트 → B 1세트 → A 2세트 → B 2세트 → A 3세트`

`완료 후 다음 세트`는 이 순서에서 이후의 미기록 세트를 찾는다. 이미 완료/제외한 세트는 다시 완료할 세트로 안내하지 않는다. 운동별 원래 번호와 경로 ID는 유지하며, 화면 정렬 때문에 기록의 소속이 바뀌지 않는다. 세트를 직접 눌러 순서와 다른 세트를 기록하는 기존 기능도 막지 않는다.

### 6.3 AMRAP 기록

기준 반복 수를 보되 사용자는 실제 수행한 반복을 입력한다. 기준보다 적거나 많다는 이유만으로 완료를 금지하지 않는다. AMRAP이라는 이유로 반복을 자동 증가시키거나 RIR 0을 강제하지 않는다. 실제 RIR은 선택 입력이고 실제 반복은 명시 입력이다.

실제 반복·중량은 기존 기록 추세의 합계와 볼륨에 포함한다. 고정 반복을 전제로 한 D5 처방 비교에서는 AMRAP을 비교 근거에서 제외하고 미래 AMRAP 세트도 D5 감량 대상에서 제외한다. AMRAP 기준 반복을 고정 목표로 잘못 비교하지 않으며, 새 자동 조절 정책을 추정하지 않는다.

## 7. 휴식 타이머 계약

### 7.1 처방과 타이머는 별도다

`restSeconds`는 프로그램 지시다. 실행 타이머는 특정 계획·세션·세트에 연결된 사용자 운동 상태다. **휴식이 1초 이상 지정되어 있고 실제 완료 기록이 저장된 세트에서 사용자가 직접 시작한다.** 초안을 열거나 세트를 확인하거나 완료 버튼을 눌렀다고 자동으로 시작하지 않는다. 미지정/0초 처방에 임의의 기본 60초를 끼워 넣지 않는다. 사용자가 처방과 다른 시간을 직접 입력하는 기능은 이번 범위가 아니다.

타이머는 앱 내 한 개다. 실행 중이거나 일시정지한 타이머가 있는데 새 휴식을 시작하면 기존 타이머 교체를 확인한다. 취소하면 이전 타이머를 그대로 둔다. 확인한 새 타이머의 저장에 성공해야 교체하며 저장 실패를 성공으로 표시하지 않는다.

실행 중에는 일시정지·종료할 수 있고, 일시정지는 남은 시간을 유지한다. 재개는 남은 시간으로 새로운 종료 시각을 계산하며 최초 처방 전체 시간을 다시 부여하지 않는다. 단순 UI 재빌드·화면 복귀·기록 저장 재시도로 새 시작 시각을 만들지 않는다.

### 7.2 저장과 복원

타이머에는 소속 계획/세션/세트, 시작/종료 시각, 상태, 일시정지한 남은 밀리초와 출처 정보를 저장한다. 출처 정보는 시작 당시 실제 기록 JSON과 해당 세션의 마감/재개 사건 수를 포함한다. 시간은 UTC 기준으로 보관하며 같은 종료 시각을 기준으로 남은 시간을 계산한다. 화면의 초 단위 갱신 때문에 매초 파일을 저장하지 않는다.

앱을 다시 열면 저장된 종료 시각을 읽고 남은 시간을 복원한다. 이미 종료 시각이 지났으면 완료 상태로 표시하고 새 전체 시간을 시작하지 않는다. 음수 남은 시간을 표시하지 않는다. 시간대가 바뀌어도 같은 순간의 종료 시각은 바뀌지 않는다.

저장된 상태가 현재 활성 계획의 같은 세트·같은 실제 기록을 참조하는지 검사한다. 기록 수정, 해당 세트의 새 초안, 마감 후 재개, 계획 교체로 출처가 달라지면 이전 타이머를 다시 보여주거나 재개하지 않는다. 세션이 마감되거나 계획이 보관되었을 때도 숨기고 재개를 막는다.

이 구현은 앱 내 표시와 복원에서 UTC 종료 시각을 사용한다. 별도 단조 시계 기반의 드리프트 탐지나 종료 중 시스템 시계 조작을 완전히 검출하는 기능을 완료했다고 주장하지 않는다. 시스템 시간을 바꾸면 표시가 달라질 수 있으며 실제 기기 확인에서 이를 별도로 관찰한다.

### 7.3 완료·정정·취소 경계

새 완료와 같은 기록의 정정을 구분한다. 이번 타이머는 모두 명시 시작이므로 기존 완료의 중량·반복·메모 수정, 세트 제외, 초안 입력, 기록 재개가 새 휴식을 자동 시작시키지 않는다. 같은 시작/조절 저장 후보의 재시도는 후보의 시각을 유지한다.

휴식 종료는 기록 삭제가 아니다. 휴식을 중지해도 완료된 실제 기록은 남는다. 세션 마감이 성공하면 해당 세션의 타이머는 화면에서 숨기고 재개를 막는다. 마감을 나중에 다시 열어도 사건 수가 바뀌므로 마감 전 타이머를 되살리지 않는다. 마감 저장이 실패하면 원래 세션 상태를 유지하며 타이머를 마감 성공으로 처리하지 않는다.

타이머는 `${trainingFile.path}.rest-timer.json`에 별도로 저장한다. **타이머 저장 실패는 이미 성공한 실제 기록을 되돌리거나 다음 기록을 막지 않는다.** 타이머 실패 메시지와 재시도는 기록 저장 실패와 구분한다. 재시도한다고 실제 세트를 다시 완료시키지 않는다.

로드맵 R04에서 제안했던 신규 완료 자동 시작, 기록과 타이머의 원자 저장, 마감과 별도 타이머 파일의 원자 삭제, 단조 시계 드리프트 탐지, OS 알림까지 구현했다는 뜻은 아니다. 이번에는 명시 시작과 출처 유효성 검사를 통해 별도 파일 타이머를 안전하게 사용한다. 타이머 파일이 남더라도 무효 출처는 다시 실행하지 않는다.

## 8. 실패·취소·경합 처리

| 상황 | 보존할 것 | 화면/재시도 기준 |
|---|---|---|
| 휴식/템포 입력 형식 오류 | raw 문자열과 나머지 구성 | 위치와 이유를 안내하고 검토 확정을 막는다. |
| 그룹이 한 운동만 남거나 떨어져 있음 | 사용자가 편집한 그룹/운동 순서 | 몰래 해제/재정렬하지 않고 구성 수정으로 돌아간다. |
| 기존 초안 교체 취소 | 이전 raw 초안과 파일 bytes | 새 후보를 저장하지 않는다. |
| 관리자 초안 저장 실패 | 최신 메모리 입력과 이전 디스크 파일 | 미저장 표시와 최신 입력 재시도를 제공한다. |

오프라인에서도 로컬 편집·기록·타이머가 동작하는 범위를 목표로 한다. 온라인 서버나 알림 권한이 없다는 이유로 이미 저장한 운동 기록 열람을 차단하지 않는다. 이번에는 네트워크 요청·알림 권한 요청을 추가하지 않는다.

| AP21 | 임시 저장 실패·연속 동작·늦은 콜백 | 파일 원자성/최신 후보/중복 시작 보호를 직접 검증한다. |

## 10. 운영자가 확인할 순서

실제 앱 조작 명령과 지원 기기는 [기기 가이드](2026-09-08-device-test-guide.md)를 따른다. 현재 문서 작성은 실행 허가나 시뮬레이터 재개가 아니다. 아래 합성 프로그램은 QA에만 사용하며 기본 프로그램을 덮어쓰지 않는다.

1. 기존 프로그램을 복제하고 새 ID·버전을 입력한다.
2. 두 운동을 연속 배치하고 하나의 슈퍼세트로 지정한다.
3. 첫 운동 3세트, 다음 운동 2세트로 구성하여 순서가 교차하는지 검토한다.
4. 한 세트에 휴식과 템포를 입력하고 다른 세트에는 AMRAP을 지정한다.
5. 휴식에 잘못된 소수를 넣고 검토 실패와 입력 보존을 확인한 후 정상값으로 바꾼다.
6. 한 주를 복사하고 복사본 한 세트만 변경하여 원본 값이 바뀌지 않는지 확인한다.
7. undo/redo 후 프로그램 변경 검토에서 새 처방과 그룹이 보이는지 확인한다.
8. 새 버전 저장·내보내기 후 새 저장소에서 다시 읽어 동일한 내용을 확인한다.
9. QA 사용자 계획을 새로 시작하고 상세/결과/검색/운동 화면의 처방을 비교한다.
10. AMRAP 기준보다 다른 실제 반복 수를 입력하고 저장 후 다음 순서를 확인한다.
11. 저장된 완료 세트에서 휴식을 명시 시작한 뒤 일시정지/재개·교체 확인/취소·종료/만료를 확인한다. 완료 정정·마감 후 재개에서는 이전 휴식이 되살아나지 않아야 한다.
12. 저장 성공을 확인한 후 허용된 실제 기기에서 OS 종료/재실행하여 같은 상태가 남는지 기록한다.

테스트 결과에는 기기/화면 크기, 새/구 파일 버전, 프로그램 ID·버전, 선택 주차/세션/세트, 수행 작업, 기대/실제, 저장 상태, 전후 화면을 남긴다. 프로세스 재생성이 아닌 hot reload나 테스트 객체 재생성을 실제 OS 재실행 성공으로 기록하지 않는다.

구독·원격 관리자·사용자 계정·결제/문의 서버·앱 백업/복원은 [로드맵](2026-09-08-development-roadmap.md)의 별도 단위다. 이번 기능 완료 보고서에는 네 기능의 실제 연결 범위와 검증 근거만 기록한다.
