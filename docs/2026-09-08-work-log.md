# 9/8 · 인터랙티브 랜딩 개발·검증·인수인계

> 작업일: 2026-09-08 · 대상: `apps/strength_routine/landing/` · 상태: 로컬 구현·브라우저 검증 완료, 외부 배포 전.

## 요청과 적용 범위

사용자 요청: **“랜딩 페이지가 필요해 인터랙티브하게”**.

이전 지시인 기능 단위 커밋, 날짜별 상세 문서, Claude 인수인계, 시뮬레이터 실행 보류를 유지했다. 이번에는 독립 정적 웹 랜딩을 추가했으며 Flutter 앱 화면·훈련 정책·실제 프로그램 카탈로그를 변경하지 않았다.

주목적을 앱 소개·기능 체험 / 출시 알림 / 트레이너 모집 중 질문했다. 답변은 아직 없어, 질문할 때 밝힌 **앱 소개·기능 체험**을 가정해 진행했다. 이 가정은 출시 알림 수집이나 트레이너 모집에 대한 승인이 아니다.

사용자가 확정한 “트레이너의 완성 프로그램 선택, 운동·세트 구성 유지, 중량·시작일·요일 개인화”를 설명의 기준으로 삼았다. 배포용 카탈로그는 비어 있고 첫 실제 프로그램도 미선정이다. 체험은 기존 QA 구성과 같은 1주·주 1회·스쿼트 2세트의 명시적 예시이며 실제 훈련 처방이 아니다. 앱 다운로드·가상 코치·사용자 수·성과 수치·허위 후기·신청 전송은 넣지 않았다.

## 추가된 디테일 — 한 문장씩

- 첫 화면에서 프로그램 구성·일정·기록을 직접 눌러볼 수 있다.
- 시작일과 운동요일을 선택하면 첫 해당 날짜가 즉시 바뀐다.
- 중량·반복·RIR을 직접 입력하며 목표값을 실제 기록으로 자동 복사하지 않는다.
- 빈 중량·소수 반복·범위를 벗어난 RIR은 완료 전에 필드 오류로 표시한다.
- 중량 0과 RIR 0은 유효한 입력이며 RIR은 비워둘 수 있다.
- 세트를 완료하면 실제 수행 수와 진행 표시가 바뀌고 다음 미기록 입력으로 이동한다.
- 제외한 세트는 수행 수에 포함하지 않으며 다시 수정할 수 있다.
- `42.`처럼 작성 중인 원문도 그대로 저장해 새로고침 후 복원한다.
- 완료나 제외가 있는 체험은 일정을 잠가 기록의 날짜가 바뀌지 않게 한다.
- 초기화는 취소와 Escape를 지원하며 이 체험의 저장 키만 지운다.
- 저장 차단과 손상 데이터는 별도 경고로 표시하고 손상 원본을 자동 덮어쓰지 않는다.
- 초기화 삭제가 실패하면 재실행 시 이전 기록이 돌아올 수 있다고 직접 알린다.
- FAQ를 펼치면 개발 상태·저장 위치·자동 조절·트레이너 도구 범위를 확인할 수 있다.
- 모바일 레이아웃, 키보드 탭 이동, 초점 표시와 모션 감소 설정을 지원한다.

## 상태·저장 계약

전용 키: `strength-landing-demo-v1`. Flutter의 `training-state.json`·`habits-state.json`과 연결되지 않는다. 저장 범위는 **이 페이지를 연 origin과 브라우저**이며 같은 브라우저라도 포트·주소가 바뀌면 다른 저장소다. 입력 내용은 네트워크로 전송하지 않는다.

저장값은 버전·선택 단계·시작일·ISO 운동요일·2개 세트를 가진다. 각 세트의 중량/반복/RIR은 최대 256자 문자열이며 상태는 pending/completed/skipped다. 미완성 입력을 숫자로 정규화하지 않는다. 완료 상태만 유효한 수치를 요구한다. 제외에 남은 원문은 수정 시 다시 표시한다. 실제 수행·제외·초안은 따로 집계한다.

날짜 계산은 시간대/DST 영향을 피하는 UTC 달력 연산이다. 복원된 과거 날짜는 허용한다. 이 웹 체험은 실제 운동 일정 변경 정책이나 중량 처방을 구현한 엔진이 아니다.

저장된 JSON·버전·구조가 잘못되면 기본 체험을 보여주되 원본 키는 명시적 초기화 전까지 보존한다. 저장이 차단되면 현재 메모리에서 체험할 수 있으며 지속 저장 성공을 표시하지 않는다. 초기화는 해당 키의 삭제를 먼저 시도한다. 삭제는 성공했지만 새 기본값 쓰기가 실패한 경우 이전 기록이 다시 복원되지 않는다. 삭제 자체가 실패하면 메모리 체험만 초기화하고 기존 데이터가 다시 나타날 수 있다는 경고를 표시한다.

## 디자인 검토와 수정

[디자인 근거](../DESIGN.md)의 9/8 섹션에 Strong·Hevy·Boostcamp의 공식 페이지와 9/7 보관 캡처 관찰을 연결했다. 기존 Console v2의 어두운 바탕·시안 행동·초록 완료를 유지했고 한글/숫자 폰트를 구분했다. 사진이나 가상 앱 화면 대신 작동하는 DOM 입력을 주 시각 요소로 사용했다.

첫 렌더에서 우선 검토한 항목은 모바일 저장 안내의 짧은 꼬리 줄바꿈, 320px 제목 여유, 단계 전환 중 캡처의 잔상이다. 긴 저장 성공 문구를 **“이 브라우저에 저장했습니다.”**로 줄이고, 좁은 화면의 제목 크기를 역할 토큰으로 조절했다. 1100px 제목과 모바일 상단 높이도 토큰 파일로 옮겼다. 캡처는 전환이 끝난 뒤 생성하도록 바꿨다.

초기화 코드 리뷰에서는 쓰기 실패 시 이전 저장값이 돌아오는 경계를 발견해 삭제 우선 처리와 실패 안내를 추가했다. 모바일 일정 패널의 긴 요소 캡처가 하단을 비워 보이는 현상은 DOM 높이와 전체 페이지 렌더로 대조했다. 실제 footer가 존재함을 확인한 뒤 캡처 캔버스만 높여 전체 요소를 보존했다.

브라우저 검증은 ① 첫 탭·폰트 ② 요일 날짜 계산·빈 날짜 차단 ③ 필드 오류·0 입력·다음 세트 초점 ④ 단계/완료/원문 복원 ⑤ 완료 뒤 일정 잠금 ⑥ 제외/수정 ⑦ 초기화 취소/Escape/다른 키 보존 ⑧ 방향키/End/FAQ/CTA ⑨ 모바일 3단계 가로 넘침 ⑩ 모션 감소 ⑪ 페이지 오류·리소스 실패 없음 ⑫ 손상 데이터 보존 ⑬ 저장 차단 체험 ⑭ 초기화 실패 안내·이전 데이터 제거를 포함한다.

검증 중 대화상자 `close` 이벤트 전에 결과를 읽는 자동화의 타이밍 문제가 한 번 발생했다. 임의 대기 대신 초기화된 첫 패널이 표시될 때까지 기다리도록 수정한 최종 실행이 위 결과다. Chromium의 기본 샌드박스 실행과 Flutter SDK 캐시 쓰기는 환경 권한에 막혀 허용된 권한 상승으로 실행했다. 자동 승인 거절은 없었다. 시뮬레이터는 실행하지 않았다.

Flutter 코드·의존성은 바꾸지 않아 네이티브 전체 68개 테스트는 이번에 반복하지 않았다. 그 결과는 [9/7 자체 검증](2026-09-07-verification.md)의 별도 이력이다. 브라우저 검증은 iOS 앱 조작·네이티브 재실행 검증을 의미하지 않는다. Safari·실제 휴대폰의 키보드·스크린리더·배포 환경은 아직 확인하지 않았다.

## 실행과 다음 재개 지점

macOS 터미널에서 앱 루트로 이동한 뒤:

```sh
python3 -m http.server 4175 --bind 127.0.0.1
```

[로컬 랜딩](http://127.0.0.1:4175/landing/)을 연다. `file://`가 아닌 정적 서버를 사용한다. `landing/` 파일은 상위 `assets/fonts/`를 참조하므로 배포 시 이 구조와 OFL 라이선스를 함께 포함해야 한다. 현재 서버는 로컬 확인용이고 외부에 배포하지 않았다.

Claude가 이어받을 때 이 문서 → [landing README](../landing/README.md) → [디자인 근거](../DESIGN.md)의 9/8 섹션 → [디자인 시스템](03-design-system.md)의 웹 랜딩 절을 읽는다. 제품 범위를 바꾸기 전에 [개요](00-overview.md)의 미결정 사항을 확인한다.

다음은 사용자 피드백에 따른 카피·상호작용 수정이다. 실제 프로그램 선정 뒤에만 체험 콘텐츠를 실제 제공 범위와 다시 맞춘다. 출시 알림·트레이너 모집·앱 다운로드·공개 배포는 각각 목적과 연결 대상이 정해진 뒤 추가한다.
