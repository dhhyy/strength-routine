## 이 문서가 추가하는 것

[운동 앱 비교 분석](2026-09-07-fitness-app-analysis.md)은 **왜 개선할지**를 설명한다. 이 문서와 아래 상세 문서는 같은 IM01~15를 **어떤 흐름·데이터·예외 처리로 개발하고 어떻게 확인할지**까지 분석한다. 앱 순위나 새로운 기능 목록을 다시 만드는 문서가 아니다.

| 읽을 문서 | 담당 기능 | 내용 |
|---|---|---|
| [프로그램·시작·검색](feature-analysis/2026-09-07-programs.md) | IM01·04·05·11·14 | 카탈로그, 선택 정보, 설정 초안, 운동 설명, 콘텐츠별 표현 계약 |
| [운동 중 기록·요약·정정](feature-analysis/2026-09-07-workout.md) | IM07·08·10·13 | 지난 값, 숫자 증감, 다음 세트, 타이머, 비교와 수정 |
| [상태·날짜·일정·백업](feature-analysis/2026-09-07-data-reliability.md) | IM03·06·09·12 | 마감/수행의 의미, 공통 운동 ID, 실제 날짜, 일정 이동, 파일 복원 |
| 이 문서 | IM02·15 및 공통 기준 | 출시 전 검증, 후속 플랫폼 기능, 의존성·미결정 사항·추적표 |

상세 문서의 데이터 이름은 **논리 계약의 제안**이다. 최종 Dart 타입·필드명·파일 경로·스키마 번호가 확정되었다는 뜻은 아니다. 구현 직전 실제 코드와 이전 날짜 이후 변경을 대조한다.

## 1. 모든 기능에서 유지할 기준

| 구분 | 기준 |
|---|---|
| 사용자 확정 | 트레이너 완성 프로그램을 선택. 운동·세트 구성 보존. 중량·시작일·요일 개인화. 기록 없는 시작 중량 임의 추정 금지. 등록 도구는 후속 개발 |
| 현재 구현 | 계획/실제/초안 분리, 프로그램 스냅샷·파일 저장/복원·실패 재시도, kg/lb·RIR·메모, 다음 세트·실제 집계·보관 초안, 프로그램 운동 검색·습관 저장 |
| 현재 제약 | 실제 카탈로그 비어 있음, 네이티브 조작 미검증·현재 보류, 운동 설명 사전 미구현, 유한 주차·매주 같은 세션 수·고정 반복 |
| 설계 제안 | 기록 마감의 별도 상태, 공통 운동 ID, 실제 수행일, 지난 값 선택 복사, 타이머·일정·요약·백업 등 아래 상세 규칙 |
| 아직 결정할 것 | 첫 콘텐츠·처방, 기록 마감과 미기록 세트 처리, 놓친 운동 이동 범위, 이전값 비교 범위, 보관 기록 정정 범위 |

공통 불변 조건:

1. **값 복사와 세트 완료를 분리한다.** 계획·이전 실제값을 초안에 가져와도 새 실적은 생기지 않는다. 지난 RIR·메모 역시 이번 운동의 관찰값으로 간주하지 않는다.
2. **식별자는 보존한다.** 날짜 이동·실제 값 정정·데이터 복원 때문에 기존 plan/session/set ID를 새로 만들지 않는다. 공통 종목 ID는 기존 계획 안의 운동 ID를 대체하지 않는 별도 연결이다.
3. **저장 완료와 화면 전환을 연결한다.** 입력은 보존하며, 저장 실패 시 완료 안내·다음 세트 이동 등 성공 후 동작을 실행하지 않는다. 재시도·앱 재개로 같은 완료·휴식 시작을 반복하지 않는다.
4. **현재 시각을 과거 사실로 채우지 않는다.** 옛 기록의 실제 수행일·운동 시간·사용자 명시 마감 시점은 알 수 없으면 미상이다. 파일 수정 시각이나 계획일에서 추정하지 않는다.
5. **시작한 프로그램을 소급 재작성하지 않는다.** 새 콘텐츠·메타데이터·기록 정정이 과거 목표·운동·세트 구성을 바꾸지 않는다.
6. **UI 상태와 데이터 상태를 구별한다.** 요약창을 봤는지, 필수 세트에 기록이 있는지, 운동을 실제로 수행했는지, 사용자가 기록을 마감했는지는 서로 다르다.
7. **집계의 단위를 명시한다.** 실제 완료 세트 수·필수 세트 처리율·중량×반복량·주간 hard set 수를 같은 지표로 합치지 않는다. RIR 미입력은 0이 아니다.
8. **파일 이행·복원은 전부 검증한 뒤 적용한다.** 오류가 있는 부분을 조용히 버리지 않는다. 입력을 유지하는 현재 일반 저장과, 전체 상태를 교체하는 복원은 별도 작업 경계가 필요하다.

저장 실패 때 입력을 메모리에 유지하는 것과 프로세스 종료 뒤 복원하는 것은 다르다. 재실행 보장 범위는 **마지막으로 영구 저장에 성공한 값과 초안**까지다. 실패한 최신 쓰기까지 복원된다고 약속하지 않는다. 정정 시에도 기존 마감이 확인된 경우만 ‘재마감’으로 안내하고, 옛 마감 여부 미상은 그대로 보존한다.

## 3. 기능 사이의 의존성과 개발 경계

| 묶음 | 독립적으로 진행 가능한 부분 | 함께 맞춰야 하는 부분 | 끝낼 때 확인할 결과 |
|---|---|---|---|
| A · 실제 사용 준비 | IM02의 검증·목업 상태 정리, IM03의 집계/문구 의미 정리 | IM01 콘텐츠와 필요한 IM14 표현 | 일반 실행에서 첫 프로그램 시작→기록→프로세스 재실행 |
| B · 기록 편의 | IM05 설정 초안, IM07 중 현재 세트 저장 후 이동, IM08 앱 내 타이머 | IM06 공통 식별·날짜, IM07 지난 수행 선택, IM03 상태 | 실패·취소·재시작을 포함한 입력 유지, 중복 이벤트 없음 |
| C · 기록 활용 | IM04 선택 정보·IM11 설명 콘텐츠 준비, IM12 포맷/검증 설계 | IM09 일정·IM10 비교·IM13 정정은 IM06 기반, IM12는 당시 전체 상태 포함 | 지난 운동을 올바른 조건으로 비교하고 기기를 바꿔도 기록 보존 |

**IM14의 일부는 조건부로 A보다 앞선다.** 고정 반복·유한 주차 계약에 맞지 않는 프로그램을 고르면 그 콘텐츠에 필요한 지원만 먼저 확장한다. 지원하지 않는 원작 규칙을 누락한 채 첫 콘텐츠로 수록하지 않는다.

**IM06 전체를 기다려 모든 UI 작업을 멈출 필요는 없다.** 현재 세션의 다음 미기록 세트로 이동하거나 기존 완료/제외 수를 정확하게 보여주는 것은 현재 데이터로 가능하다. 교차 프로그램 비교와 실제 날짜 통계부터는 새 계약이 필요하다.

데이터 계약이 늘어날 때는 프로그램 카탈로그의 형식 버전과 사용자 저장 파일의 형식 버전을 별도로 관리한다. 현재 두 파일이 모두 `schemaVersion: 1`이라는 사실이 같은 스키마임을 뜻하지 않는다. 코드 위치: [카탈로그 로더](../lib/app/training_controller.dart), [사용자 저장소](../lib/data/local_training_store.dart).

## 4. IM02 · 네이티브 입력·복원과 미완성 탭

**목적/현재 차이.** 분석 당시에는 39개 테스트와 iPhone QA 빌드를 확인한 상태였고 검색/습관이 목업이었다. 이후 두 탭을 실제 데이터 기능으로 바꾸고 자체 검증을 확대했다. 네이티브 조작·종료 후 기록 관찰은 여전히 미완료이며 현재 사용자 지시로 보류한다. 이전 근거는 [APP12](../research/2026-09-07/expanded/current-app-audit.md), 최신 근거는 [자체 검증](2026-09-07-verification.md)과 [검증 실행 순서](../tool/README.md)를 따른다.

**제안 흐름.** 일반 시작/빈 목록 → 콘텐츠가 있으면 프로그램 시작 → 실제 세트 입력·초안 닫기/다시 열기 → 완료·제외·기록 조회 → 앱 프로세스 종료 → 재실행. QA 합성 데이터와 일반 카탈로그의 결과를 따로 기록한다. 기능이 없는 탭은 기존 5탭 틀 안에서 상태와 가능한 다음 행동을 안내하고, 실기능이 준비되면 해당 안내를 대체한다.

**데이터/상태.** 새로운 운동 데이터 모델은 필요하지 않다. 검증 증거에는 빌드/진입점·장치/OS·검증 시각·재현 순서·기대/실제·캡처·결과를 기록한다. 이 증거를 앱의 사용자 기록에 넣지 않는다. 빈 카탈로그, 카탈로그 로딩 실패, 저장소 읽기 실패를 별도로 확인한다.

**실패·취소·이탈.** 읽기 실패는 처음 설치처럼 초기화하지 않고 원본을 보존한다. 저장 실패 시 초안을 유지한다. 미완성 추가/검색 컨트롤은 눌렀는데 반응 없는 장식으로 남기지 않는다. 키보드·큰 글자·가이드 진입으로 기록 버튼에 접근할 수 없으면 수정 후 재검증한다.

| 수용 기준 | 주어진 상태 → 행동 → 기대 결과 |
|---|---|
| IM02-AC01 | 실제값과 작성 중 초안의 기기 저장에 성공한 앱 → 프로세스 종료·재실행 → 동일 계획 ID·실제값·초안 복원. hot reload만으로 통과하지 않음 |
| IM02-AC02 | 작은 화면/큰 글자/키보드 표시 → 모든 입력과 저장·닫기 수행 → 잘림·누를 수 없는 필수 버튼·입력 유실 없음 |
| IM02-AC03 | 데이터 없는 검색/습관 → 해당 탭 진입 → 사용자가 작성하지 않은 완료 수·고정 과거 날짜를 실적처럼 표시하지 않음 |
| IM02-AC04 | 빈 파일 경로/손상 파일/저장 실패 각각 → 앱 열기·재시도 → 빈 상태와 오류 구별, 성공 전 성공 문구 없음 |

영향: `main.dart`, `search_screen.dart`, `habits_screen.dart`, 관련 화면/위젯 테스트, `tool/README.md`, 당일 검증 기록. **미결정:** 출시 지원 OS/기기와 습관의 후속 확장 범위. 현재 자체 검증을 기본으로 하며 시뮬레이터 실행은 사용자 재요청 전까지 자동 재개하지 않는다. 테스트·기존 위젯 렌더·네이티브 관찰을 구분하고 문서만으로 미수행 검증을 통과 처리하지 않는다.

## 5. IM15 · 후속 플랫폼 기능을 분리해 분석

이 항목은 하나의 기능으로 한꺼번에 개발하기에 크다. IM15-A~D는 원래 IM15의 **하위 범위**이며 전체 개선안 15개를 늘리는 번호가 아니다. 기존 자료의 [Hevy/Alpha 기록 조사](../research/2026-09-07/expanded/logging-apps.md), [Caliber 코칭 조사](../research/2026-09-07/expanded/guidance-apps.md), [플릭 공유 조사](../research/2026-09-07/expanded/korean-apps.md)를 근거로 범위를 나눴다. 실제 OS API·지원 버전은 구현 시 공식 문서로 확인한다.

| 하위 범위 | 목적·정상 흐름 | 필요한 계약 | 실패/취소·검증 기준 |
|---|---|---|---|
| IM15-A · 진행 중 운동 외부 표시 | 앱에서 시작한 현재 세트/휴식을 지원 외부 화면에 표시 → 앱으로 복귀 | IM08 타이머, 현재 session/set ID, 표시 시점/상태 버전 | 권한 거부/지원 안 됨이어도 앱 내 운동 가능. 오래된 완료 버튼은 다른 세트를 완료하지 않음 |
| IM15-B · 워치 기록 | 선택한 현재 세트 확인 → 실제 입력 → 반영 결과 확인 | 명령 식별자·중복 방지·기기 연결 상태·충돌 정책 | 연결 끊김 때 성공으로 표시하지 않음. 재전송한 같은 명령이 세트/타이머를 중복 생성하지 않음 |
| IM15-C · 기록 공유 | 공유할 요약과 포함 필드 선택 → 미리보기 → 사용자가 전송 | 공개 필드와 비공개 메모 구분, 단위·수행일·집계 기준 | 취소하면 외부 전송 없음. 내보낸 뒤 외부에서 삭제/수정되는 범위는 앱 내부 편집과 다름을 명확히 함 |
| IM15-D · 코치 소통 | 특정 운동/세션 맥락에서 질문 또는 피드백 확인 | 트레이너 도구·계정·대화 저장/전달·첨부·콘텐츠 권한 | 전달 실패/오프라인/재전송 상태가 구별됨. 피드백 수신만으로 기존 프로그램 구성 변경 없음 |

공통 사용자 흐름은 **선택 → 대상과 내용을 확인 → 실행 → 반영 상태 확인**이다. 읽기만 가능한 외부 표시부터 시작할 수 있으며, 수정 가능한 외부 입력은 앱 내부와 동일한 검증·저장 경로를 사용해야 한다. 공유/코치 소통은 외부 전달 기능이므로 실제 사용자 행동 없이 자동 전송하는 방식으로 설계하지 않는다.

**영향과 미결정.** 앱 내 상태·타이머·도메인 명령 처리 외에 플랫폼 연동, 계정/서버가 필요할 수 있다. 이번 단계에서 새 의존성·권한·서버 도입을 확정하지 않는다. 먼저 지원 플랫폼, 외부 화면의 읽기/쓰기 범위, 워치 우선 여부, 공유 채널·공개 항목, 코치 서비스 운영 방식을 정한다.

**공통 수용 기준 IM15-AC01~03:** 지원하지 않는 환경에서도 핵심 기록 가능 / 같은 외부 명령의 재시도에 같은 결과 / 원본 구성 보존과 사용자 선택 범위 밖의 기록·메모 비전송. 각 하위 기능의 실기 검증은 후속 구현 범위가 정해진 뒤 분리한다.

## 6. 미결정 사항과 기술 판단을 구별하기

| 결정 대상 | 결정이 필요한 시점 | 답변 없이 먼저 할 수 있는 분석/개발 준비 |
|---|---|---|
| 첫 프로그램·정확한 처방 | IM01 실제 콘텐츠 연결 전 | 현재 지원 형식 검사, 목록·입력 상태·QA |
| 명시 마감과 남은 필수 세트 처리 | IM03의 새 마감 동작 전 | 완료/제외/미기록 집계·문구 구분, 상태 전이 테스트 설계 |
| 놓친 운동과 남은 일정 처리 | IM09 적용 전 | 예정/실제 날짜 계약, 단일 세션 미리보기, 변경 영향 계산 |

| 외부 기기·공유·코치 서비스 | IM15 구현 전 | 현재 앱과 공통으로 쓸 명령/상태 경계 분석 |

파일 배치·타입 이름·토큰 재사용·저장 큐 구현처럼 제품 의미를 바꾸지 않는 기술 판단은 매번 사용자에게 묻지 않는다. 새 제안을 한 번에 모두 승인받는 절차를 추가하지 않으며, 이미 확정된 프로그램 보존·개인화 범위도 재질문하지 않는다.

## 7. 검증과 이후 기록

모든 기능의 최소 검증 축은 **정상 수행 / 데이터 없음 / 잘못된 입력 / 저장 실패 / 취소 / 앱 이탈·재실행 / 기존 파일과의 호환**이다. 계산 함수 테스트, 실제 파일 저장 테스트, 화면 동작 테스트, 네이티브 관찰을 목적에 맞게 선택한다. 문서의 수용 기준은 아직 실행한 테스트가 아니다.

개발을 시작할 때 기능 ID·선택한 정책·변경 파일·검증 결과를 [작업 기록](2026-09-07-work-log.md)에 이어 쓴다. 코드로 완료된 부분은 이 문서의 `분석됨` 상태와 구분하여 갱신하고 [Claude 인수인계](2026-09-07-claude-handoff.md)에서도 동일하게 반영한다. 경쟁사 근거는 [출처 목록](../research/2026-09-07/expanded/sources.md)을 유지한다.
