# 9/8 · 관리자 연속 버전 저장과 이력 시험 안정화

기준: 검토 커밋 `064509f`. 이 문서는 SF02·SF03 구현 전에 작성했다. [안정화 명세](2026-09-08-review-fixes.md)와 [관리자 검토 증거](../research/2026-09-08/review/admin-review.md)를 따른다.

## SF02 · 같은 편집 화면의 사용 버전 보호

수정 전 정밀 편집 화면은 진입 때의 이력과 최신 카탈로그만 검사했다. 저장 후 카탈로그가 교체되면 직전 버전이 검사에서 빠졌다. 저장소는 이 충돌을 거부하지만 화면이 일반 파일 저장 실패로 안내하는 것이 원인이었다.

- 초기 카탈로그와 버전 이력에서 ID·버전 쌍을 수집한다.
- 영구 저장이 성공한 버전만 이 집합에 추가하고 화면을 떠날 때까지 유지한다.
- 같은 버전을 다른 프로그램 ID에서 쓰는 것은 허용한다.
- 변경 검토 전에 사용한 버전을 차단하고 입력과 되돌리기 이력을 보존한다.
- 저장 시 도메인 검증 오류가 발생하면 원인을 표시하고 편집 화면으로 돌아가게 한다.
- 파일 저장 실패는 검토한 후보를 유지하며 기존 재시도 흐름으로 처리한다.
- 카탈로그·버전 이력의 불변성과 저장 스키마는 바꾸지 않는다.

검증은 초기 이력이 빈 카탈로그와 이미 이력이 있는 카탈로그에서 같은 화면으로 여러 새 버전을 저장한 뒤 원래/중간 버전을 재사용하는 순서를 포함한다. 저장 실패 뒤 같은 미사용 버전으로 재시도하는 경우와 검토 이후 도메인 충돌 안내도 확인한다.

## SF03 · 실제 저장 완료에 맞춘 관리자 위젯 시험

기존 helper는 실제 시간 10×5ms 뒤 `pumpAndSettle`을 호출한다. 파일 I/O가 더 걸리면 진행 표시가 계속되는 동안 fake async에서 기다려 시간초과할 수 있다.

고정 횟수 대기를 관찰 가능한 완료 상태를 확인하는 제한 시간 대기로 바꾼다. 이력 복구 진입과 검토 저장 경계에 제어 가능한 파일 작업 지연을 넣어, 기다리는 동안 중복 저장이 차단되고 완료 전 원본이 유지되는지 확인한다. 지연을 해제한 뒤 파일 재로딩과 과거 스냅샷 불변 assertion을 유지한다.

## 실행 결과

SF02·SF03을 구현하고 해당 관리자 위젯 시험 **21개를 통과**했다. 정밀 편집 14개는 38초, 확장 편집·보관·이력 7개는 32초에 통과했다. 이는 두 파일의 합이며 앱 전체 시험 수는 [안정화 결과 정본](2026-09-08-review-fixes.md)에서 별도로 확인한다. Simulator·실기기는 실행하지 않았다.

### 기능 구현과 보존 경계

[정밀 편집 화면](../lib/admin/detailed_routine_screen.dart)의 `_usedVersions`는 초기 카탈로그·이력에서 `(프로그램 ID, 버전)` 쌍을 수집한다. 문자열을 구분자로 결합하지 않아 ID에 구분자가 들어가도 다른 프로그램과 충돌하지 않는다. `_preview`는 생성된 후보의 쌍을 먼저 검사하고, 저장 화면이 성공을 반환한 뒤에만 새 쌍을 추가한다. 저장 실패·취소는 사용 목록을 늘리지 않으며 기존 카탈로그를 교체하지 않는다.

`onSaveProgram`의 `false`는 재시도 가능한 실패이고 `FormatException`은 후보 수정이 필요한 검증 오류다. [관리자 부모 화면](../lib/admin/admin_screen.dart)의 `_commitProgram`은 `AdminWorkspace.withProgram`의 검증 오류를 정밀 검토 화면으로 전달한다. 검토 화면은 오류 원문과 `편집으로 돌아가기`를 표시하고 동일 후보 재시도를 차단한다. 편집 화면으로 돌아가도 원문 초안과 undo/redo를 초기화하지 않는다. 기본 생성 화면의 기존 `FormatException` 처리도 유지된다.

파일 쓰기 오류는 여전히 검토한 후보로 `카탈로그 저장 재시도`를 제공한다. 기존 실패→성공 시험은 두 저장 후보의 JSON이 같고 성공 뒤 편집기로 돌아오는지 확인한다. 사용 목록은 화면 내 사전 안내를 위한 보완이고, 실제 불변 버전 방어는 기존 `AdminWorkspace.withProgram`이 계속 담당한다. 저장 모델·불변 스냅샷·파일 스키마·패키지는 변경하지 않았다.

SF03의 helper는 최대 10초의 실제 시간 안에서 진행 표시·초안 저장 상태·`AbsorbPointer.absorbing` 잠금 또는 명시한 완료 조건을 관찰한다. 각 반복은 `runAsync`로 실제 I/O를 진행시키고 `pump(16ms)`로 경로 전환 애니메이션의 가상 시간도 진행시킨다. 두 시간이 함께 진행돼야 저장이 끝난 검토 화면의 퇴장 애니메이션을 파일 저장 지연으로 오인하지 않는다. 카탈로그 저장 잠금은 화면 아래의 버튼이 아직 생성되지 않아도 관찰할 수 있다.

시험용 `_BarrierFile`/`_BarrierDirectory`는 실제 파일의 부모 생성만 잠시 보류한다. 운영 `AdminProgramStore`의 직렬 큐·JSON 직렬화·임시 파일 flush·rename·재로딩 경로를 그대로 실행한다. 운영 저장소에 테스트 훅이나 지연 옵션을 추가하지 않았다.

### 렌더 확인

IBM Plex Sans KR·IBM Plex Mono·Material Icons의 번들 글꼴을 로드한 headless 렌더를 생성했다. [새 버전 충돌 화면](../research/2026-09-08/review-fixes/admin/render/version-conflict-mobile.png)을 직접 확인해 오류 문장과 복귀 버튼이 겹치지 않고 375px 화면에서 전체 버튼을 읽을 수 있음을 확인했다. 첫 캡처는 오류 추가로 버튼 하단이 화면 밖에 있었으므로, 기존 스크롤 경로로 버튼을 보이게 한 뒤 다시 캡처했다. 제품 여백·색·서체·배치는 변경하지 않았다.

### 중간 시험 실패의 처리

중간 시험 실패를 제품 정상 결과로 세지 않았다. [첫 조정 로그](../research/2026-09-08/review-fixes/admin/intermediate-tests.txt)에는 가상 시간을 0으로 진행한 helper, 복귀 후 닫힌 정보 패널을 열지 않은 finder, 보관 완료를 너무 빨리 판단한 오류가 남아 있다. [다음 렌더 실행](../research/2026-09-08/review-fixes/admin/intermediate-render-tests.txt)은 프로그램 ID finder가 세션 ID까지 찾은 2개 실패와 보관 저장 대기 정체로 중단했다. 최종 시험은 정보 패널 안으로 finder를 제한하고, 실제 저장 잠금·경로 전환 시간을 함께 관찰한 결과다.

### 재실행 방법

실행 위치: **macOS 호스트**의 앱 루트 `apps/strength_routine`.

```sh
flutter test test/detailed_admin_screen_test.dart --no-pub --reporter expanded --timeout 1m --dart-define=DETAILED_ADMIN_RENDER_DIR=research/2026-09-08/review-fixes/admin/render
flutter test test/local_admin_extension_screen_test.dart --no-pub --reporter expanded --timeout 1m
```

수정 전 재현은 해당 커밋의 별도 작업 사본에서 현재 신규 시험을 실행해야 한다. 작업 중인 제품 소스를 되돌릴 필요는 없다. 운영자의 실제 장시간 편집·파일 권한 오류·OS 강제 종료·실제 IME·스크린리더는 [실기기 가이드](2026-09-08-device-test-guide.md)의 수동 검증으로 남는다. 이력의 새 버전 복구가 원본 버전의 덮어쓰기를 허용한다는 뜻은 아니다.
