# 신규 브리프 vs 현재 앱 · 겹침·괴리·미포함 분석

> 작성: 2026-09-10  
> 대상: 사용자가 다시 보낸 **스트렝스·근비대 루틴 생성기** 원문 요구  
> 대조 기준: [01-requirements](01-requirements.md) (특히 8/27 초안 이력), [00-overview](00-overview.md), [06-engine-spec](06-engine-spec.md), [2026-09-08-remaining-work](2026-09-08-remaining-work.md), [2026-09-08-training-insights](2026-09-08-training-insights.md)  
> 성격: **요구 재정렬 분석**. 이 문서만으로 구현 완료·엔진 수치 확정을 주장하지 않는다.

---

## 1. 한 줄 결론

지금 보낸 원문은 **처음부터 있던 제품 비전(8/27 초안)에 가깝고**, 현재 `strength_routine` 코드·9/8 계약은 그 비전에서 **의도적으로 축소·전환한 버전**이다.

| 축 | 원문 브리프 (지금 개발하라고 온 것) | 현재 앱 (구현·계약) |
|---|---|---|
| 루틴 공급 | 사용자가 **목표·요일·회복·블록**으로 **생성** | 운영자가 만든 **완성 프로그램 선택** + 중량·시작일·요일만 개인화 |
| 처방 기준 | **e1RM %** + 기록으로 **실시간 수정** | 명시 **baseline kg × %** 또는 고정 kg. **자동 e1RM 없음** |
| 자율성 | 요일 고정 아님, postpone, 종목 이월(오토파일럿) | 요일에 배치된 세션, **미래 일정 이동**은 있음. 종목 단위 이월·준비일 자율은 없음 |
| 5탭 | 오늘 / 기록(+e1RM) / 검색(인앱 영상) / **게시판** / 프로필(루틴 수정) | 오늘 / 기록(+추세·D5) / 검색(오프라인 가이드+외부 링크) / **습관** / 프로필 |
| 과금 | 둘러보기 → 생성 → **1주 체험 → 유료** | 구독 **준비 안내**만. 실결제·체험 타이머 미연결 |
| 커뮤니티 | 자유+Q&A, 중복 질문 억제, 서로 소통 | **로컬 FAQ**. 서버 게시판·유저 간 소통 없음 |

**겹침(방향·IA):** 높음 — 5탭 골격, 오늘 우선, 달력 기록, 검색, 프로필, RPE보다 무게 처방, 규칙 기반(비생성형 AI)은 처음부터 같다.  
**겹침(실행 모델):** 낮음~중간 — “선택형 코치 프로그램 앱” vs “사용자 루틴 생성기+오토파일럿”로 **제품 정의가 갈라져 있다.**  
**괴리감:** 사용자가 체감하는 핵심(내가 목표 정하면 루틴이 생기고 e1RM이 살아 움직임)은 **아직 제품의 중심 경로가 아니다.**

## 2. 원문이 문서에 이미 있었는지

`docs/01-requirements.md`의 **「8/27 제품 초안 이력」**(접힌 이력 블록)에 같은 문장군이 거의 그대로 있다.

| 원문 요지 | 8/27 초안에 이미 있음 | 비고 |
|---|---|---|
| 오늘 루틴이 첫 화면 | ✅ | 현재도 유지 |
| 기록=달력, 당일 상세·컨디션, e1RM 추세 | ✅ | 달력·당일 상세·추세는 있음. **e1RM 곡선/실시간 갱신은 미구현** |
| 검색+유튜브 | ✅ | 현재는 오프라인 가이드+**외부** 링크. **인앱/임베드 재생 아님** |
| 생활습관 | ✅ (4번째 탭이 습관) | 원문은 **게시판**을 4번째로 재지정 → **탭 교체** |
| Q&A·중복 질문 억제 | ✅ (프로필 하위 독립 화면으로 설계) | 원문은 **하단 4번째 탭**. 구현은 로컬 FAQ 수준 |
| 프로필에서 루틴 수정 | ✅ | 현재 프로필은 설정·백업·구독 안내 중심. **사용자 생성 루틴 편집기 없음** |
| 목표 스트렝스/근비대/파워빌딩 | ✅ | 현재는 프로그램 **메타/선택** 쪽. 생성기 온보딩 아님 |
| 주당 일수·요일 | ✅ | 시작 시 요일 선택 있음. **생성기 입력**과는 단계가 다름 |
| 회복(수면·영양·스트레스)→운동량 | ✅ 초안(생활습관·컨디션 신호) | **운동량 자동 배분 엔진 미연결** |
| 블록 길이(4주 근비대+4주 스트렝스 등) | ✅ | **사용자 블록 빌더 없음**. 관리자가 주차 구성 |
| RPE 대신 무게 처방 | ✅ | 현재 `% of baseline`으로 **부분 충족**. baseline≠자동 e1RM |
| e1RM 실시간 수정 | ✅ 방향 / 엔진 D7 미확정 | **미구현**. D5는 RIR 기반 **수동 감량 제안**만 |
| 7일 체험→유료 | ✅ | **미연결** |
| DUP | 원문에 명시, 초안엔 약함 | “내가 DUP 루틴 만든다” → **콘텐츠/템플릿** 이슈 |
| postpone / 종목 이월 / 준비된 날 | 초안의 “당일 조절·제안”에 **약하게** 대응 | **세션/운동 단위 이월 UX·도메인 미구현** |
| wiggle room(지속 수정 장치) | 철학·엔진 “이유+되돌리기”와 정합 | 제품화는 D5 되돌리기 정도. **생성기용 실험 스위치는 없음** |

즉, “문서에도 있을 거야”는 **맞고**, 그 문서는 이후 **현재 계약이 아니라고 명시적으로 내려간 이력**이다(01 §「8/27 … 현재 구현 계약이 아님」).

## 4. 루틴 생성기 · 엔진 (가장 큰 괴리)

### 4.1 원문이 원하는 생성 입력

1. 목표: 근비대 / 스트렝스 / 파워빌딩  
2. 주당 일수 + 요일 선택  
3. 회복(수면·영양·일스트레스) → 운동량  
4. 블록 길이·블록 목표 시퀀스 (예: 4주 근비대 → 4주 스트렝스)  
5. DUP 가능 (템플릿은 코치가 작성)  
6. 설치→둘러보기→생성→**1주 무료→유료**  
7. e1RM 베이스 % 처방 + 기록 중 **실시간 e1RM/부하 조정**  
8. 오토파일럿: 고정 요일 강제 완화, postpone, **오늘 일부 종목만·나머지 이월**

### 4.2 현재가 하는 일

1. 관리자(`main_admin`)가 완성 프로그램 작성·내보내기  
2. 사용자가 카탈로그에서 선택  
3. 최근 기록(메인 리프트)·**명시 baseline**·시작일·요일 → `createActivePlan`  
4. `% of baseline` / fixed / manual  
5. 기록·마감·백업·일정(미래) 이동·D5(RIR 기반 감량 제안+되돌리기)

### 4.3 엔진 문서상의 “이상” vs “실행”

[06-engine-spec](06-engine-spec.md) / [02-engine-logic](02-engine-logic.md)에는 working max(e1RM), 회복 우선, 규칙 레지스트리 등 **원문과 같은 이상향**이 설계 이력으로 남아 있다.  
동시에 **「자동 볼륨·e1RM 갱신·진급은 구현하지 않았다」**가 현재 실행 계약이다. D7(e1RM 갱신)은 **논의 중**으로 남아 있다.

| 원문 장치 | 가장 가까운 현재 조각 | 부족한 것 |
|---|---|---|
| e1RM % 처방 | `percentOfBaseline` | 기록을 e1RM으로 환산·갱신하는 공식·UI·신뢰도 |
| 실시간 올리기/내리기 | D5 감량 제안(수동) | 증량 규칙, 세션 중/직후 working max 갱신, 이유 카피 체계화 |
| 회복→볼륨 | 습관 체크(신호만) | 회복 점수→세트/악세사리 상한 규칙 |
| 블록 빌더 | 관리자 주차 편집 | 사용자 온보딩 블록 UI + 프리셋 |
| DUP | 관리자가 요일별 다른 세션을 직접 넣으면 **표현 가능** | “DUP 모드” 생성 UX·코치 템플릿 슬롯 |
| postpone | 미래 세션 날짜 변경(LC02) | “오늘 스킵→다음 가능일” 원탭, 준비 안 됨 플로우 |
| 종목 이월 | 없음 | 세션 내 운동 단위 분할·잔여 큐·다음 세션 병합 규칙 |
| 체험·유료 | 구독 안내 문구 | Store/Supabase entitlement, 7일 타이머, 페이월 |

## 5. 포함되지 않은 기능 목록 (원문 기준 체크리스트)

구현·계약상 **아직 없다고 봐야 하는 것**만 모았다.

**생성·처방**

- [x] 사용자 대면 루틴 생성 마법사(목표·일수·회복·블록) — 회복=악세 −0/1/2, 블록=전체/4주/8주 MVP  
- [x] e1RM 추정 UI(Epley·출처 정책 id)  
- [x] 기록 기반 working max **제안 갱신** 및 미래 % 재처방 (자동 덮어쓰기 아님)

**오토파일럿·유연성**

- [ ] 준비된 날 운동(요일 느슨한 스케줄러)

**정보 구조**

- [ ] 4번째 탭 = 게시판/커뮤니티(서버) — **차단: 서버·모더레이션. 프로필에 준비 중 안내**

- [ ] 유저 간 댓글/소통 모더레이션  
- [x] 검색 탭 인앱 브라우저(우선) + 외부 폴백 — 전용 유튜브 CMS/임베드는 미구현  

**비즈니스**

- [x] 로컬 7일 체험 **안내 타이머** (페이월·스토어 검증 없음)  
- [ ] 유료 전환·복원·만료(스토어 검증) — 계정(Kakao/Supabase)과 연동은 **골격만**  

**지속 개선(wiggle room)**

- [x] 처방·e1RM·생성기 피처 플래그 (`LIVE_E1RM_V1`, `GENERATOR_V1`)  
- [ ] 엔진·템플릿 버전을 사용자에게 보이는 “왜 이렇게 나왔는지” 패널의 생성기 버전

## 6. 이미 있어 재사용 가능한 자산

원문으로 다시 갈 때 **바닥부터가 아닌** 것:

- 5탭 셸, 오늘 기록 UX, 로컬 저장·복원·백업  
- 프로그램 스냅샷·세트 상태·마감/재개  
- `% of baseline` 인프라 → e1RM을 baseline 공급원으로 바꾸면 확장 가능  
- D5의 **제안→적용→되돌리기·이유** 패턴 → 오토레그 일반화에 적합  
- 미래 일정 이동(postpone의 데이터 뼈대)  
- 관리자 정밀 편집 → 코치가 DUP/블록 템플릿을 **콘텐츠로 공급**하는 경로  
- 디자인 토큰·온보딩·(최근) 가입 강제/세션 게이트 방향

## 7. 의견: 최고의 루틴 빌더로 가려면 (분석에 붙이는 권고)

원문 질문(“어떻게 가면 좋은지”, “루틴을 내가 직접 만들까?”)에 대한 **제품 의견**이다. 확정 결정이 아니다.

1. **하이브리드가 현실적이다.**  
   - 코치가 **틀(템플릿)**: 주당 분할·DUP 패턴·블록 프리셋·운동 풀을 관리자로 작성.  
   - 앱이 **숫자**: e1RM(또는 명시 1RM/5RM)→%, 회복 상한, 반올림, 이유·되돌리기.  
   - 사용자가 **의도**: 목표·일수·블록 길이·“오늘은 이만큼만”.  
   → “AI가 루틴을 짠다”가 아니라 **코치 틀 + 계산기 + 오토파일럿**이 원문·기존 엔진 철학과 가장 잘 맞는다.

2. **e1RM은 한 번에 ‘완전 자동’보다 단계가 안전하다.**  
   - 1단계: 공식으로 e1RM **표시·수동 채택** → baseline에 반영.  
   - 2단계: 조건 충족 시에만 working max **제안 갱신**(D5처럼 확인).  
   - 3단계: 세션 중 소폭 자동 조절.  
   → 오류 없는 구동을 원문도 강조함. 현재 D5 패턴을 확장하는 편이 기존 코드와 충돌이 적다.

3. **오토파일럿은 스케줄러를 바꿔야 한다.**  
   “요일에 세션을 고정 배치”만으로는 postpone·종목 이월이 어색하다.  
   **세션 큐 + 예정일(느슨함) + 잔여 운동 큐** 모델이 필요하다. 일정 이동(LC02)은 출발점일 뿐이다.

4. **게시판은 4번 탭으로 바로 올리지 않는 편이 IA·운영에 유리할 수 있다.**  
   운동 중 복잡도를 올리지 않으려면 8/27안(프로필 하위 Q&A)+공지/검색이 맞고,  
   커뮤니티가 핵심 KPI면 습관을 옮기고 4번을 게시판으로 교체한다. **둘 다 하면 탭이 비대해진다.**

5. **코치가 루틴(틀)을 만드는 것은 맞다.**  
   주간 분배·운동량 감각은 도메인 자산이다. 앱은 그 틀을 **버전 있는 템플릿**으로 받고, 사용자마다 숫자만 맞춘다.  
   모든 분할을 알고리즘만으로 생성하면 검수·설명·책임 비용이 커진다.

6. **wiggle room:** 엔진 규칙·공식·페이월·탭 IA를 **플래그로 켜고 끄며** 같이 보는 전제를 문서·빌드에 넣는다(이미 AUTH_BYPASS 같은 우회 전례가 있음).

## 8. 괴리 요약 점수 (정성)

| 영역 | 겹침 | 괴리 | 메모 |
|---|---|---|---|
| 정보 구조(오늘·기록·검색·프로필) | 높음 | 낮음 | 4번 탭만 습관↔게시판 충돌 |
| 기록 UX | 높음 | 중간 | e1RM·컨디션 깊이 |
| 루틴 **생성** | 낮음 | **매우 높음** | 선택형 vs 생성기 |
| 자동 조절 | 낮음 | 높음 | D5 ≪ 원문 오토레그 |
| 오토파일럿(미루기·이월) | 낮음 | 높음 | 일정 이동만 부분 |
| 커뮤니티·결제 | 낮음 | 높음 | FAQ·구독 안내만 |
| 코치 콘텐츠 공급 | 중간 | 중간 | 관리자 도구는 강함, 사용자 생성기는 없음 |

**종합:** 문장·비전은 **같은 제품의 원래 스펙**이고, 코드는 **그 스펙의 MVP 축소판(코치 프로그램 러너)**이다. 지금 브리프대로 “개발해야 하는 상황”이면, 단순 기능 추가가 아니라 **제품 계약을 8/27 생성기+오토파일럿 쪽으로 재승격**하는 작업이다.
