# 9/8 · 실제 수행일·운동 마감·요약 — 구현 명세

상태: **첫 단위 구현·자동 검증 완료, 실제 기기 시험 미실행**. 사용자 요청은 “문서를 상세하게 적고, 기능 구현 시작”이다. [남은 작업 상태표](2026-09-08-remaining-work.md)의 첫 단위를 구현했으며, 후속 항목은 [개발 로드맵](2026-09-08-development-roadmap.md)에 분리한다. 실제 실행 근거는 [검증 보고서](2026-09-08-session-lifecycle-verification.md)를 따른다.

## 1. 문제와 이번 완료 목표

기존 `SetActual`에는 중량·단위·반복·RIR·메모만 있었다. 기록 달력과 D5 추세는 계획일을 기준으로 묶었으며, 늦게 수행한 운동의 실제 날짜를 보존할 수 없었다. `isSessionComplete`는 필수 세트에 완료 또는 제외 기록이 존재하는지 검사하고, `completionNotified`는 일회성 안내를 봤는지 보관한다. 둘 다 사용자가 운동 기록을 명시적으로 마쳤다는 증거가 아니다.

이번 완료 목표는 **실제 날짜를 확인하며 세트를 기록 → 요약 검토 → 명시 마감 → 저장된 요약 조회 → 필요 시 확인 후 재개 → 수정·다시 마감**이다. 일반 파일 저장과 재실행 복원에 새 데이터를 포함한다. 마감 시각을 실제 운동 종료 시각으로 표시하지 않는다.

### 1.1 기존에 확정된 불변 조건

- 트레이너가 작성한 프로그램·운동·세트·목표 스냅샷을 바꾸지 않는다.
- 중량 0은 실제 수행이며 제외·미기록과 다르다.
- 완료·제외·초안은 별도 상태이며 초안 값을 실적으로 집계하지 않는다.
- 과거 기록의 실제 수행일과 마감 여부를 계획일·파일 수정 시각·이행 시각에서 추정하지 않는다.
- 보관 계획과 미래 계획의 기존 읽기 전용 규칙을 유지한다.
- 저장 실패·취소·재시도에서 원래 값과 사용자가 쓴 입력을 보존한다.
- 사용자의 시뮬레이터 실행 금지 지시를 유지한다.

### 1.2 이번 구현에서 채택한 제품 결정

사용자가 기능 구현을 지시한 범위에서 기존 분석의 보수적인 초기안을 채택했다. 아래 수용 기준은 이번 버전의 실제 동작 계약이며, 사용자가 개별 숫자·문구에 답변했다고 기록하는 것이 아니다.

| 결정 | 선택한 동작 | 이유 |
|---|---|---|
| 필수 미기록 | 필수 세트를 직접 완료/제외하기 전 마감 차단 | 실제 수행 여부를 앱이 대신 결정하지 않음 |
| 선택 세트 미기록 | 그대로 남기고 마감 가능, 요약에 수 표시 | 선택 세트를 자동 제외하거나 완료로 만들지 않음 |
| 작성 중 초안 | 필수/선택 관계없이 초안이 있으면 마감 차단 | 미완성 입력을 숨기거나 지우지 않음 |
| 필수 세트가 0개 | 초안이 없으면 명시 마감 가능 | 과거 getter의 false를 새 마감 조건으로 그대로 사용하지 않음 |
| 전부 제외 | 실제 수행 0세트로 마감 가능 | 기록 정리와 실제 운동을 분리 |
| 마감 후 수정 | 먼저 ‘기록 다시 열기’를 확인하고 재개한 뒤 편집 | 마감 상태를 모르게 바꾸지 않고 취소 경계 명확화 |
| 새 수행 날짜 | 사용자에게 보이는 오늘 날짜를 기본으로 제안, 저장 전에 변경 가능 | 입력일을 숨겨 실제 날짜로 확정하지 않음 |
| 과거 날짜 미상 | 미상 유지, 사용자가 날짜를 지정했을 때만 확인 상태로 변경 | 단순 중량 수정으로 오늘 수행한 것처럼 바뀌지 않음 |
| 달력 | 기존 예정일 보기 유지 + 실제 수행일 보기 제공 | 과거 기록 접근을 유지하면서 새 날짜를 활용 |
| D5 | 현재 계획일 기준 정책 유지 | 실제 날짜 수집과 추천 정책 변경을 한 번에 섞지 않음 |

### 1.3 이번에 추가하지 않는 기능

운동 소요시간·시작 시각 추정, 휴식 타이머, 자동 알림, 실제 1RM/e1RM, 계획 날짜 이동, 보관 기록 정정 허용, 공통 운동 사전, 백업 파일 선택·가져오기, 원격 동기화는 이 단위에 포함하지 않는다. 날짜 저장만으로 프로그램 간 운동 ID를 합치지 않는다.

## 2. 사용자 흐름

### 2.1 새 세트 기록

1. 오늘 화면 또는 예정일 달력에서 편집 가능한 운동을 연다.
2. 세트를 누르면 실제 중량·반복·선택 RIR·메모와 실제 수행일이 보인다.
3. 새 세트의 수행일 기본값은 주입 가능한 현재 시계의 현지 달력 날짜다. 사용자가 과거 날짜를 선택할 수 있고 미래 날짜는 허용하지 않는다.
4. 입력한 숫자 원문과 수행일 선택을 초안에 저장한다. 미완성 숫자도 그대로 유지한다.
5. ‘세트 완료’ 또는 ‘저장하고 다음 세트’를 누르면 입력 검증 후 실제값을 저장한다.
6. 저장 성공 후에만 편집기를 닫거나 다음 세트로 이동한다. 기존 완료 안내는 필수 기록 충족 알림이며 명시 마감과 별개다.
7. 이미 저장된 초안을 열고 아무 입력도 바꾸지 않은 채 닫으면 원문을 다시 구성하지 않는다. 기존 초안에 수행일 키가 없더라도 화면에 제안한 오늘 날짜를 자동 저장하지 않는다. 실제 사용자 편집·날짜 선택·완료 동작에서만 새 필드를 반영한다.

### 2.2 과거 날짜가 없는 실제 기록 수정

1. 예전 파일에서 복원한 완료 세트를 열면 `수행일 미상`으로 표시한다.
2. 중량만 고쳐 저장해도 실제 수행일은 미상으로 남는다.
3. 사용자가 날짜 지정 동작을 통해 실제 수행일을 선택했을 때만 새 날짜를 저장한다.
4. 최초 입력 시각이 미상이면 계속 미상으로 두고, 이번 수정 시각만 저장한다.

### 2.3 기록 마감

1. 운동 화면에서 실제 수행·제외·미기록·작성 중 집계와 실제 날짜를 확인한다.
2. 필수 미기록 또는 초안이 있으면 이유를 안내하고 마감 버튼을 비활성화한다.
3. ‘기록 마감’에서 확인창을 열어 이번 마감 대상과 요약을 검토하고 ‘마감하기’를 누른다.
4. 취소/뒤로 가기는 원래 기록·초안·마감 이력을 바꾸지 않는다.
5. 확인하면 하나의 마감 동작 ID와 UTC 시각을 고정해 저장한다.
6. 저장 성공 뒤에만 `기록 마침` 상태와 요약을 표시한다. 전부 제외한 경우 `실제 수행 0세트`로 남는다.
7. 저장 실패 시 확인창을 유지하고 재시도한다. 원래 메모리 상태가 먼저 마감으로 바뀌지 않는다.

### 2.4 재개·다시 마감

1. 마감된 운동은 세트 입력을 막고 요약을 보여준다.
2. ‘기록 다시 열기’의 확인창에서 ‘취소’하면 마감 상태를 유지하고, ‘다시 열기’를 누르면 재개 저장을 시작한다.
3. 재개 저장 성공 후 입력을 다시 허용한다. 기존 완료값·원래 목표·마감 사건은 남는다.
4. 재개 자체는 세트 완료나 운동 수행으로 집계하지 않는다.
5. 이후 편집기에서 닫으면 현재 초안 보존 계약을 따른다. 다시 마감할 때 초안 처리를 안내한다.
6. 재마감은 새로운 사건이다. 이전 마감 요약과 시각을 덮어쓰지 않는다.

### 2.5 실제 수행일 달력

1. 기록 탭에서 예정일/수행일 보기 기준을 선택한다.
2. 예정일 보기는 기존 계획과 완료/제외/초안 탐색을 유지한다.
3. 수행일 보기는 완료 실제값 중 확인된 `performedDate`가 있는 세트만 표시한다.
4. 날짜 미상·제외·초안은 실제 수행일의 점이나 운동 횟수를 만들어내지 않는다.
5. 하나의 세션이 여러 날에 걸쳐 수행됐다면 해당 날짜 각각에서 동일 세션으로 접근한다. 새 세션 ID를 만들지 않는다.
6. 수행일을 모르는 완료 세트 수와 예정일에서 확인하는 방법을 안내한다.
7. 수행일 카드의 ‘선택한 날 실제 수행’은 선택한 날짜의 세트만 센다. ‘세션 전체’ 수와 여러 수행일 목록을 따로 보여 하루 실적으로 오인하지 않게 한다.
8. 메모·과거 완료 안내만 있는 보관 세션도 예정일 보기에서 찾아 읽을 수 있다. 세션 메모는 조회만 제공하며 새 메모 편집 기능을 추가한 것은 아니다.

## 3. 데이터 계약

### 3.1 실제 세트의 추가 필드

| 필드 | 타입·의미 | 신규 값·이전 데이터 |
|---|---|---|
| `performedDate` | nullable ISO 달력 날짜 | 새 입력에서 확인한 실제 날짜; 과거 미상은 null |
| `recordedAt` | nullable UTC ISO 시각 | 새 실제값 최초 저장 시각; 과거 기록 수정 시 임의 채움 금지 |
| `updatedAt` | nullable UTC ISO 시각 | 새 입력 또는 이번 수정 시각; 실제 운동 종료 시각 아님 |

달력 날짜는 `calendarDate`의 UTC 자정 표현을 사용하지만 실제 UTC 순간을 의미하지 않는다. 사용자 현지 날짜의 연·월·일을 보존하며 다른 시간대에서 열어도 날짜를 재해석하지 않는다. 입력/수정/마감 사건의 UTC 시각과 분리한다.

제외 상태에는 실제 수행 날짜·시각을 넣지 않는다. JSON에서 제외 세트에 수행 메타데이터가 잘못 들어 있으면 거부한다. 날짜·시각이 null인 이전 실제값은 새 키를 생략해 직렬화한다. 기존 D5 `evidenceRecords`가 실제값 JSON을 근거 문자열로 보관하므로, 새 null 키를 일괄 추가해 옛 근거의 동일성을 깨지 않도록 한다.

초안 허용 키에 `performedDate`를 추가한다. ISO 날짜 문자열 또는 명시적인 빈 문자열을 보관하며, 누락된 이전 초안과 미상 값 처리 기준은 편집기에서 구별한다. 잘못된 초안 원문을 읽을 때 자동으로 오늘 날짜로 고치지 않는다.

### 3.2 세션 요약 `SessionSummary`

| 필드 | 집계 기준 |
|---|---|
| `totalSets` / `requiredSets` | 계획 스냅샷의 전체/필수 세트 수 |
| `performedSets` | `SetActualStatus.completed` 실제값 수, 0kg 포함 |
| `skippedSets` | `SetActualStatus.skipped` 수 |
| `unrecordedSets` | 실제값이 없는 세트 수, 초안만 있는 세트 포함 |
| `draftSets` | 별도의 초안이 있는 세트 수; 실제값을 수정 중이면 다른 집계와 중첩 가능 |
| `requiredUnrecordedSets` | 실제값이 없는 필수 세트 수 |
| `unknownDateSets` | 완료 실제값 중 실제 수행일이 없는 수 |
| `performedDates` | 완료 실제값에서 얻은 확인된 실제 날짜의 정렬·중복 제거 목록 |
| `canClose` | 필수 미기록 0이고 초안 0일 때 true |

`performedSets + skippedSets + unrecordedSets == totalSets`를 유지한다. 초안 수는 이 합계에 다시 더하지 않는다. 요약은 실제 기록과 제외 수를 보여주며 ‘운동 시간’ 또는 ‘운동일 수’로 이름을 바꾸지 않는다.

### 3.3 명시 마감/재개 사건

`TrainingAppState.sessionEvents`는 `SessionLifecycleEvent` 목록이다.

| 필드 | 계약 |
|---|---|
| `id` | 확인 동작의 식별자; 저장 재시도 동안 유지 |
| `sessionId` | 기존 계획의 실제 세션 ID 참조; 새로 만들지 않음 |
| `kind` | `closed` 또는 `reopened` |
| `at` | 사건의 UTC 시각; 실제 수행 시각과 별개 |
| `summary` | 사건 당시의 요약 스냅샷 |

세션별 사건은 closed→reopened→closed 순서다. 마감 사건이 없는 신규 세션은 미마감이며, `legacySessionIds`에 있고 명시 사건이 없으면 과거 마감 여부 미상이다. 같은 동작 ID·세션·종류·시각의 재시도는 no-op으로 처리하고, 같은 ID로 다른 명령을 보내면 거부한다. 고아 세션 참조·중복 ID·잘못된 종류/순서·불가능한 요약은 파일 읽기 단계에서 거부한다.

전체 사건 목록의 UTC 시각은 역행할 수 없으며 같은 시각은 허용한다. 재개 사건의 요약은 직전 마감 스냅샷과 같아야 한다. 마지막 상태가 마감이면 현재 실제 기록의 요약도 마지막 마감 요약과 일치해야 한다. 기기 시계를 과거로 돌려 사건 시각이 역행하면 검증 오류를 내며 시각을 조용히 고치거나 사건을 재정렬하지 않는다.

마감 상태에서 세트 실제값·초안·세션 메모 변경을 도메인에서도 막는다. UI만 버튼을 감추는 방식으로 제한하지 않는다. 명시 재개 후 편집하고 새 요약으로 다시 마감한다. 계획 교체로 이전 계획을 보관하더라도 날짜·사건·요약을 유지한다.

### 3.4 과거 마감 미상

`legacySessionIds`는 이전 파일에서 실제값·초안·세션 메모·완료 안내 이력이 있던 세션을 나타낸다. 과거에 기록을 마쳤다고 단정하지 않는다. `completionNotified`를 closed 사건으로 변환하지 않는다. 새로 시작한 세션과 미상 세션을 구분하되, 둘 다 조건을 충족하면 사용자가 첫 명시 마감을 할 수 있다.

## 4. 저장 스키마와 이행

운동 저장 envelope는 **v1/v2 읽기 + v3 쓰기**로 확장한다. 프로그램 카탈로그 schemaVersion과 설정/습관 파일 버전은 별개이며 변경하지 않는다.

| 입력 파일 | 읽기 결과 | 다음 저장 |
|---|---|---|
| 파일 없음 | 새 빈 상태, 사건/legacy 집합 없음 | v3 |
| v1 | 원래 계획·기록·초안 보존, D5 기본값·새 메타데이터 미상 | v3 |
| v2 | 기존 D5 포함 보존, 수행일 추정 없음, 과거 마감 미상 추출 | v3 |
| v3 | 새 필드·사건 구조·참조 검증 | v3 |
| 알 수 없는 버전/손상 | 읽기 실패, 원본 보존 | 자동 저장/초기화 금지 |

v3에서 새 루트 필드가 빠지면 이전 파일처럼 조용히 읽지 않는다. 기존 null 수행 메타데이터를 덧붙여 D5 근거 문자열을 바꾸지 않는다. 이행을 반복해도 프로그램/세트 ID·목표·실제 중량/단위·초안 원문·조정 이력·마감 미상 여부가 바뀌지 않아야 한다.

## 5. 컨트롤러와 실패 경계

기존 자동 입력 저장은 메모리의 최신 입력을 먼저 유지하고 저장을 직렬화한다. 마감/재개는 이와 구별해 **후보 계산 → 파일 저장 → 메모리 확정**으로 처리한다.

- `TrainingController.now`로 시계를 주입해 날짜·시각 테스트를 재현한다.
- `closeSession`/`reopenSession`은 `Future<bool>`로 저장 성공 여부를 반환한다.
- `sessionActionPending` 동안 새 일반 `update`와 중복 마감/재개를 받지 않는다.
- 일반 입력 저장이 진행 중이거나 실패 상태면 먼저 그 저장을 해결하도록 안내한다.
- `sessionActionError`는 일반 `saveError`와 분리한다. 마감 실패를 일반 입력 재저장 성공으로 숨기지 않는다.
- 마감/재개 실패 시 원래 메모리와 세트 입력을 보존하고 확인창의 같은 동작 ID로 재시도한다.
- 저장 성공 뒤에만 revision을 갱신하고 화면 상태를 통지한다.
- 컨트롤러를 dispose한 뒤에도 진행 중 파일 작업은 완료될 수 있으나 폐기된 화면에 notify하지 않는다.

실제 파일 교체는 기존 같은 디렉터리의 임시 파일 flush→rename과 writer queue를 사용한다. 임의의 전원 차단·OS 파일 시스템 장애 전체에서 보존된다고 주장하지 않는다. 파일 손상·백업 복원은 별도 단위다.

## 6. 화면·접근성·렌더 계약

기존 Console v2·하단 5탭·FlowPage·GlassPanel·ConsoleField·PrimaryAction을 유지한다. Fixed 앱바, Fluid 스크롤 본문, Hybrid 세트 편집 시트/확인창으로 조립한다. 마감 요약의 실제 숫자와 날짜는 mono, 한글 상태/설명은 KR 폰트다. 새 브랜드 색·장식·탭을 추가하지 않는다.

마감/재개 확인창은 버튼 초점·취소·저장 중 중복 차단·실패 문구를 포함한다. 375×812, 키보드 inset, 큰 글자 조건에서 본문/날짜/마감/재개 버튼을 스크롤해 누를 수 있어야 한다. 세트별 날짜를 한꺼번에 모든 행의 큰 제목으로 반복하지 않고 목표/실제 구분 아래 보조 정보로 표시한다.

디자인 근거는 기존 [Hevy 기록 화면 관찰](../research/2026-09-08/concepts/visual-references.md)의 숫자 정렬·완료 상태와 현재 앱의 D5 확인창을 재사용한다. 새 시각 방향을 탐색하는 작업이 아니다. 실제 위젯 렌더를 보고 가장 큰 문제를 수정한 뒤 재렌더한다.
