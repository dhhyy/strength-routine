# 9/8 문서 — Strength 기본 프로그램 5개

작성·공식 자료 확인: 2026-09-08. 사용자의 “일반 카탈로그에 제안하는 실제 프로그램 5개를 만들어 등록” 요청에 따라 [실제 카탈로그](../assets/programs.json)에 수록했다. 작성자 표시는 **Strength**, 프로그램 버전은 모두 `2026-09-08.1`이다.

다섯 구성은 이번 제품을 위해 독자 작성했다. 자격을 가진 특정 트레이너의 처방이나 공식 기관의 인증 프로그램으로 표시하지 않는다. 이전에 조사한 StrongLifts·GZCLP·5/3/1의 프로그램을 채택하거나 복제한 것이 아니며, 해당 후보의 재사용·수록 결정은 별개로 남는다. 아래 운동 조합과 수치는 제품 제안이고, 기관 자료에서 그대로 가져온 처방표가 아니다.

## 선택지와 총량

모두 **4주**, 매주 같은 세션 수와 순서를 유지한다. 표의 세트 수는 준비운동을 제외한 **전신 전체 작업 세트 합계**이며, 부위별 주간 세트 수가 아니다.

권장 요일은 설명에 제공하는 예시다. 현재 모델은 별도의 기본 요일 필드를 저장하지 않고, 사용자가 주간 횟수만큼 요일을 선택한다. 엔진이 회복 간격의 적절성까지 판정하지 않으므로, 전신 프로그램을 연속 요일로 배치하는 선택을 자동으로 막지는 않는다.

## 공통 수행·기록 원칙

- 일반적인 건강한 성인이 기본 동작을 배우고 시작하는 구성이다. 첫 운동 전 가벼운 준비운동을 하며, 준비운동 세트는 이 표나 자동 생성 세트에 포함하지 않았다.
- 각 작업 세트는 자세를 유지하며 약 3회 더 할 수 있는 여유인 **RIR 3**을 목표로 한다. 이 여유를 판단하기 어렵다면 가벼운 중량부터 동작을 익힌다. 통증·어지러움이 생기면 중단한다.
- 세트 사이에는 약 2분 이상 충분히 쉰다. 이는 각 세트에 저장된 타이머 값이나 정확한 휴식 종료 명령이 아니라 프로그램 설명이다.
- 덤벨은 **한 개의 무게**, 바벨은 **봉을 포함한 전체 무게**, 머신은 **표시 중량**, 맨몸은 **0kg**으로 기록한다. 서로 다른 머신의 표시 중량을 같은 저항이라고 해석하지 않는다.
- 덤벨 전용 프로그램은 고블렛 스쿼트·글루트 브리지에 덤벨 1개, 나머지 덤벨 종목에 같은 무게 2개를 사용한다.
- 운동·세트 구성은 유지하고 사용자가 시작일·운동 요일·중량을 정한다. 4주 내 자동 증량·실패 반복·최대 중량 시험은 카탈로그에 처방하지 않는다.
- 4주는 일정과 기록을 검토할 초기 단위다. 마지막 주를 자동 디로딩 주로 해석하지 않는다. 완료 후 자동 반복·장기 진급 규칙도 카탈로그에 넣지 않았다.

기존 질환·부상에 맞춘 개별 처방이나 동작 지도는 이 데이터만으로 제공되지 않는다. 이 문서는 각 사용자의 수행 능력을 확인한 기록이 아니다.

## 중량 입력과 기존 기능 연결

**수동 프로그램 4개:** 모든 처방은 `manual`, 운동의 `mainLift`는 비어 있다. 루틴 생성 시 최근 리프트 기록이나 기준중량을 강제하지 않는다. 생성된 목표 kg는 `null`이며 사용자가 실제 세트에서 kg·반복·RIR을 입력한다. 최근 기록이 없는 초급 사용자도 설정에서 결과 확인까지 진행할 수 있음을 위젯 테스트로 확인했다. 장비 최소 증량 단위 입력은 현재 설정 화면의 공통 필수값이다.

**바벨 기본 프로그램:** 백스쿼트와 벤치프레스만 각각 `mainLift: squat / bench_press`, `percentOfBaseline: 100`이다. 여기서 기준은 **본인이 자세를 유지하며 8회 수행한 뒤 RIR 3을 남길 수 있는 것으로 알고 있는 작업중량**이다. 1RM·추정 1RM·새로운 최대 시도 중량이 아니다. 현재 설정 흐름에서는 두 리프트의 최근 기록과 사용자가 직접 입력하는 기준값을 모두 요구한다. 기준값이 없다면 임의 계산으로 채우지 않고 수동 프로그램을 선택하도록 설명했다.

다른 바벨 종목인 루마니안 데드리프트·오버헤드프레스는 수동 처방이다. 루마니안 데드리프트를 컨벤셔널 데드리프트의 기준값으로 잘못 묶지 않는다. 초기 목표는 기준값에 장비 증량 단위 반올림을 적용하므로, 입력값이 해당 단위의 배수가 아니면 표시 kg가 달라질 수 있다.

향후 목표 kg가 있는 두 종목은 별도의 D5 감량 기능과 연결 가능한 데이터다. 카탈로그 자체에 새로운 감량률·발동 조건·되돌리기 규칙을 넣지는 않았다. 수동 처방은 미래 목표 kg가 없어 같은 방식의 목표 조정 대상으로 취급하지 않는다.

## 데이터 계약과 변경 원칙

- JSON 스키마는 1이며, 모델이 지원하는 유한 주차·매주 동일 세션 수·고정 반복·RIR·수동 또는 기준값 비율만 사용했다.
- `TrainingProgram.id`는 프로그램별 고유값, `ProgramSession.id`는 각 프로그램 내 고유값이다. 같은 종목은 주차·세션이 달라도 동일한 `ProgramExercise.id`·이름·`mainLift`를 유지한다.
- 세트 ID는 운동 내 `work-1 / work-2`다. 실제 기록 키는 계획·세션·운동·세트 식별자의 조합이므로 다른 주차의 같은 종목과 충돌하지 않는다.
- 일반 `loadBundledPrograms()`가 이 파일을 읽는다. QA 전용 주입이 필요하지 않으며, 사용자 계획·운동 기록을 미리 만들거나 완료 상태를 생성하지 않았다.
- 시작 시 프로그램 버전과 구성이 계획 스냅샷에 보존된다. 이후 카탈로그 개정 시 새 버전을 부여하고, 이미 진행 중인 사용자의 스냅샷을 덮어쓰지 않는다.
- 장비·대상·권장 요일·기록 단위 설명은 현재 `description`에 있다. 검색 가능한 장비 태그나 대체 종목 규칙을 구현했다고 보지 않는다.
