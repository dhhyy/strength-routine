**최신 개발 기준:** [기능 개발·커밋 기록](2026-09-07-development.md)의 F01~05. 다음 세트 이동, 수행/제외 구분, 실제 운동 검색, 생활습관 저장, 보관 초안 열람을 추가했다. 전체 65개 테스트가 통과했으며 현재 구현과 검증 범위는 아래와 같다.

## 현재 상태 · 9/7 기능 개발 완료분

**프로그램 선택 → 기록·일정 설정 → 결과 확인 → 시작 → 세트 기록 → 로컬 저장·복원**을 코드로 연결했다. 현재 배포용 [프로그램 카탈로그](../assets/programs.json)는 비어 있다. 공개 프로그램 후보를 조사했고 특정 원작의 선정·앱 수록·배포는 아직 미확정이다.

- 구현: 프로그램 버전·일정·목표 스냅샷, 실제 세트/초안·완료/제외·메모, 저장 후 다음 미기록 세트 이동과 실패 재시도, 실제 오늘/달력/프로필, 보관 초안 원문 조회. 실제 수행·제외·작성 중 집계를 구분하며 명시 마감 스키마는 신설하지 않았다.
- 검색·습관: 등록 프로그램과 진행/보관 계획의 운동 검색·출처별 읽기 전용 구성 상세, 사용자 습관 추가·날짜별 체크·보관/활성화·기기 저장을 구현했다. 습관은 `habits-state.json`에 저장하며 운동의 `training-state.json`과 분리한다. 운동 설명 사전·미디어 가이드는 후속 범위다.
- 검증: `flutter analyze` 문제 없음, 전체 **65개 테스트 통과**. 375×812 위젯 렌더와 키보드 inset·긴 한글·큰 글자 조건을 확인했다. 최신 QA 네이티브 빌드·설치는 성공했지만 직접 실행은 `NSMachErrorDomain -308`로 실패했고, 전용 `003D93A6-D728-4968-92EE-7996BD1E568E` 기기를 `flutter run`이 두 차례 인식하지 못했다. 실제 네이티브 조작·프로세스 재실행 후 화면 복원은 미검증이다.
- 검증용 진입점: [tool/qa_preview.dart](../tool/qa_preview.dart). 합성 프로그램 1주·1세션·2세트를 주입하고 `qa-training-state.json`·`qa-habits-state.json`에 별도 저장한다. QA 데이터는 출시 콘텐츠가 아니다.
- 한계·미결정: 매주 동일 세션 수의 유한 프로그램만 지원. 직접 빌드 방식으로 전환할지 묻는 질문은 미응답이며 기존 구성 보존 결정을 유지한다. 첫 실제 프로그램·D5 정량 정책은 미정이다. AMRAP·진급·무한 주기·자동 e1RM/조절·시작 후 일정 변경 UI·트레이너 도구·동기화는 미구현이다.

## 초기 UI 진행 이력

초기에는 모든 화면의 시각적 틀을 먼저 개발했다. 아래 ‘5탭 완성’은 당시 UI 포팅 완료를 뜻하며 실사용 기능·전체 출시 완료를 뜻하지 않는다.
- ✅ 요구사항 정리
- ✅ 디자인 파운데이션 (Console v2: 깊이·은은함)
- ✅ 디자인 하네스 (Skill · CLAUDE.md · Hook)
- ✅ 첫 화면 `오늘 루틴` Flutter 구현
- ✅ **나머지 4개 탭 (기록 · 검색 · 습관 · 프로필)** — 시안 + Flutter 포팅 + **시뮬레이터 배포·검증** (5탭 완성)
- ✅ git 초기화 · 첫 커밋 (진행 스냅샷)
- ✅ **온보딩 인트로(소개 5장)** — 시안 + **Flutter 포팅·시뮬 검증** (앱 진입 → 온보딩 → 5탭 연결, `RootGate`)
- ✅ 9/7 초기 최근 기록 타입·검증·JSON 변환. 당시 정적 분석 및 12개 테스트 통과.
- 이전 검증 이력: 첫 프로그램 시작·기록·저장 연결 단계에서 39개 테스트가 통과했고, 당시 Mac 잠금으로 네이티브 조작을 확인하지 못했다. 현재 검증 수와 실행 장애는 위 최신 상태를 따른다.

현재 흐름은 **소개 온보딩과 프로그램 선택·시작을 분리**한다. 사용자는 트레이너의 완성된 프로그램을 선택하며, 앱은 운동·세트 구성을 유지하고 중량·시작일·요일만 맞춘다. 과거 직접 루틴 생성·공통 4주 블록 제안은 현재 흐름보다 우선하지 않는다.

## 다음 할 일
현재 작업과 기능별 커밋은 [9/7 개발 기록](2026-09-07-development.md), 답변 원문과 이력은 [인터뷰·작업 기록](2026-09-07-work-log.md)을 따른다. I08의 공개 후보 조사 요청은 처리했지만 첫 콘텐츠 선정과 직접 빌드 전환 여부는 아직 답이 없다.

후속 요청으로 [15개 개선 기능 상세 분석](2026-09-07-feature-specification.md)을 남겼다. 현재 구현과 설계 제안을 구분한 문서이며, 마감·실제 수행일·일정 이동·백업 등의 새 기능이 구현됐다는 뜻은 아니다. 기능 개발 시 해당 IM의 데이터 계약·실패/취소 조건과 기존 코드를 함께 확인한다.

1. 전용 시뮬레이터 인식·실행 문제를 해결한 뒤 QA 합성 프로그램과 일반 빈 카탈로그의 실제 조작·종료 후 복원을 확인한다. 통과한 65개 테스트와 네이티브 검증을 구분한다.
2. 직접 빌드 전환 질문의 답변, 공개 후보의 첫 선정·버전·기간·수록 조건을 반영한다. 후보를 자동 선택하거나 미지원 처방을 고정 세트로 바꾸지 않는다.
3. 후속 설정, 실제 수행일·공통 운동 식별에 기반한 기록 추세, 시작 후 일정 변경과 D5 조절 정책을 구체화한다. 감량 수치를 임의로 정하지 않는다.
4. 전체 설정·코치 Q&A·트레이너 등록 도구·계정/서버 동기화·구독·배포는 후속 단계다.
