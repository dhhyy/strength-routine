# 00 · 프로젝트 개요 (진입점)

> 트레이너 프로그램 선택·운동 기록 — Flutter 모바일 앱. **여기서부터 읽으세요.**
> 최종 갱신: 2026-09-08 · 갱신 규칙: 마일스톤마다.

**9/8 최신 고급 처방 개발:** [휴식·템포·슈퍼세트·AMRAP](2026-09-08-advanced-prescriptions.md)을 관리자 편집→검토/저장→사용자 처방 표시·운동 순서·실제 기록·복원으로 연결했다. 휴식은 완료된 세트에서 직접 시작하고 일시정지/재개/종료한다. 타이머 실패는 운동 기록 저장과 분리한다. 고급 처방을 쓸 때만 카탈로그/관리자/운동 스키마를 2/3/4로 승격하고 기본 5개 파일은 유지한다. 최종 검증과 남은 범위는 해당 문서가 우선한다.

**9/8 최신 관리자 개발:** 사용자의 세밀한 편집 요청으로 [주차·세트 정밀 편집](2026-09-08-admin-precise-editor.md)을 추가했다. 기존 프로그램 불러오기/복제, 독립 주차와 세트별 처방, 순서·복사·삭제·되돌리기, 새 버전 검토·저장을 연결했다. 원래 사용자 계획과 기본 5개 카탈로그 파일을 자동 변경하지 않는다. 로드맵 R05를 먼저 진행했으며, 백업·복원은 계속 후속이다.

**9/8 최신 앱 개발:** [실제 수행일·기록 마감 보고서](2026-09-08-session-lifecycle-verification.md)와 [상세 명세](2026-09-08-session-lifecycle.md)에 수행일·입력/수정 시각, 명시 마감·재개·요약, 수행일 달력, v1/v2→v3 이행과 실패·취소 보존을 기록했다. [후속 10개 개발 로드맵](2026-09-08-development-roadmap.md)은 다음 작업의 상세 설계이며 구현 완료 목록이 아니다.

**남은 기능 확인:** [9/8 남은 구현·검증 상태표](2026-09-08-remaining-work.md)는 완료된 앱 기능, 후속 사용성 제안, 구독 등 운영 연결, 실기기 미검증을 구분한다. 아래의 9/7 초기 상태를 현재 미구현 목록으로 사용하지 않는다.

**9/8 최신 랜딩 디자인:** [Three.js 인터랙티브 시안 5개](2026-09-08-interactive-landing-concepts.md)를 추가했다. 중량·프로그램·요일·세트 기록·감량 제안을 서로 다른 화면에서 직접 체험한다. [로컬 비교 페이지](http://127.0.0.1:4175/landing/concepts/)와 [실행 안내](../landing/concepts/README.md)를 따른다. 기존 앱과 독립적이며 외부 배포 전이다.

**9/8 앱 기능 확장:** 기본 프로그램 5개를 카탈로그에 등록했고 관리자 전용 내부 진입점, 기록 추세·D5 감량 제안/영구 되돌리기, 기본 단위/제안 표시 설정, 로컬 도움말·구독 준비 안내를 추가했다. [기능 검증·현재 상태](2026-09-08-feature-verification.md)와 [실기기 테스트 순서](2026-09-08-device-test-guide.md)를 먼저 읽는다. 과거의 빈 카탈로그·D5 미구현·트레이너 등록 예정은 아래 이력 당시 상태다. 트레이너는 운영자 1명이며 다중 트레이너 등록/모집 기능은 제외한다.

**9/8 웹 랜딩:** [인터랙티브 체험·검증 기록](2026-09-08-work-log.md)을 추가했다. 독립 `landing/`에서 구성 확인·요일 선택·세트 입력·브라우저 저장 복원을 체험한다. 앱 카탈로그/훈련 정책과 별개이며 로컬 검증 완료, 외부 배포 전이다.

**9/7 앱 개발 이력:** [기능 개발·커밋 기록](2026-09-07-development.md)의 F01~05에서 다음 세트 이동, 수행/제외 구분, 실제 운동 검색, 생활습관 저장, 보관 초안 열람을 추가했다. 9/7 검증과 앞선 9/8의 120개·153개·189개 결과는 당시 이력이며 최신 전체 회귀는 위 고급 처방 문서에서 확인한다.

**현재 검증 지시:** 사용자는 시뮬레이터를 띄우지 않고 자체 검증·상세 문서 갱신을 요청했다. 정적 분석과 자동 테스트를 기본으로 하며, 사용자 재요청 전까지 시뮬레이터 실행·조작·장애 해결 재시도를 자동 재개하지 않는다.

## 과거 상태 · 9/7 기능 개발 완료분

**프로그램 선택 → 기록·일정 설정 → 결과 확인 → 시작 → 세트 기록 → 로컬 저장·복원**을 코드로 연결했다. 현재 배포용 [프로그램 카탈로그](../assets/programs.json)는 비어 있다. 공개 프로그램 후보를 조사했고 특정 원작의 선정·앱 수록·배포는 아직 미확정이다.

- 구현: 프로그램 버전·일정·목표 스냅샷, 실제 세트/초안·완료/제외·메모, 저장 후 다음 미기록 세트 이동과 실패 재시도, 실제 오늘/달력/프로필, 보관 초안 원문 조회. 실제 수행·제외·작성 중 집계를 구분하며 명시 마감 스키마는 신설하지 않았다.
- 검색·습관: 등록 프로그램과 진행/보관 계획의 운동 검색·출처별 읽기 전용 구성 상세, 사용자 습관 추가·날짜별 체크·보관/활성화·기기 저장을 구현했다. 습관은 `habits-state.json`에 저장하며 운동의 `training-state.json`과 분리한다. 운동 설명 사전·미디어 가이드는 후속 범위다.
- 검증: 최신 실행 결과와 [V01 습관 탭·V02 프로그램 시작일 선택기의 날짜 경계](2026-09-07-verification.md)는 자체 검증 보고서에서 확인한다. 기존 375×812 위젯 렌더·키보드 inset·긴 한글·큰 글자 증거는 네이티브 조작과 구별한다. 이전 QA 실행의 `NSMachErrorDomain -308` 및 전용 기기 인식 실패 이력은 유지한다. 요청 변경 전 마지막 재시도는 Xcode 빌드(124.0초)까지 성공했지만 앱 화면은 확인하지 못했다. 실제 네이티브 입력·프로세스 재실행 후 화면 복원은 미검증이며 현재 보류다.
- 검증용 진입점: [tool/qa_preview.dart](../tool/qa_preview.dart). 합성 프로그램 1주·1세션·2세트를 주입하고 `qa-training-state.json`·`qa-habits-state.json`에 별도 저장한다. QA 데이터는 출시 콘텐츠가 아니다.
- 한계·미결정: 매주 동일 세션 수의 유한 프로그램만 지원. 직접 빌드 방식으로 전환할지 묻는 질문은 미응답이며 기존 구성 보존 결정을 유지한다. 첫 실제 프로그램·D5 정량 정책은 미정이다. AMRAP·진급·무한 주기·자동 e1RM/조절·시작 후 일정 변경 UI·트레이너 도구·동기화는 미구현이다.

## 초기 UI 진행 이력

초기에는 모든 화면의 시각적 틀을 먼저 개발했다. 아래 ‘5탭 완성’은 당시 UI 포팅 완료를 뜻하며 실사용 기능·전체 출시 완료를 뜻하지 않는다.
- ✅ 요구사항 정리
- ✅ 디자인 파운데이션 (Console v2: 깊이·은은함)
- ✅ 디자인 하네스 (Skill · CLAUDE.md · Hook)
- ✅ 첫 화면 `오늘 루틴` Flutter 구현
- ✅ **나머지 4개 탭 (기록 · 검색 · 습관 · 프로필)** — 시안 + Flutter 포팅 + **시뮬레이터 배포·검증** (5탭 완성)
- ✅ git 초기화 · 첫 커밋 (진행 스냅샷)
- ✅ **온보딩 인트로(소개 5장)** — 시안 + **Flutter 포팅·시뮬 검증** (앱 진입 → 온보딩 → 5탭 연결, `RootGate`)
- ✅ 9/7 초기 최근 기록 타입·검증·JSON 변환. 당시 정적 분석 및 12개 테스트 통과.
- 이전 검증 이력: 첫 프로그램 시작·기록·저장 연결 단계에서 39개 테스트가 통과했고, 당시 Mac 잠금으로 네이티브 조작을 확인하지 못했다. 현재 검증 수와 실행 장애는 위 최신 상태를 따른다.

현재 흐름은 **소개 온보딩과 프로그램 선택·시작을 분리**한다. 사용자는 트레이너의 완성된 프로그램을 선택하며, 앱은 운동·세트 구성을 유지하고 중량·시작일·요일만 맞춘다. 과거 직접 루틴 생성·공통 4주 블록 제안은 현재 흐름보다 우선하지 않는다.
