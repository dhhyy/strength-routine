# 00 · 프로젝트 개요 (진입점)

> 갱신: 2026-09-08 · 현재 계약 기준: 로컬 기능 완료 `5eaaed8`, 개발 검토 `064509f`. 후속 안정화는 [검토 후 수정 명세·결과](2026-09-08-review-fixes.md)에서 진행 상태와 검증을 확인한다.

트레이너 1명이 만든 완성 프로그램을 선택하고, 운동·세트 구성을 보존한 채 중량·시작일·요일을 맞추며, 운동 기록을 기기에 저장하는 Flutter 앱이다. 일반 사용자의 직접 루틴 생성과 다중 트레이너 등록은 제공하지 않는다.

## 현재 상태를 읽는 순서

1. [남은 구현·검증·운영 상태](2026-09-08-remaining-work.md): 현재 범위와 다음 작업의 정본이다.
2. [검토 후 안정화](2026-09-08-review-fixes.md): 확인된 오류·문서 충돌·시험 대기·여백 토큰 수정의 진행과 실제 결과다.
3. [여섯 로컬 기능의 계약·검증](2026-09-08-local-completion.md): 백업·복원, 미래 일정, 이전 실제값 복사, 관리자 확장, 휴식 설정, 운동 가이드의 구현 근거다.
4. [실제 기기 확인](2026-09-08-device-test-guide.md): 준비할 자료·조작 순서·미실행 결과표다.

기본 프로그램 5개 → 시작 전 검토 → 실제 세트/초안/완료·제외 → 명시 마감/재개 → 파일 저장·복원이 연결돼 있다. 기록 달력·추세·D5 제안과 되돌리기, 검색·습관·설정, 내부 관리자 정밀 편집, 휴식·템포·슈퍼세트·AMRAP, 로컬 FAQ·구독 준비 안내도 구현돼 있다.

로컬 기능 완료 당시 전체 349개 시험·정적 분석·iOS 서명 없는 기기 대상 빌드가 통과했다. 이후 [문서별 개발 검토](2026-09-08-development-review.md)에서 기존 349개 시험이 통과한 상태에서도 자동 휴식 재시도와 관리자 연속 버전 저장의 오류를 확인했다. 따라서 당시 통과 수는 오류 수정 완료나 출시 완료를 뜻하지 않는다. 수정 후 결과는 안정화 문서에 실제 실행대로 기록한다.

내부 관리자는 `lib/main_admin.dart`라는 별도 실행 진입점이며 서버 인증된 웹 관리자가 아니다. 백업은 운동 파일 범위이며 전체 앱/클라우드 동기화가 아니다. 실제 결제·문의 전송·OS 알림·원격 카탈로그 운영, 기기 시험과 공개 배포는 상태표에서 별도로 관리한다.

**검증 지시:** 사용자 재요청 전 Simulator를 실행하지 않는다. 정적 분석·자동 파일/위젯 시험·headless 렌더를 기본으로 하고 실제 기기 OS 종료/재실행은 따로 기록한다. 기능 단위로 문서·코드·검증을 함께 커밋한다.

## 과거 상태 · 9/7 기능 개발 완료분

**프로그램 선택 → 기록·일정 설정 → 결과 확인 → 시작 → 세트 기록 → 로컬 저장·복원**을 코드로 연결했다. 당시 배포용 [프로그램 카탈로그](../assets/programs.json)는 비어 있다. 공개 프로그램 후보를 조사했고 특정 원작의 선정·앱 수록·배포는 아직 미확정이다.

- 구현: 프로그램 버전·일정·목표 스냅샷, 실제 세트/초안·완료/제외·메모, 저장 후 다음 미기록 세트 이동과 실패 재시도, 실제 오늘/달력/프로필, 보관 초안 원문 조회. 실제 수행·제외·작성 중 집계를 구분하며 명시 마감 스키마는 신설하지 않았다.
- 검색·습관: 등록 프로그램과 진행/보관 계획의 운동 검색·출처별 읽기 전용 구성 상세, 사용자 습관 추가·날짜별 체크·보관/활성화·기기 저장을 구현했다. 습관은 `habits-state.json`에 저장하며 운동의 `training-state.json`과 분리한다. 운동 설명 사전·미디어 가이드는 후속 범위다.
- 검증: 최신 실행 결과와 [V01 습관 탭·V02 프로그램 시작일 선택기의 날짜 경계](2026-09-07-verification.md)는 자체 검증 보고서에서 확인한다. 기존 375×812 위젯 렌더·키보드 inset·긴 한글·큰 글자 증거는 네이티브 조작과 구별한다. 이전 QA 실행의 `NSMachErrorDomain -308` 및 전용 기기 인식 실패 이력은 유지한다. 요청 변경 전 마지막 재시도는 Xcode 빌드(124.0초)까지 성공했지만 앱 화면은 확인하지 못했다. 실제 네이티브 입력·프로세스 재실행 후 화면 복원은 미검증이며 현재 보류다.
- 검증용 진입점: [tool/qa_preview.dart](../tool/qa_preview.dart). 합성 프로그램 1주·1세션·2세트를 주입하고 `qa-training-state.json`·`qa-habits-state.json`에 별도 저장한다. QA 데이터는 출시 콘텐츠가 아니다.
- 한계·미결정: 매주 동일 세션 수의 유한 프로그램만 지원. 직접 빌드 방식으로 전환할지 묻는 질문은 미응답이며 기존 구성 보존 결정을 유지한다. 첫 실제 프로그램·D5 정량 정책은 미정이다. AMRAP·진급·무한 주기·자동 e1RM/조절·시작 후 일정 변경 UI·트레이너 도구·동기화는 미구현이다.

## 초기 UI 진행 이력

초기에는 모든 화면의 시각적 틀을 먼저 개발했다. 아래 ‘5탭 완성’은 당시 UI 포팅 완료를 뜻하며 실사용 기능·전체 출시 완료를 뜻하지 않는다.
- ✅ 요구사항 정리
- ✅ 디자인 파운데이션 (Console v2: 깊이·은은함)
- ✅ 디자인 하네스 (Skill · CLAUDE.md · Hook)
- ✅ 첫 화면 `오늘 루틴` Flutter 구현
- ✅ **나머지 4개 탭 (기록 · 검색 · 습관 · 프로필)** — 시안 + Flutter 포팅 + **시뮬레이터 배포·검증** (5탭 완성)
- ✅ git 초기화 · 첫 커밋 (진행 스냅샷)
- ✅ **온보딩 인트로(소개 5장)** — 시안 + **Flutter 포팅·시뮬 검증** (앱 진입 → 온보딩 → 5탭 연결, `RootGate`)
- ✅ 9/7 초기 최근 기록 타입·검증·JSON 변환. 당시 정적 분석 및 12개 테스트 통과.
- 이전 검증 이력: 첫 프로그램 시작·기록·저장 연결 단계에서 39개 테스트가 통과했고, 당시 Mac 잠금으로 네이티브 조작을 확인하지 못했다. 현재 검증 수와 실행 장애는 현재 상태표를 따른다.

마일스톤마다 이 진입점과 [현재 상태표](2026-09-08-remaining-work.md)를 갱신한다. 작업일마다 `docs/YYYY-MM-DD-work-log.md`에 결정·작업·검증·재개 지점을 남긴다. 기능 명세는 현행 계약을 갱신하고, 당시 시험 결과·커밋은 날짜와 범위를 붙여 보존한다. 과거 제안을 새 ‘다음 작업’으로 다시 안내하지 않는다.
