# 9/8 · 관리자 프로그램 정밀 편집 명세와 확인 절차

작성일: 2026-09-08. 대상은 `strength_routine`의 운영자 1인용 내부 Flutter 앱이다. 사용자의 “잘 편집이 가능할까? 세밀하게 컨트롤이 되어야 하는데” 요청을 받아, 기존 프로그램을 불러와 **주차 → 세션 → 운동 → 개별 세트**까지 수정하는 기능을 첫 개발 단위로 정했다.

**이 문서를 작성하는 시점에는 구현·검증 진행 중이다.** 아래의 기능 계약과 ME 확인 항목은 완료 결과가 아니라 이번 개발의 수용 기준이다. 마지막의 검증 결과가 채워지기 전에는 테스트 통과, 실제 기기 사용, 공개 배포를 완료한 것으로 읽지 않는다. 앞선 기본 관리자 도구의 동작은 [관리자 루틴 생성 문서](2026-09-08-admin-routine-builder.md), 원래 프로그램 5개의 내용은 [프로그램 문서](2026-09-08-programs.md)를 함께 읽는다.

## 1. 현재 편집이 부족한 이유와 이번 변경

기존 `RoutineBlueprint`는 **한 주의 운동 구성**과 **운동당 하나의 처방**을 보관한다. 예를 들어 스쿼트에 `3세트 × 8회, RIR 3`을 입력하면 세 세트에 같은 처방을 복사하고, 그 한 주를 전체 기간에 반복한다. 따라서 1주차 첫 세트만 6회로 바꾸거나 4주차에 세트 수를 줄이는 내용을 원문 그대로 표현할 수 없다. 이미 저장된 `TrainingProgram`을 이 단순 입력 형식으로 거꾸로 변환하면 주차별 차이·세트별 중량·선택 세트 같은 정보가 사라질 위험도 있다.

반면 사용자 앱의 `TrainingProgram`은 이미 각 주차·세션·운동·세트를 독립적으로 저장한다. 이번에는 사용자 프로그램 형식을 바꾸는 대신, 그 구조를 그대로 편집할 수 있는 관리자 초안과 화면을 추가한다. 기본 반복 생성기는 짧은 새 프로그램을 만드는 출발점으로 유지하고, 정밀 편집기는 기존 프로그램을 수정하거나 기본 생성 결과를 세부 조정하는 데 사용한다.

이번 작업의 핵심 완료 예시는 다음과 같다. 운영자가 카탈로그에서 프로그램을 열고 **2주차 B 세션의 첫 운동, 두 번째 세트만 반복 수·RIR·중량·필수 여부를 수정**한다. 다른 주차와 세트는 그대로 남아야 하며, 검토·새 버전 저장·JSON 내보내기를 거쳐 새로 시작하는 사용자에게 전달할 수 있어야 한다. 이미 시작한 사용자 계획과 기록은 변경하지 않는다.

## 2. 사용자 요구와 구현 판단의 구분

| 구분 | 내용 |
|---|---|
| 사용자 요구 | 관리자에게 세밀한 프로그램 편집이 필요하다. |
| 이전에 확정한 운영 방식 | 트레이너는 운영자 1명이며, 사용자는 완성 프로그램을 선택하고 중량·시작일·운동 요일을 맞춘다. |
| 이번 개발의 판단 | 기존 카탈로그 편집, 주차별 구성, 세트별 처방, 복사·순서 변경·삭제, 실행 취소·재실행을 한 편집 흐름으로 연결한다. |
| 아직 확정하지 않은 사항 | 개별 세트·주차 구성·운동 교체 중 운영자가 가장 자주 쓰는 업무의 우선순위, 구체적인 프로그램 개정 내용, 원격 관리자 운영 여부. |
| 수치의 성격 | 아래 입력 범위와 실행 취소 50단계는 편집기 구현 제한이다. 사용자에게 권장하는 운동량·강도·훈련 원칙이 아니다. |

새 편집 기능을 만들었다는 이유로 초기 프로그램 5개의 운동·중량을 자동 개정하지 않는다. 어떤 운동을 어떤 주차에 넣을지는 운영자가 작성하는 콘텐츠이며, 앱이 미정 처방을 추정하지 않는다.

## 3. 어느 수준까지 조절할 수 있는가

| 수준 | 이번 편집 대상 | 변경 영향 |
|---|---|---|
| 프로그램 | ID, 이름, 작성자, 버전, 설명 | 선택한 관리자 초안에만 반영하고, 검토한 후보를 저장해야 카탈로그에 반영한다. |
| 주차 | 주차별 독립 구성, 한 주 복사 후 추가, 기존 주차에 복사, 주차 삭제 | 명시한 주차에만 반영한다. 기간은 실제 주차 목록과 일치해야 한다. |
| 세션 | 주차 안의 세션 이름·순서·추가·삭제 | 선택한 주차에만 반영한다. 모든 주차의 세션 수를 같게 맞춰야 최종 프로그램으로 저장할 수 있다. |
| 운동 | 운동 ID, 이름, 메인 리프트 분류, 운동 순서·추가·삭제 | 선택한 세션의 운동을 편집한다. 같은 운동 ID의 의미는 프로그램 전체에서 일치해야 한다. |
| 개별 세트 | 세트 ID, 반복 수, RIR, 필수/선택, 중량 방식, 중량 값, 기준 리프트 | 선택한 세트에만 반영한다. 같은 운동의 나머지 세트로 자동 전파하지 않는다. |
| 편집 이력 | 되돌리기·다시 실행, 연속 텍스트 입력 묶음 | 현재 편집 세션의 초안 상태를 되돌린다. 이미 배포한 프로그램이나 사용자 기록을 되돌리는 기능이 아니다. |

세션의 `dayOrder`는 **그 주에서 몇 번째 운동인지**를 나타낸다. 월요일·목요일 같은 실제 요일은 사용자가 프로그램을 시작할 때 정하므로, 관리자 편집기에서 특정 사용자의 달력을 직접 수정하지 않는다.

### 3.1 세트별로 달라질 수 있는 예시

다음 표는 편집 능력을 설명하는 합성 예시이며, 기본 프로그램에 새로 반영할 훈련 처방이 아니다.

| 위치 | 반복 | RIR | 중량 방식 | 필수 여부 |
|---|---:|---:|---|---|
| 1주차 A · 운동 1 · 세트 1 | 8 | 3 | 운동 시 직접 입력 | 필수 |
| 1주차 A · 운동 1 · 세트 2 | 6 | 2 | 고정 40kg | 필수 |
| 1주차 A · 운동 1 · 세트 3 | 10 | 미지정 | 스쿼트 기준 작업중량의 60% | 선택 |
| 2주차 A · 운동 1 · 세트 1 | 7 | 3 | 운동 시 직접 입력 | 필수 |

이 네 행을 입력·저장·다시 불러왔을 때 각 값이 그대로 남는 것이 정밀 편집의 기준이다. 세트 수를 숫자로만 저장하고 같은 처방을 다시 펼치는 방식으로 돌아가면 안 된다.

### 3.2 메인 리프트와 기준 리프트를 분리한다

`ProgramExercise.mainLift`는 운동의 메인 리프트 분류다. `ProgramSet.load.lift`는 **해당 세트의 목표 중량을 계산할 기준 리프트**다. 서로 다른 필드이므로 편집기가 두 값을 임의로 같게 만들지 않는다. 메인 리프트가 비어 있는 보조운동도 명시한 리프트의 작업중량 비율을 사용할 수 있다.

사용자 설정 화면은 메인 리프트와 비율 처방이 참조하는 리프트를 모두 확인하며, 비율 처방에 필요한 기준중량이 없으면 계획 생성을 차단한다. 비율의 의미는 사용자가 입력한 기준 작업중량 대비 비율이다. 1RM 자동 추정, 운동 이름에서의 기준 리프트 추론, 직전 실제 중량의 자동 채택을 추가하지 않는다.

## 4. 화면 흐름과 상태

편집 화면 이름은 **주차·세트 정밀 편집**으로 정한다. 세부 라벨과 검증 결과는 구현 완료 후 실제 화면과 대조한다.

1. 관리자 카탈로그에서 수정할 프로그램을 선택해 정밀 편집으로 연다.
2. `프로그램 정보`에서 원래 ID·버전·작성자·설명을 확인한다.
3. 주차 선택 → 세션 선택 → 운동 목록 순서로 이동한다.
4. 필요한 운동이나 세트의 값만 바꾸고, 초안 저장 상태를 확인한다.
5. `변경 검토`를 눌러 전체 구조·입력값·기존 ID/버전 충돌을 검사한다.
6. 검토 화면에서 전체 주차·세션·운동·세트와 카탈로그 교체 여부를 확인한다.
7. `검토한 프로그램 저장`을 눌러 검토한 후보를 관리자 카탈로그에 저장한다.
8. 저장 성공 후 카탈로그에서 해당 ID·버전을 확인하고, 필요할 때 별도로 내보낸다.

| 상태 | 보여줄 정보와 허용 동작 |
|---|---|
| 작업 파일 읽는 중 | 로딩 상태를 표시한다. 아직 복원되지 않은 작업 위에 새 초안을 저장하지 않는다. |
| 카탈로그가 비어 있음 | 빈 목록과 작성 시작 경로를 제공한다. 샘플을 이미 저장한 것처럼 표시하지 않는다. |
| 새 정밀 초안 없음 | 기존 프로그램 열기 또는 유효한 기본 생성 결과에서 정밀 편집을 시작한다. |
| 편집 중 | 원문, 현재 주차·세션, 되돌리기 가능 여부, 초안 저장 상태를 표시한다. |
| 검증 실패 | 문제가 있는 주차·세션·운동·세트와 이유를 알려주고 입력을 유지한다. |
| 초안 저장 실패 | 미저장 상태를 표시하고 최신 입력을 유지한다. 재시도할 수 있다. |
| 프로그램 저장 중 | 검토한 후보의 중복 저장과 다른 카탈로그 변경이 겹치지 않게 한다. |
| 프로그램 저장 실패 | 검토 화면과 편집 원문을 유지하고 같은 후보를 재시도한다. 카탈로그 목록은 성공한 것처럼 바꾸지 않는다. |
| 내보내기 실패 | 관리자 작업을 유지하고 재시도를 제공한다. 온라인 게시 완료로 표시하지 않는다. |

주차와 세션을 바꾸는 것은 탐색이다. 값이 바뀌지 않았다면 실행 취소 단계를 늘리지 않는다. 좁은 화면에서도 선택 칩과 액션이 줄바꿈되거나 스크롤되어 모든 입력에 접근할 수 있어야 한다. 숫자 키보드가 열린 상태에서 검토·취소·오류 내용을 볼 수 있는지도 별도로 확인한다.

## 5. 입력·식별자·검증 계약

### 5.1 원문을 보존하는 초안

편집 도중의 반복 수 `3.`, 비어 있는 필수값, 아직 맞추지 않은 주차별 세션 수는 최종 프로그램이 아니다. 이 상태를 즉시 정수 변환하거나 정상값으로 치환하지 않고 **관리자 초안으로 저장**한다. 검토할 때만 최종 `TrainingProgram`으로 변환한다.

입력값을 읽거나 화면에 표시했다는 이유로 `3.`을 `3`으로 바꾸지 않는다. RIR 빈 값과 `0`은 서로 다르며, 직접 입력 방식의 세트와 고정 `0kg` 처방도 다르다. 중량 방식 전환 중 남은 원문은 초안에서 다룰 수 있지만, 최종 프로그램에는 선택한 방식에 유효한 값만 넣는다.

### 5.2 최종 프로그램의 허용 범위

| 필드 | 검토·저장 기준 |
|---|---|
| 프로그램·세션·운동·세트 ID | 공백만으로 이루어지지 않은 1~80자 문자열. 정밀 편집기는 기존 소비자 모델의 ID를 손실 없이 읽기 위해 기본 생성기의 slug 규칙을 소급 강제하지 않는다. 기존 ID를 화면 순번에서 다시 만들지 않는다. |
| 이름·작성자·세션 이름 | 공백만으로 이루어지지 않은 1~80자 문자열. 원문의 앞뒤 공백을 포함해 임의로 잘라서 바꾸지 않는다. |
| 버전 | 공백만으로 이루어지지 않은 1~30자 문자열. 같은 프로그램 ID가 이미 있으면 기존 버전과 달라야 저장할 수 있다. 자동 증가를 가정하지 않는다. |
| 설명 | 공백만으로 이루어지지 않은 1~2000자 문자열. 프로그램의 대상·중량 기준·기록 단위·운영자가 필요한 안내를 담고 변경하지 않은 원문을 보존한다. |
| 주차 | 1~52주, 빠지거나 중복된 순번 없이 구성한다. |
| 세션 | 주마다 1~7개, 모든 주의 개수가 같고 각 주의 순서는 1부터 연속한다. |
| 운동 | 세션마다 1~20개, 같은 세션에서 운동 ID가 중복되지 않는다. |
| 세트 | 운동마다 1~10개, 같은 운동 안에서 세트 ID가 중복되지 않는다. |
| 반복 | 1~100의 정수. 소수·빈 값·범위 밖 값은 저장을 막는다. |
| RIR | 빈 값 또는 0~10의 유한한 수. 빈 값은 미지정이며 0으로 채우지 않는다. |
| 직접 입력 중량 | 목표 kg를 정하지 않는다. 일반 앱에서 실제 운동 시 입력한다. |
| 고정 중량 | 0보다 큰 유한한 kg. 고정 0kg 대신 직접 입력 방식을 사용한다. |
| 기준중량 비율 | 0보다 큰 유한한 비율과 명시적인 기준 리프트가 필요하다. |
| 필수/선택 | 세트마다 별도로 저장한다. 선택 세트를 자동 삭제하거나 필수로 바꾸지 않는다. |

`TrainingProgram` 자체가 허용하는 범위와 관리자 UI의 편집 제한을 혼동하지 않는다. 외부에서 작성한 프로그램이 편집기 제한을 초과하더라도 불러오기 과정에서 값을 자르거나 세트를 버리면 안 된다. 그대로 보여주고 저장 검증의 제한을 설명해야 한다. 이번 자동 테스트의 무손실 왕복 대상에는 현재 번들 5개와 지원 범위 안에서 주차·세트 차이가 있는 합성 프로그램을 포함한다.

### 5.3 ID를 보존해야 하는 이유

세션·운동·세트 ID는 화면의 1번, 2번 표시와 다르다. 실제 사용자 기록 키에는 계획·세션·운동·세트 식별자가 사용된다. 운동 추세와 D5 근거도 운동의 의미에 의존한다. 편집기가 순서를 바꿀 때 모든 ID를 다시 생성하면 콘텐츠가 동일한지 확인하기 어려워진다.

- 불러온 프로그램에서 값만 수정하거나 순서를 바꿀 때 기존 ID를 유지한다.
- 새로 만든 세션과 세트에는 해당 범위에서 중복되지 않는 새 ID가 필요하다.
- 같은 운동을 다른 세션·주차에서도 사용한다면 운동 ID·이름·메인 리프트의 의미를 일치시킨다.
- 기존 운동 ID를 유지하면서 전혀 다른 운동 이름이나 분류로 바꾸는 것은 단순 표시 수정이 아니다. 운동 교체 의도라면 별도의 운동 ID를 사용한다.
- 이름·분류가 일치하지 않는 같은 운동 ID는 검토 단계에서 충돌 위치를 알려준다. 편집기가 다른 주차를 조용히 바꾸어 맞추지 않는다.
- 프로그램 ID를 변경한 저장은 기존 ID 교체와 다르다. 새 ID가 비어 있거나 카탈로그에서 충돌하면 검증해야 하며, 전체 프로그램 복제 버튼의 제공 여부는 최종 구현 목록으로 구분한다.

## 6. 복사·순서 변경·삭제의 정확한 의미

### 6.1 한 주를 복사해 추가

`이 주차를 복사해 추가`는 선택한 주의 세션·운동·세트 값을 **깊은 복사**하여 마지막 주차에 붙인다. 복사본을 바꿔도 원본 주차는 변하지 않아야 한다. 새 주차의 세션 ID는 기존 전체 프로그램의 세션 ID와 충돌하지 않게 만든다. 운동 ID는 같은 운동 의미를 유지하며, 세트 ID는 해당 운동 안에서 유일하면 된다. 52주 상태에서는 추가를 허용하지 않는다.

주차 복사는 프로그램 기간을 늘린다. 이미 생성된 사용자 계획의 종료일을 늘리는 동작이 아니다. 새 버전으로 새 계획을 만들 때만 새 기간을 사용한다.

### 6.2 다른 주차에 덮어쓰기

`다른 주차에 덮어쓰기`는 원본 주차와 대상 주차를 명시하고 대상에 있던 구성이 바뀐다는 확인을 받는다. 확인 전에는 변이하지 않으며 취소하면 JSON 원문이 같아야 한다. 원본·대상의 세션 수가 다르면 **대상 세션 수가 원본과 같아진다**는 영향을 표시한다. 예를 들어 원본 2세션을 대상 3세션에 복사하면 대상의 세 번째 세션은 교체 결과에 남지 않는다. 선택한 대상 주차 전체를 바꾸는 작업이며, 남은 세션에만 일부 복사하는 동작이 아니다.

대상 세션에 내용을 복사할 때는 **대상의 같은 순번에 세션이 있으면 그 ID와 주차 위치를 유지**한다. 원본이 3세션이고 대상이 2세션이면 처음 두 세션은 대상 ID를 유지하고 새 세 번째 세션에는 고유 ID를 만든다. 원본의 세션 ID를 그대로 가져오면 같은 프로그램 안에서 ID가 충돌한다. 대상의 운동·세트 구성과 처방은 원본의 깊은 복사본으로 교체한다. 이때 “대상 ID 유지”는 이미 사용자에게 시작된 계획을 수정한다는 뜻이 아니다. 편집 중인 새 프로그램 후보 안의 식별자를 보존한다는 뜻이다.

### 6.3 순서 변경

운동·세트의 위/아래 이동은 목록 위치만 바꾼다. 옮긴 항목의 ID·이름·처방을 유지한다. 맨 위에서 위로, 맨 아래에서 아래로 이동하는 버튼은 동작하지 않아야 한다. 세션을 옮길 때도 순서와 실제 데이터를 함께 옮기고, 그 주차의 `dayOrder`를 연속한 순번으로 맞춘다.

주차 선택과 세션 선택은 현재 보이는 위치를 바꾸는 동작이므로 저장된 운동 순서를 바꾸지 않는다. 드래그 정렬을 전제로 하지 않고 명확한 위/아래 조작으로도 순서를 바꿀 수 있어야 한다.

### 6.4 추가·삭제

`세션 추가`와 `세션 삭제`는 선택한 주차에 적용한다. 다른 주차에도 자동 추가·삭제하지 않는다. 그래서 초안에서는 주차별 세션 수가 일시적으로 달라질 수 있으며, 전체 검토에서 차이를 알려주고 모든 주차를 맞출 때까지 카탈로그 저장을 막는다.

삭제 확인에는 주차·세션·운동·세트 중 무엇을 지우는지와 포함된 내용의 범위를 표시한다. 취소는 원문을 유지한다. 삭제 후 현재 선택이 범위를 벗어나면 남아 있는 유효한 주차·세션으로 이동해야 한다. 마지막 주차·세션·운동·세트를 삭제하여 저장 가능한 최소 구조를 잃는 동작은 제한하거나, 허용하는 초안 상태라면 복구 경로와 검증 오류를 분명하게 보여준다. 최종 구현에서는 모델과 버튼의 경계 동작을 동일하게 검증한다.

삭제는 관리자 초안의 콘텐츠 삭제다. 사용자 계획·실제 세트 기록·마감 이력·D5 적용 이력을 찾아 지우는 기능은 포함하지 않는다. **관리자 카탈로그에서 프로그램 전체를 삭제하는 운영 기능**도 이 문서의 필수 구현 범위에 넣지 않는다.

## 7. 되돌리기·초안 저장·실패 처리

### 7.1 실행 취소의 단위

실행 취소는 현재 편집 세션에서 최대 50개의 이전 초안 상태를 유지한다. 같은 텍스트 필드에서 연속으로 입력하는 작업은 한 묶음으로 취급하여 `123`을 입력한 뒤 세 번 취소해야만 원상복구되는 문제를 줄인다. 다른 필드로 이동하거나 추가·삭제·복사·정렬 같은 구조 작업을 수행하면 별도의 변경 단위가 된다.

`되돌리기`는 바로 전 원문과 구조를 복원하고, `다시 실행`은 취소했던 상태를 다시 적용한다. 되돌린 상태에서 새로운 값을 입력하면 이전의 다시 실행 경로는 비운다. 입력값이 실제로 바뀌지 않은 조작은 새 스냅샷을 만들지 않는다. 50단계를 넘은 오래된 편집 이력은 버리되 현재 초안은 유지한다.

이력은 로컬 메모리 범위이며 앱을 다시 실행하면 초안은 복원하지만 실행 취소 스택까지 복원한다고 약속하지 않는다. 프로그램을 새로 열거나 편집 세션을 교체하면 이전 프로그램으로 취소가 넘어가지 않아야 한다. 운영자의 변경 감사 로그·작성자별 이력·과거 게시 버전으로 롤백하는 기능과는 별개다.

### 7.2 초안 저장과 카탈로그 저장을 구분한다

초안 자동 저장은 아직 미완성인 원문을 복원하기 위한 기능이다. 자동 저장이 성공해도 사용자에게 선택 가능한 프로그램 목록이 바뀌면 안 된다. 반대로 `검토한 프로그램 저장`은 검증된 `TrainingProgram` 후보를 카탈로그에 추가하거나 같은 ID의 기존 항목과 교체하는 명시적인 동작이다.

정밀 편집기의 원문 변경 콜백을 관리자 작업 저장 경로에 연결한다. 빠른 연속 입력·복사·되돌리기에서 나중 상태가 먼저 상태로 덮이지 않도록 저장 작업을 직렬화하고 최신 revision을 확인한다. 먼저 시작한 저장이 끝났다는 이유로 더 최근 입력의 “미저장” 표시를 지워서는 안 된다.

파일 저장이 실패하면 원문을 화면에 유지하고 실패 상태를 표시한다. 실패를 정상적인 저장으로 표시하거나 기본 초안으로 초기화하지 않는다. 재시도는 최신 초안을 대상으로 한다. “화면에 입력이 남아 있음”과 “앱 종료 후에도 복원할 수 있음”을 구별하여, 저장이 확인되기 전에는 재실행 복원이 보장된 것처럼 안내하지 않는다.

### 7.3 검토한 후보의 저장

저장은 검토 시점의 프로그램 후보를 고정한 뒤 실행한다. 기존 ID가 있으면 새 버전을 요구하고 교체 사실을 보여준다. 저장 중 버튼을 반복 눌러 같은 항목이 중복 추가되지 않게 한다. 저장 완료 전에는 관리자 카탈로그의 메모리 목록을 성공 상태로 교체하지 않는다.

저장 실패 후 재시도할 때에도 검토한 후보와 버전을 유지한다. 검토 화면에서 뒤로 돌아가 입력을 바꾸면 다시 검증·검토해야 하며, 이전에 승인한 후보에 나중 입력을 섞어서 저장하지 않는다. 편집기 전환·다른 프로그램 열기·내보내기가 저장 작업과 겹칠 때에는 현재 저장을 마친 뒤 진행하거나 진입을 잠가 일관된 작업 파일을 보장한다.

같은 ID에 다른 버전을 저장하는 것은 기존 관리자 카탈로그 항목의 교체다. 모든 과거 버전을 별도 항목으로 보관하는 버전 저장소를 구현하는 것은 아니다. 버전 문자열에 의미론적 버전 순서나 날짜 정렬을 가정하지 않고, 최소한 기존 버전과의 동일 값 충돌을 막는다.

## 8. 저장 형식과 구버전 작업 이행

| 저장 대상 | 이번 계약 |
|---|---|
| 관리자 작업 파일 | `strength-admin/workspace.json`, 관리자 v1 읽기 및 v2 쓰기. |
| 기존 기본 입력 | `draft`의 `RoutineBlueprint`를 유지한다. 미완성 원문을 정밀 초안으로 자동 생성하지 않는다. |
| 정밀 입력 | 별도 nullable `detailedDraft`에 독립 주차·세션·운동·세트 원문과 필요한 편집 메타데이터를 저장한다. |
| 관리자 카탈로그 | `programs`의 검증된 `TrainingProgram` 목록을 유지한다. |
| 소비자 카탈로그 내보내기 | 기존 `schemaVersion: 1`과 `programs`를 유지한다. 관리자 초안과 편집 이력은 내보내지 않는다. |
| 사용자 운동 저장 | 기존 v3를 유지한다. 사용자 계획·기록·초안·마감 이력에 새 관리자 필드를 넣지 않는다. |

v1 관리자 작업에는 `detailedDraft`가 없다. 이를 읽을 때 정밀 초안 없음으로 처리하고 기존 기본 초안과 카탈로그를 복원한다. 특히 기간이 `3.`이거나 반복 수가 비어 있는 기존 초안을 읽었다고 자동으로 유효한 프로그램을 만들어서는 안 된다. 기본 생성기에서 검증을 통과한 결과를 운영자가 명시적으로 정밀 편집으로 여는 경로를 사용한다.

v2 작업은 정밀 초안이 `null`인지 실제 원문인지 구분한다. 구조가 잘못된 데이터, 해석할 수 없는 enum, 미지원 미래 버전은 정상적인 빈 작업으로 취급하지 않는다. 읽기 오류를 표시하고 원본 파일을 보존한다. 스키마 검증으로 읽지 못한 데이터를 덮어쓸 때 “새 작업 만들기”를 암묵적으로 실행하지 않는다.

기존 프로그램을 불러와 아무 수정 없이 변환한 결과에서는 프로그램·세션·운동·세트 ID, 작성자, 이름, 설명, 버전, 주차, 순서, 반복, nullable RIR, 필수 여부, 중량 유형·값·기준 리프트가 보존되어야 한다. 리스트 순서를 임의 정렬하거나 ID를 화면 순번으로 다시 만드는 것도 값 보존 검증의 대상이다.

정밀 초안의 계층은 `DetailedRoutineDraft.weeks → DetailedWeekDraft.sessions → DetailedSessionDraft.exercises → DetailedExerciseDraft.sets`다. 각 주차·세션 순번은 리스트 위치로 결정하고 최종 변환할 때 `week`·`dayOrder`로 내보낸다. 원래 JSON의 `sessions` 배열이 실제 운동 순서와 다르게 배치돼 있을 수 있으므로, 불러올 때의 세션 ID 배열을 별도 `sourceSessionOrder` 메타데이터로 보존한다. 실행 순서는 계속 `week`·`dayOrder`에 따르며, 원본 배열 순서를 유지하기 위해 실제 운동 순서를 되돌리지 않는다. 새로 추가한 세션은 원본에 있던 세션 뒤에 직렬화하되 자신의 명시적 주차·순번을 가진다.

`detailedDraft`의 텍스트 값, enum과 nullable 리프트, `isRequired` bool, 하위 목록은 타입을 검사한다. 초안에는 미완성 숫자나 빈 목록을 저장할 수 있지만 예상하지 못한 필드·필수 키 누락·enum 해석 실패를 원문 숫자 오류와 똑같이 취급하지 않는다. 전자는 파일 구조 오류로 복원을 막고, 후자는 복원 가능한 편집 중 상태로 보존한 뒤 프로그램 검토에서 막는다.

파일 저장은 임시 파일에 쓰고 대상 파일로 교체하는 기존 원칙을 유지한다. 파일 실패 테스트에서 확인한 범위만 결과에 적는다. 임의의 OS 장애·전원 손실·동시 외부 파일 편집까지 모두 복구된다고 확대하지 않는다.

## 9. 사용자 계획·기록·D5에 미치는 영향

사용자가 프로그램을 시작하면 프로그램 전체 스냅샷과 계산한 세트 중량·날짜를 자신의 계획에 저장한다. 관리자 카탈로그에서 같은 ID의 새 버전을 저장해도 그 스냅샷을 다시 생성하지 않는다. 따라서 이미 수행한 중량·초안·수행일·명시 마감·다시 열기 이력은 유지되어야 한다.

이번 편집기는 `TrainingAppState`를 직접 읽거나 쓰지 않는다. 관리자 저장과 사용자 저장 경계를 테스트로 확인하고, 내보낸 새 버전으로 새 계획을 만들 수 있는지를 별도로 확인한다. 기존 계획의 프로그램 버전과 JSON이 관리자 편집 전후 동일한지 회귀 검증한다.

운동 ID의 의미를 재사용하면 향후 기록 비교에서 서로 다른 운동이 하나로 보일 수 있다. 그래서 같은 ID에 다른 운동 이름·분류가 섞이지 않도록 검증한다. 다만 기존 D5 정책이나 감량 계산식을 관리자 편집기에 복사하지 않는다. D5는 사용자의 현재 계획 스냅샷과 기록을 사용하며, 새 카탈로그 버전을 기존 제안의 근거로 끼워 넣지 않는다.

선택 세트는 기존 사용자 앱의 필수/선택 규칙을 따른다. 정밀 편집에서 필수 여부를 바꾼 새 버전이 만들어져도 이전 계획의 운동 마감 조건을 소급해서 바꾸지 않는다. 수동 중량 세트에는 목표 kg가 없으므로 새로 수동 세트를 만든 것을 자동 D5 조정 대상 추가로 해석하지 않는다.

## 10. 운영자가 직접 확인하는 순서

이 절차는 실제 운영 확인용이며, 이 문서 작성 중에는 **미실행**이다. 사용자의 지시에 따라 자동 작업에서 시뮬레이터를 실행하지 않는다. 내부 앱 실행 여부는 사용자가 직접 선택한다.

### 10.1 기존 프로그램의 한 세트만 수정

1. 내부 관리자 카탈로그에서 수정 대상 프로그램의 ID와 원래 버전을 적는다.
2. 정밀 편집을 열고 `프로그램 정보`에 작성자·설명이 유지되는지 확인한다.
3. 2주차와 두 번째 세션을 선택한 뒤 첫 운동의 두 번째 세트를 찾는다.
4. 반복을 이전과 다른 정수로, RIR을 `0` 또는 빈 값으로, 필수 여부를 선택으로 바꾼다.
5. 같은 운동의 첫 세트와 1주차 동일 위치를 확인해 값이 바뀌지 않았는지 확인한다.
6. 같은 ID·같은 버전 상태로 검토해 저장이 차단되는지 확인한다.
7. 명시적으로 새 버전을 입력하고 `변경 검토`를 누른다.
8. 검토에서 변경된 위치와 다른 주차의 값, 기존 카탈로그 교체 안내를 확인한다.
9. `검토한 프로그램 저장`을 누르고 성공 후 카탈로그에서 새 버전을 다시 연다.
10. 수정한 세트의 값·필수 여부와 수정하지 않은 세트가 모두 유지되는지 확인한다.

### 10.2 복사·삭제·실행 취소

1. 한 주의 특정 세트에 구분 가능한 값을 적은 뒤 `이 주차를 복사해 추가`한다.
2. 추가된 주차의 값을 바꾸고 원본 주차의 값이 유지되는지 확인한다.
3. `다른 주차에 덮어쓰기`에서 원본·대상을 확인하고 한 번 취소한다.
4. 취소 전후 대상의 이름·세트 수·처방이 같은지 확인한다.
5. 다시 열어 복사를 확인하고, 대상 주차에는 복사한 값이 반영되는지 확인한다.
6. `되돌리기`로 대상의 이전 구성을 복원하고 `다시 실행`으로 복사 결과를 되살린다.
7. 운동 또는 세트를 위/아래로 이동하고 ID와 각 처방이 같이 이동하는지 확인한다.
8. 삭제 확인을 취소했을 때 값이 유지되고, 확인 후 되돌리기로 구조가 복원되는지 확인한다.
9. 선택 주차에 세션을 하나 추가하여 주간 세션 수를 다르게 만든 뒤 검토한다.
10. 어느 주차를 맞춰야 하는지 오류가 표시되고 입력은 남아 있는지 확인한다.

### 10.3 초안과 재실행

1. 반복 수에 `3.`을 입력한 뒤 초안 저장 완료 표시를 확인한다.
2. 관리자 앱을 닫았다가 다시 열어 동일 정밀 초안을 복원한다.
3. 입력값이 `3.` 그대로 남고, 아직 카탈로그의 확정 프로그램은 바뀌지 않았는지 확인한다.
4. `3.` 상태에서 검토하면 오류가 표시되는지 확인하고, 유효한 정수로 고친다.
5. 재실행한 편집기에서 이전 실행의 되돌리기 스택이 복원된 것으로 오해할 표시가 없는지 확인한다.

단순 화면 이동 후 복원과 OS 프로세스 종료 후 복원은 다른 확인이다. 자동 위젯·파일 테스트를 실제 Mac 앱 종료·재실행 시험으로 기록하지 않는다. 사용자 앱의 운동 복원 확인은 [실제 기기 테스트 가이드](2026-09-08-device-test-guide.md)를 따른다.

### 10.4 내보내기와 사용자 앱 반영

1. 검토한 프로그램을 관리자 카탈로그에 저장한다.
2. 카탈로그 내보내기를 실행하고 대화상자에 표시되는 실제 파일 경로를 확인한다.
3. `admin-export/programs.json`의 `schemaVersion: 1`, 프로그램 수, 수정한 ID·새 버전을 확인한다.
4. 내보낸 파일에 관리자 초안·실행 취소 이력·사용자 기록이 들어 있지 않은지 확인한다.
5. 사용자 앱의 `assets/programs.json`과 diff를 확인하고 의도한 프로그램 개정만 반영한다.
6. 번들·프로그램 생성 테스트와 정적 분석을 실행한다. 프로그램 수나 기대 버전이 바뀌면 승인한 콘텐츠에 맞춰 테스트 기대값도 갱신한다.
7. 사용자 앱은 `lib/main.dart` 진입점으로 빌드한다. 관리자 `lib/main_admin.dart` 실행물을 사용자 배포물로 사용하지 않는다.
8. 새로 시작한 계획에 새 버전이 적용되고 기존 계획·기록은 유지되는지 확인한다.

현재는 로컬 JSON 전달과 재빌드 과정이다. 관리자에서 저장·내보냈다고 사용자 기기나 서버에 즉시 게시되는 것은 아니다. 기존 번들 5개가 이번 편집기 개발만으로 개정되는 것도 아니다.

## 11. 자동 검증의 수용 기준

각 항목은 실제 테스트 파일·테스트 이름·결과를 최종 검증 기록에 연결한다. 실패를 수정했으면 최초 실패의 원인과 최종 결과를 구분한다. 검증하지 않은 행을 통과로 채우지 않는다.

| ID | 확인 내용 | 통과 조건 |
|---|---|---|
| ME01 | 기존 5개 불러오기·왕복 | 정밀 초안에서 다시 만든 전체 프로그램 JSON이 원본과 동등하고 ID·작성자·세트 처방이 보존된다. |
| ME02 | 주차·세트별 차이 보존 | 주차마다 운동/세트가 다르고 세트별 RIR·중량·필수 여부가 다른 합성 프로그램이 손실 없이 왕복한다. |
| ME03 | 한 세트 수정 | 선택한 세트만 바뀌고 다른 세트·운동·세션·주차는 동일하다. |
| ME04 | 메인/기준 리프트 분리 | 메인 리프트와 다른 기준 리프트, 메인 리프트 없는 비율 처방이 유지되고 필요한 기준값으로 계획을 생성한다. |
| ME05 | 원문 복원 | 빈 값·`3.`·중량 입력 중 원문이 작업 파일 왕복 후 그대로이며 검토 전 카탈로그를 바꾸지 않는다. |
| ME06 | 숫자·필수값 경계 | 반복 소수/0/101, RIR 범위 밖/비유한 수, 비양수 중량, 빠진 기준 리프트, 빈 필수 필드가 검토에서 거부된다. |
| ME07 | 구조·ID 검증 | 주간 세션 수 불일치, 범위 초과, 중복 세션/운동/세트 ID, 같은 운동 ID의 의미 충돌을 거부한다. |
| ME08 | 주차 복사 후 추가 | 원본과 복사본이 독립적이고 새 세션 ID가 충돌하지 않으며 기간이 실제 주차 수와 맞는다. |
| ME09 | 주차 덮어쓰기 | 취소 시 원문 동일, 확인 시 대상 세션 ID 유지, 원본 불변, 대상 처방 복사, 실행 취소 가능. |
| ME10 | 순서 변경 | 세션·운동·세트가 ID/처방을 가진 채 이동하고 경계에서 추가 변이가 없다. |
| ME11 | 추가·삭제 | 선택 범위에만 적용하고 확인 취소는 원문을 유지하며 삭제 후 유효한 선택 위치와 복구 동작을 제공한다. |
| ME12 | 실행 취소·재실행 | 구조 변경과 원문을 복원하고 동일 필드 연속 입력을 묶으며 새 편집 시 redo를 버리고 50단계 제한을 지킨다. |
| ME13 | 관리자 v1 → v2 | 기존 기본 초안 원문/카탈로그를 유지하고 정밀 초안 없음으로 이행한다. 미완성 기본 입력을 자동 생성하지 않는다. |
| ME14 | v2 오류·미지원 버전 | 잘못된 구조·미지원 버전 읽기 실패 시 원본을 유지하고 빈 작업으로 덮어쓰지 않는다. |
| ME15 | 버전 교체 | 같은 ID/같은 버전 저장 차단, 새 버전 검토 후 같은 ID 항목 한 개 교체, 다른 프로그램 유지. |
| ME16 | 카탈로그 저장 실패 | 파일 저장 성공 전 메모리 목록 불변, 실패 후 검토 원문 유지, 같은 후보 재시도 성공, 중복 저장 없음. |
| ME17 | 초안 저장 순서 | 빠른 입력/undo와 지연 저장이 겹쳐도 최신 초안이 유지되고 오래된 완료 응답이 최신 실패 표시를 지우지 않는다. |
| ME18 | 내보내기 | 소비자 스키마 1의 유효한 카탈로그이며 초안/이력은 제외되고 다시 읽어 계획을 생성할 수 있다. |
| ME19 | 사용자 기록 경계 | 기존 계획 스냅샷·세트 실제값·초안·수행일·마감/D5 이력이 관리자 편집 전후 동일하다. |
| ME20 | 넓은 화면 렌더 | 1200px 너비에서 전체 계층·주차/세션 선택·세트 행·액션이 읽히고 잘림/겹침이 없다. |
| ME21 | 좁은 화면·큰 글자 | 375px 너비와 큰 글자에서 가로 넘침 없이 세트 편집·확인 대화상자·검토에 접근한다. |
| ME22 | 키보드·오류 렌더 | 키보드 인셋 상태에서도 입력·오류·주요 액션에 접근하고 스크롤 후 올바른 세트를 수정한다. |
| ME23 | 일반 앱 접근 경계 | 일반 앱 import 경로에 관리자 코드가 새로 포함되지 않고 일반 프로그램 선택 흐름이 유지된다. |

렌더 검증은 실제 폰트를 로드한 헤드리스 위젯 렌더를 사용한다. 처음 렌더에서 계층·정렬·밀도·한글/숫자 폰트·터치 영역을 보고 발견한 구체적인 문제를 수정한 뒤 다시 렌더한다. 자동 스크린샷 생성 자체를 시각 검토 완료로 세지 않는다.

| AMRAP·반복 범위 | 고정 반복 수 한 개만 저장한다. `8~12`나 `8+`를 문자열로 넣어 지원한 것처럼 만들지 않는다. | 완료 판정, 실제 반복과 목표 비교, 기록/추세 표시. |
| 휴식 시간·템포·워밍업 유형 | 세트별 구조화 필드가 없다. 설명에 쓴 안내는 타이머나 운동 제어가 아니다. | 시간 단위, 세트 유형, 사용자 기록 화면 연결. |
| 슈퍼세트·드롭세트 | 단일 운동의 순서 있는 세트 목록이다. 그룹·교대·연속 수행 의미가 없다. | 그룹 ID, 수행 순서, 휴식과 완료 조건. |
| 주차마다 다른 훈련 횟수 | 모든 주차의 세션 수가 같아야 현재 요일 개인화가 가능하다. | 주별 요일 선택·날짜 생성·일정 변경 계약. |
| 자동 증량·진급·블록 규칙 | 관리자가 명시한 주차별 고정 처방을 편집한다. 기록에 따라 다음 주를 자동 생성하지 않는다. | 근거 기록, 계산식, 반올림, 실패/취소/재계산 규칙. |
| 운동 라이브러리·대체 운동 | 프로그램 안의 이름·ID를 편집한다. 공통 동작 사전·영상·장비 검색은 별도다. | 운동 식별자 정본, 대체 가능 조건, 기존 기록 비교 방식. |
| 전체 프로그램 복제·카탈로그 삭제 | 이번 필수 범위는 기존 프로그램 정밀 수정과 새 버전 저장이다. | 새 ID/버전 기본값, 삭제 복구, 배포 상태와 참조 처리. |
| 대량 값 조정·다중 선택 | 개별 세트 수정과 주차 복사를 제공한다. 선택 영역의 모든 중량을 일괄 증가시키는 연산은 별도다. | 대상 범위, 고정/비율/수동 혼합 처리, 변경 전후 검토. |
| 서버 로그인·권한 검사 | 내부 실행물을 운영자에게만 전달하는 현재 방식이다. | 관리자 계정, 서버 권한 검사, 세션 만료, 감사 로그. |
| 온라인 게시·예약·취소 | 로컬 카탈로그 저장과 JSON 내보내기까지다. | 원격 카탈로그 저장소, 배포 버전, 캐시/실패/롤백. |
| 과거 게시 버전 복구 | 같은 ID의 현재 관리자 항목을 교체한다. 편집기 undo는 게시 이력이 아니다. | 버전별 불변 보관, 변경 비교, 롤백 배포 정책. |
| 구독·사용자 관리 | 이번 편집기와 연결하지 않는다. 다중 트레이너 가입도 사용자 지시로 제외했다. | 실제 상품·권한·결제 운영은 [구독 운영안](2026-09-08-subscription-operations.md)에서 결정. |

운영자가 원하는 “세밀함”을 전부 구현했다고 선언하지 않는다. 먼저 개별 주차·세트 처방을 직접 편집할 수 있게 만든 뒤, 실제로 작성할 프로그램을 이 편집기로 입력하면서 부족한 구조화 필드를 다음 기능 단위로 확정한다. 동작하지 않는 입력칸을 미리 늘리거나 설명 문자열에 엔진 기능을 숨겨 넣지 않는다.
