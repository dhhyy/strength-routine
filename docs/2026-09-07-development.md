전체 기능 단위 테스트와 앱 통합 테스트는 **65개 통과**했다. `flutter analyze`도 문제없음으로 종료했다. 이 중 실제 파일 저장·새 저장소로 복원하는 검증과, 네이티브 프로세스 종료 후 화면을 관찰하는 검증은 구분한다.

기존 미커밋 개발분도 별도로 보존했다: 도메인 `4c36689`, 로컬 폰트 `04e082d`, 영구 저장 `18aa39f`, 프로그램 시작→기록 화면 `e62b9b6`, 조사/설계 문서 `c27d181`. 작업 저장소는 `apps/strength_routine` 자체 Git이며 워크스페이스 루트의 다른 앱은 커밋하지 않았다. 원격 push는 하지 않았다.

## 설계와 검증에서 확인한 점

- ‘필수 세트 기록 충족’은 사용자 명시 마감이나 실제 수행 횟수가 아니다. 이번 F02는 집계·문구를 정확하게 만들었으며 별도 마감 스키마를 신설하지 않았다.
- 검색은 프로그램 안의 운동 발생 항목을 출처별로 보여준다. 같은 이름을 공통 종목으로 자동 병합하지 않으며 운동 설명 사전·미디어 가이드는 아직 별도 범위다.
- 보관 초안은 `42.`, `-`, `0`, 공백·줄바꿈 등 원문을 그대로 표시한다. 원래 목표나 과거 확정값으로 누락된 필드를 채우지 않는다.
- 습관은 `habits-state.json`에 저장하며 기존 `training-state.json`과 별도 스키마 1이다. QA는 각각 `qa-habits-state.json`, `qa-training-state.json`을 사용한다. 전체 앱 백업을 개발할 때 두 저장소를 모두 포함해야 한다.
- 습관을 보관해도 날짜별 체크는 남는다. 전경에서 자정을 넘긴 첫 체크는 날짜만 갱신하고 전날 체크를 바꾸지 않는다. 다음 탭부터 새 날짜에 저장한다.
- 새 습관 저장소의 비동기 초기화를 통합 테스트도 기다리도록 수정했다. 시간 초과를 숨기거나 앱의 로딩/저장 검증을 제거한 것이 아니다.

### 네이티브 검증 상태

- `flutter build ios --simulator --debug -t tool/qa_preview.dart`: 성공, Xcode 단계 76.6초.
- 다른 앱의 시뮬레이터와 분리하려고 **Strength QA / iOS 26.5 / iPhone 17 Pro**를 생성했다. 기기 ID: `003D93A6-D728-4968-92EE-7996BD1E568E`.
- 해당 기기의 iOS 초기 데이터 이행은 11분 4초 뒤 완료됐고 앱 설치는 성공했다.
- 직접 실행은 `NSMachErrorDomain -308 (ipc/mig server died)`로 실패했다. UI 도구에서도 다른 작업의 Simulator 창 전환과 `windowNotFoundAtPosition`/`noWindowsAvailable`이 반복됐다. 이를 앱 입력·복원 검증 통과로 기록하지 않는다.
- `flutter run`으로 두 차례 재시도했으나 전용 기기가 지원 장치 목록에 나타나지 않아 실행되지 않았다. 중간의 해당 기기 `simctl boot`는 성공 종료했지만 Flutter 연결은 복구되지 않았다. 실제 터치·OS 키보드·앱 종료 후 화면 복원 관찰은 **미검증**으로 남긴다. 다른 기기를 종료하거나 초기화하지 않았다.

## 남은 범위와 미결정 사항

1. **직접 빌드 vs 트레이너 프로그램 선택:** 이번 메시지의 직접 빌드 순서가 이전 확정 방식을 대체하는지 질문했고 아직 미응답이다. 기존 운동·세트 구성 보존을 유지하면서 공통 기능을 개발했다. 새 목표/기간/리프트 우선순위 생성기는 추가하지 않았다.
2. **첫 실제 프로그램:** 일반 카탈로그는 여전히 비어 있다. 공개 후보의 정확한 버전·처방이 정해지면 수록하고 일반 진입점의 시작→기록→재실행을 검증한다. QA 합성 프로그램을 출시 콘텐츠로 바꾸지 않았다.
3. **기록 추세와 D5:** 실제 수행일·공통 운동 식별과 D5의 신호창/임계·감량 대상·폭이 미정이다. 추천 숫자를 임의로 정하지 않았다. 미래 일정 변경 UI·목표 감량 적용/되돌리기도 아직 미구현이다.
4. **설정·Q&A·구독:** 현재 실제 프로필과 라이선스 조회가 있으며 전체 설정, 코치 Q&A, 결제/구독·서버는 후속 범위다. 트레이너 등록 도구는 이전 결정대로 별도 후속 개발이다.
