# 9/8 · 프로그램 운영·기록 조절 구현과 검증

기준일: 2026-09-08, Asia/Seoul. 작업 환경: macOS 로컬 Flutter, `apps/strength_routine`. 이 문서는 같은 날 랜딩 개발 이후 프로그램/관리자/D5/설정을 처음 연결한 단계의 검증 이력이다. 구현 커밋은 `f4225ef`·`5dd5f35`·`9fe514e`·`7c4a021`이며 아래120개와 당시 로그/렌더를 그대로 보존한다. 현재 상태와 형식은 [상태표](2026-09-08-remaining-work.md), 추가 구현은 [로컬 완성](2026-09-08-local-completion.md), 검토 후 수정은 [안정화 기록](2026-09-08-review-fixes.md)을 따른다.

**당시 결과:** 프로그램 5개, 내부 관리자 루틴 생성, 기록 추세·D5 감량 제안·되돌리기, 저장되는 설정과 로컬 도움말을 구현했다. 전체 Flutter 테스트 **120개 통과**, 정적 분석 **문제 없음**이다. 실제 기기의 OS 종료·재실행과 결제는 실행하지 않았다. 시뮬레이터도 실행하지 않았다.

## 당시 추가한 디테일 — 한 문장씩

- 일반 카탈로그에서 성격과 빈도가 다른 4주 프로그램 5개를 선택할 수 있다.
- 프로그램에 최근 기록이 필요하지 않으면 최근 리프트 입력 없이 시작할 수 있다.
- 관리자 내부 빌드에서 주간 세션과 운동·세트·반복·RIR·중량 방식을 작성할 수 있다.
- 관리자가 입력한 원문은 잘못된 숫자와 빈 필드까지 초안으로 저장한다.
- 생성 결과 전체를 확인한 뒤 관리자 카탈로그에 저장할 수 있다.
- 같은 프로그램을 교체할 때는 버전을 변경해야 한다.
- 관리자 카탈로그를 일반 앱이 읽는 JSON 형식으로 내보낼 수 있다.
- 기록 탭에서 프로그램별 실제 중량·반복·RIR을 볼 수 있다.
- 비교 가능한 최근 3회에서 목표보다 힘들게 수행한 기록이 이어지면 감량을 제안한다.
- 변경할 날짜와 세트별 중량을 확인하고 직접 적용하거나 취소할 수 있다.
- 적용한 중량은 미래 운동 상세에 `조정 목표`로 표시한다.
- 되돌리기는 변경 이력과 근거를 남기며 원래 목표로 복구한다.
- 실제 기록이나 초안이 생긴 대상은 일괄 되돌리기를 제한한다.
- 설정에서 새 입력의 기본 중량 단위와 감량 제안 표시를 저장한다.
- 기존 기록과 초안의 중량 단위·숫자는 설정을 바꿔도 유지한다.
- 프로필에서 로컬 도움말과 구독 준비 안내를 열 수 있다.
- 운동 저장 파일은 기존 v1을 읽고 새 조정 이력을 포함하는 v2로 저장한다.
- 실기기 검증용 합성 자료는 전용 파일에 최초 한 번만 생성한다.

## 프로그램 5개

모두 이 앱을 위해 작성한 제안 프로그램이며 타사 유료 프로그램의 복제나 실제 코치의 승인을 뜻하지 않는다. 세부 운동·세트표와 근거/제품 판단 구분은 프로그램 문서에 있다.

| 프로그램 | 기간·빈도 | 시작 중량 |
|---|---|---|
| 전신 시작 | 4주·주 2일 | 실제 세트에서 직접 입력 |
| 전신 습관 | 4주·주 3일 | 실제 세트에서 직접 입력 |
| 상하체 나누기 | 4주·주 4일 | 실제 세트에서 직접 입력 |
| 바벨 기본 동작 | 4주·주 3일 | 스쿼트·벤치의 최근 기록과 기준 작업 중량 입력; 나머지는 직접 입력 |
| 덤벨로 전신 | 4주·주 2일 | 실제 세트에서 직접 입력 |

바벨 프로그램의 기준 중량은 사용자가 입력한 해당 작업 중량의 100%이며 1RM의 100%가 아니다. 앱은 최근 기록에서 최대 중량을 자동 추정하지 않는다. 프로그램의 운동·세트 구성은 시작 후에도 스냅샷으로 유지한다.

D5는 숫자로 지정된 미래 목표가 있어야 제안한다. 기본 카탈로그에서는 바벨 프로그램의 스쿼트·벤치가 해당하며, 중량을 직접 입력하는 다른 항목에 제안이 없는 것은 정상이다. 기다리지 않고 기능을 확인하려면 실기기 가이드의 합성 QA 자료를 사용한다.

관리자 방식과 D5 수치에 대한 선택 질문에는 이번 작업 종료 시점까지 답변이 없어 추천했던 내부 빌드와 보수적인 초기 정책으로 진행했다. 이를 사용자 확정 정책으로 기록하지 않는다.

### 관리자 배포에서 구분할 점

`lib/main.dart`는 일반 앱, `lib/main_admin.dart`는 운영자 내부 도구, `tool/device_qa.dart`는 합성 QA 진입점이다. 일반 앱에는 관리자 생성 메뉴와 생성 코드 import가 없다. 그러나 **현재 같은 네이티브 프로젝트·앱 식별자를 사용하는 서로 다른 빌드**이므로 별도 계정 인증이나 동시에 설치하는 독립 앱으로 설명하면 안 된다. 내부 관리자/QA 실행파일은 사용자 배포물이 아니다. 배포할 때는 일반 진입점으로 다시 빌드하고 산출물을 확인한다.

관리자 문서에 작성부터 내보내기까지의 명령과 검토 순서를 남겼다. 이번에는 실제 macOS 관리자 앱을 실행하거나 스토어에 배포하지 않았다.

### 당시 저장·실패 검증에서 구분한 점

- 원래 계획 목표와 실제 수행값을 덮어쓰지 않고 조정 이력을 따로 적용한다.
- 운동 JSON envelope v1을 읽고 v2로 쓰며, 미지원 미래 버전은 보존하고 읽기를 거부한다.
- 설정은 별도 파일이며 설정 손상이 운동 기록 파일을 초기화하지 않는다.
- 쓰기 실패 후 최신 입력/조정은 메모리에 남지만 OS 프로세스 종료 후에는 마지막 영구 저장 성공분까지만 복원된다.
- 임시 파일 flush/rename과 쓰기 큐는 확인했으나 모든 전원 차단·OS 장애의 데이터 보존을 보장하지 않는다.
- 실기기 검증 시 앱 삭제·데이터 지우기·재설치를 복원 절차로 사용하지 않는다.
