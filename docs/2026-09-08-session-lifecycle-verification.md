## 2. 추가한 디테일 — 한 문장씩

- 새 세트를 기록할 때 실제 수행일을 확인하고 과거 날짜로 바꿀 수 있다.
- 예정일과 실제 수행일을 서로 다른 값으로 저장한다.
- 예전 기록의 날짜를 오늘이나 예정일로 임의 채우지 않는다.
- 날짜 미상 세트의 중량만 수정하면 날짜는 계속 미상이다.
- 최초 입력 시각과 이번 수정 시각을 실제 수행일과 분리한다.
- 날짜를 포함한 미완성 입력은 초안 원문으로 보존한다.
- 필수 미기록이나 작성 중 초안이 있으면 마감 이유를 안내하고 막는다.
- 선택 세트를 기록하지 않아도 해당 수를 남긴 채 마감할 수 있다.
- 전부 제외한 운동은 실제 수행 0세트로 마감한다.
- 마감 전에 실제 수행·제외·미기록·초안·날짜를 검토한다.
- 마감 후에는 먼저 ‘기록 다시 열기’를 거쳐야 수정할 수 있다.
- 마감과 재개의 시각·요약 이력을 덮어쓰지 않고 보존한다.
- 마감 저장 실패 중에는 원래 메모리 상태와 확인창을 유지한다.
- 수행일 달력은 확인된 완료 세트의 날짜만 표시한다.
- 여러 날 수행한 한 세션의 날짜별 수와 세션 전체 수를 나눈다.
- 메모만 남은 보관 세션도 예정일 달력에서 다시 읽을 수 있다.
- 큰 글자에서도 날짜 두 줄이 잘리지 않도록 달력 셀 높이를 늘린다.

새 패키지, 서버, 사용자 계정, 푸시 알림, 결제 SDK는 추가하지 않았다. 일반 앱의 5개 탭과 내부 관리자 진입점 구조는 유지한다. 수행일 저장이 생겼지만 D5의 비교 순서는 여전히 계획일 기준이다.

### 저장 성공의 의미

일반 세트/초안 자동 저장은 기존처럼 최신 메모리 입력을 먼저 유지한다. 저장 실패 상태에서 프로세스를 종료하면 마지막 성공 저장 이후 입력은 복원되지 않을 수 있다. 마감/재개는 후보 상태를 파일에 저장한 뒤에만 메모리에 확정하며, 저장 실패를 화면의 성공 상태로 처리하지 않는다.

테스트에서 성공한 파일 왕복은 같은 앱 파일의 직렬화·재로딩을 검증한다. OS 전원 차단, 파일 시스템 고장, 앱 삭제, 기기 이동, 임의의 다중 프로세스 동시 쓰기까지 보장한 결과가 아니다. 사용자 백업/복원 화면은 다음 단위이며 이번 기능에 포함되지 않는다.

### v3 이행에서 지킨 값

- 기존 계획·프로그램 버전·세트 ID·원래 목표·실제 원단위/원수치·원문 초안을 유지한다.
- 예전 실제값의 nullable 수행일/최초 시각을 생략한 JSON 표현을 유지해 기존 D5 근거 문자열을 보존한다.
- 이전의 `completionNotified`를 명시 마감 사건으로 바꾸지 않는다.
- 이전 파일의 실제값·초안·메모·완료 안내가 있는 세션만 `legacySessionIds`에 기록한다.
- v3에 `sessionEvents` 또는 `legacySessionIds`가 빠지면 구버전으로 간주해 축소 저장하지 않는다.
- 프로그램 카탈로그·설정·습관 파일의 스키마 번호는 변경하지 않는다.

## 4. 실행 환경과 자동 검사

macOS 호스트에서 Flutter/Dart 테스트를 실행한다. Simulator를 실행하지 않는다. 기기 시험용 데이터를 출시 데이터와 혼동하지 않도록 테스트는 임시 디렉터리·고정 시계·합성 계획을 사용한다. OS 기기 시계나 사용자의 실제 기록 파일을 바꾸지 않았다.

아래 명령은 **[macOS Terminal]**, 앱 루트 `apps/strength_routine`에서 실행한다.

```sh
flutter analyze
flutter test --concurrency=2 --reporter expanded
flutter test test/workout_session_lifecycle_screen_test.dart --concurrency=1 --reporter expanded --dart-define=CAPTURE_LIFECYCLE=true
flutter test test/training_calendar_test.dart --concurrency=1 --reporter expanded --dart-define=SESSION_CALENDAR_RENDER_DIR=/tmp/strength-calendar-lifecycle-final
```

쓰기 실패 시험은 파일 경로를 디렉터리로 만들어 장애를 주입한다. 이는 원래 메모리 상태, 확인창, 재시도와 성공 후 파일 복원을 검증하며 **실패 중 기존 디스크 파일 bytes 보존**의 직접 증거로 확대하지 않는다. 읽기 거부 시험에서 bytes를 별도로 비교한다.

### 회귀 검사에서 찾은 초안 변경 문제

첫 전체 실행은 153개 중 152개 통과·1개 실패였다. 기존 `settings_integration_test.dart`의 ‘프로필 기본값을 lb로 바꿔도 기존 kg 초안과 실제 기록의 단위·숫자를 유지한다’가, 아무 수정 없이 닫은 옛 초안에 `performedDate`가 추가됐음을 발견했다. 기존 초안의 존재를 이번 편집기의 변경으로 취급하던 초기값이 원인이었다.

초안을 읽은 것과 실제 편집을 구별하도록 수정했다. 값을 바꾸지 않고 닫으면 원문을 유지하고, 미저장 오류만 재시도할 때도 기존 상태를 그대로 저장한다. 테스트 기대값을 새 자동 변경에 맞춰 완화하지 않았다. 최초 실패 로그는 [전체 회귀 최초 실행](../research/2026-09-08/session-lifecycle/flutter-tests-before.txt)에 보존했으며 수정 후 153개 전체 회귀가 통과했다.

## 5. 렌더 검토와 수정

폰트는 번들 IBM Plex Sans KR/IBM Plex Mono, 색·간격은 기존 Console v2 토큰을 사용했다. 작은 화면에 긴 세션·메모와 큰 글자 조건을 넣어 레이아웃을 확인했다.

첫 수행일 달력 렌더에서 날짜 숫자와 기록 점의 두 줄이 정사각 셀 높이를 **7.9px** 넘었다. 이미지의 잘림과 Flutter RenderFlex 오류를 함께 확인했다. 날짜 셀의 세로 길이를 글자 크기에 따라 늘리는 방식으로 수정하고 동일한 테스트·폰트 조건으로 다시 렌더했다. 글자 축소나 예외 무시로 통과시키지 않았다.

날짜별 카드에는 ‘세션 전체’와 ‘선택한 날 실제 수행’을 따로 표시했다. 예를 들어 세션 전체 3세트 중 9/11 수행이 1세트이면 둘을 같은 하루의 수치로 읽지 않게 한다. 미상 1세트는 특정 날짜에 임의 표시하지 않는다.

마감한 선택 미기록 행의 청록색이 수정 가능한 상태처럼 보여 비클릭 행을 중립색으로 바꿨다. 실패 확인창의 중복 보존 설명을 줄여 오류와 확인 버튼 사이 공간을 정리했다. 같은 조건의 최종 PNG에서 날짜 목록·요약·재개 버튼 접근과 줄바꿈을 다시 확인했다. 이미지 생성이 실기기 운영체제 입력 시험을 대체하지 않는다.

## 7. 수행일 단위 종료 당시 남긴 후속 이력

**당시 미구현:** 사용자 백업/복원 UI, 일정 이동 UI, 이전 실제값 복사, 휴식 타이머, 관리자 주차별 세부 편집, 공통 운동 가이드. 계정·동기화·원격 카탈로그·실제 문의·구독은 운영 선택/상품·채널 준비가 필요한 후속 단위다. 상세 설계가 있다는 이유로 구현 완료로 표시하지 않는다.

**미검증:** 실기기 운동 입력 완료, OS 강제 종료/아이콘 재실행, 네이티브 키보드·VoiceOver/TalkBack, 릴리스 서명·배포, 스토어 결제. 사용자 지시대로 Simulator는 실행하지 않았다. [기기 확인 절차](2026-09-08-device-test-guide.md)의 결과란을 실제 수행 후 채운다.

당시 다음 제안 단위는 **운동 기록 파일 백업·복원**이었다. 이 계획은 이후 LC01에서 구현됐으므로 새 다음 작업으로 재개하지 않는다. 당시 제안은 [로드맵 R01](2026-09-08-development-roadmap.md#r01--사용자-기록-백업파일-복원)에 보존한다. v3 사건과 날짜 미상을 포함한 전체 운동 상태를 왕복하고, 습관·설정까지 포함하는 전체 앱 백업과 범위를 구분한다. 당시에는 파일 검사→교체 영향 검토→취소→원본 보존→writer 제어→성공 후 공개 순서를 다음 개발의 기준으로 제안했다.
