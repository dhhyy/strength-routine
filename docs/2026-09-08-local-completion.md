# 9/8 · 독립 구현 가능한 남은 기능 전체 — 구현 전 명세

작성: 2026-09-08. 사용자 요청: “모두 문서 작성 후, 기능 구현해줘”. 직전 답변에서 나열한 여섯 묶음을 모두 개발한다. 이전 문서의 ‘제안/결정 필요’는 아래의 명시한 로컬 기본 정책으로 구체화한다. 상세 구현·검증 결과는 문서 마지막에 후속으로 기록하며 계획을 완료로 표시하지 않는다.

## 1. 범위와 불변 조건

## 2. LC01 · 운동 기록 백업과 복원

진입은 프로필의 ‘운동 기록 백업’. 파일에는 TrainingAppState 전체, 즉 활성/보관 계획·프로그램 스냅샷·최근 리프트·세트 실제값/초안/메모·예정일/수행일·마감/재개·D5 이력·미상 날짜를 포함한다. 습관·설정·관리자 작업·계정과 별도 휴식 타이머는 제외하고 화면에서 고지한다. 앱 전체 백업이라고 부르지 않는다.

내보내기는 마지막 저장 성공 상태에서 만든 일관된 버전 파일이다. 저장 실패/대기 중이면 해결 후 내보낸다. 파일 종류/백업 버전/생성 UTC 시각/운동 데이터 envelope/손상 확인값을 담는다. 손상 확인값은 인증이나 암호화가 아니다. 파일은 개인정보가 포함된 일반 JSON이며 사용자가 저장 위치를 선택한다.

복원은 파일 선택 → 크기/구조/버전/무결성 검사 → 계획·기록·초안 개수와 현재 교체 영향 → 확인 → 저장 성공 후 화면 교체. 자동 병합하지 않는다. 검토 후 현재 상태가 바뀌면 재검토한다. 복원 중 운동 writer 진입을 막고 이전 저장 큐를 기다린다. 원래 상태 복구본을 먼저 확보하고 원자 파일 교체를 수행한다. 실패는 원래 상태를 유지하며 가져온 파일 자체는 수정하지 않는다. 복원 전 복구본을 다시 가져올 수 있어야 한다.

타이머는 백업에 포함하지 않으며 복원 뒤 기존 타이머를 적용하지 않는다. 운동 파일과 타이머 파일의 두 번 rename을 일괄 트랜잭션으로 설명하지 않는다. 교체된 운동 저장 세대에 타이머 자격을 묶어 프로세스 재시작 뒤에도 구 타이머가 살아나지 않도록 한다.

취소는 변경 없음. 손상·미지원 미래 버전·중복 ID·고아 참조·읽기/쓰기 실패는 별도 오류와 재시도. 파일 크기와 중첩을 제한한다. OS 저장 대화상자 성공은 플랫폼이 보고한 결과이며 사용자의 클라우드 보관 완료까지 보증하지 않는다.

검증: 최신/기존 스키마 왕복, 고급 처방 포함, 잘못된 파일 불변, 취소, 실제 임시 파일 재로딩, 저장 대기/검토 후 변경/중복 적용 차단, 실패 원본 보존, 복원 후 구 타이머 차단, 좁은 화면·큰 글자 렌더.

## 3. LC02 · 일정 편집

활성 계획에서만 편집한다. 기존 도메인 계약대로 오늘/과거 예정일은 이동하지 않고, 실제 기록/제외/초안/메모/마감 이력이 있는 세션은 미래라도 보호한다. 선택 훈련 요일·시작일·세션 순서 조건을 유지하며 입력 오류를 구체적으로 표시한다. 미래 날짜를 골라 변경 전/후 목록을 검토한 뒤 저장 성공 시 적용한다.

놓친 운동은 기존 예정일 그대로 열어 실제 수행일을 입력해 기록한다. 과거 날짜를 오늘로 자동 덮어쓰지 않는다. 날짜 변경으로 목표 중량·원본 프로그램·기록·조정 이력을 재생성하지 않는다. 계획 ID/revision이 바뀌면 검토를 폐기하고 다시 연다. 실패하면 기존 일정과 편집 후보를 보존한다.

검증: 유효 이동, 오늘/과거·기록 있는 미래 세션 거부, 요일/순서 오류, 저장 실패/동시 변경, 날짜 미상과 D5/마감 이력 보존, 화면 진입·검토·취소·적용.

## 4. LC03 · 이전 기록 가져오기

현재 세트 입력 안에서 사용자가 명시적으로 선택한다. 실제 수행일이 확인된 완료 기록만 자동 후보로 삼고 날짜 미상/제외/초안은 복사하지 않는다. 이름이 우연히 같은 다른 프로그램을 자동 합치지 않는다. 동일 프로그램의 명시적 종목 식별과 세트 위치를 사용하며 장비/종목 모호함이 있으면 후보를 내놓지 않는다. 이전 수행일·프로그램·세트와 원래 단위를 보여준다.

복사는 중량 숫자·원래 단위·반복만 초안에 넣는다. 현재 RIR/메모/수행일은 유지하고 완료 처리하지 않는다. 이미 입력한 중량/반복이 있으면 덮어쓰기 확인을 받는다. 취소하면 원문 초안 그대로다. 완료 기록 원본이나 원래 처방은 바뀌지 않는다.

검증: kg/lb 보존, 확인 날짜 순서, 미상 제외, 다른 종목 불일치, 현재 RIR/메모 보존, 초안 저장·재실행, 취소/저장 실패, 빈 후보와 작은 화면.

## 5. LC04 · 관리자 편집 확장

반복 범위는 기존 repetitions를 하한으로 보존하고 선택 상한을 추가한다. 양수·상한≥하한, AMRAP과 범위는 동시 사용하지 않는다. 사용자에게 ‘8–12회’로 표시하고 실제 반복은 별도 입력한다. D5에서 범위는 하한을 기준으로 판단하며 워밍업/드롭세트는 고정 작업 세트와 다른 의도이므로 감량 비교·대상에서 제외한다.

세트 종류는 기본 작업/워밍업/드롭세트이다. 기본값은 기존 파일 바이트 형태를 가능한 한 유지한다. 워밍업은 별도 강제 증량이나 준비 알고리즘이 아니며 관리자 수동 처방이다. 드롭세트도 각 하위 세트를 순서대로 직접 작성하고 자동 중량 감소를 추정하지 않는다. 라벨·검토·카탈로그·계획 스냅샷으로 전달한다.

일괄 수정은 선택 범위와 필드를 명시하고 적용 전 영향 개수·값을 검토한다. 범위는 현재 운동/세션/주차/프로그램 등 구현 화면에 노출된 단위만 주장한다. 관련 없는 필드를 보존한다. 실패/유효성 오류/취소/되돌리기를 지원한다.

카탈로그에서는 삭제 대신 보관을 기본으로 제공한다. 보관본은 사용자 배포 목록에서 제외하고 관리자에서 복원한다. 변경 버전 스냅샷을 보존하여 과거 버전을 새 버전 후보로 불러와 검토 후 저장한다. 같은 ID/버전을 다른 콘텐츠로 덮지 않는다. 이미 사용자가 시작한 계획에 소급 적용하지 않는다. 원문 편집 초안 자동 저장과 확정 카탈로그 변경은 구분한다.

새 의미 필드를 구버전 앱이 무시하고 축소 저장하지 못하게 envelope 버전을 상향하고 구버전 읽기는 유지한다. 확정한 버전 번호는 구현 후 스키마 표에 기록한다. 검증: 옛5개 프로그램 유지, 새 값 roundtrip, raw invalid draft, 범위/종류 검증, 일괄 변경 undo/실패, 보관 export 제외/복원, 과거 스냅샷 불변/새 버전 복구, D5 회귀, 관리자 1200px/375px 렌더.

## 6. LC05 · 휴식 설정

설정 기본값은 자동 시작 꺼짐·사용자 시간 미지정이다. 사용자 지정은 1~3600초이며 기기 설정으로 저장한다. 시간 우선순위는 세트 처방(명시 0초 포함) → 사용자 기본값 → 사용 불가다. 처방0초는 휴식 안 함이며 기본값으로 대체하지 않는다. 설정 변경으로 이미 진행 중인 타이머의 시간을 바꾸지 않는다.

자동 시작은 사용자가 옵션을 켠 뒤 새 완료 기록을 저장한 성공 콜백에만 적용한다. 단순 화면 재진입/파일 읽기/기존 기록 수정/재시도 때문에 반복 시작하지 않는다. 진행 중 타이머가 있으면 조용히 교체하지 않으며 기존 명시 교체 흐름을 쓴다. 타이머 저장 실패가 성공한 운동 저장을 취소하지 않는다. 앱 내 카운트다운과 만료 상태만 제공한다. OS 알림은 실제 플랫폼 권한/백그라운드 검증이 필요한 별도 범위로 §9에 남긴다.

타이머에는 처방/사용자 기본값 출처를 보존한다. 설정이 바뀌어도 당시 정상 시작한 타이머가 무효화되지 않으며 실제 기록/세대/마감 경계는 기존처럼 검증한다. 이전 타이머 파일을 읽는다.

검증: 기본 꺼짐, 사용자 시간 검증/복원, 0초 우선, 시작 성공/실패·중복/교체·기존 수정 제외, source 보존, 실제값 변경 시 무효화, 설정 화면 큰 글자.

## 7. LC06 · 운동 가이드

검색에 별도 가이드 진입을 추가하고 프로그램 운동 상세에서도 명시적으로 연결한다. 기본5개 프로그램에 등장하는 종목을 조사해 시작 자세·움직임·확인할 점을 짧고 구체적으로 작성한다. 세트/반복/RIR/AMRAP/템포/슈퍼세트·워밍업·드롭세트를 설명한다. 의학적 진단이나 통증 치료를 하지 않는다.

공통 가이드 식별은 명시적 허용 이름/별칭으로 매핑하며 검색 문자열을 모든 종목 동일성으로 쓰지 않는다. 미등록 사용자 종목에는 ‘가이드 없음’을 표시하고 다른 종목 가이드를 추정하지 않는다. 텍스트는 로컬 오프라인으로 읽으며 외부 공식 출처는 링크로 연다. 열기 실패는 텍스트를 유지하며 재시도를 제공한다. 검증 출처·조사일은 문서에 보존하고 영상은 실제 검토한 경우에만 붙인다.

검증: 기본 카탈로그 커버리지, 검색·빈 결과, 명시 별칭/미등록 동작, 출처 URL 검증, 링크 실패, 긴 문장·큰 글자 렌더.

## 8. 구현 순서·디자인·증거

이 명세를 먼저 저장한 다음 독립된 작업으로 나눈다. 루트는 LC01·통합, 담당자는 LC02/03, LC04, LC05/06을 수행한다. 공통 TrainingController/저장 스키마 수정은 소유권을 조율한다. 커밋은 문서 → 백업 → 일정 → 이전 복사 → 관리자 편집 → 휴식 → 가이드 → 통합 검증 기록처럼 각 기능 단위로 분리한다. 순서는 독립 기능 완성에 따라 달라질 수 있다.
