# 9/8 · 실제 확인·실기기 재실행 테스트 절차

> 상태: 실행 가능한 테스트 절차·합성 데이터 준비. 실제 iPhone/Android에서의 완료·강제 종료·복원은 **이번 작업에서 실행하지 않음**. 시뮬레이터 자동 실행 보류를 유지한다.

**수행일·마감, LC-D01~14, SF-D01~03 모두 실기기 미실행이다.** 현재 계약과 전체 저장 지원 범위는 [상태표](2026-09-08-remaining-work.md), 로컬 기능 검증은 [LC보고서](2026-09-08-local-completion.md), 검토 후 수정·자동 결과는 [안정화 기록](2026-09-08-review-fixes.md)을 따른다. 이 문서는 자료 준비와 조작 절차이며 시험 통과 증거가 아니다. 아래 기본 QA자료·과거 이행자료·추가 합성자료를 구별한다.

## 실기기 연결 준비

iPhone은 Mac의 Xcode에서 Apple 계정·서명 팀을 설정하고, 연결된 iPhone을 신뢰하며 개발자 모드를 활성화한다. 실제 기기를 선택한다. Apple 공식 절차: [실제 기기에서 앱 실행](https://developer.apple.com/documentation/Xcode/running-your-app-on-simulated-or-physical-devices), [릴리스 빌드 검사](https://developer.apple.com/documentation/xcode/testing-a-release-build).

**[macOS 터미널 · 실제 iPhone/Android를 USB 연결]**

```sh
flutter devices
```

출력에서 실제 연결 기기의 ID를 복사한다. 시뮬레이터 ID를 쓰지 않는다.

```sh
STRENGTH_DEVICE_ID='여기에 실제 기기 ID 입력'
flutter run --release -d "$STRENGTH_DEVICE_ID" -t tool/device_qa.dart
```

위 값은 예시 자리이며 실제 ID로 바꾼다. 코드 서명·SDK가 준비되지 않으면 먼저 그 오류를 해결한다. Android의 현재 release 설정은 debug 서명 구성이므로 스토어 배포 전 별도 릴리스 서명이 필요하다.

**[Windows PowerShell · 실제 Android]**에서도 Android SDK·USB 디버깅이 준비됐다면:

```powershell
flutter devices
$STRENGTH_DEVICE_ID = '여기에 실제 Android ID 입력'
flutter run --release -d $STRENGTH_DEVICE_ID -t tool/device_qa.dart
```

Windows에서 iPhone 앱을 직접 빌드하는 절차가 아니다. iPhone 빌드·서명은 Mac/Xcode에서 수행한다.

## QA 데이터가 일반 기록을 건드리지 않도록

`tool/device_qa.dart`는 **처음 파일이 없을 때만** 전용 데이터를 만든다. 과거 3회 완료 기록·오늘 세션·향후 2회가 있는 합성 프로그램이다. 수치는 UI 검증값이며 실제 운동을 권하는 처방이 아니다.

- 운동: `device-qa-v1-training.json`
- 습관: `device-qa-v1-habits.json`
- 설정: `device-qa-v1-training.json.settings.json`
- 일반 실행: `training-state.json`, `habits-state.json`, `app-settings.json`
- 관리자: `strength-admin/workspace.json`

재실행하면 저장된 날짜를 그대로 쓴다. **A·B는 최초 QA 데이터 생성 당일 완료한다.** 날짜가 바뀌어도 기록 탭에서 원래 세션을 조회할 수 있지만, 7일이 지나면 다음 미기록 세션이 비교 창에 포함되고 미래 세션 수도 줄어 B의 전제가 깨진다. 새 시험 자료가 필요하면 이전 복원 시험 결과를 먼저 남긴 뒤 운영자가 QA 파일만 백업/제거하고 별도 회차로 시작한다. **앱 전체 삭제나 일반 저장 파일 삭제를 복원 테스트 단계로 사용하지 않는다.** 손상 파일은 자동 초기화하지 않는다.

수행일·마감 시험에서 추가로 구분한다.

- `device-qa-v1-training.json`의 **파일명에 있는 v1은 QA 경로 이름**이다. 현행 저장소 전체는 envelope1~6을 읽고 기본3/고급 처방4/추가 처방5, 백업 복원 세대가 있으면6으로 쓴다. **기본 QA의 고급/추가 처방과 복원 세대가 없는 상태만 v3으로 저장**되므로 아래 F7의 v3 기대는 해당 자료 조건이다. 경로 이름을 바꾸거나 새 파일로 갈아타서 복원이 된 것처럼 시험하지 않는다. 프로그램 카탈로그·습관·설정 버전과도 별개다.
- 새 QA 파일은 과거 합성 완료 세트에 실제 수행일을 넣지 않는다. 따라서 날짜 미상 UI는 확인할 수 있다. 하지만 처음부터 v3으로 생성한 파일에 `legacySessionIds`가 비어 있는 것은 정상이며, 이것만으로 **v1/v2→v3 이행**이나 과거 마감 미상 추출을 시험했다고 할 수 없다.
- 기존 v1/v2 QA 원본이 있을 때만 F7의 실제 이행 시험을 수행한다. 없으면 `시험자료 미준비·미실행`으로 기록한다. 최신 파일의 버전 숫자만 1/2로 바꾸는 방식은 과거 파일 재현이 아니다.
- 현행 QA 프로그램은 각 세션에 필수 2세트만 있다. 선택 미기록·필수 0개 시험은 별도 합성 fixture가 필요하다. 일반 사용자의 프로그램을 바꿔 이 조건을 만들지 않는다.
- F의 날짜 표기는 `D=QA 생성 및 A·B 수행 당일`, `D−1=그 전 달력 날짜`, `D−2=이틀 전 달력 날짜`다. 시작 전에 실제 ISO 날짜를 결과표에 적는다. 월말·윤일은 날짜 선택기에서 달력 날짜로 선택하고, 임의 UTC 시각을 실제 수행일로 입력하지 않는다.

## 실제 조작 시나리오

따라 할 순서는 **D1~4 → A(A3에서 F1·C) → B(중간에 C 적용·되돌림 복원) → D5~7 → F2~F6 → E**다. F7은 구버전 자료가 있을 때 별도 회차, F8은 준비된 실패 주입/추가 fixture가 있을 때 별도 회차로 수행한다. D5의 제안 숨김 확인은 B2에서, 이력 보존 확인은 B5 이후에 끼워 넣는다. F4/F6은 합성 실제값을 수정·제외하므로 B의 증거를 먼저 남긴다.

### A. 초안과 운동 완료

먼저 아래 D1~4의 단위 확인을 수행한다. 빈 세트를 사용하는 시험이므로 A 완료 이후에 수행하지 않는다. D4 종료 시 기본 단위를 kg로 돌려놓는다.

1. QA 앱의 오늘 화면에서 `저장·복원 검증 4`를 열고 1세트 단위가 kg인지 확인한다.
2. 1세트 중량에 `60.`을 입력하고 닫는다.
3. 다시 열어 마지막 소수점까지 같은 원문인지 확인한다. 아래 **F1**에서 수행일을 선택하고, 그 절차 중 C를 한 번 실행해 **날짜와 작성 중 초안**의 OS 종료·복원을 확인한다. 복원된 1세트를 다시 열고 이어서 진행한다.
4. `60 kg`, 반복 `5`, RIR `1`을 입력하고 **`저장하고 다음 세트`**를 누른다.
5. 저장 성공 후 2세트로 이동하는지 확인한다.
6. 2세트를 제외해 실제 수행 1/제외 1인지 확인한다.
7. 제외한 2세트를 다시 편집해 `60 kg`, `5회`, RIR `1`로 완료한다.
8. 실제 수행 2/제외 0이고 모든 필수 세트 기록 안내가 표시되는지 확인한다. 이것은 명시 마감이 아니다. `기록 마감`을 누르지 않은 현재 단계에서는 ‘아직 마감 전이에요’ 안내가 남아야 한다.

RIR 제안까지 한 번에 확인하려면 마지막 상태는 두 세트 모두 완료/RIR 1이어야 한다. 제외나 RIR 누락 상태에서 제안이 보류되는 것은 정상이다.

### B. D5 감량 적용과 되돌리기

1. 기록 탭 → `기록 추세·중량 조절`로 이동한다.
2. 동일 QA 운동의 최근 3개 비교 가능 기록과 제안 이유를 확인한다.
3. `변경 내용 확인`을 눌러 향후 2세션의 각 세트가 `60 → 57.5 kg`인지 확인한다.
4. 취소하면 적용 이력이 생기지 않아야 한다.
5. 다시 확인하고 적용한다.
6. 오늘/과거 값은 60kg로 남고 미래 계획 상세에는 조정 목표 57.5kg가 표시돼야 한다.
7. 아래 C의 강제 종료·복원을 다시 수행하고 완료 기록과 적용 이력이 남는지 확인한다. 이 시점에는 작성 중 초안이 없는 것이 정상이다.
8. `조정 되돌리기`의 전/후 값을 확인하고 실행한다.
9. 향후 목표가 60kg로 돌아오고 되돌린 이력이 남아야 한다.
10. 다시 같은 근거로 중복 감량을 제안하지 않아야 한다.

오늘/과거가 됐거나 실제 기록/초안이 생긴 대상은 전체 되돌리기를 제한한다. 제한 이유가 보이면 값을 임의로 바꾸지 않는지 확인한다. 이는 일반적인 치료·부상 판정이 아닌 초기 제품 규칙이다.

### C. 실제 OS 종료·앱 재실행

이 절차는 A3/F1의 날짜·초안 상태, B7의 조정 적용 상태, B9의 되돌린 상태, F3의 마감, F4의 재개·수정 초안·재마감 상태에서 각각 실행한다. 단계별로 존재하는 상태만 대조하고 없는 초안이나 이력을 만들지 않는다. 반복할 때 결과표에 출발 단계와 회차를 적는다.

1. 입력 시트를 닫은 운동 상세에서 `기기에 저장됨`을 확인한다. 기록 추세 화면에서 확인할 때의 문구는 `기기에 저장했어요`이며, 저장 중/실패 상태에서 성공으로 판정하지 않는다.
2. 프로그램 이름, **계획한 날짜**, 세트별 **실제 수행일 또는 수행일 미상**, 실제 값/단위/RIR·작성 중 원문·적용/되돌림 상태, 기본 단위를 캡처한다. 마감 이후면 `기록을 마감했어요`/`기록 다시 열기`와 `마감 시각 · 기기 시간`, 재개 이후면 `기록 마감`과 `다시 연 시각 · 기기 시간`도 남긴다. 마감 시각을 운동 종료 시각으로 기록하지 않는다.
3. 앱을 백그라운드로 보낸다.
4. iPhone은 앱 전환기에서 해당 앱을 종료하고, Android는 앱 정보에서 강제 종료한다.
5. **삭제·재설치·데이터 지우기를 하지 않는다.**
6. 기기의 앱 아이콘을 눌러 다시 연다. 개발 도구의 hot reload/hot restart로 대신하지 않는다.
7. 종료 직전에 있던 계획·날짜·기록·초안·조정 이력·설정이 그대로인지 전 화면과 대조한다. 마감 상태면 세트 입력이 여전히 잠겨 있어야 하고, 재개 상태면 별도 재개 없이 편집할 수 있어야 한다. 재마감 전 초안이 있었으면 자동으로 마감하거나 제외하지 않아야 한다. 앱이 다른 시작 화면을 열어도 기록 탭의 `예정일`에서 같은 세션을 찾아 대조하며, 같은 화면 위치 복원까지 보장한다고 해석하지 않는다.
8. 네트워크를 끈 상태에서도 2~7을 반복해 로컬 저장 흐름을 확인한다.
9. A3에서 왔다면 A4부터 복원된 초안을 완료한다. 완료 후 이 절차를 한 번 더 실행해 초안이 완료 기록으로 바뀐 상태가 남는지 확인한다. B 또는 F에서 왔다면 해당 출발 단계의 다음 조작으로 돌아간다.

마감/재개 확인창의 `저장 중…` 또는 저장 실패 상태에서 종료한 시험은 **저장 성공 후 복원 시험과 분리**한다. 마지막 성공분까지만 복원 대상이며, 디스크에 쓰지 못한 입력·마감 후보를 복구하지 못했다고 성공 저장분 유실과 혼동하지 않는다. 강제 종료 후 같은 확인창이 자동 복구되거나 미저장 명령이 자동 실행되는 기능은 없다. 임의 전원 차단·파일시스템 장애 전체를 이 절차로 검증했다고 표시하지 않는다.

### D. 설정·도움말·구독 안내

**D1~4는 A 전에**, D5~7은 B 진행 중 또는 이후에 확인한다.

1. 기본값 kg 상태에서 오늘 1세트 중량에 `60.`만 입력하고 닫아 kg 초안을 만든다. 프로필 → 앱 설정에서 기본 단위를 lb로 저장한다.
2. 오늘의 **아직 열지 않은 2세트**를 열어 lb로 시작하는지 확인하고 값을 입력하지 않은 채 닫는다.
3. 1세트 초안은 `60.`/kg를 유지해야 한다. 과거 QA 완료 세션의 실제 값도 `60 kg` 그대로인지 확인한다. 숫자를 자동 환산하지 않아야 한다.
4. 프로필 → 프로그램 선택 → `바벨 기본 동작 · 주 3일` → `이 프로그램으로 시작` → 최근 기록 입력에서 새 입력의 lb 기본값을 확인한다. 저장·최종 `이 일정으로 시작`을 누르지 않고 취소/뒤로 돌아와 QA 계획을 유지한다. 앱 설정 기본 단위를 kg로 다시 저장한 후 A를 시작한다.
5. B2에서 감량 제안 표시를 끄고 기록 추세에 다시 진입하면 새 제안이 숨겨져야 한다. 다시 켜고 B를 진행한다. B5 이후에도 껐다 다시 진입해 기존 적용 이력/되돌리기는 남는지 확인한다.
6. 도움말 질문을 펼쳐 내용을 확인한다.
7. 구독 화면은 준비 상태를 표시하고 실제 구매 성공이나 유료 권한을 생성하지 않아야 한다.

결제 테스트는 상품·스토어 계정·검증 서버 연결 이후에만 별도 진행한다. [1인 구독 운영안](2026-09-08-subscription-operations.md)의 Sandbox/TestFlight/Play 라이선스 테스트 조건을 따른다.

### E. 일반 앱과 관리자

QA 이후 일반 사용자 흐름을 확인하려면 같은 기기에 `lib/main.dart`로 실행하고 프로그램 5개 목록부터 시작한다. QA 저장 파일을 읽지 않아야 한다. 관리자 생성 메뉴가 없어야 한다.

```sh
flutter run --release -d "$STRENGTH_DEVICE_ID" -t lib/main.dart
```

관리자 Mac 도구의 생성·내보내기는 [관리자 루틴 생성 문서](2026-09-08-admin-routine-builder.md)의 절차를 따른다. 내부 관리자 실행파일을 사용자에게 배포하지 않는다.

### F. 실제 수행일·기록 마감·재개·수행일 달력 — 실기기 미실행

아래 기대 결과는 현재 구현 명세·코드·자동 테스트의 계약을 기기 조작으로 확인하기 위한 것이다. 실제 기기에서 아직 실행하지 않았다. 화면 진입 버튼은 **`기록 마감` / `기록 다시 열기`**, 확인창의 확정 버튼은 **`마감하기` / `다시 열기`**다. `기록 마감`과 개별 `세트 완료`를 혼동하지 않는다.

#### F1. 날짜 선택·취소·원문 초안·미래 날짜 차단

**출발:** A3, 오늘 예정 `저장·복원 검증 4`의 1세트 `60.` 초안. D1~4를 마쳐 기본 단위는 kg, 2세트는 아직 미기록이다.

1. 편집기의 `실제 수행일`이 D인지 확인한다. 날짜가 없는 신규 세트는 보이는 오늘 날짜가 기본값이다. 계획한 날짜는 위 운동 상세에서 별도로 캡처한다.
2. `날짜 변경`을 누른다. 날짜 선택기에서 D−1을 선택한 뒤 `취소`한다. 편집기의 날짜는 D, 중량 원문은 `60.`로 남아야 한다.
3. 다시 날짜 선택기를 열어 오늘 이후 날짜가 선택되지 않는지 확인한다. 날짜 선택기의 입력 모드가 제공되면 미래 날짜 입력 시에도 확정되지 않아야 한다. 비정상 날짜 문자열 복원은 일반 UI에서 만들지 않고 F8의 자동 시험 범위로 둔다.
4. D−1을 골라 `선택`한다. 편집기에는 D−1, 중량에는 `60.`이 보이고 아직 실제 수행은 늘지 않아야 한다.
5. 닫기 버튼(접근성 설명 `기록 초안 저장하고 닫기`)으로 닫는다. 저장 성공을 확인한 뒤 하단 요약에서 필수 미기록과 초안 때문에 `기록 마감`이 비활성화됐는지 확인한다. 자동 완료/제외가 없어야 한다.
6. C의 OS 종료→아이콘 재실행을 수행한다. 같은 세션 1세트를 열면 D−1과 `60.`/kg가 그대로여야 한다. 날짜가 D로 돌아가거나 실제 기록으로 바뀌면 실패다.
7. A4부터 진행한다. 1세트는 D−1·60kg·5회·RIR1로 완료, 2세트는 D·60kg·5회·RIR1로 완료한다. 날짜 선택 뒤 다음 세트의 날짜까지 같은 과거 날짜로 몰래 바꾸지 않아야 한다. B의 D5는 현재 계약상 계획일 기준이며, 이 실제 날짜 분리가 곧 D5 정책 변경은 아니다.

**기록:** 선택 전/취소 후/선택 후/재실행 후 날짜·원문 캡처, 미래 날짜 선택 시 실제 반응, 마감 비활성 사유. 저장 실패가 있으면 정상 복원 회차를 계속하지 말고 실패 문구와 마지막 저장 성공 시점을 먼저 남긴다.

#### F2. 예전 날짜 미상 기록은 중량 수정만으로 오늘이 되지 않음

**출발:** B의 적용·undo 증거를 모두 남긴 뒤, 기록→`예정일`에서 가장 오래된 `저장·복원 검증 1`을 연다. 현재 QA seed의 과거 완료 세트는 수행일이 없다. 이미 날짜를 지정한 회차라면 별도 미상 세트를 사용하고 대상 이름을 기록한다.

1. 완료된 1세트의 행과 편집기에서 `수행일 미상`, 버튼 `날짜 지정`, ‘이전 기록에 날짜가 없어요. 지정하기 전까지 미상으로 남겨요.’를 확인한다.
2. `날짜 지정`에서 날짜를 눌러 보되 `취소`한다. 미상이 유지돼야 한다.
3. 중량만 `62.5`로 고쳐 `수정한 기록 저장`을 누른다. 수행일을 따로 지정하지 않는다. 수정 후에도 미상, 반복·단위·RIR·원래 목표는 기존 값이어야 한다.
4. C를 수행해 수정된 중량과 미상이 함께 남는지 확인한다. 이 단계는 수정 시각이 존재할 수 있으나 최초 기록 시각이나 실제 수행일이 오늘로 추정되지 않는 계약이다. `recordedAt`/`updatedAt`은 화면에서 모두 노출하지 않으므로 파일 항목 검증은 별도 QA 파일 읽기 또는 아래 자동 시험 근거로 구분한다.
5. 미상 유지 증거를 저장한 뒤에만 `날짜 지정`→D−2→`선택`→`수정한 기록 저장`을 수행한다. 이제 지정한 세트만 D−2가 되고 다른 미상 세트는 그대로 남아야 한다.

**기록:** 대상 예정일·세트 번호, 수정 전/후 중량, 미상 유지·명시 날짜 지정 전후 캡처. 새 v3 QA 파일의 미상 날짜 시험을 구버전 파일 이행 통과로 기록하지 않는다.

#### F3. 필수 기록 충족과 명시 마감 구분·마감 취소·마감 복원

**출발:** `저장·복원 검증 4`의 두 세트가 A에서 완료됐고 B가 끝난 상태. 아직 `기록 마감`을 누르지 않은 회차를 사용한다.

1. 하단에 `모든 필수 세트가 기록됐어요`와 ‘아직 마감 전이에요’가 있고, `기록 마감`이 가능해야 한다. 이때 C를 수행해도 명시 마감으로 변하면 안 된다.
2. `기록 마감`을 누른다. `기록을 마감할까요?` 확인창에서 실제 수행 2세트·제외 0세트·미기록 0세트·초안 0세트와 D−1/D를 확인한다. 마감 시각과 운동 종료 시각을 구별하는 설명도 확인한다.
3. `취소`한다. 두 실제값·날짜·초안 수와 미마감 상태가 그대로여야 한다. 아직 마감 시각을 만들지 않아야 한다.
4. 다시 `기록 마감`→`마감하기`를 누른다. 저장 중에는 중복 확정/새 입력을 실행하지 않아야 한다. 저장 성공 뒤 확인창이 닫히고 `기록을 마감했어요`, `마감 시각 · 기기 시간`, `기록 다시 열기`가 나타나야 한다.
5. 완료 세트를 눌러도 편집 시트가 열리지 않아야 한다. 기록 달력의 같은 세션은 `기록 마침`으로 표시해야 한다.
6. C를 수행한다. 같은 날짜·실제값·요약·마감 시각과 입력 잠금이 유지되는지 확인한다. 마감 시각은 기기 시계가 동일한 조건에서 비교하며 운동 지속시간으로 환산하지 않는다.

**기록:** 취소 전/후, 확정 저장 전/후, OS 재실행 후의 짝 캡처. 화면은 최신 마감 정보를 보여주며 전체 `sessionEvents` 사건 목록을 나열하는 UI는 없다. 사건 1건·동작 ID 중복 방지는 자동 시험 또는 복사한 QA 파일을 읽어 별도 증거로 기록한다.

#### F4. 재개 취소·재개·수정 초안·0kg 수행·재마감

1. F3에서 마감한 세션의 `기록 다시 열기`를 누른다. `기록을 다시 열까요?`에서 `취소`하면 마감 시각·잠금·실제값이 모두 그대로여야 한다.
2. 다시 `기록 다시 열기`→`다시 열기`를 누른다. 저장 성공 후 `기록 마감`이 다시 나타나고 세트 편집이 가능해야 한다. 재개만으로 실제 수행 수가 증가하거나 기존 세트를 미기록으로 바꾸지 않는다.
3. `다시 연 시각 · 기기 시간`과 기존 두 실제값을 캡처하고 C를 수행한다. 재실행 뒤 재개 상태와 기존 실제값이 유지돼야 한다.
4. 1세트를 열어 중량을 `0.`으로 수정하고 RIR을 `0`으로 적은 뒤 초안으로 닫는다. 기존 실제값은 아직 확정값이며 초안 수가 중첩될 수 있다. `필수 미기록 0세트 · 초안 1세트를 먼저 확인해 주세요.` 안내와 마감 차단을 확인한다.
5. C를 수행해 `0.`/RIR0/D−1 초안을 확인한다. `0`kg·5회·RIR0로 `수정한 기록 저장`한다. 실제 수행 수는 여전히 2이며 중량 0을 제외·미기록으로 취급하지 않아야 한다. 원래 목표 60kg·2세트 실제값·선택한 날짜는 바뀌지 않는다.
6. `기록 마감`→변경된 요약 검토→`마감하기`로 재마감한다. C를 수행해 수정된 값·날짜와 새 마감 상태가 유지되는지 확인한다.

**기록:** 재개 취소/성공·초안 복원·수정 저장·재마감 복원의 각 상태. 기존 사건이 없는 새 시험이면 저장 데이터의 사건 순서는 `closed → reopened → closed`다. 반복 회차면 전체 건수를 임의 고정하지 말고 시험 전/후 증가분을 대조한다. 이전 마감 요약/시각 보존은 최신 화면만으로 증명하지 않고 자동 시험 또는 QA 파일 읽기에서 확인한다. 단순 편집기 닫기는 수정 취소가 아니라 초안 보존이다.

#### F5. 수행일 달력은 실제 날짜만 표시하고 동일 세션을 유지

1. 기록 탭에서 `예정일`을 고르고 D를 누른다. `저장·복원 검증 4`의 계획한 날짜는 그대로 D여야 한다.
2. `수행일`로 바꾼다. ‘확인된 실제 수행일 · 완료 세트만 표시’와 미상 세트가 남았을 때의 ‘수행일 미상 N세트는 예정일 보기에서 확인할 수 있어요.’를 확인한다. N은 시험 중 지정한 날짜에 따라 달라지므로 고정 숫자를 복사하지 않는다.
3. D−1과 D를 각각 누른다. 양쪽에서 같은 `저장·복원 검증 4`가 나타나고 카드의 `선택한 날 실제 수행 1세트`, `세션 전체 · 실제 수행 2세트`를 구분해야 한다. 제목만 같고 다른 세션이 생성된 것으로 보이면 실패이며 필요하면 QA ID로 대조한다.
4. 각 카드에서 상세를 열어 예정 D와 전체 실제 날짜 D−1/D를 확인한다. 한 세션의 여러 날짜를 서로 다른 세션으로 복제하지 않아야 한다. F4의 0kg 세트도 D−1 실제 수행에 포함한다.
5. 실제 완료가 없는 날짜를 누르면 `확인된 실제 수행이 없어요`와 제외·초안·미상이 포함되지 않는 안내가 보인다. 날짜 미상 과거 세션은 `예정일`로 바꿔 찾아 열 수 있어야 한다.
6. C 후 `수행일` 보기를 다시 선택해 같은 날짜/카드 관계를 확인한다. **보기 기준·선택 날짜·스크롤 위치의 영구 저장은 이번 계약이 아니다.** 재실행 후 예정일 보기가 기본이어도 데이터가 같으면 정상이다.

#### F6. 전부 제외한 마감·미래/보관 읽기 전용

**B·F1~F5 증거를 먼저 보관한다. 아래는 QA 실제값을 의도적으로 바꾸는 별도 마지막 회차다.**

1. 오늘 QA 세션을 `기록 다시 열기`로 재개한다. 각 세트 편집기에서 `이번 세트 제외`를 눌러 두 세트를 제외한다. 제외 상태가 수행 날짜를 새로 갖지 않아야 한다.
2. `기록 마감` 확인창의 실제 수행 0세트·제외 2세트·미기록 0세트·초안 0세트와 `실제 수행 기록 없음`을 확인한 뒤 마감한다.
3. 예정일 보기에서는 이 세션의 `기록 마침`과 실제 수행 0/제외 2를 확인한다. 수행일 보기에서는 이 세션 때문에 D−1/D의 실제 수행 점이나 카드가 남지 않아야 한다. 같은 날짜에 다른 세션의 실제 기록이 있으면 그 표시까지 사라지면 안 된다.
4. C로 재실행한 뒤도 수행 0·제외 2·명시 마감과 수행일 표시가 같아야 한다. ‘모든 세트 기록됨’과 실제 수행 0은 함께 존재할 수 있다.
5. 예정일 달력에서 향후 `저장·복원 검증 5`를 연다. 목표/날짜 조회만 가능하고 세트 입력·`기록 마감`·`기록 다시 열기`는 없어야 한다.
6. **모든 QA 복원 증거 후 선택적으로** 다른 번들 프로그램을 최종 시작해 QA 계획을 보관한다. 이전 QA 세션을 예정일/수행일에서 찾아 요약·날짜·마감 상태를 읽되 수정/마감/재개는 불가능해야 한다. 새 계획 시작은 QA 상태를 바꾸므로 취소/검토 단계만으로 이 보관 시험을 통과 처리하지 않는다.

#### F7. v1/v2 원본의 날짜·마감 미상 유지와 v3 재실행

**별도 자료가 필요한 시험이며 현재 실기기 미실행이다.** 먼저 이전 버전 앱으로 작성된 합성 QA 파일의 원본·버전·생성 환경을 확보한다. 현재 제공 `device_qa.dart`는 새 v3 자료를 만들 수 있지만 구버전 파일을 자동 생성/가져오는 도구가 아니다. 파일이 없으면 이 절차는 자료 미준비로 남기고 [구버전 이행 자동 시험](../test/session_lifecycle_test.dart)을 별도 근거로 연결한다.

1. 앱이 꺼진 QA 환경에서 v1 또는 v2 원본을 안전한 위치에 복사하고, 운동 파일 경로·envelope 버전·활성/보관 계획 ID·세트 값/단위·초안 원문·메모·완료 안내·v2 D5 이력의 기준값을 기록한다. 일반 운동 파일을 대신 사용하거나 새 형식의 파일을 숫자만 바꿔 낮추지 않는다.
2. 같은 QA 앱 데이터 영역에 새 버전을 덮어 설치하되 앱 삭제/데이터 초기화는 하지 않는다. OS/서명 때문에 같은 데이터 영역을 유지할 수 없으면 중단 사유를 적고 이행 성공으로 표시하지 않는다.
3. 기존 실제 기록은 `수행일 미상`이어야 하고, 기록/초안/메모/완료 안내가 있던 구 세션은 카드의 `이전 기록 · 마감 여부 미상` 또는 상세의 `이전 기록 · 마감 여부 미확인`으로 보여야 한다. 명시 사건이 없는데 마감 시각이 생기면 실패다. 아무 기록도 없던 세션까지 과거 마감으로 채우면 안 된다.
4. F2처럼 중량이나 메모만 수정하고 성공 저장한다. 확인하지 않은 수행일·최초 입력 시각은 계속 미상이며 D5 근거 원문·원목표·기존 세트 ID를 임의 변환하지 않아야 한다.
5. 고급/추가 처방과 백업 복원 세대가 없는 기본 구 QA자료를 사용했다면 허용된 QA 파일 읽기에서 envelope가v3인지 확인한다. 이 조건이 다르면 [현행 저장 표](2026-09-08-remaining-work.md#현재-저장-계약)의4/5/6 쓰기 조건을 대조한다. `sessionEvents`/`legacySessionIds`가 있어야 하며 사용자가 명시 마감하기 전 closed 사건은 없어야 한다. 파일을 읽는 수단이 준비되지 않았다면 화면 시험만 기록하고 저장 구조 확인은 미실행으로 둔다.
6. C 후 같은 미상 날짜/마감 미상·수정값·기존 기록을 대조한다. 이후 사용자가 날짜 지정/기록 마감을 명시적으로 했을 때만 그 데이터가 새로 생겨야 한다.

v1과 v2는 각각 독립 회차로 확인한다. 미래 스키마·누락된 v3 루트 필드·손상 파일을 자동 초기화하지 않는 시험은 먼저 자동 임시 파일 시험으로 확인하며, 일반 기기 파일을 손상시켜 만들지 않는다.

|---|---|---|

강제 디스크 부족이나 일반 파일 삭제로 오류를 만들지 않는다. 현재 앱에 실패 주입 버튼은 없으며, 임시 파일을 대상으로 한 [컨트롤러 시험](../test/session_lifecycle_controller_test.dart)이 저장 경합/재시도 근거다. 실기기에서 재현 못한 조건은 자동 검증만 수행한 것으로 기록한다. 네트워크를 끄는 것만으로 로컬 저장 실패가 재현되지는 않는다.

새 기능 자동 시험의 역할은 [도메인·v1/v2/v3 이행](../test/session_lifecycle_test.dart), [원본 보존·경합·재시도](../test/session_lifecycle_controller_test.dart), [실제 화면 문구·수행일·마감/재개](../test/workout_session_lifecycle_screen_test.dart), [수행일 달력](../test/training_calendar_test.dart), [저장 버전 보호](../test/storage_schema_upgrade_test.dart)로 나뉜다. 실행 결과/통과 수는 [현재 상태표](2026-09-08-remaining-work.md)에서 연결한 담당 검증 문서에서 확인하고, 여기에 기기 통과 수로 옮겨 적지 않는다.

## 검토 후 안정화 추가 기기 확인 SF-D01~03

[안정화 명세](2026-09-08-review-fixes.md)의 SF01~03을 실제 기기/내부 관리자 환경에서 확인하는 절차다. 아래는 완료 결과가 아니다. 현재 앱에는 일반 사용자용 저장 실패/지연 주입 버튼이 없으므로 자연 발생한 해당 오류나 별도 격리 QA주입을 확보하지 못했다면 실행하지 않고 자동 검증 근거만 적는다. 기기 전체 디스크를 채우거나 일반 기록을 삭제/손상시키지 않는다. 비행기 모드는 로컬 저장 실패를 만들지 않는다.

### SF-D01 · 최초 완료 저장 실패 뒤 세 가지 재시도

1. 격리한 합성 QA에서 아직 영구 완료되지 않은 세트를 준비하고 기본 휴식90초·자동 시작 켜짐을 저장한다. 해당 세트의 처방은 미지정, 다른 타이머는 없음으로 시작한다.
2. 실제 중량·반복을 입력하고 최초 완료의 운동 저장 실패를 해당 QA경로에만 주입한다. 실패 원인·시점·화면 문구와 타이머 미시작을 기록한다.
3. 실패 원인을 해소하고 기본 저장 버튼으로 재시도한다. 세트 영구 저장 성공 뒤 휴식90초가 한 번 시작하는지 확인한다.
4. 별도의 미완료 합성 세트/격리된 초기 상태에서 같은 실패를 다시 준비해 `저장하고 다음 세트`, 전용 `저장 다시 시도` 경로를 각각 확인한다. 이미 영구 완료한 같은 세트를 최초 완료 시험으로 재사용하지 않는다.
5. 새 타이머의 출처·시작/종료 시각·운동 파일 저장 상태를 가능한 수단으로 기록하고, 화면 재진입/기존 완료 수정에서 새 타이머가 중복 생성되지 않는지 확인한다. 파일 검사 수단이 없으면 UI 관찰과 구조 미확인을 구별한다.
6. 기존 타이머가 있는 별도 회차에서는 교체 취소 시 기존 타이머를 유지하며 운동 기록 저장은 완료되는지 확인한다.

기대 결과는 [휴식 명세](2026-09-08-rest-guides.md)와 SF01을 따른다. 현재 결과: **자료 미준비·실기기 미실행**. 각 재시도 버튼을 별도 행으로 남긴다.

### SF-D02 · 같은 관리자 화면의 연속 버전 저장

1. 사용자 콘텐츠와 구별한 합성 프로그램v1을 준비한다. 과거 버전 이력이 없는 초기 작업에서 시작했는지 파일/준비 기록으로 확인한다.
2. 정밀 편집에서v2로 검토·저장하고, 화면을 나가지 않은 채v3로 다시 검토·저장한다.
3. 동일 화면에서 버전을v2로 바꾸고 `변경 검토`를 누른다. 이미 사용한 버전이라는 오류와 버전 수정 경로를 보여야 하며 저장 검토로 진행하면 안 된다.
4. v1도 같은 방식으로 확인하고 새 미사용 버전으로 고쳐 정상 검토·저장이 가능한지 확인한다.
5. 관리자 파일의 최신 내용과v1/v2/v3 불변 스냅샷이 보존되는지 확인한다. 파일 쓰기 실패의 일반 재시도와 버전 입력 오류를 구별한다.

현재 결과: **합성 자료 준비 필요·실제 내부 앱/기기 미실행**. 관리자 빌드의 배포 통제는 서버 로그인 검증을 뜻하지 않는다.

### SF-D03 · 지연된 관리자 저장의 진행 잠금

1. 격리된 관리자 작업에서 과거 버전의 `새 버전 초안으로 복구`를 선택하고 초안 교체를 확인한다.
2. 해당 저장 완료를 의도적으로 지연할 수 있는 QA주입이 있다면 저장 중 중복 복구/다른 진입이 차단되는지 관찰한다. 주입이 없다면 빠른 저장을 느린 저장 시험으로 계산하지 않는다.
3. 저장을 성공으로 완료시킨 뒤 한 번만 정밀 편집에 진입하고 새 초안/이전 카탈로그/불변 이력을 보존하는지 확인한다.
4. 별도 회차의 저장 실패에서는 이전 초안과 카탈로그를 유지하고 실패 안내·해소 후 재시도를 확인한다.

현재 결과: **지연 주입 자료 미준비·실기기 미실행**. 자동 시험의 저장 완료 관찰·지연 주입 결과는 SF03 검증에서 확인한다.
