# 9/8 · 자동 휴식 저장 재시도 안정화

기준: 2026-09-08, Asia/Seoul. [개발 검토](2026-09-08-development-review.md)의 RV01과 구현 전 [안정화 명세](2026-09-08-review-fixes.md)의 SF01을 처리한다. 기존 검토 결과는 당시 코드의 이력으로 보존한다. 이번 작업은 자동 휴식의 저장 실패·재시도 경계를 수정하며 데이터 형식, 운동 기록의 의미, 화면 디자인을 바꾸지 않는다.

## 한 문장씩 확인할 변경

- 최초 완료 저장에 실패해도 기본 저장·다음 세트·전용 재시도에서 같은 완료의 자동 휴식 의도를 유지한다.
- 새 완료가 파일에 저장되고 수정 초안이 없는 것을 확인한 뒤 자동 휴식을 한 번 시도한다.
- 이미 저장된 완료 기록을 수정하는 동작에는 새 자동 휴식 의도를 만들지 않는다.
- 제외·기록 전으로 되돌리기·초안 저장하고 닫기를 선택하면 이전 완료의 자동 휴식 의도를 해제한다.
- 저장 실패 후 입력을 바꾸면 초안 재시도만으로 타이머를 시작하거나 편집기를 닫지 않는다.
- 다른 실제 기록으로 교체된 경우에는 이전 실패 후보의 자동 시작 의도를 이어받지 않는다.
- 진행 중인 타이머 교체는 기존 확인을 유지하며 취소하면 원래 타이머와 저장한 실제 기록을 보존한다.

## 원인과 수정 범위

`TrainingController.update`는 사용자의 최신 입력을 먼저 메모리에 반영하고 파일 쓰기에 실패해도 그 후보를 보존한다. 수정 전 `SetEditor._commit`은 메모리의 상태가 `completed`인지로 매번 자동 시작 여부를 새로 계산했다. 따라서 최초 완료의 쓰기가 실패한 뒤 기본 `수정한 기록 저장` 또는 `저장하고 다음 세트`를 누르면 아직 영구 저장하지 못한 후보를 기존 완료 수정으로 잘못 판단했다. 전용 `저장 다시 시도`만 이전 bool을 보존했기 때문에 경로별 동작이 달랐다.

bool을 단순히 OR로 유지하면 반대 오류가 생길 수 있다. 확장 시험은 복원된 초안을 입력 변경 없이 완료한 후 쓰기에 실패하고, `기록 초안 저장하고 닫기`도 실패한 다음 전용 재시도를 누르는 경로에서 취소한 자동 휴식이 시작되는 기존 동작까지 재현했다. 닫기 재시도는 완료 재시도와 분리해야 한다.

이번 수정은 [workout_screen.dart](../lib/workout_screen.dart)의 `SetEditor` 내부로 한정했다. bool 대신 해당 편집기가 만든 신규 완료 후보 `SetActual` 객체를 기억한다. `TrainingAppState`는 불변 객체이며 초안 추가는 기존 실제 객체를 유지하므로, 같은 후보의 재완료와 다른 실제 기록으로의 교체를 구분할 수 있다. 저장 성공 뒤 현재 실제값이 후보와 같고, 수정 초안이 없고, 여전히 편집 가능하며, 결과가 ‘닫기’가 아닌 경우에만 기존 자동 휴식 함수를 호출한다. 후보는 호출 전에 해제하여 저장 이후 UI 재빌드나 타이머 교체 취소가 같은 완료를 다시 시작하지 않게 한다.

`TrainingController`, `LocalTrainingStore`, `RestTimerController`, 저장 스키마와 패키지는 변경하지 않았다. 모든 재시도는 기존 파일 저장 경로를 이용한다. 타이머 파일 쓰기 실패의 후보·재시도는 기존 `RestTimerController` 계약을 따른다.

## 상태별 계약

| 사용자 상태·동작 | 기록 저장 결과 | 자동 휴식·화면 결과 |
|---|---|---|
| 새 세트 완료의 첫 쓰기 실패 | 메모리에 완료 후보 유지, 오류 표시 | 시작하지 않고 편집기를 유지한다. |
| 같은 후보를 기본 저장으로 재시도 | 실제 완료를 영구 저장 | 자동 시작을 한 번 시도하고 목록으로 돌아간다. |
| 같은 후보를 다음 세트로 재시도 | 실제 완료를 영구 저장 | 자동 시작을 한 번 시도하고 다음 미기록 세트를 연다. |
| 같은 후보를 전용 버튼으로 재시도 | 현재 후보를 영구 저장 | 원래 완료 동작을 이어간다. |
| 기존 영구 완료를 수정하다 저장 실패 후 재시도 | 수정 실제값을 영구 저장 | 새 자동 시작은 없다. |
| 실패한 신규 완료 후 제외·기록 전으로 변경 | 제외 또는 실제값 제거·원문 초안 보존 | 기존 자동 시작 의도를 해제하며 변경 저장 실패의 재시도도 자동 시작하지 않는다. |
| 실패한 완료 후 초안 저장하고 닫기 | 기존 닫기 동작대로 현재 실제·초안을 저장 | 닫기 의도를 따르고 자동 휴식을 취소한다. 닫기는 완료 후보의 값을 과거로 되돌리는 동작이 아니다. |
| 실패한 신규 완료 후 입력 변경·초안 재시도 | 완료 후보와 새 원문 초안이 함께 저장될 수 있음 | 편집기를 유지하며 자동 시작하지 않는다. 수정 입력을 명시적으로 완료 저장한 뒤에만 시작할 수 있다. |
| 다른 실제 객체로 후보가 교체됨 | 현재 실제를 기존 기록으로 취급 | 이전 후보의 의도를 상속하지 않는다. |
| 시작 가능한 다른 타이머가 진행 중 | 새 운동 기록은 이미 저장됨 | 기존 교체 확인을 표시하며 취소하면 원래 타이머를 보존한다. |
| 자동 시작 꺼짐·명시 처방 0초 | 완료 저장 정상 | 기존 정책대로 자동 시작하지 않는다. |
| 타이머 자체 파일 쓰기 실패 | 운동 실제 완료는 영구 저장됨 | 타이머 저장 오류·전용 재시도를 유지하며 원래 종료 시각을 보존한다. |

자동 시작 의도는 편집 중인 메모리 상태다. 앱 강제 종료 뒤 임의로 휴식을 시작하거나 복원하지 않으며, 저장된 타이머의 복원은 기존 타이머 파일 기능이다. 일반 기록 복원에서 새 타이머를 만드는 기능을 추가하지 않았다.

## 시험 설계와 결과

시험 파일: [rest_auto_start_screen_test.dart](../test/rest_auto_start_screen_test.dart). 기존 6개 시험을 17개로 확장했다. 기존 전용 재시도 한 건을 세 재시도 경로로 확장했으며, 새로운 총 시험 수를 기존 시험 수와 중복 합산하지 않는다.

저장 실패는 mock 반환값으로 대체하지 않았다. 임시 운동 파일을 보관 경로로 옮기고 최종 파일 경로를 디렉터리로 막아 실제 쓰기가 실패하도록 했다. 재시도 전에 경로를 복구하고 새 `LocalTrainingStore`로 읽어 첫 실패 당시 완료가 디스크에 없었음을 검사한다. 성공 후 다시 읽은 실제 완료·초안 여부와 타이머를 함께 검사한다. 세 정상 재시도 경로는 타이머 저장 시작 횟수를 관찰해 한 번인지 확인하고 화면 재진입 뒤 종료 시각도 비교한다.

|---|---|---|

수정 전 5개 실패는 기본 저장, 다음 세트, 닫기 재시도, 변경 초안의 명시 완료, 실패 복구 후 타이머 교체 확인이었다. 수정 후 최초 실행의 한 실패는 정상으로 표시된 `운동 기록을 저장했어요` 안내를 시험이 닫지 않고 아래 세트 행을 누른 결과다. 재시도·교체 취소 assertion은 이미 통과했다. 시험에 안내를 확인하고 닫는 단계를 추가했으며 기존 assertion은 제거하지 않았다. 최종 63개 회귀에는 자동 시작 17개와 기존 세트 입력·고급 처방·타이머·설정·수행 마감 검사가 포함된다. 렌더용 선택 시험 1개는 63개에 포함된 시험을 다시 실행한 것이며 추가 기능 시험으로 합산하지 않는다.

## 실제 기기에서 확인할 경계

자동 시험은 임시 파일의 쓰기 실패와 headless 위젯 입력·파일 재로딩을 확인한다. 실제 기기의 저장 공간 부족, 앱 강제 종료, 키보드, 접근성 서비스, 백그라운드 동작을 검증했다는 뜻은 아니다. 실기기 수행은 [기기 검증 가이드](2026-09-08-device-test-guide.md)를 따르며, 이번 수정에는 OS 휴식 알림을 추가하지 않았다.
