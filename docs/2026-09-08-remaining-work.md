# 9/8 · 남은 기능과 확인할 항목

최종 갱신: 관리자 주차·세트별 정밀 편집에 이어 **휴식·템포·슈퍼세트·AMRAP**의 관리자 작성·사용자 표시·기록 연결을 반영했다. 네 기능의 상세 계약과 최종 자동 검증 결과는 [고급 처방 명세](2026-09-08-advanced-prescriptions.md)를 따른다. “다 구현”은 직전 미구현이라고 안내한 네 기능의 요청이며 아래 전체 로드맵의 운영·출시 완료로 확대하지 않는다.

## 이미 구현한 범위

최신 고급 처방 포함 **전체 테스트 252개 통과·정적 분석 정상**이며, [상세 근거](2026-09-08-advanced-prescriptions.md#12-구현검증커밋-기록)는 실제 기기 미검증과 구분한다.

- 프로그램 5개 선택 → 최근 기록·기준 중량·일정 입력 → 결과 검토 → 시작 → 세트 기록 → 기기 파일 저장·복원.
- 세트별 완료·제외·수정·초안, 저장 실패 재시도, 다음 미기록 세트 이동.
- 실제 수행일·입력/수정 시각, 요약 검토·명시 마감·다시 열기·재마감 이력, 예정일/수행일 달력, 과거 날짜/마감 미상 보존과 운동 파일 v3 이행.
- 기록 달력·계획 안에서의 운동 추세·D5 감량 제안·명시 적용·이력·되돌리기.
- 실제 프로그램 운동 검색, 사용자 습관·일별 체크·저장, 기본 단위·제안 표시 설정.
- 운영자 내부 빌드의 루틴 작성·반복 생성·검토·카탈로그 저장·JSON 내보내기.
- 관리자 기존 프로그램 정밀 편집·새 ID로 복제, 주차/세션/운동/세트별 처방, 주차 복사·순서·삭제·되돌리기·새 버전 검토·저장.
- 세트별 휴식·템포·AMRAP과 연속 운동 슈퍼세트의 편집·표시·교차 다음 세트 이동·실제 반복 저장.
- 저장된 실제 완료의 명시 휴식 시작·일시정지/재개·종료·교체 확인·독립 파일 복원과 출처 검사.
- 로컬 FAQ와 구독 준비 안내.
- 독립 웹 랜딩과 Three.js 시안 5개.

관리자 정밀 편집 단위 당시 앱 전체 테스트는 **189개 통과**, 정적 분석 문제 없음이었다. [당시 검증](2026-09-08-admin-precise-editor.md#13-구현검증커밋-기록)에 코드·실패/충돌 수정·렌더·커밋을 보존한다. 새 고급 처방의 검증 결과는 [고급 처방 명세](2026-09-08-advanced-prescriptions.md)에서 확인하며 189개를 새 기능 통과 수로 재사용하지 않는다. 앞선 153개·120개와 랜딩의 59개 브라우저 검사는 각 당시 결과이며 실제 기기 시험을 의미하지 않는다.

현재 저장 형식은 고급 처방 사용 여부에 따라 **카탈로그 1/2, 관리자 2/3, 운동 3/4 쓰기**로 구분하고 이전 버전 읽기를 유지한다. 휴식 타이머는 운동 파일과 별도의 `.rest-timer.json`이다. 새 처방을 쓰지 않는 기본 5개 카탈로그는 기존 형식을 유지하며 사용자 진행/보관 계획을 자동 개정하지 않는다.

## 앱 사용성을 위해 제안하는 다음 개발

아래 순서는 현재 코드 의존성을 고려한 제안이다. [후속 10개 상세 개발 로드맵](2026-09-08-development-roadmap.md)에 각 단위의 범위·사용자 흐름·데이터·이행·실패·취소·테스트·완료 기준을 적었다. 제안을 완료 기능으로 해석하지 않는다.

| 순서 | 남은 기능 | 현재와 달라지는 점·완료 기준 |
|---|---|---|
| 1 | 사용자 기록 백업·파일 복원 | 현재는 같은 기기의 저장 파일을 다시 읽는다. 내보내기·가져오기 화면과 최신 운동 v3/v4 검사·복원 전 검토·취소·실패 보존을 구현한다. 별도 타이머 파일의 포함/초기화 정책도 정한다. |
| 2 | 놓친 운동·미래 일정 변경 화면 | 도메인의 `rescheduleFuture`는 있지만 사용자 조작 화면이 없다. 날짜 변경 영향 확인 후 기록·초안·조정·마감 이력을 보호하며 적용한다. |
| 3 | 지난 기록 가져오기·휴식 기능의 추가 확장 | 다음 세트 이동과 처방 기반 명시 휴식 타이머는 구현했다. 지난 실제값의 출처 확인·새 초안 복사, 사용자 휴식 설정·자동 시작·OS 알림은 별도 후속이다. |
| 4 | 운동 설명·가이드 | 현재 검색은 프로그램/계획의 운동 구성을 보여준다. 공통 운동 설명과 검토한 영상 링크를 추가한다. |

근거: [상태·날짜·일정·백업 분석](feature-analysis/2026-09-07-data-reliability.md), [운동 중 기록 분석](feature-analysis/2026-09-07-workout.md), [프로그램·검색 분석](feature-analysis/2026-09-07-programs.md). 보관 기록 정정과 프로그램 간 비교도 이 분석의 후속 제안이며 현재 읽기 전용 범위를 자동 변경하지 않는다.

## 운영 방식에 따라 추가할 기능

| 항목 | 현재 상태 | 남은 구현·결정 |
|---|---|---|
| 관리자 정밀 편집 | 주차별·세트별 편집·새 버전 저장 및 휴식/템포·AMRAP·슈퍼세트 연결 | 반복 범위·워밍업·드롭세트·대량 조정·카탈로그 삭제/과거 버전 복구는 후속. [새 제어·검증](2026-09-08-advanced-prescriptions.md) 참조. |
| 휴식 운영 | 양수 처방·저장된 실제 완료에서 명시 시작하는 앱 내 타이머 | 자동 시작·임의 시간 설정·OS 알림·워치·파일 간 원자 저장은 후속. 출처 실제값·마감/재개 사건·활성 계획이 달라지면 이전 타이머는 적용하지 않는다. |
| 관리자 접근·콘텐츠 배포 | 내부 빌드 배포 통제, JSON 반영 후 사용자 앱 재빌드 | 원격 운영이 필요하면 관리자 계정·서버 권한 검사·카탈로그 배포/버전 관리. 현재 관리자 로그인은 없다. |
| 실제 구독 | 준비 안내·운영 문서만 제공 | 제공 혜택·가격·플랫폼 상품을 정한 뒤 결제 SDK·거래 검증·유료 권한·구매 복원·갱신/만료/환불 처리를 연결한다. |
| 실제 Q&A/문의 | 고정 FAQ 6개 | 접수 채널·답변 범위를 정한 뒤 질문 저장·전송·운영자 답변·실패/재시도를 구현한다. |
| 계정·여러 기기 동기화 | 기기 로컬 저장 | 필요 시 계정·동기화·충돌 처리를 추가한다. 파일 백업과 별개다. |
| 고급 훈련 엔진 | 수동/고정/명시 기준 비율, D5, AMRAP 세트의 기준/실제 반복 구분 | e1RM·자동 증량·AMRAP 성과 기반 진급·블록 자동 처방은 미구현이다. AMRAP은 D5 근거와 미래 감량 대상에서 제외하고 실제 통계에는 포함한다. |

다중 트레이너 가입·승인·정산은 사용자 지시로 제외했다. [구독 운영안](2026-09-08-subscription-operations.md)과 [관리자 생성 문서](2026-09-08-admin-routine-builder.md)를 따른다.

## 기능 구현과 별도로 남은 확인

1. 실제 기기에서 운동 입력·완료 후 OS 프로세스 종료→아이콘 재실행→기록/초안/설정/D5와 새 처방·휴식 타이머 복원을 확인한다.
2. 실제 기기의 키보드·접근성·오프라인·릴리스 빌드와 배포 서명을 확인한다.
3. 운영자가 프로그램 5개와 D5 초기 정책을 검토한다.
4. 최종 랜딩을 선택·보완한 뒤 별도의 공개 배포와 실제 앱 링크를 준비한다.

현재 기기 복원 코드와 자동 파일 왕복 테스트는 있지만 **실기기 검증은 미실행**이다. [실기기 확인 가이드](2026-09-08-device-test-guide.md)에 버튼 순서·명령·결과표가 있다. 사용자 재요청 전 시뮬레이터는 실행하지 않는다.

## 집에서 시안을 확인할 때

같은 컴퓨터라면 서버 실행 상태에서 [비교 페이지](http://127.0.0.1:4175/landing/concepts/)를 연다. `127.0.0.1`은 접속하는 컴퓨터 자신이므로 다른 컴퓨터에서 현재 서버로 연결되는 공유 주소가 아니다.

다른 컴퓨터라면 프로젝트 파일을 옮기고 [시안 실행 안내](../landing/concepts/README.md)에 따라 앱 루트에서 정적 서버를 실행한다. `landing/concepts/`만 옮기면 상위 상태 모듈·토큰·프로그램·폰트가 빠지므로 앱 폴더 구조를 보존한다. 현재 저장소에는 Git 원격이 등록돼 있지 않고 이번 작업은 로컬 커밋까지 완료된 상태다. 외부 배포·원격 푸시는 수행하지 않았다.
