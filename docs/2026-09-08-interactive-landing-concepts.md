# 9/8 · 인터랙티브 랜딩 5개 시안

사용자 요청: 인터랙티브의 정의와 레퍼런스를 스스로 조사하고, Three.js 같은 기술로 서로 다른 랜딩 시안 5개를 구현한다. **[로컬 비교 페이지](http://127.0.0.1:4175/landing/concepts/)**에서 모두 직접 조작할 수 있다. 기존 Flutter 앱과 기존 랜딩을 보존하고 `landing/concepts/`에 추가했다.

## 인터랙티브를 판단하는 기준

이번 제품의 작업 정의는 **사용자 입력 → 상태 변화 → 바로 읽을 수 있는 결과 → 다시 변경하거나 초기화**다. [NN/g의 Microinteractions](https://www.nngroup.com/articles/microinteractions/)에서 입력과 피드백 관계를 참고해 이 프로젝트의 평가 기준으로 확장했다. 전체 랜딩을 하나의 microinteraction이라고 부르는 뜻은 아니다.

자동 회전이나 배경 효과의 유무로 완료를 판정하지 않는다. 중량을 바꾸면 실제 원판 구성과 kg, 프로그램을 선택하면 실제 구성 설명과 강조된 오브젝트가 함께 바뀌어야 한다. 성공·실패·취소·복원이 어떻게 보이는지도 같은 체험의 일부다.

## 조사와 반영

| 공식 레퍼런스 | 실제 확인한 내용 | 적용한 부분 |
|---|---|---|
| [Three.js material variants](https://threejs.org/examples/webgl_loader_gltf_variants.html) | 모델 로딩 완료 후 midnight→beach 선택, 같은 모델의 재질 변경 | 큰 3D 대상과 작은 조작의 직접적인 관계 |
| [Apple Watch](https://www.apple.com/watch/) | 동일한 크기의 제품군과 넓은 여백·정보 위계 | 프로그램 5개를 같은 정보 순서로 비교 |
| [Linear](https://linear.app/) | 히어로·제품 섹션·스크롤 후 계획/차트 영역 | 넓은 일정·그래프를 핵심 설명으로 사용 |
| [Hevy 기록 기능](https://www.hevyapp.com/features/track-exercises/) | 설명 옆 실제 제품 이미지의 숫자 열·완료 상태 | 입력·완료·다음 세트 피드백을 한 화면에 연결 |

Apple 색상 선택, Linear 내부 편집, Hevy 네이티브 앱 입력은 직접 검증하지 않았다. 원본 사진·모델·성과·브랜드 색은 가져오지 않았다. Three.js 코드는 요청한 구현을 위한 MIT 의존성이며 로컬 고정 버전을 사용한다.

원문 근거는 [인터랙션·접근성·기술 조사](../research/2026-09-08/concepts/interaction-research.md), 실제 캡처와 관찰 범위는 [시각 레퍼런스 분석](../research/2026-09-08/concepts/visual-references.md)에 남겼다. 연구 문서의 후보 동작은 초기 제안이며 최종 구현은 아래 표를 따른다.

02·03의 실제 콘텐츠는 [프로그램 카탈로그](../assets/programs.json)다. 03의 3D 격자는 주간 패턴이며 시작일에 따른 실제 날짜는 DOM 미리보기와 전체 일정 표에 표시한다. 04는 기존 웹 상태 모델을 재사용한 2세트 체험이다. 05는 [QA 합성 데이터](../tool/device_qa_state.dart)를 참고한 정해진 예시이며 실제 사용자 기록에서 제안을 산출하지 않는다.

## 공통 구현과 경계

Console v2의 다크·시안·의미색을 유지했다. 한글은 IBM Plex Sans KR, 라틴 글자·숫자는 IBM Plex Mono로 표시한다. 같은 번들 Mono를 ASCII 글자·숫자 범위로 선언해 한글 사이 공백이 불필요하게 넓어지는 현상을 막았다. 토큰은 `landing/concepts/tokens.css`, 구성 요소는 [디자인 시스템](03-design-system.md)에 등록했다.

Three.js **0.185.1**의 공식 npm core/module과 MIT 라이선스를 `vendor/`에 고정하고 출처·무결성·파일 SHA256을 기록했다. 새 Flutter 의존성이나 빌드 도구는 추가하지 않았다. `scenes.mjs`는 필요할 때 동적으로 읽으므로 모듈/WebGL 실패가 HTML 기능 전체를 막지 않는다.

드래그와 같은 결과에 도달하는 회전 버튼·초기 시점을 제공하고, 선택 가능한 오브젝트마다 HTML 버튼도 제공했다. 이는 [W3C 드래그 대체 조작 설명](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)을 반영한 것이다. [모션 감소 설명](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)에 따라 `prefers-reduced-motion`에서는 보간 없이 상태를 반영한다. 이 두 항목으로 WCAG 전체 준수를 선언하지 않는다.

입력이 없는 동안 상시 자동 회전하지 않는다. DPR 상한 1.5, 보이지 않는 장면·탭의 렌더 중지, 장면/그림자/재질/지오메트리 정리, WebGL context 손실·복구, BFCache 복귀를 처리한다. 실제 기기의 FPS·배터리 사용량은 측정하지 않았다.

04만 `strength-concept-session-v1`에 저장하며 다른 브라우저 키와 앱의 운동 파일을 바꾸지 않는다. 손상된 저장값은 명시적 초기화 전까지 보존하고, 삭제 실패는 현재 입력을 유지한다. 01·02·03·05는 페이지 체험 상태다. 외부 전송·결제·가입·앱 설치·호스팅 배포는 없다.

| 검사 | 최종 결과·근거 |

| 렌더 | 5개 시안 각각 1440×1000·390×844·320×844, 1440/390에서 입력 전후와 05 검토창, 목차 3개 폭; [렌더 상태](../research/2026-09-08/concepts/render-evidence.json) |
| 소스·문서 | JavaScript 문법 검사, `git diff --check`, 새 문서의 로컬 링크, Three.js 3개 공급 파일 SHA256 일치 |

59개 검사는 실제 카탈로그와 DOM/3D 선택 동기화, 전체 일정의 날짜·순서, 잘못된 입력·0kg/RIR0, 두 번째 세트 먼저 완료, 초안 원문 복원, 초기화 취소·다른 키 보존, 감량 검토/적용/되돌림, 좁은 화면, 감소된 모션, 강제 WebGL 실패, 카탈로그 실패/재시도, 쓰기 차단·손상 보존, 실제 WebGL context 손실/복구, 숨김/복귀와 리소스 수 증가 경계를 포함한다.

중간 재실행에서 첫 페이지의 폰트·스크롤 안정화 대기 4초가 초과해 **58/59**였던 이력이 있다. `document.fonts.ready` 이후 스크롤 대상을 확인하고 해당 안정화 대기를 12초로 조정했다. 캔버스 초기화 수정 후 전체 재실행이 위 59/59다. 검사 성공으로 빈 캔버스 캡처를 무시하지 않고 실제 이미지를 별도로 검토했다.

05의 초기 캡처 조사에서는 첫 준비 완료 후 같은 크기의 버퍼 재설정이 4회→0회로 줄어든 것을 계측했다. 원본의 단발성 빈 캡처를 같은 조건에서 재현하지 못했으므로 이것이 유일 원인이라고 단정하지 않는다. 전역 RAF를 지연시킨 진단은 이전 로딩 화면을 캡처해 픽셀 판정에 사용할 수 없었다. 최종 일반 실행의 390px 기본/변경 화면에서 그래프가 표시되는 것은 직접 확인했다.

환경은 headless Chromium과 SwiftShader다. `data-scene-state`는 상태/렌더 통계이며 픽셀 비교가 아니다. 리소스 검사는 보고된 지오메트리/텍스처 개수로 총 GPU 메모리나 성능 보장을 의미하지 않는다. 화면 숨김 검사는 브라우저 조건 주입이며 실제 OS 백그라운드 동작 검증이 아니다. 이번 변경은 웹 파일만 다뤄 Flutter 전체 120개 테스트를 반복하지 않았고, 그 결과는 [앞선 앱 검증 이력](2026-09-08-feature-verification.md)이다.

## 사용자가 확인하는 순서

1. [비교 페이지](http://127.0.0.1:4175/landing/concepts/)에서 각 시안을 연다.
2. 01에서 중량을 바꾸고 3D를 회전·초기화한다.
3. 02에서 다른 프로그램을 선택하고 ‘요일 맞춰보기’로 이동한다.
4. 03에서 요일 수를 맞춘 뒤 시작일을 바꾸고 전체 예정일을 확인한다.
5. 04에서 두 번째 세트부터 완료하고 첫 번째 입력 중 새로고침하여 복원을 확인한다.
6. 05에서 변경 내용 검토→취소→다시 검토→적용→되돌리기를 확인한다.
7. 브라우저 폭을 줄여 같은 버튼과 결과를 읽을 수 있는지 확인한다.

로컬 실행·검사 명령은 [시안 README](../landing/concepts/README.md)를 따른다. 시뮬레이터는 사용하지 않는다. Safari·Firefox·실제 휴대폰 터치/키보드·VoiceOver·실제 GPU·배포 환경은 별도 확인 대상이다.

## 짧은 변경 기록

- 중량 조절에 맞춰 바벨 원판이 바뀝니다.
- 프로그램 선택에 맞춰 실제 구성과 3D 패널이 바뀝니다.
- 요일 선택에 맞춰 달력 블록과 예정일이 바뀝니다.
- 세트를 완료하면 해당 기록 패널과 완료 수가 바뀝니다.
- 새로고침하면 이 시안의 세트 입력이 복원됩니다.
- 감량 적용 전에 변경할 목표를 확인할 수 있습니다.
- 되돌리기로 미래 목표를 원래 값으로 복원합니다.
