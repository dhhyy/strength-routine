### V01 · 자정 후 습관 탭의 날짜 표시

- 재현 조건: 전날 앱을 켠 상태에서 검색 탭으로 이동하고, 앱을 백그라운드로 보내지 않은 채 다음 날 습관 탭에 진입한다.
- 원인: `HomeShell`의 `IndexedStack`이 습관 화면 상태를 유지하지만 탭 전환은 `resumed` 이벤트가 아니다. 기존 날짜 갱신은 초기화·앱 복귀·날짜/체크 동작에만 연결돼 있었다.
- 영향: 전날 날짜와 완료 수가 먼저 표시된다. 기존 자정 체크 보호로 첫 체크가 전날 기록을 바꾸는 문제는 차단돼 있었지만 표시 자체는 갱신되지 않았다.
- 수정: `HabitsScreen.didUpdateWidget`에서 기존 날짜 갱신을 호출한다. 오늘을 보던 경우 새 오늘로 이동하고 의도적으로 선택한 과거 날짜는 유지한다. 커밋 **`b813d85`**.
- 검증: 실제 HomeShell에서 탭을 바꾸는 회귀 1개가 수정 전 실패(다음 날 날짜 0개)했고 수정 후 통과했다. 과거 날짜 선택과 보관 이력의 JSON 전체도 유지된다. [수정 전 증거](../research/2026-09-07/qa/self-check/habits-tab-before.txt), [수정 후 증거](../research/2026-09-07/qa/self-check/habits-tab-after.txt).
- 한계: 자동 자정 타이머는 없다. 앱 복귀·부모 위젯 갱신·사용자 조작을 계기로 날짜를 확인하며 습관 화면의 시간대 변경/시계 역행 전체를 보장하지 않는다.

### V02 · 자정 후 프로그램 시작일 선택기

- 재현 조건: 전날 ‘기록과 일정’ 화면을 열어 시작일을 전날로 둔 뒤 다음 날 날짜 선택기를 연다.
- 원인: 초기 `_start`는 화면 진입 당시 날짜이고 선택기의 `firstDate`는 버튼을 누른 현재 날짜여서 `initialDate < firstDate`가 될 수 있다.
- 영향: 날짜 선택기가 범위 검증 오류로 열리지 않을 수 있다.
- 수정: 선택기 초기 표시일만 허용 범위로 보정한다. 취소 시 기존 시작일을 유지하고 확인 때만 선택일을 반영한다. 기존 실패 재시도 계획은 바꾸지 않는다. 커밋 **`46ef544`**.
- 검증: 다음 날 진입과 주입한 기기 날짜 역행의 2개 회귀가 수정 전 실제 assertion으로 실패했고 수정 후 통과했다. 취소/확인 반영과 기존 시작/실패재시도/복원까지 해당 파일 4개를 함께 통과했다. [수정 전 증거](../research/2026-09-07/qa/self-check/program-date-before.txt), [수정 후 증거](../research/2026-09-07/qa/self-check/program-date-after.txt).
- 한계: 과거 시작일로 새 계획을 만드는 것을 허용할지 금지할지까지 새 정책으로 확정하지 않았다. 주입한 시각을 바꾼 위젯 테스트이며 실제 OS 설정을 바꾼 검증은 아니다.

## 저장·복원을 해석할 때의 구체적 한계

1. **마지막 영구 저장 성공분까지 복원한다.** 실패한 최신 변경은 앱 메모리에 남아 재시도할 수 있지만 프로세스를 종료하면 그 변경의 복원을 보장하지 않는다.
2. **‘손상 원본 보존’은 자동 수리를 뜻하지 않는다.** 잘못된 JSON/스키마를 읽지 않고 오류로 보여주며 정상 파일로 복구한 뒤 재시도하는 테스트다.
3. **운동과 습관은 별도 파일이다.** `training-state.json`과 `habits-state.json`은 각각 저장되고 두 파일의 동시 원자적 백업/복원은 없다. QA도 각각 별도 파일을 사용한다.
4. **세트 목록의 수행 집계는 메모리 상태를 먼저 반영할 수 있다.** 저장 실패 배너를 함께 보여주므로 숫자 변경만으로 파일 저장 성공을 판단하면 안 된다.
5. **원자적 교체 테스트는 OS 장애 주입이 아니다.** 임시 파일 쓰기·flush·rename 코드와 파일 오류를 확인했으나 전원 차단·디스크 용량 고갈·OS 파일 보호·여러 프로세스 동시 쓰기는 실행하지 않았다.
6. **완료 안내는 반복 억제를 검증했다.** 안내 이력 저장 실패 또는 저장 직후 종료 상황에서 알림 전달을 정확히 한 번 보장하는 기능은 아니다.
