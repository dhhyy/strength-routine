# 9/7 기능 분석 · 프로그램과 운동 콘텐츠

관찰일: **2026-09-07 · Asia/Seoul**. 대상: IM01·IM04·IM05·IM11·IM14. [운동 앱 종합 분석](../2026-09-07-fitness-app-analysis.md)의 ID와 우선순위를 유지한다.

읽기 시작점: [기능 분석 정본·공통 기준](../2026-09-07-feature-specification.md).

이 문서는 현재 코드를 읽어 구체화한 **개발 제안**이다. 필드 이름·상태 정책·수용 기준은 논리 설계안이며 확정 요구나 구현 완료가 아니다. 이번 작업에서는 코드·프로그램 데이터·저장 파일을 변경하거나 새 앱 실기 검증을 하지 않았다.

공통 경계는 트레이너의 운동·세트 구성 보존, 사용자 중량·시작일·요일 개인화다. 최근 기록으로 e1RM/TM을 자동 계산하지 않는다. 트레이너 등록 도구와 원격 동기화는 후속 범위다. [공개 프로그램 후보](../../research/2026-09-07/program-candidates.md)는 아직 선정·수록 승인 전이며 세 후보의 제3자 앱 재배포 권한은 UNKNOWN이다.

UI 개발 시 기존 Console v2 토큰·컴포넌트·한글/숫자 폰트 규칙을 적용하고 작은 화면·큰 글자·키보드와 상태별 렌더를 확인한다. 아래 상태는 이를 위한 동작 분석이며 새 시각 디자인을 확정하지 않는다. GWT는 **주어진 상태(Given) → 행동(When) → 관찰 결과(Then)**다.

## IM01 · 첫 실제 프로그램 수록과 지원 형식 검사 · P0/M

**목적:** 일반 실행에서도 사용자가 선택한 실제 프로그램으로 시작·기록·재실행 복원을 끝낸다. **현재와 차이:** [카탈로그](../../assets/programs.json)는 `schemaVersion: 1`, 빈 `programs`다. [로더](../../lib/app/training_controller.dart)의 `loadBundledPrograms`는 스키마·중복 프로그램 ID와 모델 생성을 검증한다. 선택→설정→`PlanReviewScreen`→저장 흐름은 이미 있다. 새 범위는 검토한 콘텐츠와 누락·미지원 처방을 식별하는 검사다.

**정상 흐름 제안**

1. 운영자가 후보·원본 버전·변형·수록 사용 범위를 확인하고 원작과 앱 데이터의 대응표를 준비한다. 이는 트레이너 등록 UI 개발과 별개다.
2. 배포 전 검사가 주차/세션/운동/세트 식별자, 누락·중복·필수 입력, 지원 처방과 단위를 검사한다. 통과한 콘텐츠만 카탈로그에 포함한다.
3. 사용자는 상세·입력·기존 결과확인을 거쳐 시작한다. 시작 당시 프로그램·목표·일정을 보존하고 이후 카탈로그 변경으로 덮어쓰지 않는다.

**데이터 제안**

- 필수: 현행 프로그램 필드에 대응하는 원작 데이터, 콘텐츠 출처 URL·작성자·원본 버전/변형·확인일·수록 사용 범위 근거. 사용 범위 근거는 운영 관리 정보이며 소비자에게 모두 노출할 필요는 없다.
- 필수 검사 결과: 프로그램 ID/버전, 실패 위치(주차·세션·세트 또는 필드 경로), 오류 종류, 지원 여부. 카탈로그 스키마와 운동 콘텐츠 버전은 별개다.
- 선택: 원작 변경 메모, 검토자·검토일, 콘텐츠 해시. 출처의 정보가 없으면 추정값을 채우지 않는다.

**상태 제안**

- 빈 상태: 현행 ‘등록된 프로그램 없음’을 유지한다. QA 합성 프로그램을 일반 카탈로그의 대체 콘텐츠로 표시하지 않는다.
- 로딩: 현재 목록 로딩 표시를 재사용한다. 프로그램을 읽는 중에는 미확인 데이터를 시작 대상으로 제공하지 않는다.
- 실패: 배포 전 오류는 위치·원인을 운영자에게 알린다. 런타임 목록 실패는 재시도를 제공하고 저장된 활성 계획·기록은 보존한다.
- 취소: 결과확인에서 나가면 새 계획을 시작하지 않는다. 별도로 이미 저장한 최근 기록은 취소 대상이 아니다.
- 이탈: 시작 저장 성공 후에는 기존 복원 경로를 사용한다. 저장 실패 시 같은 계획의 재시도를 유지하며 성공으로 안내하지 않는다.

**선행·영향:** 후보·버전·사용 범위 결정이 필요하다. 표현 불가능한 규칙이 있으면 **IM14의 해당 최소 확장을 IM01 선행으로 승격**한다. 주요 영향은 `assets/programs.json`, [모델](../../lib/domain/training_program.dart), 로더, [프로그램 흐름](../../lib/program_screen.dart), [흐름 테스트](../../test/program_flow_test.dart)다.

**GWT 수용 기준 제안**

- G 지원되는 검토 완료 콘텐츠가 있음 → W 일반 앱에서 시작·세트 기록 후 프로세스 종료/재실행 → T 같은 프로그램 버전·일정·목표·실제가 복원된다.
- G 콘텐츠에 미지원 처방 또는 참조 누락이 있음 → W 배포 전 검사 → T 정확한 위치와 사유로 수록이 중단되며 고정 반복·중량으로 대체되지 않는다.
- G 이전 버전으로 시작한 계획이 있음 → W 새 카탈로그 버전을 읽음 → T 활성/보관 계획의 원래 운동·세트·목표·실제가 그대로다.

**미결정 정책:** 첫 후보·정확한 변형·원작 버전, 콘텐츠 수록 조건, 검토 책임자, 원작 업데이트 제공 방식. 공식 공개 여부를 수록 허락으로 간주하지 않는다.
**참고:** 지원 검사·저장 전 확인의 참고는 [Liftosaur REST API · PROG10](https://www.liftosaur.com/doc/api). 우리 앱의 데이터 계약은 별도로 검증한다.

## IM04 · 프로그램 적합성 요약 · P1/M

**목적:** 사용자가 시작 전에 필요한 장비·일정·입력 조건을 이해하고 프로그램을 고른다. **현재와 차이:** [목록/상세](../../lib/program_screen.dart)는 제목·트레이너 검색, 기간·주당 횟수, 설명과 전체 운동 구성을 제공한다. [모델](../../lib/domain/training_program.dart)에는 목표·대상 수준·필수 장비·예상 시간 메타데이터가 없다. 상세의 판단 정보와 선택적 필터를 보강한다.

**정상 흐름 제안**

1. 목록 카드에는 기간·주당 횟수와 제공된 핵심 조건을 표시한다. 작은 카탈로그는 설명 카드부터 만들고 필터 수를 늘리지 않는다.
2. 사용자가 조건을 선택하면 일치 결과와 적용한 조건을 보여준다. 상세 상단에서 장비·대상·기간·필요 기록을 확인하고 주차별 구성을 펼쳐 본다.
3. ‘시작 설정’에서 상세에 안내한 것과 같은 필수 입력을 요구한다. 장비가 맞지 않거나 기록이 없으면 다른 프로그램 탐색/입력으로 연결한다.

**데이터 제안**

- 필수: ID/버전·작성자·기간·세션 일정, 메타데이터별 제공/미제공 상태. 현행 주당 횟수는 세션 데이터에서 계산하여 중복 값의 불일치를 피한다.
- 조건부 필수: 필터로 제공할 항목의 검토된 값(예: 필수 장비 식별자). 선택한 필터에 필요한 정보가 없으면 적합하다고 판정하지 않는다.
- 선택: 작성자 제공 목표·대상 수준·시간 범위·소개. 필요한 최근 리프트 기록과 비율 기준값은 현행 설정의 `mainLift`/`load.lift`와 동일한 계약에서 도출한다.

**상태 제안**

- 빈 상태: 전체 카탈로그 0건과 조건 결과 0건을 나누고, 후자는 조건별 해제/모두 해제를 제공한다.
- 로딩: 목록 로딩과 메타데이터 미제공을 다른 상태로 표현한다. 외부 추천 서비스를 필수 의존성으로 만들지 않는다.
- 실패: 목록 오류에는 재시도, 일부 설명 미제공에는 ‘정보 없음’을 제공한다. 제목으로 수준·장비를 추정하지 않는다.
- 취소: 필터 해제는 검색 조건만 바꾼다. 상세 뒤로 가기는 검색어·필터·목록 위치를 유지한다.
- 이탈: 탭 이동 후 탐색 조건 유지 범위를 정한다. 시작하지 않은 탐색이 활성 계획이나 실제 기록을 변경하지 않는다.

**선행·영향:** IM01의 콘텐츠 검토와 동일한 메타데이터 공급 경로가 필요하다. 필수 입력 판정은 설정과 공유한다. 모델·카탈로그·프로그램 화면/테스트가 영향 대상이고 IM14로 일정 구조가 달라지면 횟수 요약도 함께 바뀐다.

**GWT 수용 기준 제안**

- G 장비 정보가 있는 프로그램과 없는 프로그램이 있음 → W 장비 조건 적용 → T 미제공 항목은 일치로 분류되지 않고 사용자가 그 이유를 확인할 수 있다.
- G 적용 조건의 결과가 0건 → W 조건을 해제 → T 해당 조건이 제거되어 목록을 다시 탐색할 수 있고 기존 계획은 바뀌지 않는다.
- G 프로그램에 최근 기록/비율 기준값이 필요함 → W 상세에서 준비 정보를 보고 설정 진입 → T 같은 리프트·같은 입력 목적을 요구하며 미입력 때문에 원작 운동을 잘라내지 않는다.

**미결정 정책:** 수준/목표 분류, 장비 조건의 일치 규칙, 미제공 항목의 별도 노출 방식, 탐색 조건의 재실행 보존 여부. 적합성은 운동 효과나 안전성을 보증하는 점수로 만들지 않는다.
**참고:** [Boostcamp Program Selector · PROG01](https://www.boostcamp.app/program-selector), [프로그램 목록 · PROG02](https://www.boostcamp.app/programs/all). 필터 원칙만 참고하며 추천 가중치를 추정하지 않는다.

## IM05 · 시작 설정 초안과 중량 기준 설명 · P1/M

**목적:** 입력을 반복하지 않고 최근 실제 기록·프로그램 기준값·계산된 목표의 관계를 이해한 뒤 시작한다. **현재와 차이:** [설정 화면](../../lib/program_screen.dart)의 시작일·요일·기준값·증량 단위는 화면 상태다. 최근 기록은 입력 후 즉시 저장한다. `PlanReviewScreen`은 이미 날짜·운동·목표를 보여준다. 새 범위는 설정 초안 저장/복원과 처방·계산 근거 설명이다.

**정상 흐름 제안**

1. 동일 프로그램 ID/버전의 미완료 설정을 복원하고 사용자가 계속 수정한다. 최근 기록은 검증된 실제 정보, 기준 중량은 프로그램용 명시 입력으로 각각 설명한다.
2. 기존 미리보기에서 수동/고정 중량/기준값 비율을 구분한다. 비율은 원작 비율·사용자 기준 kg·계산값·반올림 결과를 펼쳐 확인한다.
3. ‘이 일정으로 시작’ 저장과 해당 설정 초안 정리를 한 저장 작업으로 처리한다. 실패 시 입력과 재시도 대상을 유지하고 완료 안내는 저장 성공 후 표시한다.

**데이터 제안**

- 필수 초안: 프로그램 ID/버전, 시작일·요일, 증량 단위/기준값의 입력 문자열, 초안 스키마·수정 시각. 입력 중인 빈값·잘못된 문자열도 초안으로 보존하되 계획 생성에는 사용하지 않는다.
- 필수 설명: 원래 처방 종류/값, 기준값 출처와 단위, 적용한 증량 간격, 반올림 전후 값. 최근 기록을 읽었다는 이유로 `userEntered` 기준값을 자동 추정하지 않는다.
- 선택: 마지막 입력 위치·콘텐츠 해시. 최근 기록은 기존 저장 목록을 재사용하며 검증되지 않은 초안 입력을 실제 기록으로 올리지 않는다.

**상태 제안**

- 빈 상태: 해당 버전의 초안이 없으면 현재 빈 입력으로 시작한다. 필요한 기준값을 모르면 설명/기록 입력으로 안내하며 임의 숫자로 채우지 않는다.
- 로딩: 복원 완료 전에 빈 기본값으로 저장해 기존 초안을 덮어쓰지 않는다. 시작은 필요한 검증과 복원 이후 허용한다.
- 실패: 초안 저장 실패 시 화면 입력·미저장 상태·재시도를 유지한다. 지원하지 않는 초안 버전은 원본을 보존하고 새 설정 시작을 별도로 선택하게 한다.
- 취소: 결과확인에서 설정으로 돌아오면 입력을 유지한다. ‘설정 초안 버리기’는 해당 초안만 지우고 이미 저장한 최근 기록이나 현재 계획을 삭제하지 않는다.
- 이탈: 변경 입력을 직렬 저장한다. 재진입 시 과거가 된 시작일/바뀐 콘텐츠 버전을 재검증하고 사용자 확인 없이 오늘 날짜나 새 버전으로 바꾸지 않는다.

**선행·영향:** IM01의 기준 중량 의미/처방 설명과 초안 수명 정책이 필요하다. [앱 상태](../../lib/domain/training_program.dart), [컨트롤러](../../lib/app/training_controller.dart), [파일 저장](../../lib/data/local_training_store.dart), 프로그램 화면·저장/흐름 테스트에 영향. 기존 저장 파일 이행과 마지막 입력 저장 순서를 검증한다.

**GWT 수용 기준 제안**

- G 일부 입력이 유효하지 않은 설정 초안이 기기에 저장됨 → W 앱 종료/재실행 후 같은 버전 설정 열기 → T 원문 입력이 복원되고 오류 필드는 시작 전에 다시 검증된다.
- G 명시 기준값과 비율 처방이 있음 → W 결과확인에서 계산 근거 열기 → T 원작 비율·기준·간격·실제 목표가 일치하고 최근 반복 기록으로 e1RM이 생성되지 않는다.
- G 시작 저장이 실패함 → W 같은 계획 저장 재시도 후 재실행 → T 한 계획만 활성화되고 이전 계획의 중복 보관이 없으며 성공한 시작의 초안만 정리된다.

**미결정 정책:** 초안 한 건/프로그램별 보관, 저장 시점·만료, 오래된 시작일 처리, 기준값의 프로그램별 의미·단위·반올림 규칙. 현재 고정 중량도 장비 간격으로 반올림되므로 원작과 맞는지 콘텐츠별 확인이 필요하다.
**참고:** [Fitbod My Plan · GUIDE01](https://help.fitbod.me/hc/en-us/articles/34336407191191-My-Plan), [Liftosaur REST API · PROG10](https://www.liftosaur.com/doc/api). 입력 목적·원래 처방/계산 결과 구분을 참고한다.

## IM11 · 실제 운동 검색과 수행 가이드 · P1/L

**목적:** 검색 탭과 운동 기록에서 해당 종목의 검토된 설명을 찾아 입력 맥락을 유지한다. **현재와 차이:** [SearchScreen](../../lib/search_screen.dart)은 입력되지 않는 검색 모양, 고정 필터/6개 종목이다. [ProgramExercise](../../lib/domain/training_program.dart)는 프로그램 내부 ID·이름·선택 `MainLift`만 가진다. 실제 검색 데이터·공통 종목 연결·설명 열기가 새 범위다.

**정상 흐름 제안**

1. 검토된 운동 사전을 읽고 운동명·별칭·장비 조건으로 검색한다. 이름이 비슷한 장비/변형은 구분해서 표시한다.
2. 종목 상세에서 장비·짧은 수행 설명·검토된 안내를 읽는다. 승인된 매체가 있을 때만 추가로 열며 외부 링크라면 이동을 표시한다.
3. 운동 기록의 해당 종목에서 같은 가이드를 열고 닫는다. 돌아오면 기존 초안·편집 대상·기록 화면 위치가 유지된다.

**데이터 제안**

- 필수: IM06과 공유할 공통 종목 ID, 표시 이름, 장비/변형 식별, 설명 제공 상태. 프로그램 내부 운동 ID는 별도로 유지하고 공통 ID를 참조한다.
- 가이드 제공 시 필수: 안내 버전·출처/작성 주체·검토 상태·내용 또는 사용 가능한 링크. 프로그램 전용 수행 지시와 공통 운동 설명은 구분한다.
- 선택: 검색 별칭·부위, 승인된 영상/이미지, 검토일. 매체 없이도 텍스트 검색·설명·기록이 가능하게 한다.

**상태 제안**

- 빈 상태: 사전 미등록과 검색 0건을 구분한다. 미등록 프로그램 운동에는 이름을 보존하고 ‘설명 준비 중’으로 표시한다.
- 로딩: 사전/가이드 로딩이 현재 세트 입력을 막지 않게 한다. 로컬 텍스트와 외부 매체의 로딩 상태를 분리한다.
- 실패: 설명·영상 실패는 해당 영역에서 재시도/닫기를 제공한다. 실패 때문에 세트 초안을 지우거나 운동 기록을 종료하지 않는다.
- 취소: 필터 취소는 검색 조건만 변경한다. 가이드 닫기는 실제 세트 완료·제외·운동 교체로 해석하지 않는다.
- 이탈: 가이드 전환 전 입력을 기존 초안 경로로 저장한다. 외부 매체에서 복귀할 때도 재입력을 요구하지 않도록 확인한다.

**선행·영향:** IM06의 공통 운동 식별 계약과 콘텐츠 공급/검토 경로가 필요하다. 검색 화면·모델·프로그램 데이터·[운동 기록 화면](../../lib/workout_screen.dart), 새 사전 로더/가이드 컴포넌트와 해당 테스트가 영향 대상이다. 파일 분할은 구현 때 결정한다.

**GWT 수용 기준 제안**

- G 같은 이름 계열의 서로 다른 장비/변형이 있음 → W 별칭 검색 후 종목 열기 → T 구분된 종목과 대응 설명을 표시하고 이름만으로 기존 실제 기록을 병합하지 않는다.
- G 세트 초안을 입력한 상태 → W 가이드 열기·닫기 또는 외부 링크 복귀 → T 입력·대상 세트가 유지되고 완료/제외 상태는 변하지 않는다.
- G 종목 가이드가 없거나 매체를 읽지 못함 → W 해당 가이드 열기 → T 미제공/실패를 구분하고 닫은 뒤 운동 기록을 계속할 수 있다.

**미결정 정책:** 사전 범위·별칭 표준, 설명 검토 책임, 매체 수록/외부 연결 범위, 공통 안내 갱신과 시작 당시 프로그램 지시 보존 정책. 운동 교체 기능이나 코치 채팅은 포함하지 않는다.
**참고:** [플랜핏 운동 가이드 · KOR02](https://planfit.ai/ko/exercise), [Caliber Workout App · GUIDE04](https://caliberstrong.com/workout-app/). 공개 가이드 구조를 참고하며 설명·매체를 자동 복제하지 않는다.

## IM14 · 선택한 콘텐츠에 필요한 프로그램 표현 확장 · P2/L, 조건부 선행

**목적:** 선정 원작의 규칙을 손실 없이 표현하고 이미 저장된 프로그램·목표·실제 기록과 함께 읽는다. **현재와 차이:** [현행 모델](../../lib/domain/training_program.dart)은 유한 주차, 매주 같은 세션 수와 순서, 양의 고정 반복, 수동/고정 kg/명시 기준값 비율을 지원한다. AMRAP·반복 범위·진급·무한 주기·주차별 횟수 변화는 현재 계약 밖이다. 범용 스크립트 엔진을 선행 개발하자는 항목이 아니다.

**정상 흐름 제안**

1. 선정 원작의 규칙별로 현행 지원/미지원/해석 불명확을 기록한다. 미지원 규칙은 조용히 단순화하지 않고 콘텐츠 결정자에게 차이를 보여준다.
2. 필요한 표현만 명시 타입으로 추가하고 원작 의도·입력·종료/실패 조건을 정한다. 작가가 처방한 변화와 앱이 독자적으로 구성하는 추천은 분리한다.
3. 검증용 원작 사례로 미리보기→실제 기록→재실행을 확인한다. 규칙 실행이 필요하면 중복 실행 방지와 적용 근거까지 확인한 후 수록한다.

**데이터 제안**

- 필수: 콘텐츠/저장 스키마 버전, 지원 능력과 검증 결과, 원작 버전/규칙의 출처, 저장 당시 처방 및 계산 결과. 기존 식별자와 실제 기록 연결을 보존한다.
- 조건부 필수: 선정 규칙에 필요한 반복 목표 타입·범위·세트 유형·주차별 일정·진급 입력과 결과. 종료 조건이 없는 주기를 임의 기간으로 잘라 완성본이라고 표시하지 않는다.
- 선택: 규칙 설명·변경 메모·추적용 계산 근거. 단계적 확장에서는 실제 사용하는 타입만 모델에 포함한다.

**상태 제안**

- 빈 상태: 확정 콘텐츠에 필요한 확장이 없으면 현행 형식을 유지한다. 알 수 없는 규칙을 기본 고정 반복으로 채우지 않는다.
- 로딩: 저장 파일 이행/처방 검증이 끝나기 전에 계산된 것처럼 미리보기를 보여주지 않는다.
- 실패: 모르는 타입·잘못된 범위·누락 참조·저장 버전 오류는 명시적으로 중단한다. 저장 원본을 보존하고 가능한 복구/재시도 경로를 알린다.
- 취소: 새 버전 미리보기를 닫으면 현재 활성/보관 계획을 변경하지 않는다. 이행 실패·취소로 기존 파일을 삭제하지 않는다.
- 이탈: 재실행해도 이행·규칙 처리가 중복 적용되지 않아야 한다. 이미 저장한 목표는 최신 원작으로 재계산하지 않는다.

**선행·영향:** 선정 콘텐츠의 정확한 계약이 먼저다. 미지원 규칙이 첫 수록을 막으면 해당 확장만 **IM01보다 앞선 P0 작업**이다. 모델·카탈로그 로더·파일 이행·설정/미리보기·기록·달력/요약·기존 테스트 전반이 영향 대상이며 실제 범위는 선택 규칙으로 좁힌다.

**GWT 수용 기준 제안**

- G 선정 콘텐츠에 미지원 규칙이 있음 → W 수록 적합성 검사 → T 필요한 확장과 해석 미결정 사항을 표시하며 임의 공식/운동·세트로 대체하지 않는다.
- G 이전 저장 버전의 활성/보관 계획과 실제 기록이 있음 → W 새 앱에서 읽고 재실행 → T 원래 식별자·처방·목표·실제가 보존되고 허용한 이행만 한 번 반영된다.
- G 선택 규칙이 새 타입으로 지원됨 → W 원작에서 확인한 정상/경계/누락 입력 사례 실행 → T 원작 규칙과 결과가 일치하고 누락 입력은 자동 추정 대신 필요한 입력으로 표시된다.

**미결정 정책:** 최초 확장 타입, 반복/진급 해석, 무한 주기의 실행 단위, 결과 적용 시점, 오래된 앱의 새 스키마 처리. 원작 설명이 모호하면 인터뷰/콘텐츠 확인이 필요하며 이번 조사로 수치·공식을 확정하지 않는다.
**참고:** [Liftoscript · PROG09](https://www.liftosaur.com/doc/liftoscript), [원작 후보와 제한](../../research/2026-09-07/program-candidates.md). 규칙 표현의 참고 자료이며 소비자 스크립트나 자동 e1RM의 도입 근거가 아니다.
