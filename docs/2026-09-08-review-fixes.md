### 한 문장씩 확인할 변경

- 완료 저장에 실패해도 기본 저장·다음 세트·전용 재시도가 같은 자동 휴식 동작으로 이어진다.
- 기존 완료 수정이나 초안 저장·제외·닫기는 새 자동 휴식을 시작하지 않는다.
- 같은 관리자 화면에서 여러 버전을 저장해도 이전에 사용한 버전을 다시 쓰지 못한다.
- 수정이 필요한 버전 오류는 편집으로 돌아가고 일시적인 파일 오류는 저장을 재시도한다.
- 느린 관리자 저장 중에도 원본 파일을 유지하고 중복 저장을 막는지 시험한다.
- 공용 카드 여백이 기존 디자인 토큰을 직접 사용한다.
- 현재 기능·저장 형식·남은 운영 작업을 하나의 상태표에서 확인할 수 있다.
- 실제 기기용 실패·버전·지연 확인 절차를 추가하고 준비 자료와 미실행 상태를 표시했다.

### 오류 재현과 회귀의 의미

SF01의 수정 전 단일 재현은1개 실패했고, 확장된17개 시험에서는12개 통과·5개 실패했다. 최초 완료의 기본 저장/다음 세트 누락뿐 아니라, 복원 초안의 완료 쓰기가 실패한 뒤 닫기 저장도 실패하고 전용 재시도를 누를 때 취소한 휴식이 시작되는 경로를 확인했다. 성공한 실제값을 기록 저장소에서 다시 읽고 타이머 저장 시작 횟수·종료 시각을 함께 검사한다. 기능 회귀는17개 자동 시작 시험을 포함한6개 파일63개이며 별도 렌더 재실행 수를 합산하지 않는다.

SF02는 저장 성공 때만 사용 버전을 집합에 추가한다. 실패한 버전을 미리 차단하지 않으며 프로그램 ID가 다르면 같은 버전을 사용할 수 있다. 초기 이력 유무와 같은 편집기의 연속 저장, 원문 보존, 영구 검증 오류와 파일 오류의 다른 경로를 검사한다. 관리자 저장 계층의 기존 불변 이력 방어도 유지한다.

SF03의 예전 방식은 실시간50ms 뒤 `pumpAndSettle`에 의존했다. 새 방식은 최대10초 동안 화면의 저장 상태와 실제 쓰기 완료를 관찰하며, 실제 I/O를 진행시키는 시간과 Flutter 화면 전환 시간을 모두 진행시킨다. 시험 전용 장벽으로 부모 디렉터리 생성 직전 쓰기를 붙잡고100ms 뒤에도 이전 JSON과 저장 잠금을 확인하며, 별도250ms 뒤 장벽을 해제한다. 제품 저장소의 직렬화·임시 쓰기·rename 경로는 대체하지 않는다. 상세 실패 이력과 최종 시험 결과는 관리자 명세에 남긴다.

중간 실패 로그를 지우거나 제품 회귀로 일괄 해석하지 않는다. 휴식 시험의 안내 대화상자 닫기 누락, 관리자 시험의 프로그램 ID finder 범위·실제 I/O/route 전환 대기는 시험 도구 문제로 구별했다. 기존 assertion을 없애 통과시키지 않았다. [기존 검토 증거](../research/2026-09-08/review/)는 수정 전 상태 그대로 남겨 둔다.

### 화면·코드 검토

번들 한국어·숫자 글꼴을 로드한 headless Flutter 렌더를 사용했다. 휴식 실패/복구375×900에서 입력값·오류·재시도 버튼·90초 타이머가 읽히고 겹치지 않는 것을 직접 확인했다. 공용 여백은 백업 화면375×900·큰 글자1.8배에서 검토했다. 관리자 최종 이미지와 확인 범위는 해당 수정 명세에 연결한다. 모든 기기·글자 크기·접근성 서비스를 확인했다는 뜻은 아니다.

관리자 [버전 충돌 화면](../research/2026-09-08/review-fixes/admin/render/version-conflict-mobile.png)에서는 오류 원문과 전체 복귀 버튼을375px에서 직접 확인했다. 저장 모델/스키마·패키지·기본 프로그램5개·랜딩 코드는 이번 수정 대상이 아니다. Flutter 자동 시험과 headless 렌더를 사용했으며 Simulator·실제 기기·내부 네이티브 앱·웹 브라우저·배포 빌드는 이번 단위에서 실행하지 않았다. 이전 iOS 빌드/랜딩 검증을 이번 실행으로 재기록하지 않는다.
