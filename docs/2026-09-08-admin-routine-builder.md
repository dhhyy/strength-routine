# 9/8 · 관리자 루틴 생성 기능

현재 계약: 기본 반복 생성기와 주차·세트 정밀 편집을 모두 제공한다. 이후 휴식·템포·슈퍼세트·AMRAP 및 반복 범위·세트 종류·일괄 수정·보관·버전 복구까지 연결했다. [정밀 편집](2026-09-08-admin-precise-editor.md), [고급 처방](2026-09-08-advanced-prescriptions.md), [관리자 확장 LC04](2026-09-08-local-admin.md)를 함께 읽는다. 아래 ‘한 주 반복’ 제한은 **기본 생성기 경로만**의 제한이다.

전체 현재 상태·파일 형식은 [상태표](2026-09-08-remaining-work.md), 연속 버전 저장 오류의 수정·검증은 [안정화 기록](2026-09-08-review-fixes.md)을 따른다. 첫 기본 생성120개·정밀 편집189개·고급 처방252개는 각 단계 검증 이력으로 보존하며 새 기능 결과로 합산하지 않는다. 실제 내부 앱/기기 확인은 별도다.

## 확정 요청과 구현 방식

사용자가 직접 생성 기능을 **관리자만** 사용하도록 요청했다. 트레이너는 운영자 1명이므로 회원별 트레이너 가입·심사·마켓플레이스는 만들지 않는다. 일반 사용자는 등록된 프로그램을 선택하고 중량·날짜·요일을 맞춘다.

서버 인증이 없는 현재 구조에서는 **별도 내부 빌드**를 기본으로 적용했다. 사용자에게 별도 빌드/서버 로그인 선택을 질문했으며 답변 전 추천안을 가정한 것이다. `lib/main.dart` 소비자 진입점의 import graph에는 관리자 코드가 없다. `lib/main_admin.dart`로 실행하는 도구를 운영자의 신뢰할 수 있는 Mac에서만 사용한다.

기본 macOS 제품명·번들 ID는 동일하므로 별도 설치 앱을 생성하는 방식은 아니다. 내부 빌드 뒤 사용자 배포물을 만들 때 반드시 `-t lib/main.dart`로 다시 빌드한다. 같은 출력 경로의 관리자 실행파일을 잘못 배포하지 않게 구분해 보관한다.

이것은 서버 관리자 계정 인증이 아니다. 내부 실행파일을 가진 사람은 사용할 수 있으므로 공개 배포하면 안 된다. 앱 속 비밀 탭·공유 PIN·로컬 관리자 스위치를 권한 확인처럼 사용하지 않는다. 원격 관리자 접근이 필요해지면 서버 인증·권한 검사·감사 로그가 선행돼야 한다.

## 현재 편집 진입점

| 진입 버튼 | 실제 동작 |
|---|---|
| 카탈로그의 `정밀 편집` | 선택한 프로그램의 모든 주차·세션·운동·세트를 원래 ID·작성자·버전과 함께 불러온다. 같은 프로그램을 개정하려면 새 버전을 입력한다. |
| 카탈로그의 `복제해서 만들기` | 전체 구성을 복사하고 프로그램 ID는 비우며 버전은 `1`로 둔다. 운영자가 새 ID를 입력해야 저장할 수 있다. 기존 카탈로그 항목은 그대로 유지한다. |
| `새 정밀 프로그램` | 최소 주차·세션·운동·세트 구조에서 새 프로그램을 작성한다. 이름·ID·반복 등 미입력 값은 운영자가 채운다. |
| `정밀 초안 이어서` | 관리자 기기에 저장한 마지막 정밀 초안을 이어서 편집한다. 카탈로그 원본에서 다시 불러와 초안을 덮지 않는다. |
| 기본 생성기의 `주차·세트별로 편집` | 기본 입력을 먼저 검증하고, 생성 가능한 결과를 각 주차·세트가 독립된 정밀 초안으로 펼친다. `3.` 같은 미완성 입력은 오류를 표시하며 그대로 유지한다. |

정밀 초안은 한 개를 유지한다. 다른 프로그램을 열거나 복제·새 작성으로 초안을 바꿀 때 기존 정밀 초안이 있으면 `정밀 초안을 바꿀까요?` 확인을 표시한다. 취소는 기존 원문을 유지하고, `초안 바꾸기`를 확인해도 **새 초안의 파일 저장이 성공한 뒤에만 교체·진입**한다. 저장된 카탈로그와 기본 생성기 초안은 이 조작으로 바뀌지 않는다.

`주차·세트 정밀 편집`에서는 주차와 세션을 선택하고 운동·세트의 순서·추가·삭제, 주차 복사·덮어쓰기·삭제를 조절한다. 각 세트의 반복·RIR·필수 여부·중량 방식·값·기준 리프트를 따로 편집한다. 같은 운동의 다른 세트나 다른 주차에 값을 자동 적용하지 않는다. 입력·복사·구조 변경은 현재 편집 세션의 최대 50단계 `되돌리기`·`다시 실행`으로 복구하며, 실행 취소 스택 자체는 재실행 시 복원하지 않는다.

정밀 편집에는 세트별 휴식 0~3600초 또는 미지정, 4구간 템포, AMRAP 여부를 추가했고, 운동에는 같은 세션에서 연속된 두 운동 이상의 슈퍼세트 그룹을 지정한다. AMRAP의 반복 수는 기준값이며 실제 완료의 최소 조건이 아니다. 그룹의 세트 수가 달라도 존재하는 세트를 라운드별로 교차한다. 새 값은 원문 초안·복사·undo·검토·확정·내보내기에 포함한다. 기본 반복 생성기는 이 고급 입력을 직접 제공하지 않으므로 기본 결과를 `주차·세트별로 편집`으로 연 뒤 조정한다.

`변경 검토` → 전체 구성과 교체 여부 확인 → `검토한 프로그램 저장` 순서로 카탈로그에 반영한다. 이미 같은 ID가 있으면 다른 버전이 필요하다. 프로그램 복제는 새 ID를 만드는 시작 경로이며, 아직 ID가 비어 있는 복사본을 자동 등록하지 않는다. 저장 전 편집은 초안에만 반영된다.

## 기본 반복 생성기의 실제 동작

1. 프로그램 ID·이름·버전·설명·기간을 입력한다.
2. 주간 세션을 추가하고 세션마다 운동을 입력한다.
3. 각 운동의 안정적인 ID·이름·메인 리프트 여부·세트·반복·RIR·중량 방식을 정한다.
4. 생성 요청 시 모든 필드를 검증하고 동일 주간 구성을 지정한 기간만큼 반복한다.
5. 생성된 모든 주차·세션·운동의 구성을 확인한다.
6. 확인 버튼을 눌러 관리자 로컬 카탈로그에 저장한다.
7. 카탈로그를 JSON 파일로 내보내고 사용자 앱 번들에 반영한다.

입력 중인 원문은 별도의 관리자 파일에 저장한다. 앱을 다시 열면 `3.` 같은 미완성 입력도 돌아오지만, 생성 시에는 올바른 정수가 필요하다. 파일을 읽지 못하면 빈 초안으로 덮어쓰지 않고 재시도를 표시한다. 저장 실패 시 최신 입력을 유지하고 실패 상태와 재시도를 제공한다. 검토한 프로그램의 저장은 파일 쓰기가 성공한 뒤 카탈로그 목록을 교체하므로 실패를 성공한 새 버전으로 표시하지 않는다.

## 기본 생성 계약과 정밀 편집의 차이

다음 표는 기존 **기본 반복 생성기**의 입력 계약이다. 정밀 편집기는 기존 소비자 프로그램을 보존하기 위해 ID 문자열을 소급해서 slug로 바꾸지 않으며, 세트마다 서로 다른 처방을 갖는다. 두 입력기를 같은 원문 형식으로 축소하지 않는다.

| 입력 | 계약 |
|---|---|
| 프로그램·운동 ID | 영문 소문자/숫자/밑줄/하이픈, 1~80자; 같은 운동은 세션·주차에 걸쳐 같은 ID·이름·mainLift 유지 |
| 메타데이터 | 이름 1~80자, 버전 1~30자, 설명 1~2000자 |
| 기간·빈도 | 1~52주, 매주 같은 1~7개 세션; 사용자가 시작할 때 실제 요일 선택 |
| 운동·세트 | 세션당 1~20종목, 종목당 1~10세트, 세트당 1~100회; 같은 종목 내 모든 세트에 입력한 처방 적용 |
| RIR | 미지정 또는 0~10의 유한한 수 |
| 중량 | 운동 시 직접 입력 / 양수 고정 kg / 명시한 메인 리프트 기준 작업중량의 양수 비율 |
| 동일 프로그램 ID | 새 버전을 입력해야 관리자 카탈로그 교체 가능; 미리보기에서 교체를 알림 |

숫자 범위는 데이터/편집기 제한이며 권장 운동량이 아니다. 기본 생성기는 목표에 맞는 세트나 강도를 추정하지 않고 한 주의 처방을 전체 기간에 반복한다. **주차마다 다른 구성은 이제 정밀 편집 화면에서 작성할 수 있으므로 JSON을 직접 편집할 필요가 없다.** 초기 카탈로그의 서로 다른 5개 프로그램은 자동 개정하지 않는다.

정밀 편집도 최종 저장 시 1~52주, 매주 같은 1~7개 세션, 세션당 1~20종목, 운동당 1~10세트, 반복 1~100회, RIR 미지정 또는 0~10 범위를 검증한다. 초안에서 주차별 세션 수가 달라져도 원문을 유지하지만 모든 주차의 수를 맞추기 전에는 카탈로그 저장을 막는다. 비율 처방의 기준 리프트는 각 세트에 따로 지정하며 운동의 메인 리프트 분류와 달라도 된다.

정밀 편집은 휴식·템포·슈퍼세트·AMRAP 외에도 반복 하한/상한, 작업/워밍업/드롭 종류, 운동/세션/주차/프로그램 범위의 한 필드 일괄 수정을 지원한다. 카탈로그 보관/복원과 불변 버전 이력의 새 버전 초안 복구는 [LC04](2026-09-08-local-admin.md)를 따른다. 영구 삭제·원격 게시 롤백·서버 로그인·온라인 게시/취소·무한 주기·자동 진급/증량은 별도 범위다. 명시 처방 편집과 기록 기반 자동 엔진을 구분한다.

메인 리프트 지정은 사용자 시작 시 최근 기록을 요구하게 한다. 기준 비율은 1RM 자동 추정이 아니며 관리자는 프로그램 설명에 기준 중량의 뜻을 명시해야 한다.

## 저장과 사용자 반영

- 관리자 작업: 앱 지원 디렉터리의 `strength-admin/workspace.json`.
- 관리자 작업 형식: **v1~v4 읽기; 추가 처방·보관·버전 이력이 있으면v4, 고급 처방/고급 원문만 있으면v3, 그 외v2 쓰기**. 기본 `draft`를 보존하고 nullable `detailedDraft`를 별도로 저장한다. v1의 미완성 기본 초안을 자동 생성·확장하지 않는다.
- 내보내기: 그 디렉터리 아래 `admin-export/programs.json`.
- 내보내는 형식: `programs` 목록과 카탈로그 `schemaVersion`을 사용하며 **내보낼 프로그램에 추가 처방이 있으면3, 고급 처방만 있으면2, 기본은1**이다. 보관 ID를 제외한 목록만 내보내며 소비자 reader는1~3을 지원한다. 구 envelope에 미지원 새 필드가 있으면 오류로 처리한다.
- 첫 관리자 실행에서는 현재 번들 5개를 초기 카탈로그로 읽는다.
- 기존 관리자 작업 파일이 있으면 그 작업을 우선 복원한다.
- 내보내기는 온라인 게시가 아니며 사용자 기기의 계획을 직접 바꾸지 않는다.
- 소비자 카탈로그는 프로그램 전체 스냅샷을 시작할 때 저장하므로 번들 교체가 기존 계획을 다시 계산하지 않는다.

사용자 운동 파일은 **v1~v6을 읽고, 복원 세대가 있으면v6, 없으면 진행/보관 계획에 추가 처방v5·고급 처방v4·기본v3**으로 저장한다. [현행 형식 표](2026-09-08-remaining-work.md#현재-저장-계약)가 파일별 정본이다. 관리자 raw 초안/undo는 사용자 운동 파일에 넣지 않는다. 새 처방은 프로그램 스냅샷으로 전달하고 이전 앱이 새 필드를 조용히 누락하여 저장하지 못하도록 envelope를 구분한다.

휴식 실행 상태는 운동 파일 경로에 `.rest-timer.json`을 붙인 별도 파일이다. 저장된 실제 완료와 양수 휴식 처방이 있는 세트에서 사용자가 명시 시작하며 일시정지·재개·종료·교체 확인·복원을 제공한다. 실제 기록과 세션 사건 수를 담은 출처가 바뀌거나 마감/보관/새 계획으로 유효하지 않으면 이전 타이머를 다시 적용하지 않는다. 미지정 처방의 사용자 기본 시간과 최초 완료 영구 저장 후 자동 시작은 [휴식 설정 확장](2026-09-08-rest-guides.md)에서 지원한다. 명시0초는 기본 시간으로 대체하지 않는다. 타이머는 처방 출처v1/사용자 출처v2를 읽고 쓴다. OS 알림·처방이 있는 세트의 임의 시간 덮어쓰기·운동/타이머 파일 간 원자 저장은 미구현이다.

초안 자동 저장과 카탈로그 확정 저장은 별도 동작이다. 확정 후보를 저장하는 동안 `_committing` 상태로 기본 입력·정밀 초안 변경·다른 확정 동작을 막아 늦은 기본 입력이 과거 카탈로그를 다시 저장하는 문제를 방지한다. 저장 성공 전에는 확정 목록을 바꾸지 않고, 실패하면 이전 카탈로그와 검토 원문을 유지한다. 이는 한 내부 앱 인스턴스의 동시 쓰기 제어이며 여러 프로세스의 공동 편집·서버 동기화를 지원한다는 뜻은 아니다.

**운영자의 Mac 터미널, 앱 루트:**

```sh
flutter run -d macos -t lib/main_admin.dart
```

macOS 데스크톱 앱으로 실행하는 명령이며 iOS 시뮬레이터 명령이 아니다. 이번 작업에서는 실행하지 않고 위젯 렌더로 검증한다. 생성 후 내보내기 대화상자의 실제 경로에서 파일을 확인하고 `assets/programs.json`에 반영한다. 기존 파일을 무조건 복사하기 전 프로그램 수·ID·버전과 diff를 확인한다.

```sh
flutter test test/bundled_programs_test.dart --reporter expanded
flutter analyze
```

현재 번들 테스트는 승인된 첫 5개를 검증하므로 새 프로그램을 추가하면 테스트의 개수·기대 목록도 의도적으로 갱신한다. 이후 일반 진입점 `lib/main.dart`로 사용자 앱을 빌드한다. 관리자 진입점을 앱스토어 제출이나 사용자 설치 안내에 넣지 않는다.

## 기본 생성기 확인 방법

- 빈 ID·기간 `3.`·소수 반복·동일 세션 중복 운동 ID로 생성하면 오류가 표시돼야 한다.
- 올바른 3주·주 2회 구성은 6세션으로 생성돼야 한다.
- 미리보기에서 뒤로 가면 원문이 유지되고 저장 버튼 전에는 카탈로그에 추가되지 않아야 한다.
- 저장 후 프로그램 수가 증가하고 같은 ID/같은 버전 재생성은 차단돼야 한다.
- 재실행 시 초안과 관리자 목록이 복원돼야 한다.
- 내보낸 JSON을 `TrainingProgram.fromJson`으로 읽고 사용자 계획을 생성할 수 있어야 한다.
- 일반 앱에서 관리자 메뉴가 없어야 하며 소비자 import graph 검증도 통과해야 한다.

기본 생성기 자동 테스트는 `test/admin_routine_test.dart`, `test/admin_screen_test.dart`다. 첫 구현 당시 결과·렌더는 [기존 기능 검증](2026-09-08-feature-verification.md)에 남아 있다. 정밀 편집 도입 당시 테스트·렌더·실패 주입 결과는 [정밀 편집 명세의 검증 기록](2026-09-08-admin-precise-editor.md#13-구현검증커밋-기록)을 따른다. 이전 통과 수를 새 편집 기능의 검증으로 합산하지 않는다.

정밀 편집에서는 기존 5개 무손실 왕복, 한 세트 수정의 독립성, 복제 ID 입력, 주차 덮어쓰기 취소와 세션 수 변화, 실행 취소, 미완성 원문 재실행 복원, 버전 충돌, 저장 실패·재시도, 사용자 계획/D5 보존을 추가 확인한다. 실제 클릭 순서는 [정밀 편집 운영자 가이드](2026-09-08-admin-precise-editor.md#10-운영자가-직접-확인하는-순서)를 따른다. Flutter의 별도 실행 진입점/플랫폼 배포 구분은 [공식 배포 문서](https://docs.flutter.dev/deployment)와 함께 확인한다.
