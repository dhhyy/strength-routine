# 9/8 · 관리자 편집 확장 LC04

작성일: 2026-09-08. 구현 전 상세 계약이며, 실제 검증 결과는 마지막에 별도로 기록한다. 상위 범위는 [로컬 기능 전체 명세](2026-09-08-local-completion.md)다.

현재 전체 상태·스키마는 [상태표](2026-09-08-remaining-work.md), 연속 버전 충돌과 시험 대기의 검토 후 수정 상태는 [안정화 기록](2026-09-08-review-fixes.md)을 따른다. 아래 담당 검증은 LC04 구현 당시 결과이며 후속 수정의 시험 수로 재사용하지 않는다.

## 1. 반복 범위와 세트 종류

기존 `repetitions`는 하한으로 유지한다. `repetitionsMax`는 비어 있으면 고정 반복이고 지정하면 하한 이상 100 이하인 상한이다. 관리자 입력은 원문 문자열로 자동 저장하며 잘못된 값도 입력 화면에서 사라지지 않는다. 범위와 AMRAP을 동시에 지정하면 생성 검토를 차단한다. 범위를 지정한 사용자 목표는 `8–12회`처럼 표시하며 실제 횟수의 입력은 계속 독립적이다.

`ProgramSetKind`는 `work`(작업, 기본), `warmup`(워밍업), `drop`(드롭세트)다. JSON 키는 `setKind`이며 기본 작업 종류와 미지정 상한은 기존 JSON에 새 키를 쓰지 않는다. 워밍업이나 드롭세트가 필수인지는 기존 필수 여부로 별도 정한다. 드롭세트의 중량/순서/휴식은 운영자가 각각 직접 작성하며 자동 감소를 추측하지 않는다. 사용자 상세, 검색, 운동 입력에는 공유 처방 라벨로 전달한다.

D5 비교 근거와 미래 감량 대상은 작업 세트만 포함한다. 반복 범위는 실제 반복이 하한 이상/상한 이하일 때 RIR 비교에 사용할 수 있다. 범위 밖 실제 반복은 실패로 판정하지 않고 비교에서 제외한다. 고정 반복은 기존의 정확한 반복 일치 조건을 유지한다. 실제 수행 세트/반복 합계에는 모든 종류를 계속 포함한다. 세션 필수 기록 완료·초안 유무 안전 조건도 유지한다.

## 2. 일괄 수정

정밀 편집의 운동마다 ‘세트 일괄 수정’을 제공한다. 시작한 운동/현재 세션/현재 주차/전체 프로그램 중 범위를 고르고 한 번에 한 필드만 변경한다. 지원 필드는 하한 반복, 상한 반복(빈 값으로 해제), RIR(빈 값으로 해제), 휴식 초(빈 값으로 해제), 고정 중량 kg, 세트 종류다. 중량 변경만 명시적으로 고정 중량 방식으로 바꾸며 다른 필드는 중량 방식·값·리프트를 유지한다.

검토 단계는 범위명, 대상/변경 세트 수, 바꿀 필드/새 값, 개별 세트의 기존→새 값을 보여준다. 변경이 4세트 이하면 전후 목록을 펼쳐 놓고 더 크면 접힌 목록을 열어 확인한다. 적용·입력으로 돌아가기·취소 행동은 요약 아래에서 바로 찾을 수 있다. 후보는 깊은 복사에서 작성하고 영향 세트의 처방을 검증한다. 원문이 다른 필드에서 이미 유효하지 않으면 검토를 차단하고 원본을 유지한다. 취소/오류/검토 중 변경에서는 원본을 변경하지 않는다. 확정은 기존 편집 이력의 한 단계로 기록하고 되돌리기/재실행 및 초안 자동 저장을 사용한다.

## 3. 카탈로그 보관과 버전 이력

확정된 최신 프로그램을 지우지 않고 ID를 보관 목록에 추가한다. 관리자 기본 목록은 배포 대상과 보관됨을 구분하며 보관 상태 전환 전에 사용자 배포 목록에서 제외/다시 포함된다는 확인을 받는다. 내보내기는 보관 ID를 제외한 최신 프로그램만 포함한다. 활성 사용자 계획은 별도 스냅샷이므로 변경하지 않는다.

관리자 작업 파일에는 최신 프로그램별 버전 스냅샷 이력을 보존한다. 기존 파일은 현재 프로그램을 첫 스냅샷으로 취급한다. 새 확정 저장 시 기존 스냅샷과 새 스냅샷을 함께 보존한다. 같은 ID/버전은 과거 이력까지 검사하여 다른 콘텐츠로 덮어쓰지 못한다. 이력 화면에서는 각 버전 내용을 조회하고 ‘새 버전 초안으로 복구’를 선택한다. 원본 ID는 유지하고 사용된 적 없는 버전을 제안하되 편집할 수 있다. 복구는 초안 교체 확인과 자동 저장 뒤 정밀 검토 화면에서 새 버전으로 확정해야 한다. 과거 스냅샷을 현재 데이터로 직접 되감지 않는다.

초안 변경, 보관 전환, 버전 확정은 같은 관리자 저장 큐의 원자 파일 교체를 사용한다. 파일 쓰기 실패 시 최신 카탈로그·보관 상태·이력 모두 기존 상태를 유지하며 같은 행동을 다시 선택해 재시도한다. export 파일 실패는 관리자 카탈로그를 변경하지 않는다.

## 4. 파일 호환 계약

| Envelope | 기존 읽기 | 새 조건부 버전 |
|---|---|---|
| 사용자 프로그램 카탈로그 | 1·2 | 범위/종류가 있으면 3 |
| 사용자 운동 상태 | 1~4 | 범위/종류가 있으면 5 (루트 통합) |
| 관리자 작업 | 1~3 | 범위/종류 또는 보관/명시 이력이 있으면 4 |

구버전 envelope에 `repetitionsMax`/`setKind`가 들어 있으면 기본값이어도 거부한다. 관리자 보관/이력 키도 schema4 이전에는 거부한다. 상위 envelope가 지원하는 새 필드는 사용자·초안 모델 모두 읽는다. 기본 5개 번들 프로그램은 변경하지 않는다. 이력은 공개 카탈로그에 넣지 않는다. LC01에서 복원한 운동 파일은 저장 세대를 포함하는 schema6 envelope를 사용할 수 있으며 그 안에서도 확장 처방을 보존한다.

## 5. UI와 검증 계획

기존 DESIGN.md의 Console v2 방향과 렌더한 정밀 편집 근거를 재사용한다. Adaptive design harness를 적용하며 전역 스타일은 변경하지 않는다. FlowPage 고정 앱바, 유동 입력 폭, 스크롤 가능한 검토를 조립한다. 색/간격/폰트는 앱 토큰만 쓰고 숫자/ID는 mono, 한국어 설명은 KR을 사용한다. 오류/저장 중/빈 이력/취소/보관 목록을 구분한다.

검증은 새 필드 왕복·잘못된 초안 유지·구버전 거부·이력 불변·보관 export 제외·복구 신규 버전·일괄 범위/취소/undo·D5 회귀와 관리자 위젯 조작이다. 실제 번들 폰트로 1200px/375px와 큰 글자 조건을 캡처하고 관찰한 문제를 수정한 뒤 재렌더한다. Simulator와 실제 기기 조작은 하지 않는다.

관리자 확정 저장은 `AdminWorkspace.withProgram`에서 같은 ID의 모든 과거 버전을 검사한다. 시드 파일에 없던 과거 수정 내용을 소급 복구하지 않는다. 기존 카탈로그는 현재 스냅샷부터 이력을 시작하며, 이후 확정 변경은 이전 및 새 버전을 함께 보존한다. 새 버전 기본값은 기존 정수 버전의 최대값보다 큰 사용하지 않은 정수이며 운영자가 직접 다른 미사용 문자열로 편집할 수 있다. 버전 복구 후에도 보관 상태를 유지하므로 복구 저장이 자동 공개를 뜻하지 않는다.

### 6.2 운영자 확인 절차

1. 관리자 앱의 ‘프로그램 관리’에서 기존 프로그램을 정밀 편집한다. 일반 사용자 앱에는 관리자 메뉴를 추가하지 않았다.
2. 한 세트의 반복 하한을 8, 상한을 12로 정하고 종류를 워밍업으로 바꾼다. 상한은 선택이며 지우면 고정 반복으로 돌아간다.
3. 같은 세트에서 AMRAP을 켜고 변경 검토를 누르면 범위와 동시 지정 오류가 표시되는지 확인한다. 원문 8/12가 남아 있어야 한다.
4. AMRAP을 해제하고 해당 운동의 ‘세트 일괄 수정’을 연다. 현재 세션과 휴식 초 60을 선택하고 검토한다.
5. 대상 세트 수와 변경 수, 변경 전후를 확인한다. 취소하면 초안이 같고 적용하면 그 세션만 바뀌어야 한다.
6. 편집기의 되돌리기를 한 번 누르면 전체 일괄 변경이 한 번에 복구되고 다시 실행으로 같은 변경을 돌릴 수 있어야 한다.
7. 프로그램 정보에서 새 버전을 입력하고 변경 검토를 연다. 워밍업·8–12회·바뀐 휴식이 실제 검토 내용에 있어야 한다.
8. 검토한 프로그램을 저장하고 관리자 앱을 다시 읽는다. 카탈로그의 최신 버전과 정밀 초안이 유지되어야 한다.
9. 프로그램의 버전 이력을 연다. 이전 버전을 펼쳐 내용을 확인한 뒤 ‘새 버전 초안으로 복구’를 선택한다.
10. 복구한 초안은 이전 구성과 새 미사용 버전을 가지며, 확정 저장 전 최신 카탈로그는 바뀌지 않아야 한다.
11. 검토 후 새 버전으로 저장한다. 버전 이력에서 첫 버전, 직전 버전, 복구 버전이 모두 남아 있어야 한다.
12. 목록에서 보관을 선택한 뒤 취소해 보고, 다시 보관을 확정한다. ‘보관됨’에서 같은 프로그램을 찾을 수 있어야 한다.
13. 카탈로그 내보내기를 실행해 보관 프로그램이 제외되는지 확인한다. 복원 후 내보내면 최신 버전이 다시 포함되어야 한다.
14. 실제 파일 쓰기 실패를 시험할 경우 실사용 원본의 안전한 복사본에서 실행한다. 실패 후 화면의 이전 상태와 파일이 보존되고 같은 작업 재선택으로 진행해야 한다.

위 조작에 사용하는 8/12/60 값은 기능 확인용 합성 입력이며 기본 5개 프로그램의 처방을 바꾼 값이 아니다. 실제 앱을 재시작하는 8번의 OS 조작은 이 작업에서 실행하지 않았고, 자동 테스트는 새 `AdminProgramStore` 인스턴스로 파일을 다시 읽어 검증했다.

모델 시험의 핵심 경계는 상한 7/101 거부(하한 8), 상한 8 허용, 범위+AMRAP 거부, 미완성 `8.` 원문 복원, 종류 기본값 생략, 명시 기본값도 구버전 envelope에서 거부하는 감지다. 일괄 시험은 네 범위의 대상 세트 수와 비대상 원문 동일성, 필수 여부/중량 리프트 보존, 고정 kg로 바꿀 때만 기준 리프트를 해제함을 확인한다. D5 시험은 워밍업/드롭의 실제 반복 11·RIR 미입력도 수행 통계에 남고 작업 세트의 비교에는 섞이지 않는지, 범위 밖 실제가 비교 제외인지 확인한다.

### 6.4 렌더 관찰 → 수정 → 재확인

기존 Console v2 방향을 유지하고 실제 번들 IBM Plex Sans KR/Mono 및 Material Icons로 신규 7개 테스트를 실행했다. 1200×900, 375×900, 1.5배 글자, 320px 키보드 inset을 사용했다. 합성 시험 자료만 화면에 사용했고 Simulator는 실행하지 않았다.

첫 렌더에서는 상한 입력이 하한과 떨어져 있어 범위를 비교하기 어려웠다. 하한과 상한을 한 행에 두고 RIR를 다음 필드로 분리했다. 일괄 변경 8개를 8개 카드로 늘어놓아 적용 행동이 아래로 밀린 문제는 범위/대상/새값 요약과 펼칠 수 있는 전후 목록으로 고쳤다. 큰 글자에서 ‘변경’이 단어 중간에 줄바꿈된 것은 범위명과 수치 행을 나눠 해결했다.

### 6.6 한 문장씩 확인할 변경

- 반복 하한과 선택 상한을 직접 편집하고 사용자에게 범위로 표시합니다.
- 작업·워밍업·드롭세트를 세트마다 독립적으로 지정합니다.
- 운동·세션·주차·전체 프로그램 범위로 한 필드를 일괄 수정합니다.
- 적용 전에 대상 수와 변경 전후를 확인하고 한 번에 되돌립니다.
- 프로그램을 보관하면 다음 카탈로그 내보내기에서 제외합니다.
- 보관 목록에서 복원하면 최신 버전이 다시 배포 대상이 됩니다.
- 과거 버전의 내용을 새 버전 초안으로 불러와 검토 후 확정합니다.
- 이미 사용한 버전의 콘텐츠와 시작된 사용자 계획을 덮어쓰지 않습니다.
- D5는 워밍업·드롭을 감량 비교에서 제외하고 실제 수행 통계에는 남깁니다.
