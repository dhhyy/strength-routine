## 1. 질문 ↔ 답 ↔ 지금 앱 ↔ 출시 해석

### 1) e1RM 기준 · RIR으로 올리고 내리기 · 힘들면 수동 조절

**원래 질문:** 추정에 쓰는 RIR 상한(지금 ≤4)을 유지할지.

**트레이너 답 (요지):**
- 모든 루틴의 기본은 **e1RM**이어야 한다.
- 사용자가 RIR을 기록하면 **실제(추정) e1RM**과 비교해, 처방이 **오버면 내리고 / 너무 가벼우면 올려** 루틴 Range 안으로 맞춘다.
- 그와 별개로, e1RM·루틴을 떠나 **너무 힘들면 무게나 세트를 사용자가 조절**할 수 있어야 한다.

**지금 앱:**
- 공식은 Epley, 작업 세트·1–12회·RIR 비어 있거나 ≤4일 때만 후보.
- **올리기만 제안**하고, 사용자가 수락하기 전 working max를 바꾸지 않는다.
- **내리기**는 D5 감량이 살아 있으면 올리기 제안을 숨기는 쪽이다. RIR vs Range로 자동 하향은 없다.
- 오늘 세트에 **실제 중량·반복을 처방과 다르게 기록**하는 것은 된다. 미래 처방 세트 수를 사용자가 줄이는 UI는 없다.

**검토:**
- 「모든 루틴의 기본 = e1RM」은 이미 있는 모델과 맞다. `% × working max`.
- 「Range에 들어오게 자동 업/다운」은 **새 엔진**이다. 처방에 반복 범위가 있는 종목만 기계적으로 가능하다. 고정 반복만 있는 날은 “가벼움/무거움” 판정이 모호하다.
- 출시 전에 자동 업·다운을 동시에 열면, D5(감량)와 충돌하고 불평(갑자기 무게가 바뀜)이 나기 쉽다.

**출시 해석 (따름):**
1. RIR 상한 **4 유지** (별도 숫자가 안 나왔음).
2. 지금처럼 **제안 → 수락**으로 올리고, **너무 힘듦은 오늘 실제 중량을 낮춰 기록**하는 길로 먼저 안내.
3. Range 자동 맞춤·세트 수 조절 UI는 **출시 다음**. 규칙이 숫자로 오기 전 구현하지 않는다.

**코드 (2026-09-16):** RIR 4·제안 수락 유지. 설정에 **working max 자동 적용**(기본 끔) 추가. D5 중이면 자동도 하지 않음.

### 2) 워킹맥스: 물어보기 + 나중 자동

**원래 질문:** 제안 후 직접 수락이 맞는지, 자동 반영을 원하는지.

**트레이너 답:** 가이드하되 **질문**한다. 나중에는 자동 반영으로 흐르게. **직접 수락과 자동 반영 둘 다** 있으면 좋겠다.

**지금 앱:** 제안 + 수락/무시(+ undo 1회). 자동 덮어쓰기는 없음. 원래 계획도 「표시 → 수동 채택 → (나중) 소폭 자동」.

**출시 해석:**
- 출시: **질문(수락)** 만. 이미 됨.
- 출시 후: 설정에 **「제안 자동 적용」** 한 스위치. 기본은 끔. 자동이어도 **이미 기록한 날·D5 감량 중은 건드리지 않음**.

**코드 (2026-09-16):** 스위치 반영. 기본 끔. 켜면 대화 없이 적용 + 스낵바 되돌리기.

### 3) 코치 규칙 · 4주 예시 · 확신이 없어서 앱을 따르겠다

**원래 질문:** 생성기가 붙일 기본 루틴·기간·빈도 확정.

**트레이너 답 (요지):**
- 나중에 원리/규칙을 알려 주겠다. 예: 스쿼트·데드 같은 날 볼륨 금지, 벤치 강도 높은 날 오버헤드 자동 하향, 주간 스쿼트 볼륨↑이면 데드↓.
- 4주 짜는 법도 보여줄 수 있다.
- **확신이 없다. 앱이 오류 없이 돌아가는 쪽을 따른다. 빠른 출시·수익화가 우선. 불평이 없어야 한다.**

**지금 앱:** 목표·일수·블록으로 **준비된 프로그램에 매칭**. 같은 날 볼륨 충돌을 계산하는 규칙 엔진은 없다.

**검토:** 예시는 코칭적으로 타당하다. 다만 「벤치 후 OHP가 무겁게 느껴짐」은 **피로 계수**가 필요한데, 숫자 없이 코딩하면 오탐이 난다. 트레이너가 출시를 우선했으므로 **규칙 엔진은 보류**.

**출시 해석:**
- 생성기는 **지금 매칭 MVP 유지**.
- 규칙·4주 표는 이 문서 아래에 **대기 목록**으로만 둔다. 표·숫자가 오면 템플릿 JSON에 넣는 쪽이 자동 추론보다 안전하다.

**대기 목록 (숫자 오면 반영):**
- 스쿼트 + 데드 같은 날 **볼륨 동시 금지**
- 벤치 고강도일 때 OHP **% 또는 Range 하한**
- 주간 스쿼트 볼륨↑ ↔ 데드 볼륨↓
- 4주 블록 예시 루틴

### 4) 프로그램 내용 검수 — 「무슨 말인지 모르겠음」

**원래 질문:** 앱에 넣은 완성 프로그램 5개가 현장 코칭과 같은지, 종목·세트·휴식·딜로드를 승인할지.

**지금 앱:** `assets/programs.json` 카탈로그를 고르거나, 생성기가 그중 하나에 붙인다.

**설명 (다음에 트레이너에게 이렇게 물어보면 됨):**  
「앱 안에 미리 들어 있는 루틴 이름 목록을 보고, 이대로 회원에게 줘도 되는지 / 빼야 하는 프로그램이 있는지」만 보면 됩니다. 지금 당장 답이 없어도 출시는 기존 카탈로그로 갑니다.

**출시 해석:** 카탈로그 **유지**. 검수는 출시 블로커가 아님.

### 5) 가입 없이 둘러보기 + 루틴 생성까지. 이후 카카오/네이버

**원래 질문:** 스테이징에서 게스트만 / 카카오까지.

**트레이너 답:** 일단 **가입 없이 둘러보기**. 그 안에서 **루틴 생성까지** 돼야 유료 전환이 된다. 그다음 카카오·네이버.

**지금 앱:**
- 스테이징: 「가입 없이 둘러보기」 있음.
- 생성기 화면 있음 (게스트가 생성 후 시작까지 가는지는 기기에서 한 번 확인 필요).
- 로그인은 **카카오(Supabase)** 만. 네이버 없음.

**출시 해석:**
- 게스트로 **온보딩 → 생성 → 루틴 시작 → 오늘 기록**까지 막히면 출시 결함.
- 네이버는 **출시 후**. 카카오는 계정·저장이 필요할 때 연결.

**코드 (2026-09-16):** 오늘 빈 화면 카피에 가입 없이 생성 가능함을 명시. 네이버는 없음.

---

### 6) 이월은 빅리프트만. 보조는 아무 때나 추가

**원래 질문:** 못한 날/종목 이월이 현장 규칙과 맞는지.

**트레이너 답:**
- 이월 가능: **스쿼트, 오버헤드, 벤치, 데드리프트, 풀업, 딥스** 만.
- 보조는 이월이 아니라 **사용자가 아무 때나 추가**.

**지금 앱:** 「이 종목 다음에」는 **종목 종류 제한 없음**. 세션에 보조를 자유롭게 추가하는 UI는 없다.

**검토:** 이월 제한은 기존 큐에 **허용 목록**만 넣으면 된다. 오류 위험 낮음.  
보조 자유 추가는 세트 구조 보존 계약과 겹친다. 출시에서 열면 저장·D5·이전 기록 복사가 깨지기 쉽다.

**출시 해석:**
- 이월: 위 6종(+ 이름 별칭)만. 그 외는 이월 버튼 숨김.
- 보조 추가: **출시 후**. 출시에는 템플릿에 있는 보조만, 건너뛰기/미기록으로 처리.

**코드 (2026-09-16):** `isDeferrableExercise`로 버튼 제한. RDL·머신 보조는 이월 불가. 보조 자유 추가는 없음.

**이월 허용 초안 (구현 시 별칭 확정):**
- squat / overhead press / bench press / deadlift / pull-up / dip

## 3. 아직 숫자로 안 나온 것 (다음 질문용, 출시 막지 않음)

1. Range 판정: 「오버」를 RIR 0–1, 「가벼움」을 RIR 3+ 로 봐도 되는지.
2. 힘들 때 조절: **오늘만** vs **앞으로 그 종목 전체**.

4. 6종목 한글/영문 표기를 카탈로그 이름과 한 장으로 맞춰 주기.
