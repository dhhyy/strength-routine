# 상품이 되기 위한 백엔드 (쉬운 설명 + 구현 상태)

> 작성: 2026-09-11  
> 독자: 제품 담당·트레이너 공유용으로도 읽기 쉽게

---

## 1. 한 줄

앱만 있으면 **그 기기 안**에만 기록이 남습니다.  
**상품**이 되려면 서버(백엔드)에 계정이 있고, 기록을 올려 두고, (나중에는) 링크로 미리보기도 해야 합니다.

---

## 2. “스냅샷”이 뭐야?

기기에 있는 운동 데이터 전체를 **한 번에 복사**해 서버에 두는 것입니다.

| 비유 | 의미 |
|---|---|
| 사진 한 장 | 그 순간의 기록·루틴·working max |
| 서버에 올리기 | 그 사진을 클라우드에 저장 |
| 불러오기 | 클라우드 사진을 다시 기기에 넣기 |

지금은 **수동 저장/불러오기**부터 만듭니다. (매 세트 자동 동기화는 나중)

---

## 3. 이미 있는 것 / 없는 것

| 항목 | 상태 |
|---|---|
| Supabase 프로젝트 | ✅ `strength-routine-staging` |
| 카카오 로그인 Provider | ✅ |
| DB 테이블 (프로필·스냅샷 자리) | ✅ |
| 앱 → 서버 **저장/불러오기 UI·코드** | ✅ 프로필 → 「서버 기록 저장·불러오기」 |
| 웹 스테이징 URL 배포 | ❌ 아직 |
| 결제·게시판 | ❌ 나중 |

---

## 4. 상품까지 가는 순서 (권장)

1. **계정 로그인** (진행 중)  
2. **스냅샷 저장/불러오기** ← 지금 구현  
3. **스테이징 웹/설치본 배포** → 트레이너 링크 공유  
4. 자동 동기화·충돌 정책  
5. 결제·커뮤니티 등

저장소가 있어야 저장할 수 있다는 말이 맞고,  
지금은 **창고(서버)는 계약했고, 짐을 나르는 통로(앱 기능)를 만드는 단계**입니다.

---

## 5. 보안·테스트

- 키·시크릿은 `.local/` (gitignore). 채팅/깃에 올리지 않음.  
- **테스트 로그인(우회)** 으로는 서버 저장을 쓰지 않음. 카카오 실로그인 사용자만.  
- RLS: 본인 `user_id` 행만 읽기/쓰기.
