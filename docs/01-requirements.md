# 정리된 요구사항 — 스트렝스·근비대 루틴 빌더

> 상태: 9/8 후속 구현 반영 · 원본 초안 v0.1: 2026-08-27 · 최종 갱신: 2026-09-08

## 2026-09-08 · 최신 요구·구현 계약

추가 사용자 요구: 관리자가 프로그램을 세밀하게 편집할 수 있어야 한다. [정밀 편집 명세](2026-09-08-admin-precise-editor.md)에 기존 프로그램의 무손실 불러오기, 주차·세션·운동·세트별 입력, 복사·순서·삭제·되돌리기, 검토 후 새 버전 저장을 정의하고 구현했다. 이어서 사용자 요청으로 [휴식 시간·템포·슈퍼세트·AMRAP](2026-09-08-advanced-prescriptions.md)의 데이터·관리자 입력·사용자 표시와 실행·저장 복원을 연결했다. 1인용 내부 도구이며 실제 웹 관리자 운영·온라인 배포 기능과 구별한다.

사용자는 상세 문서를 남기고 기능 개발을 계속하도록 요청했다. 최신 구현과 검증은 [수행일·기록 마감 보고서](2026-09-08-session-lifecycle-verification.md), 상세 계약은 [명세](2026-09-08-session-lifecycle.md), 미구현 제안은 [로드맵](2026-09-08-development-roadmap.md)을 따른다. 아래 9/7 상태표는 당시 이력이다.

- 일반 사용자는 등록 프로그램 5개 중 선택하고 운동·세트 구조를 유지한 채 중량·시작일·요일을 맞춘다.
- 루틴 생성 도구는 운영자 1명의 내부 빌드로 제공하며 다중 트레이너 가입·승인·정산은 제외한다.
- 세트의 실제 수행일과 입력/수정 시각을 분리하고, 과거 날짜 미상은 사용자 지정 전 미상으로 보존한다.
- 기록 마감은 필수 미기록 0·초안 0에서 사용자 확인으로 진행하고 선택 미기록을 자동 처리하지 않는다.
- 마감 뒤 수정은 명시 재개를 요구하며, 취소·실패·재마감에서도 과거 요약과 사건을 보존한다.
- 예정일/수행일 달력에서 조회할 수 있으며 전체 제외·미상·초안을 실제 수행일로 집계하지 않는다.
- 운동 파일은 v1~v4를 읽고 고급 처방이 있으면 v4, 없으면 v3으로 저장하며 기존 ID·목표·실제값·초안·D5 이력을 보존한다.
- 슈퍼세트는 같은 세션의 연속한 2개 이상 운동을 묶고 한 세트씩 번갈아 진행하며 운동별 세트 수 차이를 허용한다.
- AMRAP은 실제 횟수를 명시 입력하고 기준 반복 수를 최소 완료 조건으로 사용하지 않는다. 고정 반복 D5의 수치 근거·미래 감량 대상에서는 제외한다.
- 휴식은 0~3600초 또는 미지정이며 양수 처방의 완료된 세트에서 타이머를 직접 시작한다. 템포는 4구간 초 단위이며 세 번째 구심 구간에 X를 허용한다.
- 타이머는 별도 파일에 한 개를 저장하며 일시정지·재개·종료·교체 확인·실패 재시도를 제공한다. 출처 실제값·세션 사건·활성 계획을 검사하고 저장된 UTC 종료 시각으로 복원한다.
- 검색·습관·기본 설정·추세/D5/되돌리기·로컬 FAQ·구독 준비 안내는 구현되어 있다.
- 실제 구독 결제·원격 계정·문의 전송·백업 UI·일정 변경 UI·타이머 자동 시작/OS 알림은 후속이며, 상세 문서를 기능 완료로 해석하지 않는다.
- 검증은 시뮬레이터 실행 없이 정적 분석·자동 파일/위젯 테스트·headless 렌더를 사용하고 실제 기기 OS 복원은 별도 미실행으로 남긴다.

## 2026-09-07 · 당시 구현 상태

첫 흐름인 **프로그램 선택 → 최근 기록·일정 설정 → 날짜별 운동·목표 중량 결과 확인 → 시작 → 세트 기록 → 로컬 저장·복원**을 구현했다. 정적 분석과 전체 39개 테스트는 통과했으며 네이티브 빌드·실행도 성공했다. Mac 잠금 때문에 화면 조작·재실행 확인은 미완료다. 상세 결과는 [작업 기록](2026-09-07-work-log.md)을 따른다. 코드 구현과 검증 완료·실제 콘텐츠 출시를 구분한다.

| 영역 | 현재 구현 / 제약 |
|---|---|
| 프로그램 데이터 | 작성자·ID·버전·유한 기간·주차/세션·운동·세트 전체 스냅샷. 매주 동일 세션 수 계약 |
| 개인화 | 필수 메인 리프트 최근 기록, 명시적 기준 중량, 시작일·요일·중량 간격. 운동·세트 구성 유지 |
| 처방 | 수동 입력, 고정 kg, 사용자 명시 기준 중량 대비 %. 자동 e1RM·TM 추정 없음. 실제 훈련 수치/공식 채택은 별도 결정 |
| 시작 확인 | `PlanReviewScreen`에서 날짜별 운동·세트·개인화 목표 kg를 확인하고 ‘이 일정으로 시작’에서 최종 저장 |

| 저장 | 실제 로컬 JSON, 스키마 검증, 읽기/쓰기 직렬화, 임시 파일 교체. 계획·과거 기록·소개 완료 복원 |
| 실제 탭 | 오늘/다음 운동·저장 데이터 달력·프로필. 검색·습관은 기존 목업 |
| 폰트 | 기존 IBM Plex Sans KR/Mono 로컬 번들·라이선스 연결 |

## 2026-09-07 · 첫 마일스톤

- 사용자 인터뷰 확정: **루틴 생성 → 운동 기록 → 앱 재실행 후 복원**을 끝까지 연결한다.
- 플랫폼은 `02-engine-logic.md` §7의 변경에 따라 **Flutter 네이티브 앱**을 기준으로 구현하며, 현재 검증 대상은 iPhone 시뮬레이터다. 아래 초안의 웹앱·Safari/Chrome 표현은 이전 플랫폼 기준으로 남아 있다.
- 완료 조건: 생성한 루틴을 오늘 화면에서 확인하고 세트별 실제 중량·반복·RIR을 기록하며, 앱 재실행 후에도 계획과 기록을 복원한다.
- 기록 부족 처리 확정: 첫 생성은 **최근 기록이 입력된 메인 리프트부터** 지원한다. 기록 없는 리프트의 시작 중량은 임의로 추정하지 않는다.
- 프로그램 공급 방식 확정: **트레이너가 기간·요일·운동·세트 구성이 있는 완성된 프로그램을 등록하고, 사용자가 여러 프로그램 중 선택**한다.
- 개인화 범위 확정: **트레이너의 운동·세트 구성은 유지**하고 사용자 기록에 따른 **중량·시작일·운동요일**을 맞춘다.
- 등록 도구 범위 확정: 트레이너 프로그램 등록 도구는 사용자가 별도로 후속 개발한다. 현재는 **사용자 앱**을 개발하며 트레이너 등록 화면·계정·관리 서버를 포함하지 않는다.
- 아래 초안의 공통 4주 블록과 목표·기간 기반 직접 생성 흐름은 재검토 대상이다. 모든 프로그램에 하나의 블록 구성을 강제하지 않는다. 아래 자동 운동·세트 재배분 규칙은 이번 생성 흐름에 그대로 적용하지 않는다.
- 인터뷰 및 구현 이력: [9/7 작업 문서](2026-09-07-work-log.md).

## 제품 한 줄 정의

사용자가 트레이너의 완성된 프로그램을 선택하고 자신의 기록·일정에 맞춰 시작하여, 오늘의 운동을 빠르게 기록하고 기기 재실행 후에도 계획과 수행을 이어가는 Flutter 네이티브 앱이다.

이하 본문은 8/27 제품 초안과 후속 요구를 보존한 것이다. **9/7 사용자 확정·최신 구현 상태가 우선**하며, 웹앱·직접 생성·공통 4주·자동 운동/세트 변경·미래 기능을 현재 구현으로 해석하지 않는다.

## 제품 목표와 원칙

- 목표는 사용자의 점진적 향상이다. 기록, 계획, 실제 수행, 다음 추천이 끊기지 않아야 한다.
- 기본 화면은 항상 **오늘 루틴**이다. 헬스장에서 한 손으로 빠르게 쓸 수 있어야 한다.
- 루틴 생성은 생성형 AI가 아닌 규칙·템플릿·계산식 기반으로 구현한다. 추천 이유를 짧게 설명한다.
- 기본 입력은 `중량 / 반복 / 남은 반복(RIR)`이다. RPE는 고급 사용자가 선택할 수 있게 한다.
- 운동·회복 정보는 의료 진단, 부상 예방 보장, 재활 처방으로 표현하지 않는다.

## 대상 사용자와 전제

- 스트렝스, 근비대, 파워빌딩을 체계적으로 진행하려는 건강한 성인 사용자
- 1RM을 아는 사용자와 3RM·5RM 또는 최근 작업 중량만 아는 사용자 모두
- 모바일 브라우저에서 세트 기록을 빠르게 남기려는 사용자
- 첫 출시에서는 통증·질환·약물·임신·재활 정보를 받지 않는다. 해당 정보 기반의 처방도 하지 않는다.

## 루틴 생성

### 온보딩 입력

1. 목표 선택: `스트렝스`, `근비대`, `파워빌딩`
2. 총 루틴 길이: 기본값 `4주`, `8주`, `12주`, 고급 설정에서 직접 주차 입력
3. 주당 훈련 일수와 실제 훈련 요일
4. 우선순위 메인 리프트 1~3순위
   - 스쿼트, 벤치프레스, 데드리프트, 오버헤드프레스
5. 최근 기록
   - 1RM, 3RM, 5RM 중 하나
   - 중량, 반복, 기록 날짜, 선택적 RIR/RPE
6. 보조운동 선호
   - 운동 직접 선택: 턱걸이, 딥스, 바벨컬 등
   - 부위 선택: 가슴, 등, 어깨, 하체, 팔, 코어 등
7. 장비의 최소 증량 단위와 중량 단위(kg 우선)

### 블록과 구간

- 전체 루틴은 여러 블록으로 구성한다.
- 기본 4주 블록은 `볼륨 2주 → 강도/중량 증가 1주 → 디로딩 1주`이다.
- 사용자는 블록의 전체 길이와 볼륨·강도·디로딩 구간 길이를 수정할 수 있다.
- 예시: `4주 스트렝스 → 4주 근비대 → 4주 스트렝스`, `3주 피킹`.
- 고급 편집은 프로필의 루틴 설정에서 제공하며, 시작 온보딩에서는 프리셋을 우선 노출한다.
- 디로딩이 없는 긴 블록은 경고를 보여 주되, 사용자의 편집 자체는 막지 않는다.

### 우선순위와 회복 배분

- 1순위는 해당 블록의 주된 발전 자원을 받는다.
- 2순위는 회복 충돌 여부에 따라 발전 보조 또는 유지 중심으로 배정한다.
- 3순위는 메인 리프트처럼 과도한 볼륨을 배정하지 않고 유지 볼륨을 기본으로 한다.
- 스쿼트+데드리프트, 벤치프레스+오버헤드프레스는 같은 블록에서 둘 다 최대 발전 볼륨으로 배정하지 않는다.
- 하체 1개와 상체 1개 조합은 두 종목의 발전을 함께 지원할 수 있지만, 2순위는 1순위보다 낮은 상한을 갖는다.
- 메인 리프트의 회복 부담이 높아질수록 보조운동 수와 세트를 줄이거나 대체안을 제안한다.

### 생성 경험

- 생성 버튼 후 약 3초의 구조화된 진행 화면을 보여 준다.
- 단계 예시: `기준 기록 산정 → 우선순위 배분 → 회복량 점검 → 주간 세션 구성 → 중량 반올림`.
- 이는 앱이 결정론적 계산을 수행하는 과정을 보여 주는 UX이며, 실제 AI 코칭 또는 의료 판단처럼 표현하지 않는다.
- 생성 결과에는 블록 요약, 주당 훈련일, 우선순위 배분 이유, 시작 중량의 신뢰도를 표시한다.

## 오늘 루틴과 세트 기록

### 기본 화면

- 앱 시작 시 오늘 루틴으로 이동한다.
- 화면 상단에는 날짜를 좌우로 옮기는 컨트롤, 전체 루틴 보기, 블록/주차 상태를 둔다.
- 과거 날짜는 기록 보기, 오늘은 기록하기, 미래 날짜는 계획 미리보기 중심으로 동작한다.
- 상단에는 날짜 기반으로 바뀌는 한국어 명언과 실제 인물명을 표시한다. 365개 문구는 출처·번역 권한을 검증한 데이터만 사용한다.

### 운동 수행

- 운동마다 목표 중량, 세트, 반복, 목표 RIR 또는 RPE를 보여 준다.
- 사용자는 실제 중량·반복·RIR, 선택적 메모를 세트마다 기록할 수 있다.
- 사용자는 당일 세트를 추가·삭제하고, 보조운동을 추가하며, 계획과 실제 수행의 차이를 확인할 수 있다.
- 수동으로 바꾼 값은 숨기지 않고 기록하며 다음 추천의 입력 신호로 사용한다.
- 네트워크 지연·실패 시에도 입력값을 유지하고 저장 상태와 재시도 방법을 보여 준다.
- 계획된 필수 세트를 모두 기록하거나 명시적으로 제외했을 때만 하루 운동 완료 축하 모달을 한 번 표시한다. 사용자가 임의로 추가한 보조운동은 완료 조건에 포함하지 않는다.

### 당일 조절

- 사용자는 간단한 컨디션 선택과 “오늘 가볍게 진행”을 사용할 수 있다.
- 목표보다 훨씬 어려웠거나 반복을 놓친 경우, 앱은 다음 세트 또는 다음 세션의 보수적 변경을 **제안**한다.
- 자동 조정의 결과에는 한 줄 이유와 되돌리기·수동 수정 수단이 필요하다.

## 기록과 e1RM 추세

- 기록 탭의 기본 화면은 달력이다. 운동한 날짜가 식별되어야 한다.
- 날짜를 누르면 해당 날짜의 운동, 모든 세트, 중량, 반복, RIR/RPE, 컨디션을 확인할 수 있어야 한다.
- 기본 추세 종목은 스쿼트, 벤치프레스, 데드리프트, 오버헤드프레스다.
- 옵션으로 중량 턱걸이와 중량 딥스를 메인 종목처럼 추적한다.
- e1RM은 실제 1RM 판정이 아니라 같은 운동·장비·가동범위 조건 안에서의 **추정 추세**로만 표시한다.
- 기록이 없거나 신뢰도가 낮은 날짜의 그래프에 임의 데이터를 표시하지 않는다.

## 운동 검색과 영상

- 운동명과 부위로 운동을 검색한다.
- 운동 상세에는 핵심 자세 안내와 유튜브 영상을 표시한다.
- 첫 출시의 임시 영상은 외부 공개 링크와 출처를 명시한다. 나중에는 운영자가 직접 제작한 영상으로 교체할 수 있어야 한다.

## 생활습관

- 기본 습관 예시: 물 충분히 마시기, 체중 기준 단백질 목표, 일찍 자기, 오후 3시 이후 카페인 줄이기.
- 사용자는 항목을 추가·수정·삭제하고 일별로 체크한다.
- 모든 습관을 완료하면 축하 모달을 표시한다.
- 일부만 완료했을 때는 비난하지 않는 격려 문구를 보여 준다.
- 생활습관은 훈련 조절의 보조 신호이며, 의료적 판단이나 자동 고강도 처방의 근거로 단독 사용하지 않는다.

## 프로필, 구독, Q&A

### 프로필

- 최상단에 앱 철학과 작동 방식: 계획을 유지하면서 기록에 따라 제한적으로 조절하는 도구임을 설명한다.
- 사용자 기본 정보, 구독 상태, 체험 잔여 기간을 표시한다.
- 목표, 루틴 길이, 블록, 우선순위, 훈련 요일, 보조운동 선호를 수정할 수 있다.
- 루틴 변경은 미래 세션에만 적용하고, 완료한 기록과 이전 계획 스냅샷은 보존한다.

### 구독

- 7일 무료 체험 상태를 지원한다.
- 한국 결제는 후속 단계에서 서버 검증형 PG 연동으로 구현한다. 카드 정보는 앱 서버나 DB에 저장하지 않는다.

### 질문·답변

- 질문 작성 전에 상단 검색창과 관련 글 추천을 먼저 제공한다.
- 사용자는 제목·내용으로 질문을 작성하고, 운영자 또는 사용자 답변을 볼 수 있다.
- 하단 탭은 사용자가 지정한 다섯 개를 유지한다: `오늘 루틴 / 기록 / 운동 검색 / 생활습관 / 프로필`.
- Q&A는 프로필의 도움말·커뮤니티에서 들어가는 독립 화면으로 둔다. 여섯 번째 하단 탭을 만들지 않아 운동 중 UI를 복잡하게 하지 않는다.

## 비기능 요구사항

- 모바일 Safari와 Chrome에서 가입, 생성, 세트 기록, 저장, 기록 조회가 동작해야 한다.
- 계산 엔진은 UI와 분리된 순수 함수로 만들고, 동일 입력에는 동일 결과를 반환해야 한다.
- 생성 루틴, 자동 조정 전후, 템플릿 버전, 계산 엔진 버전을 저장해 재현 가능해야 한다.
- 사용자별 운동·습관·구독 데이터는 서로 접근할 수 없어야 한다.
- 모든 중량은 장비의 최소 증량 단위에 맞춰 반올림한다.
- 운동 완료, 생활습관 완료, 저장 실패, 생성 실패, 빈 상태를 모두 설계하고 테스트한다.


## 9/8 후속 요구사항·현재 범위

사용자 요청으로 기본 프로그램 5개, 관리자 내부 루틴 생성, 기록 추세·D5 감량 제안/되돌리기, 실제 설정·로컬 Q&A 도움말·구독 준비 안내를 추가한다. 트레이너는 운영자 1명이므로 트레이너 회원 등록·모집·마켓플레이스를 제외한다. 일반 사용자 직접 생성은 제공하지 않으며 프로그램 구조 보존 결정을 유지한다.

구독은 1인 운영 계획과 스토어/서버 검증 순서를 문서화하고, 상품 준비 이전에는 결제·유료권한·문의 접수를 성공한 것처럼 표시하지 않는다. 실제 기기 완료·앱 OS 종료·재실행 복원은 별도 확인 절차로 제공하며 자동 테스트와 구분한다. 상세 최신 계약은 [9/8 기능 검증](2026-09-08-feature-verification.md)의 문서 지도를 따른다.


## 9/8 로컬 완성 기능 확정

사용자의 “모두 문서 작성 후, 기능 구현” 요청을 [여섯 기능 명세](2026-09-08-local-completion.md)로 구체화했다. 운동 기록 파일 백업/검토 후 복원, 기록 보호를 적용한 미래 일정 변경, 출처 확인 후 이전 중량·단위·반복의 초안 복사, 관리자 반복 범위·세트 종류·일괄 수정·보관·버전 복구, 저장 성공 이후 자동 휴식과 사용자 기본 시간, 기본24종목·용어9개의 오프라인 가이드를 제공한다. 시행 정책·취소/실패·저장 형식과 실제 검증은 해당 문서 및 기능별 보고서를 따른다.

계정/원격 배포/결제/실제 문의/OS 알림은 별도 범위로 유지하며, 프로그램5개와 기존 계획 스냅샷을 소급 수정하지 않는다. 실제 기기 시험은 [LC-D01~14](2026-09-08-device-test-guide.md)로 별도 기록한다.
