# 9/7 운동 앱 비교와 개선 분석

> 조사일: 2026-09-07 · 대상: `strength_routine` · 공식 자료 조사 + 현재 소스 대조
> 목적: 다음 개발 항목을 고르기 위한 분석. 아래 개선안은 **제안**이며 확정 요구나 구현 완료 목록이 아니다.

후속 문서: [9/7 개선 기능 상세 분석](2026-09-07-feature-specification.md). 이 보고서의 IM01~15를 같은 ID로 이어받아 사용자 흐름·데이터·실패/취소/복원·개발 의존성·수용 기준까지 구체화했다.

## 1. 핵심 판단

우리 앱의 우선 개선 방향은 **선택한 트레이너 프로그램을 쉽게 시작하고, 운동 중 적은 입력으로 정확히 기록하며, 다음 운동에서 그 기록을 다시 활용하는 경험**이다.

현재 코드에는 프로그램 선택·시작, 계획 스냅샷, 실제 세트/초안, 파일 저장·재시도가 연결되어 있다. 여기서 다음 세 가지를 먼저 완성하는 것이 타당하다.

1. **실제로 시작할 수 있는 프로그램과 신뢰할 수 있는 상태.** 카탈로그는 아직 비어 있다. 모든 세트를 제외한 경우에도 카드가 ‘운동 완료’로 표시되는 현재 의미를 정리하고, 미완성 탭과 네이티브 검증도 마무리해야 한다.
2. **운동 중 반복 입력 줄이기.** 지난 실제값을 선택해서 가져오기, 장비 단위 증감, 저장 후 다음 세트, 방해하지 않는 휴식 타이머를 우선 검토한다. Hevy의 이전값/루틴값 구분과 FitNotes의 세트 재사용·이동이 구체적인 참고점이다. [Hevy](https://help.hevyapp.com/hc/en-us/articles/34105442929943-Previous-Workout-Values-Vs-Routine-Values-How-to-Adjust-in-Settings), [FitNotes](https://www.fitnotesapp.com/workout_tracking/)
3. **날짜와 운동 식별을 먼저 정리한 진행 분석.** 현재 예정일과 실제 수행일이 분리되지 않았고, 여러 프로그램에서 같은 종목을 비교할 공통 운동 ID도 없다. 이 기반을 정한 뒤 지난 운동 비교·완료 요약·추세를 만든다. 이는 코드 대조에서 도출한 설계 판단이다. 실제 운동 시각을 보존하도록 명시하는 [Liftosaur API](https://www.liftosaur.com/doc/api)도 참고했다.

입력 부담 감소나 지속 사용 증가의 효과는 아직 측정하지 않았다. 경쟁사의 기능 존재는 참고 근거이고, 우리 앱의 효과는 아래 사용성 검증으로 확인해야 한다.

## 2. 조사 범위와 읽는 방법

**14개 앱**을 역할별로 비교했다. 시장 전체 순위나 점유율 조사가 아니다. 앱마다 겹치는 역할이 있어 아래 분류는 분석을 위한 것이다.

| 조사 묶음 | 앱 | 주로 살펴본 질문 | 상세 자료 |
|---|---|---|---|
| 기록과 비교 | Hevy, Strong, FitNotes, Alpha Progression | 입력을 줄이고 지난 수행을 어떻게 활용하는가? | [기록 앱 조사](../research/2026-09-07/expanded/logging-apps.md) |
| 프로그램과 코치 | Boostcamp, TrainHeroic, ABC Trainerize, Liftosaur | 선택·일정·원래 처방·실제 수행을 어떻게 연결하는가? | [프로그램 앱 조사](../research/2026-09-07/expanded/program-apps.md) |
| 개인화와 안내 | Fitbod, Caliber, RP Hypertrophy App, 번핏 | 시작에 필요한 정보·운동 설명·수행 피드백을 어떻게 제공하는가? | [개인화·안내 조사](../research/2026-09-07/expanded/guidance-apps.md) |
| 국내 서비스 보강 | 플랜핏, 플릭 | 한국어 운동 설명·기구 조건·기록 이후 확인은 어떻게 다루는가? | [국내 앱 조사](../research/2026-09-07/expanded/korean-apps.md) |

근거는 공식 도움말·공식 제품 소개·개발자가 작성한 스토어 설명이다. **공식 페이지 40개**의 본문을 직접 열어 확인했으며 개별 제목·URL·열람일은 각 조사 문서와 [출처 목록](../research/2026-09-07/expanded/sources.md)에 남겼다. 실제 앱 설치·로그인·운동 수행·터치 수 측정·이번 신규 화면 캡처는 하지 않았다. 기존 [DESIGN.md](../DESIGN.md)의 3개 웹 화면 관찰을 이번 14개 앱의 실기 검증으로 확대 해석하지 않는다.

도움말은 구체 동작의 근거, 제품 소개는 제공사의 기능 설명으로 취급한다. 문서에 없는 기능은 **미확인**이다. Strong/TrainHeroic의 일부 도움말은 수정일이 오래되었고, Strong의 Android Focus Metric 출시 범위에는 남은 불확실성이 있다. 가격·별점·이용자 수·운동 효과·‘AI 정확도’는 이번 우선순위 산정에 사용하지 않았다.

## 4. 현재 앱에서 먼저 확인된 공백

세부 코드 근거 15개는 [현재 앱 대조표](../research/2026-09-07/expanded/current-app-audit.md)에 있다. 특히 다음 항목은 새 기능 목록에 가려지면 안 된다.

- **APP01: 콘텐츠 공백.** 일반 실행 카탈로그가 비어 있어 실제 프로그램으로 첫 흐름을 끝낼 수 없다. 등록 도구 개발과 별개로 첫 프로그램의 데이터·버전·처방을 연결해야 한다.
- **APP07: 날짜의 의미.** 과거 예정 운동을 오늘 기록해도 실제로 언제 수행했는지 별도 데이터가 없다. 차트의 x축을 만들기 전에 정리한다.
- **APP08: 완료의 의미.** 모든 필수 세트에 ‘제외’를 입력해도 완료 조건이 참이 된다. 기록 마감과 실제 수행을 분리하고, 운동 횟수 통계는 마감 여부만으로 세지 않는다.
- **APP12: 작동하지 않는 탭.** 검색은 정적 문구와 고정 종목, 습관은 고정 날짜·완료 수다. 실제 사용자 기록처럼 오해되는 표현을 출시 전에 정리해야 한다.
- **APP04: 비교의 기준.** 프로그램 안의 운동 ID와 모든 프로그램에서 공유하는 종목 ID는 다르다. 같은 이름의 변형이나 다른 장비 기록을 섞지 않아야 한다.

저장·초안·스냅샷·재시도·과거 초안 접근은 이미 기반이 있으므로 새로 전면 교체할 이유는 확인되지 않았다. 이번 연구는 이 기반을 확장하는 방향이다.

## 5. 개선 백로그

우선순위는 **P0 실사용 전 해결 / P1 핵심 사용 경험 / P2 콘텐츠·정책에 따라 확장 / P3 이후**다. 작업 크기는 **S 기존 구조의 국소 변경 / M 새 상태·여러 화면·검증 / L 데이터 이행·콘텐츠·플랫폼까지 연계**라는 상대적 추정이다. 일정 약속이나 실측 공수는 아니다.

| IM09 · P1/L | 놓친 운동 수행·일정 재배치 | APP09, TrainHeroic(PROG05), Trainerize(PROG06~07). IM06 및 이동 범위 정책 필요 | 원래 일정·수행 기록 보존, 이동 영향을 확인 후 적용. 세션 ID 유지·중복 방지. 다른 운동을 자동 완료하지 않음 |
| IM10 · P1/M | 기존 완료 집계에 운동별 요약·지난 수행·다음 일정 연결 | APP10, Strong(LOG04), FitNotes(LOG09), 번핏. IM03·06 필요 | 실제 완료/제외·수행일·지난 기록 비교. 초안/목표는 실적 제외, 첫 기록은 비교 없음, 수정 후 다시 계산 |
| IM11 · P1/L | 실제 운동 검색과 수행 가이드 | APP12, 플랜핏(KOR02), Caliber·번핏. 운동 사전/검토된 설명 필요 | 운동명·별칭·장비 검색, 운동 기록에서 가이드 진입 후 초안 유지. 콘텐츠 로딩 실패 시 기록 계속 가능 |
| IM12 · P1/L | 복원용 백업과 분석용 내보내기 | APP11, Hevy(LOG02), Strong(LOG05), FitNotes(LOG10~11) | JSON 백업을 새 설치로 복원, CSV 단위·날짜 명시. 파일 오류/버전 불일치 때 현재 데이터 보존. 복원 범위 미리 확인 |
| IM13 · P2/M | 보관한 프로그램의 실제 기록 정정 | APP13, Strong(LOG07). 정정 정책 필요 | 실제 값만 바뀌고 당시 프로그램/목표 보존, 수정 시각·취소·실패 재시도 제공 |
| IM14 · P2/L | 프로그램 표현 확장 | APP14, Liftoscript(PROG09), 선택한 원작 규칙 | 실제 선정 콘텐츠에 필요한 반복 범위·세트 유형·변동 횟수부터 추가, 기존 저장 파일 이행 검증 |
| IM15 · P3/L | 잠금화면·워치·코치 소통·공유 | Hevy(LOG03), Alpha(LOG15), Caliber·플릭 | 앱 안의 저장/타이머와 같은 상태 사용. 계정·권한·중복 입력 문제까지 검증한 뒤 확장 |

진행 지표 명칭도 분리한다. 기존 D1의 볼륨은 주간 hard set 수이므로, 완료한 모든 세트 수나 중량×반복량을 같은 이름으로 표시하지 않는다. 실제 RIR 등이 없어 hard set 여부를 판단하지 못하는 기록은 미분류 상태를 보존한다.

**조건부 선행 작업:** 선택한 첫 프로그램이 현재 데이터 형식으로 표현되지 않으면, IM14 중 그 프로그램에 필요한 최소 확장을 IM01보다 먼저 수행한다. 일반적인 범용 엔진 확장 전체를 앞당기는 것은 아니다.

P1 안에서도 순서는 동일하지 않다. IM06은 비교·일정·통계의 선행 작업이다. IM08은 비교 차트와 독립적으로 개발할 수 있다. IM12는 사용자가 기록을 본격적으로 축적하기 전에 검증하는 것이 좋다. 필터는 실제 프로그램 수가 적다면 설명 카드부터 적용하고 복잡한 탐색 도구는 늦출 수 있다.

## 6. 권장 개발 묶음과 정책 결정

**다음 묶음 A — 실제 프로그램으로 첫 흐름 검증:** IM01·02·03. 첫 콘텐츠와 일반 실행 상태를 연결하고, 기존 미완료 네이티브 검증을 끝낸다. 통과 조건은 ‘테스트용 데이터 없이 한 프로그램의 시작·기록·종료·복원’이다.

**묶음 B — 운동 중 기록 개선:** IM06의 최소 식별/날짜 계약 → IM07·08, 동시에 IM04·05. 사용자에게는 지난 기록·이번 목표·다음 세트가 명확히 보이는 것이 결과다. 입력 속도는 개선 전후 같은 운동/세트로 비교한다.

**묶음 C — 지속 사용과 기록 소유:** IM09·10·11·12. 놓친 날 복귀, 실제 운동 가이드, 기록 요약·내보내기를 연결한다. IM13·14는 선택한 콘텐츠와 사용자 요구가 구체화되면 포함한다.

개발 전에 사용자 또는 콘텐츠 제공자와 정해야 할 정책은 다음 네 가지다. 이번 조사로 자동 확정하지 않는다.

| 결정 | 제안하는 출발점 | 이유 |
|---|---|---|
| 첫 콘텐츠 | 선정된 한 프로그램의 정확한 버전·기간·처방·콘텐츠 사용 범위부터 | 공통 4주로 바꾸지 않고 데이터 계약의 실제 적합성을 확인 |
| 기록 마감 | 마감 상태와 수행 세트 수를 분리. 필수 입력이 끝나면 종료 요약 제공 | 전부 제외/부분 수행/모두 수행을 구별하면서 기존 기록을 보존 |
| 놓친 운동 | 원래 예정일 보존 + ‘오늘 수행’의 실제 날짜. 나머지 일정 이동은 별도 확인 | 모든 미래 운동이 의도치 않게 밀리지 않도록 영향 범위를 명확히 함 |
| 지난 기록 범위 | 같은 공통 종목·장비/변형·비교 가능한 세트 맥락 우선, 출처 날짜 표시 | 이름만 같은 운동이나 서로 다른 목표를 잘못 비교하지 않음 |

트레이너의 운동·세트 구성을 자동 교체하는 추천, 임의 e1RM/TM 공식, 회복 점수, 소비자 스크립트 편집, 소셜 피드·구독·영양 관리의 확대는 현재 결정만으로 우선 개발하지 않는다. 특히 Fitbod/RP의 적응형 처방은 별도의 제품·훈련 정책이다. 코치가 작성한 진행 규칙을 실행하는 것과 앱이 독자적으로 프로그램을 바꾸는 것도 구분해야 한다.

## 7. 개선을 검증할 방법

모집 인원·기간·성공률 목표는 아직 확정하지 않았다. 우선 현재 버전과 개선 버전을 같은 과업으로 비교해 기준값을 만든다. 분석용 개인정보 수집이나 원격 전송은 이번 조사에서 추가하지 않았다.

| 과업 | 관찰/측정 항목 | 기능 통과 조건 |
|---|---|---|
| 프로그램 고르기 | 선택 이유 설명 가능 여부, 상세→시작 전 되돌아간 이유 | 장비·횟수·필수 입력의 차이를 사용자가 구별 |
| 같은 운동 다음 세트 기록 | 세트당 시간·터치·키보드 호출·오입력 정정 | 값 재사용 후에도 목표/실제 구별, 실패 시 값 유지 |
| 앱 전환 후 돌아오기 | 돌아온 위치·타이머 오차·초안과 완료 상태 | 마지막 편집 대상/초안 보존, 중복 완료 없음 |
| 놓친 운동 오늘 하기 | 원래 일정과 실제일 이해, 미래 일정 변화 | 사용자가 선택한 범위만 변경, 지난 기록 유지 |
| 전부 제외 후 마감 | ‘수행했는가’와 ‘기록을 마쳤는가’ 이해 | 수행 0세트를 완료 실적으로 과장하지 않음 |
| 완료 뒤 기록 정정·비교 | 이전값과 수정값 구별, 비교 기준 설명 | 저장 후 재실행에도 정정 유지, 요약 재계산 |
| 새 설치로 백업 복원 | 계획·실제·초안·단위·날짜 비교 | 원본 파일 손상 없이 동일 데이터 복원, 실패 시 기존 데이터 유지 |

실기 확인에는 작은 화면·큰 글자·키보드·네트워크 끊김·저장 오류·앱 프로세스 종료를 포함한다. 운동 앱의 잠금화면 기능이 문서에 있다는 사실만으로 우리 앱의 OS 동작까지 검증됐다고 보지 않는다.
