# 9/8 기록 추세 · 중량 감량 제안 · 되돌리기

기준일: 2026-09-08, Asia/Seoul. 사용자가 기록 추세·D5 감량 제안·되돌리기의 실제 구현을 요청한 작업이다. 시뮬레이터는 실행하지 않는다. 아래 초기 수치 정책은 논문의 보편적 처방 공식과 구분한다.

## 범위와 결정

- **기존 확정 유지:** 트레이너의 운동·세트·반복·목표 RIR을 보존한다. 완료한 실제 기록과 원래 계획 목표를 덮어쓰지 않는다.
- **이번 구현:** 프로그램별 실제 중량·반복·RIR 기록 조회, 비교 가능한 기록에 따른 수동 감량 제안, 변경 목록 확인·적용·저장·되돌리기·재시도.
- **초기 제품 정책:** 기존 D5 초안의 최근 3회·차이 1을 채택하고 최대 5% 중량 감량을 제안한다. 사용자가 눌러 적용하며 자동 적용·e1RM 추정·세트/반복 감소는 없다.
- **수행 날짜 한계:** 현재 SetActual에는 수행일이 없다. 날짜는 **계획한 날짜**를 표시하며 실제 수행일·기록 입력 시각을 추정 생성하지 않는다. 순서도 계획일 기준이다.
- **운동 식별 한계:** 같은 계획 안의 `ProgramExercise.id + name + mainLift`가 같은 항목만 비교한다. 이름만 같은 운동을 합치거나 기준중량용 `load.lift`를 운동 종목으로 해석하지 않는다. 글로벌 공통 운동/장비/변형 식별자는 새로 만들지 않았다. 프로그램 작성자는 서로 다른 운동에 같은 조합을 재사용하지 않아야 한다.
- 지난 프로그램은 별도 선택해 조회하고 현재 프로그램의 신호와 합치지 않는다. 보관 계획에는 새 감량 제안을 생성하지 않는다.

## 추세 계산

1. 선택한 계획에서 오늘 이전/오늘로 예정된 운동 발생 항목을 순서대로 읽는다.
2. 실제 `completed` 세트만 중량·반복·평균 RIR에 반영한다. 해당 세트에 수정 초안이 있으면 확정값과 초안을 섞지 않고 계산에서 제외한다.
3. `skipped`, 미기록, 초안을 구분한다. 제외 또는 누락을 0kg 수행으로 채우지 않는다. 실제 0kg는 유효한 수행 세트다.
4. lb는 `1 lb = 0.45359237 kg`로 계산하며 저장 원단위/원수치는 바꾸지 않는다. 표시만 소수 두 자리까지 반올림한다.
5. 세션별 실제 최대 중량, 수행 세트 수, 총 실제 반복, 평균 실제 RIR과 입력 세트 수를 보여준다. RIR 누락은 평균에서 제외하며 0으로 채우지 않는다.
6. 최대 중량 막대는 입력된 중량의 변화다. 반복 수가 다를 수 있으므로 근력 상승률·e1RM·성과 점수라고 부르지 않는다. 외부 중량×반복량을 D1의 hard-set 볼륨이라고 표시하지 않는다.

## D5 제안 조건

정책 ID: `d5-3x1-5pct-v1`.

- 같은 활성 계획·같은 운동의 **계획일순 최근 3개 발생 항목**을 본다. 비교 불가능한 최신 회차를 건너뛰고 오래된 유리한 기록을 모으지 않는다.
- 각 회차의 전체 필수 세트가 실제 완료되어 있고 수정 초안이 없어야 한다. 제외는 실제 완료로 취급하지 않는다.
- 대상 운동의 필수 세트 모두 목표·실제 RIR이 있어야 하고, 실제 반복 수가 그 세트 목표 반복 수와 같아야 한다.
- 각 회차에서 필수 세트의 `목표 RIR − 실제 RIR` 평균이 1 이상인 상태가 3회 연속이어야 한다.
- 적용 또는 되돌린 조정 이력이 있으면 그 적용일 이후의 새로운 계획 회차 3개를 기다린다. 같은 근거로 반복해서 감량하지 않는다.
- 대상은 같은 운동의 **오늘 이후, 실제값과 초안이 없는, kg 목표가 있는 세트**다. 수동 중량·오늘·지난 세트·완료·제외·초안은 그대로 둔다.
- `현재 유효 목표 × 0.95`를 장비 최소 증량 단위로 **올림**한다. 실제 감소율이 5%를 넘지 않는다. 결과가 현재와 같거나 0이면 그 세트는 바꾸지 않는다. 최소 한 세트가 바뀔 때만 제안을 표시한다.

세션/세트의 반복·RIR·순서·필수 여부·날짜를 변경하지 않는다. 중량의 실제 변경량은 적용 전 날짜별 `이전 → 이후 kg` 목록에서 확인한다. 명시적으로 ‘취소’를 선택하면 상태를 저장하거나 바꾸지 않는다.

## 저장 계약과 원본 보존

[상태 모델](../lib/domain/training_program.dart)에 `loadAdjustments` 이력을 추가했다. `ActiveTrainingPlan`의 `targetKgBySetId`와 `SetActual` 구조는 그대로다.

| API/필드 | 역할 |
|---|---|
| `state.effectiveTargetKg(set)` | 원래 목표 위에 현재 유효한 조정값만 반영하여 표시한다. 실제 입력값을 자동 생성하지 않는다. |
| `TargetLoadAdjustment.beforeKg / afterKg` | 영향을 받은 세트별 원래 유효 목표와 조정 목표. 변경 목록 자체를 저장한다. |
| `evidenceSessionIds / evidenceRirGaps / evidenceRecords` | 제안의 근거 회차·평균 차이·당시 실제 기록 JSON을 보존한다. |
| `appliedOn / undoneOn` | 조정 동작의 달력 날짜다. 운동 수행 날짜가 아니다. |
| `withLoadAdjustment` | 동일 ID 또는 같은 운동·근거 회차의 중복, 바뀐 근거, 오래된 날짜/계획/목표, 새 실제값/초안을 다시 검사한다. |
| `undoLoadAdjustment` | 대상 전체를 한 번에 되돌리며 되돌린 사건도 이력에 남긴다. |

`copyWith`, 새 계획 시작, 실제 기록/초안/메모/완료 안내 갱신에서도 이력을 보존한다. 기존 상태 JSON에 `loadAdjustments`가 없으면 빈 이력으로 읽는다. 상태의 새 필드가 명시되어 있으나 잘못된 경우 조용히 무시하지 않는다. 루트 통합의 `LocalTrainingStore`는 envelope v1/v2를 읽고 v2로 저장한다. 구버전 앱이 새 조정 필드를 모른 채 덮어쓰는 상황을 줄이기 위해 쓰기 버전을 올렸으며, 미지원 미래 버전은 거부한다.

## 되돌리기와 충돌

- 같은 활성 계획의 대상이 **모두** 여전히 미래이고 실제값/초안이 없어야 한다.
- 하나라도 오늘·과거가 되거나 실제값/제외/초안이 생기면 전체 되돌리기를 차단하고 이유를 표시한다. 일부만 몰래 되돌리지 않는다.
- 같은 세트에 이후 조정이 있으면 이후 조정을 먼저 되돌린다. 순서가 깨진 목표 체인을 저장하지 않는다.
- 이미 되돌린 제안은 같은 근거로 재적용하지 않는다. 근거 기록을 나중에 수정해도 과거 조정의 근거 스냅샷을 다시 쓰지 않는다.
- 새 제안 표시 설정을 꺼도 기존 조정과 되돌리기 기능은 남는다.

## 저장 실패와 재시도

`controller.update`로 이력을 포함한 전체 상태를 한 번 저장한다. 컨트롤러의 기존 정책에 따라 최신 상태는 메모리에 먼저 반영되며 파일 쓰기 실패 시 입력/조정을 롤백하지 않는다.

- 적용 실패: 제안이 중복 생성되지 않고 적용 이력과 미저장 안내·재시도 버튼이 남는다.
- 되돌리기 실패: 메모리의 되돌린 상태와 안내가 남고 동일 전체 상태를 재시도한다.
- 재시도 성공 후에만 저장 성공 안내를 표시한다.
- **프로세스 종료 후 복원은 마지막 영구 저장 성공분까지만 보장한다.** 실패한 최신 적용/되돌리기는 앱 메모리에만 있을 수 있다. 디스크 장애에서 자동 복구하거나 모든 종료 시점의 저장을 보장한다고 표현하지 않는다.

- 빈 계획/기록, 불러오기, 읽기 실패, 미저장, 제안 없음/설정 꺼짐, 적용/되돌림/되돌리기 불가를 구분한다.

저장 실패 테스트는 임시 파일 위치를 디렉터리로 바꿔 쓰기 실패를 주입한다. 이 테스트의 보장은 메모리 상태 유지와 재시도 후 복원이며, 실패 직전 디스크 바이트의 보존이나 모든 파일 손상 자동 복구를 입증하지 않는다. 통합 테스트에서 v1→v2 envelope 이행, 새 컨트롤러의 실제 운동 상세에 조정 목표 표시, 되돌린 목표 복원을 확인했다. [최종 검증 문서](2026-09-08-feature-verification.md)와 [실기기 절차](2026-09-08-device-test-guide.md)에 자동 검사와 미실행 기기 검사를 구분한다.

## 남은 경계

- 실제 수행일·공통 글로벌 운동/변형/장비 ID가 없어 계획일순·계획 내부 식별로 제한된다.
- RIR은 주관적인 입력이고 이상치/통증/피로/회복 원인을 진단하지 않는다. 수행 조건이나 목표 반복이 다르면 단순 중량 막대를 근력 변화로 해석하지 않는다.
- 실제 입력 중량이 목표 중량과 달랐는지를 별도 신호로 판정하지 않는다. 사용자가 기록한 RIR을 기준으로 제안 내용을 직접 검토한다.
- 비교 가능한 필수 RIR 데이터가 부족하거나 5% 범위 안에서 장비 단위로 낮출 수 없으면 제안이 없어도 오류가 아니다.
- 트레이너별 정책, 자동적용, 볼륨 조절, e1RM 추정, 보관 계획 정정, 네이티브 종료 시점/OS 장애는 이번 범위가 아니다.
