# 9/8 · 관리자 기능 문서 대조 리뷰

검토일: 2026-09-08. 대상 커밋: `5eaaed8`. 기능 코드·기존 문서·기존 테스트를 수정하지 않았다. 시뮬레이터와 네이티브 앱을 실행하지 않았다. 아래 신규 probe는 일반 `test/` 밖에 두었고, 현재 오동작을 관찰하는 테스트이므로 수정 후 회귀 테스트로 사용할 때 기대값을 반대로 바꿔야 한다.

## 결론

관리자 편집은 입력칸만 있는 단계가 아니다. 독립 주차/세트, 원문 초안, 50단계 undo/redo, 검토 후 확정, 실패 시 이전 카탈로그 보존, 일괄 수정, 보관, 불변 버전 이력 및 새 버전으로 복구까지 실제 모델·파일·화면 경로가 연결되어 있다. 새 필드의 소비자 전달과 스키마 구분도 구현되어 있다. 다만 같은 편집 화면에서 연속으로 개정할 때 사용했던 버전을 놓치는 UI 오류 1건을 재현했다. 주요 과거 문서 세 개는 LC04 구현 전 상태를 최신 계약처럼 안내하므로 문서 정합성은 보완해야 한다. 기존 시험 한 건은 병렬 묶음에서 시간초과하고 단독으로 통과해, 자동 검증의 안정성도 개선 여지가 있다.

## 확정 코드 결함

### ADM-01 · P2 · 연속 개정 뒤 과거 버전을 검토 단계에서 걸러내지 못한다

- 위치: `lib/admin/detailed_routine_screen.dart:227–230`(성공 후 최신 카탈로그만 갱신), `:210–213`(생성 당시 `widget.versionHistory`로 충돌 검사), `:1128–1131`(일반 저장 실패로 축약).
- 최소 재현: 이력이 없는 구 작업/초기 카탈로그의 v1을 열고, 동일 편집 화면에서 v2를 검토·저장한다. 화면을 나가지 않고 버전을 다시 v1로 입력해 변경 검토한다.
- 기대: 이미 쓴 버전임을 편집 화면에서 설명하고 새 버전을 입력하도록 막는다.
- 실제: 프로그램 변경 검토로 진입한다. 저장 시 `AdminWorkspace.withProgram`은 충돌을 정상 거절하지만 화면에는 일반 저장 실패와 `카탈로그 저장 재시도`만 보인다. 재시도해도 같은 충돌이므로 성공할 수 없다.
- 영향: 이력/카탈로그 파일은 보호된다. 데이터 손실은 아니다. 운영자는 파일 쓰기 오류로 오해하기 쉬우며 뒤로 돌아가 버전을 바꿔야 한다는 원인을 받지 못한다. 초기 이력이 있더라도 같은 화면에서 v2→v3→v4 저장 후 새로 생긴 v3을 재사용하면 같은 원리로 발생한다.
- 수정 방향: 화면 안에서도 사용한 `(programId, version)` 집합/버전 이력을 저장 성공 때 누적하거나, 검토 단계에서 최신 workspace 버전 목록을 조회한다. 저장 callback 결과도 버전 충돌과 일시 파일 실패를 분리해 재시도 가능한 오류만 재시도로 안내한다.
- 증거: [probe 소스](review_admin_probe_test.dart.txt), [실행 로그](admin-probe-tests.txt). 1개 관찰 테스트 통과, 8초. 첫 v2 성공 이후 v1 재사용이 검토에 들어가고 저장 및 재시도 두 번 모두 거부되는지, 최종 카탈로그 v2와 두 버전 이력이 보존되는지 확인했다. 실제 root의 저장 보호와 동일한 `AdminWorkspace.withProgram`을 callback으로 사용한 위젯 시험이다.

## 테스트 재실행과 한계

실행 위치는 macOS 호스트의 앱 루트다.

```sh
/opt/homebrew/bin/flutter test test/local_admin_extension_test.dart test/local_admin_extension_screen_test.dart test/detailed_admin_integration_test.dart --reporter expanded
/opt/homebrew/bin/flutter test test/local_admin_extension_screen_test.dart --plain-name '이력에서 과거 구성을 불러와 새 버전으로 저장하고 과거 스냅샷을 보존한다' --reporter expanded
cp research/2026-09-08/review/review_admin_probe_test.dart.txt test/review_admin_probe_test.dart
/opt/homebrew/bin/flutter test test/review_admin_probe_test.dart --reporter expanded
mv test/review_admin_probe_test.dart research/2026-09-08/review/review_admin_probe_test.dart.txt
```

- 기존 관리자 묶음: **31개 중 30통과·1시간초과, 19초**, [로그](admin-regression-tests.txt). 신규 모델/일괄/보관/이력/D5 20개, 신규 화면 7개, 기존 통합 4개 구성이다.
- 실패한 이력 복구 단독 재실행: **1개 통과, 2초**, [로그](admin-history-isolated-tests.txt). 이 결과로 처음 실패를 지우지 않는다.
- 실패 지점: `test/local_admin_extension_screen_test.dart:425`, 저장 버튼 후 `settle()`의 `pumpAndSettle timed out`. helper `:61–68`은 실시간으로 10×5ms만 기다린 뒤 fake async의 settle로 전환한다. 남은 실제 파일 I/O가 이보다 오래 걸리면 화면의 busy animation이 계속되어 timeout이 날 수 있다. 이번 증거로 버전 복구 기능 자체의 영구 실패를 확정하지 않는다. 테스트 대기는 저장 완료 Future/관찰 가능한 완료 상태를 명시적으로 기다리게 개선하는 것이 적절하다.
- 데이터 보존: 기존 파일 저장/재로딩·보관 export 제외·과거 이력 불변·새 버전 복구가 도메인 및 단독 UI 시험에서 확인된다.
- 시각 검토: 기존 실제 폰트 렌더 `local-admin/final/bulk-mobile-large.png`와 `range-mobile-large.png`를 직접 열어 보았다. 일괄 대상/변경 수, 적용/취소 계층은 명확하고 반복 하한/상한은 인접해 있다. 이는 기존 headless 결과 재검토이며 이번 실제 기기 렌더를 새로 수행한 것이 아니다.
- 미검증: 네이티브 내부 앱의 장시간 편집, 실제 IME/키보드·스크린리더, 52주 최대 구성 성능, 다중 프로세스 공동 편집, 전원 차단. 여러 운영자/서버 로그인/온라인 배포는 명시 범위 밖이므로 미구현 버그로 보고하지 않는다.

## 우선 처리 순서

1. ADM-01의 편집 세션 버전 목록을 누적하고 충돌 원인을 해당 화면에 전달한다.
2. ADM-DOC-01의 현행 범위/스키마 연결을 통일한다.
3. 파일 저장 UI 시험의 고정 실시간 지연을 명시적 완료 대기로 바꿔 다시 검증한다.
4. 이후 사용자 허용 시 실제 내부 앱에서 작성→검토→저장→내보내기 및 OS 재실행을 수행한다.

루트 검증 결과(담당 에이전트 전달): 동일 리뷰에서 기존 전체 349개가 137초에 통과했고 `flutter analyze`는 정상이었다. 따라서 위 관리자 묶음의 일회성 timeout은 전체 기능 실패나 349개 검증 부정을 뜻하지 않으며, **검증 도구 신뢰성에 대한 별도 관찰**이다. 고정 실시간 대기와 실제 I/O의 경합은 코드와 실패 위치에 근거한 원인 추정이며, 의도적인 저장 지연 주입으로 원인을 확정하는 추가 시험은 수행하지 않았다.

보관 확장자는 `.dart.txt`로 정리했다. 원래 관찰 실행은 로그의 research 경로에서 수행했으며, 위 명령은 일반 Dart 분석에 증거 파일을 섞지 않고 이후 재현하는 방법이다.
