## W01 · P2 · 최초 완료 저장 실패 뒤 기본 저장 버튼을 쓰면 자동 휴식이 빠진다

위치: [workout_screen.dart](../../../lib/workout_screen.dart) 1142행, `_SetEditorState._commit`의 `_autoRestPending` 재계산. 관련 상태 정책: [training_controller.dart](../../../lib/app/training_controller.dart) 129행.

문서 계약: 휴식·가이드 §1과 §7은 실제 기록이 없던 세트의 완료 저장 성공 후 자동 시작을 한 번 시도하며, 운동 저장 실패 후 재시도는 최초 완료가 확정되는 시점에 시작한다고 명시한다.

재현 순서:

1. 기본 휴식 90초·자동 시작 켜짐 상태에서 아직 실제 기록이 없는 세트에 중량 20·반복 5를 입력한다.
2. 운동 파일 쓰기를 막고 `세트 완료`를 누른다. 저장 실패가 표시되고 타이머는 시작되지 않는다.
3. 쓰기를 복구한 뒤 전용 `저장 다시 시도` 대신 화면에 그대로 활성화되어 있는 기본 `수정한 기록 저장`을 누른다.
4. 운동 파일에는 완료 기록이 영구 저장되며 편집 시트가 닫히지만 `restTimer.available`은 `null`이다.

원인: `TrainingController.update`는 파일 저장 전에 메모리 실제값을 `completed`로 반영한다. 최초 쓰기가 실패해도 이 후보는 유지된다. 두 번째 기본 저장 동작에서 `_commit`은 이 메모리 값을 기존 완료로 판단하고 기존 `_autoRestPending == true`를 `false`로 덮는다. 전용 재시도 버튼의 `_retry`는 이 플래그를 덮지 않아 현재 기존 시험은 통과한다. `저장하고 다음 세트` 역시 `_complete` → `_commit` 경로이므로 같은 원인을 공유한다. 추가 위젯 시험에서 직접 조작한 버튼은 기본 `수정한 기록 저장`이다.

영향: 설정한 자동 시작 동작이 저장 실패 복구 경로에 따라 달라진다. **운동 기록은 보존된다. 수동 휴식 시작은 계속 사용할 수 있다.** 타이머가 중복 실행되거나 운동 기록이 사라지는 결함으로 분류하지 않는다.

수정 방향: 처음 저장할 때의 실제 완료 상태와 미확정 신규 완료 후보를 구분하고, 같은 신규 완료의 재저장에서는 자동 시작 대기를 유지해야 한다. 제외·완료 취소·다른 세트/계획 전환 때는 대기를 해제하며, 저장 성공 후 실행은 여전히 한 번으로 제한한다. 대안으로 오류 중에는 전용 재시도만 허용할 수 있으나 현재 편집/저장 UX에 대한 명시적 결정이 필요하다. 이번 리뷰에서는 수정하지 않았다.

검증: 기존 시험의 실패 주입을 재사용하고 재시도 버튼만 바꾼 위젯 시험에서 재현했다. 초기 재현 2회와 helper를 줄인 최종 재현 1회에서 동일 실패를 확인했다. 최종 시험은 실패 직전 `LocalTrainingStore(file).load()`를 호출해 디스크의 단일 실제 기록이 `completed`인 것을 별도로 확인한다.

수정 방향: 과거 구현 당시 결과는 날짜가 있는 이력으로 보존하고, 최상단에 현재 정책/스키마 및 후속 명세 링크를 두며 D5 조건과 남은 경계를 현재형으로 정리한다. 코드 버그를 문서에 맞추기 위해 되돌리는 방향은 적절하지 않다.

## 문서별 상세 대조

- `ProgramSet`의 휴식·템포·AMRAP과 `ProgramExercise.supersetGroup`이 계획 스냅샷에 보존된다.

- `session.executionSets`를 다음 입력 이동에 사용해 3세트/2세트인 두 운동도 교차 순서로 이동한다. 완료/제외 항목은 건너뛴다.

### 휴식 설정·운동 가이드

- `resolveRestSeconds`의 null 병합으로 처방 미지정만 기본값으로 대체되며 명시 0은 보존된다.
