# Strength 인터랙티브 랜딩 — 시각 레퍼런스와 5개 구성안

열람·캡처: 2026-09-08 (Asia/Seoul). 조사 범위는 공개 웹페이지이며, 앱 설치나 로그인은 하지 않았다. 프로젝트 소스, Sites, 배포, Git은 변경하지 않았다.

관찰 환경: Chromium headless, 1440×1000 CSS px, DPR 1. WebGL은 SwiftShader로 렌더했다. Linear 재확인은 브라우저의 `prefers-reduced-motion: reduce`를 사용했다. 아래 캡처는 모두 이미지 뷰어로 직접 확인했다. 픽셀 크기·색 비중은 캡처에 대한 육안 추정이며 실제 CSS 측정값이나 Strength 토큰이 아니다.

### VIS01 — 입력 하나와 큰 오브젝트의 직접 연결

- **타입 대비:** 작은 모노 설명과 좁은 GUI가 큰 신발 모델에 시선을 양보한다. 화면 중앙에 별도의 대형 카피를 겹치지 않는다.
- **여백·색 비중:** 배경 환경이 캔버스 전체를 채우고 중앙 모델 주위 공간이 넓다. 모델은 대략 화면 폭 절반 이상, GUI는 우상단의 작은 면적이다. 사진형 배경의 팔레트는 Strength로 가져오지 않는다.
- **관찰한 주동작:** 모델 로딩 후 실제 `<select>`를 `midnight`에서 `beach`로 변경했다. 같은 형상·각도에서 원단과 가죽의 색이 청록에서 베이지로 바뀌었다. 두 유효 캡처가 그 결과를 보여준다. 형상 변경이나 포인터 회전은 이번에 검증하지 않았다.
- **Strength 번역:** 01 바벨 로드에서 선택한 중량이 플레이트 구성과 읽을 수 있는 총중량에 함께 반영되게 한다. 오브젝트가 크고 조작부는 작아도 입력값과 결과는 분명해야 한다. 이는 설계 제안이다.

### VIS02 — 같은 크기로 비교하는 제품군

- **타입 대비:** 큰 제품군 제목, 그보다 작은 제품명, 더 작은 메타 정보가 차례로 구분된다. 제품 이미지가 설명문보다 먼저 보인다.
- **여백·색 비중:** 같은 폭의 3개 이미지가 넓은 간격과 비슷한 시각 크기로 나열된다. 흰색·중립 영역이 대략 70–80%이고 제품 이미지가 색을 담당한다.
- **관찰한 주동작:** 제품군 탐색 화면을 확인했다. 이미지 아래 작은 색상 표식은 보이나 실제 선택 동작은 확인하지 않았다. 원래 요청한 `/shop/studio/apple-watch`는 제품군 페이지로 이동했으므로 **Apple Watch Studio 구성기를 체험한 근거로 사용하지 않는다.**
- **Strength 번역:** 02 프로그램 카탈로그에서 실제 프로그램을 동일한 크기·정보 순서로 비교한다. 선택 항목의 확대, 좌우 탐색, 기간·빈도·운동 구성의 동시 갱신은 새로운 설계 제안이다. 흰색 팔레트와 제품 이미지는 사용하지 않는다.

### VIS03 — 넓은 제품 화면으로 기능을 설명

- **타입 대비:** 좌측 대형 제목 아래 작은 설명, 그 아래 전체 폭의 제품 표면이 이어진다. 제품 내부는 작은 라벨과 숫자로 밀도를 유지한다.
- **여백·색 비중:** 히어로 좌우 여백은 약 80px, 제목 위 공간은 약 200px다. 검정·회색이 대부분이고 상태색은 작다. 제품 표면 안에 사이드바·상세·보조 패널을 겹친다. 계획 영역은 캘린더와 차트가 크게 중첩된다.
- **관찰한 주동작:** 스크롤로 제품과 계획 영역을 이동했다. 패널 내부의 편집·데이터 변경은 확인하지 않았다.
- **Strength 번역:** 03 일정은 공간 안에 시간 구조를 펼치고, 05 감량 적용은 전체 폭 그래프에 변경 전후와 되돌리기를 연결한다. 큰 카피와 넓은 증거 화면을 순서대로 둔다. Linear의 어두운 비활성 데이터 대비를 그대로 복사하지 않고 Strength의 실제 정보는 읽히게 만든다.

### VIS04 — 기록의 효용을 한 장면으로 보여주기

- **타입 대비:** 짧은 기능 표식, 두 줄 제목, 본문, 버튼의 위계가 명확하다. 오른쪽의 작은 휴대폰 화면에는 이전 값·실제 입력·완료 행이 함께 보인다.
- **여백·색 비중:** 흰색이 대략 80% 이상이고 액션은 파란색, 완료 행만 밝은 초록색이다. 두 열 사이 공간이 넓어 한 가지 기능에 집중한다.
- **관찰한 주동작:** 웹의 내장 앱 화면 이미지에서 숫자 키보드와 완료 상태를 확인했다. **Contextual:** 공식 본문은 이전 값을 눌러 현재 입력에 가져오는 동작을 설명한다. 이를 직접 앱에서 수행하지 않았다.
- **Strength 번역:** 04 두 세트 기록 시안에서 입력값·완료 표시·다음 세트 이동을 한 장면으로 보여준다. 과거 값과 새 실적은 명확히 구분한다. 참고 앱의 화면·평점·성과 수치는 사용하지 않는다.

## 5개 시안으로 옮기는 방법 — 모두 설계 제안

출처는 표현 원리의 근거이며 아래 동작을 해당 사이트에서 모두 관찰했다는 뜻이 아니다. 실제 Strength 데이터·기능 범위는 구현 시 현재 앱 계약과 대조한다. 3D 형태는 직접 만든 지오메트리로 구성하고 외부 제품 이미지나 모델을 가져오지 않는다.

| 시안 | 주목적·레이아웃 분류 | 화면 구조 | 입력 → 보이는 결과 | 적용 근거 |
|---|---|---|---|---|
| 01 금속 바벨 로드 | 중량 설정을 이해 — Hybrid | 캔버스가 화면 중심을 차지하고 하단 고정 조작부가 받침 역할. 카피는 짧은 상단 표식으로 제한 | 중량 선택 → 플레이트 수·폭·배치와 DOM 총중량이 함께 변경. 지원하지 않는 구성은 명시 | VIS01의 큰 물체와 작은 실제 제어 |

| 03 입체 4주 캘린더 | 요일 선택의 일정을 이해 — Fluid | 4주 날짜 타일을 넓게 펼치고 요일 선택 줄을 위에 둠. 모바일에서는 같은 순서의 2D 그리드 | 요일 선택 → 해당 일정 타일과 날짜별 세션이 재배치. 휴식일·운동일을 색과 기호로 구분 | VIS03의 넓은 시간 구조 |
| 04 두 세트 기록 패널 | 실제 기록 완료를 경험 — Hybrid | 중앙 수직 패널 두 장이 순서를 보이고 활성 세트가 앞쪽에 위치. 입력 조작은 읽기 쉬운 평면 DOM | 중량·반복 입력 후 완료 → 첫 패널 상태 고정·다음 패널 활성화·집계 변경. 마지막은 목록 또는 현행 요약 | VIS04의 한 장면 효용 + VIS03의 패널 깊이 |
| 05 감량 적용·Undo 그래프 | 변경과 복구를 이해 — Fluid | 전체 폭 그래프가 주인공. 아래에는 원래/제안/적용 상태와 되돌리기 조작을 시간 순서로 배치 | 제안 적용 → 실제 대상 범위의 수치·그래프 변경. Undo → 이전 수치·그림 복구. 버튼 상태도 함께 전환 | VIS03의 큰 차트와 제한된 상태색 |

## 공통 스타일·동작 기준

- Console v2의 dark/cyan 토큰과 기존 컴포넌트를 사용한다. 한글은 IBM Plex Sans KR, 라틴·숫자는 IBM Plex Mono로 분리한다. 숫자는 세로 정렬하며 단위를 항상 붙인다.
- cyan은 선택·현재 위치·주요 데이터에 집중한다. 금속은 중립 재질과 조명 대비로 표현하고 다색 글로우나 유리 카드로 대체하지 않는다.
- 입체 장면은 실제 입력 상태를 나타내야 한다. 입력 없이 반복되는 장식 회전만으로 인터랙티브라고 설명하지 않는다.
- 클릭 가능한 오브젝트에는 같은 기능의 이름 있는 DOM 버튼을 둔다. 숫자·결과·오류는 캔버스 밖에서도 읽히게 한다. 키보드 선택과 `prefers-reduced-motion`에서는 이동·기울기를 줄인다.
- 로딩은 정보 틀과 로딩 상태를 먼저 제공한다. WebGL 실패는 2D 정적 형태와 동일한 조작·결과로 대체한다. 데이터 없음은 샘플임을 명시하거나 빈 상태를 보여준다.
- 실제 저장을 하지 않는 랜딩 체험은 체험임을 밝힌다. 목표·초안·실적을 혼합하지 않고, 저장 실패 상태에서 완료처럼 보이지 않게 한다. 체험 초기화는 사용자 기록 삭제로 연결하지 않는다.
- 감량 제안은 제품의 현재 규칙과 범위를 설명하며 결과를 보장하는 수치를 만들지 않는다. 완료·제외·미기록과 0 중량 의미를 보존한다.
- 시안마다 최소 두 입력 상태와 좁은 화면을 캡처하여 제목 줄바꿈·컨트롤 겹침·가독성·선택 결과를 직접 검토한다. 이 항목은 구현의 검증 기준이며 이번 조사에서 Strength 시안을 실행했다는 뜻은 아니다.

## 증거 품질과 제한

- `three-variants-before.png`는 모델 로딩 전 배경만 보여 **제외**한다. 유효한 비교는 `three-loaded-midnight.png`와 `three-loaded-beach.png`다.
- `linear-before.png`는 애니메이션/렌더가 끝나기 전으로 내용이 비어 **제외**한다. 재확인의 `linear-loaded-hero.png`를 사용한다. 브라우저에 React hydration 오류가 기록됐으므로 사이트 전체 정상 작동을 검증했다고 주장하지 않는다.
- Apple 색상 표식, Linear 내부 도구, Hevy 네이티브 기록 입력은 실제 상호작용을 검증하지 않았다. 시각 관찰과 공식 설명을 구분했다.
- 데스크톱 한 해상도에서 조사했다. 모바일 레이아웃·성능·스크린리더·포인터 회전·실제 기기 GPU는 미검증이다.
- 스크린샷은 브라우저 출력만 저장했다. 외부 사진·폰트·모델 파일을 자산으로 내려받지 않았다. 사이트 로고·카피·제품 이미지·고객 실적을 Strength 소재로 재사용하지 않는다.
