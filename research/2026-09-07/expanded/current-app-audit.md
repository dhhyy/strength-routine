# 9/7 현재 앱 대조표 · 코드로 확인한 상태

기준: 2026-09-07 추가 개발 직후 작업 디렉터리. 커밋을 만들지 않은 상태이며 아래 행 번호는 이 시점 기준이다. **소스 대조 결과**로, 실제 사용자가 얼마나 불편한지 측정한 결과가 아니다. 이번 조사는 앱 코드를 변경하지 않는다.

## 유지해야 할 기반

- 프로그램 원본·버전·시작 입력·확정 날짜·목표 중량의 스냅샷.
- 계획/실제/초안 분리, kg/lb·RIR·메모·완료/제외 저장.
- 로컬 파일 직렬 저장·임시 파일 교체·손상 파일 보존·오류 재시도.
- 오늘/달력/프로필의 실제 데이터 연결, 과거 초안에 달력으로 접근 가능.
- 이전 개발 단계에서 정적 분석과 39개 테스트 통과. 이번 문서 작업에서 테스트를 다시 실행한 것은 아니다. 네이티브 렌더·사용자 조작·종료 후 복원 관찰은 Mac 잠금 때문에 미완료로 남아 있다.

## 판단할 때 지켜야 할 경계

- 위 항목을 모두 버그나 확정 요구로 승격하지 않는다. APP01은 콘텐츠 선행 조건, APP08은 현재 문구와 집계 의미의 문제, 나머지는 기능 공백 또는 검증 과제다.
- ‘로그인 없는 로컬 기록’과 ‘클라우드 백업 없음’을 혼동하지 않는다. 현재 로컬 복원 기반을 유지하며 이동/내보내기를 추가할 수 있다.
- 새로운 데이터를 넣으면 기존 `schemaVersion: 1` 파일에 대한 이행 정책을 함께 설계해야 한다. 조사만으로 버전을 올리거나 사용자의 저장 파일을 수정하지 않는다.
- 개선 우선순위와 수용 기준은 [종합 분석](../../../docs/2026-09-07-fitness-app-analysis.md)에 정리한다.
