# 9/7 추가 조사 · 프로그램 중심 운동 앱

조회일: **2026-09-07**. 대상: Boostcamp, TrainHeroic, ABC Trainerize, Liftosaur. 각 공식 사이트/도움말을 검색하고 본문을 직접 열어 확인했다. **앱 설치·로그인·실제 운동 체험은 하지 않았다.** 이미지 링크의 존재만으로 화면을 시각 검증했다고 표시하지 않는다. 문서에 없는 기능은 ‘없음’으로 단정하지 않는다.

이전 [프로그램 레퍼런스](../programs.md)보다 필터의 실제 항목, 처방 변경 표시, 누락 세트 처리, 일정 편집 권한, 상대 일정과 실제 달력, 규칙 시험 실행을 구체화했다. 이번 작업은 조사·문서만 수행하며 앱 코드를 변경하지 않는다. 명시 사실은 페이지별 120단어 이내로 요약했고 긴 인용·전체 프로그램 복제는 하지 않았다.

## 앱별 참고 역할

| 앱 | 이번에 참고한 역할 | 우리 제품과의 경계 |
|---|---|---|
| Boostcamp | 사용자가 프로그램을 비교하고 시작할 확신을 얻는 카탈로그 | 분류와 설명을 참고한다. 다른 서비스의 주차·변형·추천 기준을 자동 수록하지 않는다. |
| TrainHeroic | 코치의 원래 처방과 실제 수행의 차이를 기록하는 운동 화면 | 사용자의 운동 교체·세트 추가 기능은 현행 ‘운동·세트 구성 유지’ 요구와 충돌한다. 차이 표시만 참고한다. |
| ABC Trainerize | 코치와 사용자의 편집 범위, 상대 프로그램 일정과 개인 달력의 구분 | 트레이너 도구 구축은 후속 범위다. 현재 사용자 앱에는 일정·기록 보존 정책을 참고한다. |
| Liftosaur | 프로그램 규칙 표현, 실행 전 검증, 원래 처방과 계산 결과의 구분 | 자유 스크립트·자동 세트 변경·1RM 계산은 현재 범위가 아니다. 데이터 검증과 설명 방식만 검토한다. |

## 현재 앱과 대조한 개선안

아래는 **개발 해석·제안**이며 사용자 확정 요구가 아니다. 현재 코드에서 프로그램 검색·세션 미리보기·계획 스냅샷·목표/실제 표시·저장 재시도를 이미 구현한 부분은 다시 ‘새 기능’으로 제안하지 않는다.

| 우선순위 | 현재 상태 / 문제 | 구체적인 개선 | 근거와 범위 |
|---|---|---|---|
| 1 | `SetActual`에는 수행 시각이 없고 날짜는 계획의 `sessionDates`에서 온다. 지난 운동을 오늘 하면 예정일과 실제 수행일을 구별할 수 없다. `rescheduleFuture`는 오늘/과거 이동을 허용하지 않는다. | 원래 예정일을 보존하면서 실제 수행 날짜·시각을 별도로 저장한다. 놓친 운동에 ‘오늘 수행’과 ‘일정 다시 잡기’를 제공하고 다른 세션에 주는 영향을 미리 보여준다. 기존 기록의 수행일은 알 수 없으므로 마이그레이션 때 임의 추정하지 않는다. | PROG05의 날짜 확인과 PROG10의 실제 시각 보존에서 얻은 해석이다. 경쟁사가 같은 데이터 모델을 쓴다는 주장이 아니다. 운동·세트 구성 유지와 양립한다. |
| 2 | 현재 카탈로그는 이름 검색과 작성자·기간·주당 횟수만 보여준다. `TrainingProgram`에는 목표·수준·필요 장비·예상 시간 메타데이터가 없다. | 트레이너가 제공한 목표·수준·장비·예상 시간을 데이터로 추가한다. 목록은 주당 횟수와 장비를 먼저 비교하게 하고, 필터 0건이면 적용 조건과 해제 방법을 보여준다. 소수 프로그램일 때는 설명 카드만으로 시작할 수 있다. | PROG01·02·08. 추정한 수준/시간을 사실로 채우지 않는다. 장비에 맞춰 운동을 자동 교체하지 않는다. |
| 3 | 상세는 모든 주차를 길게 나열하고 반복 수를 보여준다. 필요한 기록·기준 중량의 의미를 시작 설정에 들어가서 알게 된다. | 상세 상단에 ‘누구에게/필요한 장비/주간 부담/시작 전 필요한 기록’을 요약한다. 주차별 펼치기로 분량을 줄이고 변형이 있다면 작성자가 정의한 별도 버전으로 선택한다. | PROG03·07. 기존 최종 결과 확인 화면을 유지한다. 선택한 주당 횟수에 맞춰 원작 세션을 재작성하지 않는다. |
| 4 | 이미 목표와 실제 값을 나눠 표시하지만, 실제 값이 달랐던 이유와 비율 처방의 기준을 빠르게 확인하기 어렵다. | 기록 행에 ‘목표와 다르게 수행/제외’ 설명과 선택 메모를 유지한다. 목표 kg를 누르면 원래 처방·기준 중량 출처·반올림 간격을 보여준다. 보조·추가 중량의 의미도 향후 운동 메타데이터로 구분한다. | PROG04·09·10. 구성 편집이 아니라 수행 차이를 설명하는 개선이다. 자동 e1RM·회복 판단은 추가하지 않는다. |
| 5 | 프로그램 버전 스냅샷은 이미 보존하지만 실제 카탈로그가 비어 있고, 수록 후보의 복잡한 규칙을 검증하는 공급 과정은 미완성이다. | 수록 전 데이터 검증에서 지원 처방·주차/세션 구조·필수 기준값을 점검하고 실패 이유를 보여준다. 원작 URL·변형·버전·변경 설명을 함께 보관한다. 새 버전은 진행 중 기록을 바꾸지 않고 차이 검토 후 새 시작으로 연결한다. | PROG06·07·10의 알림/변경 전파/시험 실행을 조합한 해석. 현재 스냅샷 보존을 확장하며 트레이너 제작 UI나 범용 스크립트 엔진은 후속이다. |

현재 코드 대조: [프로그램 화면](../../../lib/program_screen.dart), [도메인·기록·일정](../../../lib/domain/training_program.dart), [운동 기록 화면](../../../lib/workout_screen.dart). 파일을 읽기만 했다. 원작 프로그램 선정·수록 조건은 [기존 후보 문서](../program-candidates.md)의 미확정 상태를 유지한다.

## 기존 결정과 충돌하여 그대로 채택하지 않을 것

- TrainHeroic의 자유 운동 교체·세트 추가는 현재 ‘트레이너 운동·세트 유지’ 결정과 다르다. 현재 앱은 목표와 실제 수행의 차이를 기록하되 원작을 재구성하지 않는다.
- Liftosaur의 세트/반복 자동 변경·1RM 계산·소비자 스크립트 편집은 현재 지원 계약을 넘는다. 참조했다는 이유로 엔진 공식을 채택하지 않는다.
- Trainerize의 운영자 중심 설명 공개 범위는 소비자가 스스로 고르는 우리 앱과 다르다. 프로그램 선택에 필요한 설명은 사용자에게 보여야 한다.
- 공개 사이트의 평점·인원·효과·명칭·전체 세트표를 가져와 우리 앱의 콘텐츠나 성과처럼 표시하지 않는다. 기존 토큰/폰트/5탭 결정도 이 조사로 변경하지 않는다.
