# 2026-09-07 · 운동 기록 UX 레퍼런스

조회일: 2026-09-07 (Asia/Seoul). 범위: Hevy·Strong의 공식 제품 도움말. 목적: 프로그램 선택 → 실제 세트 기록 → 앱 재실행 복원에 필요한 동작을 구체화한다.

## 근거 수준

- 아래 관찰은 모두 **공식 문서 본문을 읽어 확인한 상호작용**이다. 스크린샷의 픽셀·레이아웃을 직접 검사하거나 실제 앱을 조작한 결과가 아니다.
- Strong 도움말은 페이지별 최종 수정일이 2021–2022년이다. 조회일에 공개된 문서를 확인했지만 최신 설치 버전과 같은 화면임을 보증하지 않는다.
- Hevy 제품 소개 페이지의 검색 본문은 읽혔으나 직접 열기는 접속 확인 화면에 막혔다. 주요 결론에는 정상 열람한 공식 Help Centre를 사용했다.
- 아래 ‘적용 제안’은 프로젝트를 위한 개발 판단이며 사용자 확정 요구나 경쟁사 기능 자체와 구분한다. 경쟁사 색상·폰트는 가져오지 않고 앱의 Console v2 토큰을 유지한다.

## 미완료 운동 복원: 확인된 사실과 요구 구분

이번 조사에서 **Hevy·Strong이 앱 강제 종료 직후 어떤 복원 화면을 보여주는지, 입력 도중 값과 완료 체크를 어디까지 보존하는지 확인할 공식 문서를 찾지 못했다.** 위 Hevy의 ‘Resume Workout Timer’는 시간 측정 재개이며 앱 재실행 후 데이터 복원 근거로 사용할 수 없다. 따라서 ‘Hevy/Strong처럼 복원’이라고 단정하지 않는다.

재실행 복원은 이 프로젝트의 사용자 확정 첫 마일스톤이다. 다음은 이를 만족시키기 위한 독립적인 구현 제안이다.

1. 진행 중 세션 ID, 프로그램 ID·버전과 시작 당시 계획, 실제 입력과 세트 상태를 로컬에 저장한다.
2. 앱 시작 시 진행 중 세션이 있으면 오늘 화면에 ‘운동 이어하기’를 먼저 보여준다. 복원 실패는 빈 프로그램 상태와 구분하고 재시도 경로를 둔다.
3. 사용자가 세션을 완료하기 전에는 미완료 상태를 유지한다. 부분 기록 후 종료 시 완료한 세트만 실제 수행으로 취급하며 미완료 세트를 자동 완료하지 않는다.
4. 저장 실패 때 ‘저장됨’이라고 표시하지 않는다. 화면의 값을 유지하고 재시도를 제공한다.
5. 데이터 유실을 피하려면 세트 완료 체크뿐 아니라 유효한 입력 변경도 보존해야 한다. 실제 저장 시점·오류 처리는 구현과 테스트에서 확정한다.

## 이번 개발에서 확인할 수용 기준

- 프로그램을 선택하여 시작해도 트레이너의 운동·세트 구성과 버전이 보존된다.
- 계획 중량과 실제 기록이 별도로 저장되며 ‘지난 기록’에 미완료 값이 섞이지 않는다.
- 중량·반복·RIR 입력 → 세트 완료 → 다른 화면 이동 → 재진입 시 값과 상태가 보존된다.
- 앱 프로세스 종료 → 다시 실행 후 진행 중 세션을 이어갈 수 있다. 단순 위젯 재생성 테스트와 실제 재실행 검증을 구분한다.
- 저장 실패·데이터 읽기 실패는 성공 또는 처음 실행으로 가장하지 않는다.
- 운동 완료 후 기록 목록에 한 번만 나타나고, 수정한 기록은 재실행 후에도 수정값을 유지한다.

위 항목은 검증 기준 제안이며 이 문서 작성 자체가 기능 구현 또는 테스트 통과를 뜻하지 않는다.
