# 9/7 프로그램 선택·시작 레퍼런스

조사일: 2026-09-07. 공식 공개 웹페이지와 공식 도움말을 직접 읽었다. 아래의 `문서 확인`은 공개 본문에서 확인한 사실이며, 앱 설치·로그인·구매·실제 운동 실행으로 검증한 것은 아니다. 화면의 색·간격·터치 동작은 이 조사에서 시각 검증하지 않았다.

제품 전제: 사용자는 트레이너가 만든 완성된 프로그램을 선택한다. 운동·세트 구성은 유지하고 중량·시작일·운동요일만 개인화한다. 트레이너 등록 도구는 후속 개발이다. 경쟁사 기능과 아래 개발 제안을 사용자 확정 요구로 간주하지 않는다.

TrainHeroic의 프로그램 배치 문서는 2025-09-02, 세션 변경 문서는 2023-08-08 수정으로 표시되어 있다. 당일 공개 문서의 내용이며 최신 설치 앱과 일치하는지는 미검증이다. TrainHeroic은 완료 세션이 있는 캘린더 복사본 제거 시 데이터가 복구되지 않는다고 명시한다. 이 동작을 우리 앱에서 채택한다는 뜻은 아니다.

## 바로 적용할 개발 제안 5개

1. **선택에 필요한 정보부터 보여준다.** 프로그램 카드에는 이름·트레이너·주당 횟수·기간·장비·수준을 우선하고, 상세에서 세션·운동·세트 미리보기를 펼친다. 초기 카탈로그가 적으면 복잡한 정렬·추천 알고리즘보다 읽기 쉬운 비교가 먼저다. 근거: Boostcamp.
2. **프로그램 선택과 시작 완료를 구분한다.** `목록 → 상세 → 필요한 최근 기록 → 시작일·요일 → 첫 주 확인 → 시작`으로 연결한다. 필요한 기록이 없으면 어떤 기록이 필요한지 설명하고 입력을 보존한다. 주당 세션 수와 선택한 요일 수가 맞는지 검증한다. 근거: TrainHeroic의 배치 개념 + 사용자 확정 개인화 범위.
3. **시작한 버전을 보존한다.** `ProgramDefinition`과 사용자 `Enrollment`를 분리하고 시작 당시 프로그램 ID·버전·정의·개인화 입력을 저장한다. 이후 원본 업데이트는 완료 기록을 덮어쓰지 않는다. 자동 업데이트 정책은 미확정으로 남긴다. 근거: Trainerize가 명시적으로 구분하는 두 전달 방식.
4. **일정 변경의 영향을 좁고 명확하게 보여준다.** 향후 변경 기능에는 ‘이번 운동만 이동’과 ‘남은 일정 변경’을 구분하고, 완료 운동을 보존한다. 첫 구현은 시작일·요일 선택까지만 해도 된다. 휴식 간격은 프로그램 데이터의 정책으로 두며 공통 숫자를 임의 지정하지 않는다. 근거: TrainHeroic의 단일 세션 변경 범위.
5. **트레이너 도구와 소비자 앱 사이에 데이터 계약을 둔다.** 초기에는 로컬 공급자를 써도 ID·버전·작성자·기간·세션·처방 유형·필수 기준 기록을 포함한다. 등록 UI 없이 목록·상세·빈 상태·검증·저장 구조를 먼저 개발할 수 있다. 근거: Liftosaur의 정의/실행 연결과 사용자 확정 후속 개발 범위.

## 채택하지 않은 것과 미확인 사항

- 경쟁사의 사진·로고·세트표·설명문·전체 훈련 프로그램을 앱 에셋으로 복제하지 않았다. 공개 페이지를 읽을 수 있다는 사실은 재배포 권한 확인과 다르다.
- Boostcamp의 자동 증량·결과 개선·사용자 수 등은 서비스 자체 설명이다. 우리 제품의 효과 근거나 수치 처방의 근거로 사용하지 않는다.
- Liftosaur의 완전 편집 기능은 우리 앱의 ‘트레이너 운동·세트 구성 유지’ 요구와 범위가 다르므로 소비자 기능으로 채택하지 않는다.
- 실제 앱의 오프라인 복원, 업데이트 충돌 처리, 삭제 이후 복원, 접근성은 이 조사에서 검증하지 않았다.
- 공개 프로그램 후보와 콘텐츠 준비 판단은 [프로그램 후보](program-candidates.md)에 별도로 기록한다.
